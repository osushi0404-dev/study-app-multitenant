# I200 修正の診断メモ（test-gate の手動 M-05 NG・2026-10-30）

## 失敗分解
- 再現手順: `docs/runbooks/danger-ops.md` の「見張り（pretooluse_guard.py）の扱い」の 4. を、`scripts/claude/hooks/pretooluse_guard.py` の `_container_risky`・`_ctr_write_targets`・`_RISKY_WORDS` と突き合わせて読む（手動テスト M-05）
- 期待値: 手順書の確認の基準が、見張りの実物と食い違わない
- 実際値: 4. が実物より狭い。(1)「コンテナの /tmp/ 以外へ**リダイレクトで**書き込むか」と書いてあるが、実物は `tee`・`sed -i`・`cp`／`mv`／`install`／`ln`／`rsync` の書き先も見る。(2)「環境変数をまとめて表示する（`ps e`・引数なしの `env`）」と書いてあるが、実物は引数なしの `set`・`export -p`・`declare -p`／`-x`・`typeset` も見る
- ログ: 敵対的レビュー 2 周目（`docs/reviews/I200_adversarial_review_20261029_2349.md`）の Low（V8）でも同じ指摘

## 根本原因
- 敵対的レビュー 1 周目の後に、見張りの確認の範囲を広げた（計画変更記録 5・台帳の F3・F6）。そのとき、変えた見張りに合わせて手順書の該当の文を直すことを、直す対象に入れていなかった（コードとテストだけを直した）
- 手順書の文は、見張りの規則を言葉で写したもの。規則を変えたら写しの文も直す、という手順が、修正の時点で抜けた
- セキュリティ観点: 手順書が実物より**狭い**（実物のほうが多く確認を出す）ので、守りが弱まる向きではない。読む人が「`sed -i` で /app/ に書いても確認は出ない」と誤解しうる

## 対応方針（全案＋推奨）
| 案 | 内容 | セキュリティ | BP | 保守性 | リスク・副作用 |
|---|---|---|---|---|---|
| A（推奨） | 4. の 2 か所を実物に合わせて直す（「リダイレクトで」→「リダイレクト・`tee`・`sed -i`・`cp`／`mv` などで」、環境変数の表示に `set`・`export -p`・`declare -p` を足す）。語の一覧は今までどおり写さない | 影響なし（文書だけ） | 手順書と実物を一致させる（runbook が判断の正） | 2 か所の言い回しだけ | 文書の変更でも、敵対的レビューの上限（2 周）を使い切った後の変更になり、1 周の延長がユーザーの承認で要る |
| B | 4. から、確認の具体的な形（書き込みの種類・表示の形）を消し、「詳しくは見張りの `_container_risky`」とだけ書く | 影響なし | 規則の写しを減らせば、今後の食い違いも起きない | 写しが減って保守しやすい | 読む人が見張りのコードを読まないと分からない。上の延長が要るのは同じ |
| C | 今回は直さず、後続のイシューで直す（M-05 を NG のまま受け入れて進む） | 影響なし | 食い違いが残る | — | 受け入れはユーザーの言葉が要る（Claude だけでは決めない） |

推奨: A（読む人がコードを読まずに分かる。直すのは 2 か所の言い回しだけ）。B の「写しを減らす」考えは、A の中でも語の一覧を写さない形で守っている。
