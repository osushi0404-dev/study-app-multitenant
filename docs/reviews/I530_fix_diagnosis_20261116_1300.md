## 根本原因
- `code-review.sh` の `classify_gate`（`:385-411`）は、ゲートの行を副作用の無い決まった形（`bash scripts/claude/tests/*.sh`・`grep …`・`! grep …`・`bash -n …`・`python3 -m json.tool`・`python3 -m py_compile`）のときだけ実走し、`;` `|` `&` `` ` `` `$(` `>` を含む行と allowlist に無い先頭コマンドは実走せず BLOCKER にする（fail-closed）
- テスト文書を書くときに、この形の決まりを照らさず、複数の判定を `&&` でつないで `bash -c` で包み、shellcheck を `pre-commit run` で書いた。実装の中身（`pr-base-sync.sh` 等）の不具合ではない
- セキュリティ: 該当なし（ゲートが走らず止まる側に倒れただけ。秘密情報・認可・入力の扱いに関わらない）

## 対応方針（全案＋推奨）
- 案 A（推奨）: ゲートの行を allowlist の形に分ける。TC-03 を `! grep -qF 'gh pr checks' scripts/claude/pr-base-sync.sh` と `! grep -qE '^ci_wait\(\)' scripts/claude/pr-base-sync.sh` の 2 行、TC-05 を `! grep -qE '^- F1 ' docs/reviews/backlog/I498.md`・`F2`・`F3`・`R1` の 4 行と `grep -qE '^- F4 ' docs/reviews/backlog/I498.md`・`! grep -qE '^- F1 ' docs/reviews/backlog/I224.md` の計 6 行にする（`|` を使わない）。shellcheck の行は `bash -n`（構文）4 行に置き換え、shellcheck そのものは pre-commit（commit のたび）と CI（Harness Tests の pre-commit）が流すことをテスト文書に書く
  - セキュリティ: 影響なし。ゲートの安全境界（`classify_gate`）を変えない
  - BP・保守性: 既存の形に合わせるだけ。新しいコードを足さない
  - リスク: shellcheck がゲートから外れる。ただし commit のたびに pre-commit が流し、この PR でも implement の commit で `shellcheck...Passed`。CI でも流れる
- 案 B: 判定を新しいテストのファイル（`scripts/claude/tests/test_i530_*.sh`）にまとめ、ゲートからはそれを呼ぶ
  - リスク: 「意図的に戻さない限り起きない」確かめを決定論テストのファイルにする形で、`plan-writing-rules.md`「決定論テストの対象の選び方」に反する。ファイルが増え保守が重い
- 案 C: TC-03・TC-05 をゲートから外し、記録だけにする
  - リスク: AC2 の確かめが review-gate で走らなくなる（読解だけになる）
- 案 D: `classify_gate` の allowlist に `bash -c` や `pre-commit run` を足す
  - リスク: 安全境界（副作用の無い形だけを実走）を広げる。このイシューの範囲外で、ゲートの安全装置そのものの変更
- 推奨: 案 A（最小・既存の形どおり・安全境界を変えない）
