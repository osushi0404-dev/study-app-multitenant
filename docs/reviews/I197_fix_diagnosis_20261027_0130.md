# I197 fix-loop 診断メモ（5 回目・§4.8 の実装の後の CI の Harness Tests の失敗）

## 失敗分解
- 再現手順: `bash scripts/claude/tests/test_i185_harness_docs.sh`（CI run 40350654263 の Harness Tests の中）
- 期待値: exit 0
- 実際値: `FAIL TC-14pin fix_loop_return が固定した文章と一致`・`FAIL TC-14⑤c 共通ルール (b) は診断レビューを通り直す`（pass=15 fail=2）。run-all は pass=40 fail=1
- ログ: CI の Harness Tests

## 根本原因
- §4.8 で `.claude/skills/fix-loop/SKILL.md` を書き直した（実装・テストのレビューをやめた）。`test_i185_harness_docs.sh` は、fix-loop の「8) 結線」から末尾までの文章を `fixtures/i185/fix_loop_return.txt` に固定し（TC-14pin）、共通ルール (b)「手順2 へ環流して再診断 → 手順3 → 手順3.5 診断レビュー → 手順4 → 手順5」の文があることを確かめる（TC-14⑤c）。書き直しで「8)」の 1 行（「ブランチ全体の差分をレビューし直す」→「差分のレビューで見直す」）と、(b) の文（実装・テストのレビューの差し戻しの分類と一緒に消した）が変わった。
- 手元で流す「関係するテスト」を、私が思い出したテストの名前で選び、変えたファイルの名前で検索して選ばなかったため、このテスト（と `test_auto_test_template_lint.sh`）を手元で流していなかった。
- セキュリティ観点: なし（文書の固定の文字のずれ）。

## 対応方針（全案＋推奨）
- 案 A（推奨）: 守りの意図（fix-loop は直した後に必ず review-gate に戻る・診断が NG なら再診断して診断レビューを通り直す）は新しい SKILL にも残っているので、テストを新しい文に合わせる。TC-14pin の固定の文章（`fix_loop_return.txt`）を新しい「8) 結線」以降に更新し、TC-14⑤c を新しい文（「手順2 で再診断・手順3 で別案を作って手順3.5 をやり直す」）に付け替える。
- 案 B: SKILL に古い文を戻す。消した実装・テストのレビューの分類の文が戻り、計画（§4.8）と食い違う。
- 推奨 A。
- 再発防止: 手元で流す関係するテストは、変えたファイルの名前で `scripts/claude/tests/` を検索して選ぶ（今回の検索で、code-review.sh・fix-loop・code-reviewer・review-gate を参照するテストは 11 本と分かった）。

## 影響調査
- 変えたファイルを参照するテスト（`grep -rln` で 11 本）: test_adversarial_trigger・test_auto_test_template_lint・test_i181_review_slim・test_fix_review・test_i193_official_flow・test_i197_adversarial_process・test_i185_harness_docs・test_i197_review_ledger・test_review_gates・test_review_verdict・test_review_commit_lifecycle。今回の修正の後にこの 11 本を流す。

- 該当なし（I197 で軽微例外は廃止。診断レビューは常時必須）。
