- 再現手順: 書き換えた規約 2 本と手順書 2 本を全文読む（手動 No.5）
- 期待値: 決まっていない選択肢・2 段書き・規約の中の食い違いが無い（AC4・AC6・AC7）

  2. `rules/react-coding-standards-integrated.md` §2 の表:「画面だけの型 ＝ `src/types/` か、使う部品と同じファイル」— どちらに置くかが決まっていない
  3. 両方の規約の §16:「新しく書くコードは、差が直る前から規約に従う」— §16 の差の行に当たる決まりのうち、まだ入っていない道具・版を前提にするもの（React §1・§8 の Zod、§14 の Vitest・MSW、§4 の `ref` を props で受ける〔React 19 が前提〕など）は、今の依存では守れない。React 18 で `forwardRef` を使わずに `ref` を props で受けると ref が届かない。規約の中で両立しない決まりがある

## 根本原因
- 1・2: 選択の基準（どんなときにどちらか）を書かずに、両方の置き場所・道具を並べた
- 3: 「あるべき姿を書き、差は移行のイシューで直す」というイシューの方針（設計確認メモ）を §16 に書くとき、差の行が直るまでの間に、新しいコードがその決まりに従えるかを確かめなかった。道具の入れ替え（依存の追加）は差の行のイシューの仕事なので、ほかのイシューの新しいコードがそれを先取りすることはできない
- セキュリティ観点: なし（文書）

## 対応方針（全案＋推奨）

### 1（Django §6 の検証の道具）
- 案 A（推奨）: 「一覧の絞り込みに使うクエリの値は django-filter の FilterSet で、それ以外のクエリの値（期間・件数の上限など）はクエリ用のシリアライザーで検証する」と、使い分けの基準を 1 行で決める。django-filter は一覧の絞り込みのための道具で、DRF のシリアライザーはそれ以外の入力の検証の道具（§1 の表のとおり）
- 案 B: すべてシリアライザーにする — 一覧の絞り込みを §1 の django-filter から外すことになり、§1 と食い違う
- 推奨: 案 A

### 2（React §2 の画面だけの型の置き場所）
- 案 A（推奨）: 「1 つの部品だけが使う型（props など）はその部品のファイル、2 つ以上のファイルが使う型は `src/types/`」と基準で決める
- 案 B: すべて `src/types/` — props の型まで別のファイルに出すと、部品を読むたびに 2 つのファイルを開くことになり、React の書き方の慣習とも合わない
- 推奨: 案 A

### 3（§16 の「差が直る前から従う」）
- 案 A（推奨）: §16 の 1 文を「§16 の差の行に当たる決まり（その行のイシューで入れる道具・版を前提にするもの）は、その行のイシューで直す。ほかのイシューで、その道具・版を先に入れない。それ以外の決まりは、新しく書くコードから守る」に直す。決まりの中身（あるべき姿）は変えず、どの決まりをいつから求めるかだけをはっきりさせる。レビュー役が、Zod の入っていない今のフォームの直しに Zod を求める、といった守れない NG を出さなくなる
  - イシューの設計確認メモ「規約にはあるべき姿をそのまま書き、差は移行のイシューとして起票する（『今は現状のまま』の 2 段書きにしない）」との関係: 決まりの本文に「今は現状のまま」を書くのではなく（本文はあるべき姿のまま）、§16 の差の表の扱いを 1 文で決めるだけなので、方針に沿う
- 案 B: 差の行に当たる決まりに、本文の中で「（#5xx の後）」と書く — 決まりの本文に 2 段の書き方を持ち込むことになり、方針に反する
- 案 C: そのままにする — 規約の中で両立しない決まりが残り、レビュー役が守れない NG を出す
- 推奨: 案 A
