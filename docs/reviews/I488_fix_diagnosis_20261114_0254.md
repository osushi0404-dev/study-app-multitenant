# I488 fix-loop 診断メモ（2026-11-14 02:54）

起点: test-gate の手動テスト No.2 の NG（`docs/tests/open/I488_manual_test.md`・6db75fe0）

## 失敗分解
- 再現手順: e2e_user_a（答え 3 問〔11/13・すべて正解〕→ 後に 11/14 に 1 問を足して 4 問）でログインし、`/statistics`（直近 30 日・すべて）を開いて「正答率」のタブを押す。90 日（週の区切り）・7 日でも同じ
- 期待値: 答えのある区切り（11/13・11/14、週なら 11/9〜）に 100% の点（`dot={{ r: 4 }}`）が出る。答えのある区切りが 1 つだけでも、その点が見える（計画 4.4「答えの無い区切りは点を打たず線を切る」の裏返しで、答えのある区切りには点を打つ）
- 実際値: 点が 1 つも出ない。答えのある区切りが 1 つだけ（前後が null）のときは何も出ない（`.evidence/I488/test-no2-accuracy-1440-a.png`・`test-no3-90days-accuracy-1440-a.png`）。2 つ続いたときは線だけが出て点が無い（`test-no2-accuracy-1440-a-2.png`・`test-no3-7days-1440-a.png`）
- ログ: コンソールに新しいエラーなし（既知の WebSocket だけ）。API は 200 で、応答の `trend` の値は正しい（カード・科目別は期待値と一致）

## 根本原因
- recharts 2.15.4 の `Line`（`node_modules/recharts/lib/cartesian/Line.js`）は、点を描く `renderDots` の先頭で `if (isAnimationActive && !this.state.isAnimationFinished) return null;`（190〜192 行）とし、線の描き始めのアニメーションが終わった合図（`handleAnimationEnd`）を受けるまで点を描かない
- 線のアニメーションは、線の全長（`totalLength`・`getTotalLength()`）に対する `strokeDasharray` の伸びで描く。今回の折れ線は答えの無い区切りが `null`（`connectNulls` なし）なので、線が途切れ途切れか、点が 1 つだけで線が引けない形になる。この形で、アニメーションの終わりの合図が来ず、`isAnimationFinished` が false のまま点が描かれない（点が 1 つだけの区切りは線も無いので何も出ない）
- 実証（スパイク）: `Line` に `isAnimationActive={false}` を付けて同じ画面を開くと、11/13・11/14 の 100% の点が出た（`.evidence/I488/fix-spike-no-animation-1440-a.png`）。点を切る範囲（clipPath）は `allowDataOverflow` を付けていないので使われておらず（`needClip` が false・364〜366 行）、上の端で切れていたのではない
- なぜ実装で気づかなかったか: 画面のテスト（Jest）は recharts を軽いモックに替えているので、本物の描き方（アニメーションと点の関係）を通らない。implement の画面確認は答えの時間が 0 秒の利用者で、学習時間の棒だけを見て、正答率のタブを開いていなかった
- セキュリティ: 該当なし（表示だけの不具合。認証・認可・入力・機密データに関係しない）

## 対応方針（全案＋推奨）
- 案 A（推奨）: 正答率の `Line` に `isAnimationActive={false}` を付ける
  - セキュリティ: 影響なし
  - BP: recharts の公式の props。答えの無い区切りで線を切る（`connectNulls` なし・計画 4.4）を保ったまま、点を確実に描く
  - 保守性: 1 行。描き始めの動きが無くなるだけで、ほかの見た目は変わらない
  - リスク: 小さい。タブの切り替えで線がすぐ出る（動きが無い）だけ。学習時間の棒（`Bar`）は点を持たず、アニメーションの後も正しく出ることを確かめているので変えない
  - 気づきにくさへの備え: 画面のテストは recharts をモックしているので、`Line` に渡す `isAnimationActive` をモックで受け取り、false であることを確かめるテストを足す（消すと本物の画面でだけ点が消え、テストでも画面確認の静止画でも気づきにくいため。失敗の注入つき）
- 案 B: `connectNulls` を付けて線をつなぐ
  - 答えの無い区切りの間を線でつなぐので、計画 4.4（線を切る）・14 章（学習していない期間を成績と見せない）に反する。点が 1 つだけのときは線が引けず、アニメーションの合図の問題も残りうる。採らない
- 案 C: 正答率も棒グラフにする
  - 点の問題は消えるが、計画 4.4・9 章（傾向を見る折れ線）と UI を変える。設計確認で決めた見せ方の変更になるので、fix-loop では採らない
- 案 D: `dot` の代わりに、答えのある区切りに別の目印（`Scatter`）を重ねる
  - 部品が増え、ツールチップが二重になる。案 A で足りるので採らない

## 影響調査
- 同型: この差分で recharts の `Line` を使うのは `frontend/src/components/statistics/StatisticsTrendChart.tsx` の 1 か所だけ（`grep -rn "<Line" frontend/src` で確認。ダッシュボードは chart.js）
- `Bar`（学習時間）: アニメーションの後に正しく出ることを画面で確かめた（`test-no5-after-answer-1440-a-2.png`）。点を持たないので同じ問題は無い。変えない
- `Pie`（科目別）: ラベルはアニメーションの後に出るが、学習時間 0 のときは円グラフ自体を出さない作り。今回の確かめでは学習時間のある科目が無く、円グラフは出ていない。案 A の範囲の外として変えず、retro で記録する
- 関連機能: API・集計・カード・科目別には影響なし
