# I586 修正の診断メモ（close の最後の確認で CI の Harness Tests が失敗・2026-11-27）

## 失敗分解
- 再現手順: `bash scripts/claude/tests/run-all.sh scripts/claude/tests/test_i202_ledger_cleanup.sh`（CI の Harness Tests・PR #623）
- 期待値: pass（fail=0）
- 実際値: `FAIL D3 実物の一覧のどの行も決まった形 expected=yes got=no`（pass=160 fail=1）
- ログ: 形に合わない行は `docs/reviews/backlog/I586.md` の「- F1・F5・F6・F8 は記録の場所（計画書・テスト記録）だけで済むので、I586 の retro で直した」の 1 行だけ（手元で `BL_FORM` の正規表現を当てて確かめた）

## 根本原因
- retro で一覧のファイルを作るとき、見出しの箇条に注記を足した。その行が `- F` で始まるので、`scripts/claude/tests/test_i202_ledger_cleanup.sh:653-660` の D3 が指摘の行と見なし、決まった形（`- F<番号> SEV=… REPRO=… KIND=… FILE=… | … | 一覧に回した理由: …`）に合わないとして落ちた。retro の段階で、一覧の形の判定（ハーネスのテスト）を手元で流さなかった
- セキュリティ: 該当なし（記録の 1 行だけ）

## 対応方針＝全案＋推奨
- 案 A（推奨）: 注記の行を `- F` で始まらない書き方（「- 記録の場所だけで済んだ F1・F5・F6・F8 は…」）に直す。直した後、手元で D3 のテストを流して pass を確かめる
  - よい点: 1 行の直しで、決まりの形を変えない。テストの意図（一覧の `- F` の行は全部決まった形）に沿う
- 案 B: 注記の行を消す。どの指摘を直したかは review の自律判断の記録にもあるので消してもよいが、一覧を読む人（次の計画）に F 番号の欠けの理由が分からなくなる。採らない
- 案 C: テストの判定を緩める。テストが守る決まりを崩すので採らない

## 影響調査の実施有無と結果
- 実施: 全一覧（`docs/reviews/backlog/*.md`）に `BL_FORM` を当て、崩れた行はこの 1 行だけだった。`- S1` の行は `- F` で始まらないので D3 の対象外（形の判定は受けない）
- 同型の問題: retro の手順 4-0 は「出力の行をそのまま貼る」とあるが、見出しの箇条を足すときの注意は無い。retro が一覧を作ったら D3 だけを手元で流すのが確実だが、CI がその場で捕まえ手戻りは 1 周だけなので、手順は足さない
