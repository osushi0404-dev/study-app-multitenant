# I539 fix-loop 診断メモ（2026-11-17 03:39・コードレビュー F5）

## 失敗分解
- 指摘: `docs/reviews/I539_code_review_20261117_0256.md` の F5（Medium・STOP=ac:13・再現あり）
- 再現手順: 学ぶ科目 X に問題を 1 問作り、その問題を削除する（論理削除 `Problem.is_deleted=True`・`problem_service.py:471-472`）。`GET /api/user/subjects/`
- 期待値: X の `problem_count == 0`（出題できる問題が無い）。ダッシュボードは「問題を作りましょう」を出し、「クイズを始める」は押せない
- 実際値: `problem_count == 1`（`Count('problems')` が削除済みも数える・`core/subject_service.py:160`）。「クイズを始める」が押せ、出題は `available_problems`（`problems/services/tenant_scope.py:34` の `is_deleted=False`）で 0 問なので 404 → 「この科目には問題が登録されていません」のエラーの通知で戻される（AC13 が防ぐ流れが残る）

## 根本原因
- 問題数の数え方（`Count('problems')`）と、出題できる問題の決め方（`available_problems` の `is_deleted=False`）が別々に書かれていて、削除済みの扱いが食い違っている
- AC13 の実装で、数え方の元（`get_user_selected_subjects(annotate_count=True)`）を出題の条件と照らしていなかった。計画の調べで `Problem` の印を `is_active` で探し、`is_deleted` を見落とした
- 同じ数え方が `get_user_subjects`（`core/subject_service.py:68`・`:76`。科目管理の一覧の「問題数」・`problems/views.py:52-55`）にもあり、科目管理でも削除済みを数えている（I539 の前からの同じ穴）
- セキュリティ: 関係なし（数は自組織の科目だけ。削除済みの問題の中身は出ない）

## 対応方針（全案＋推奨）
- 案 A（推奨）: `core/subject_service.py` に「出題できる問題の数」の式を 1 つ定義し（`Count('problems', filter=Q(problems__is_deleted=False))`）、3 か所（`:68`・`:76`・`:160`）で使う。TC-24 に削除済みの問題を足し、数に入らないことを確かめる（直す前に落ちることを確かめる）
  - 良い点: 3 か所の数え方がそろい、出題の条件（`is_deleted=False`）と合う。変更は式 1 つと置き換え 3 か所
  - 悪い点: 出題の条件の定義（`available_problems`）とは別に書くので、条件が増えるとまたずれうる（今は `is_deleted` だけ）。式のそばに「`available_problems` と同じ条件」と書いて対応を示す
- 案 B: `available_problems` を使ったサブクエリで数える
  - 悪い点: `available_problems` は利用者と組織で絞るクエリで、科目ごとの数の注釈に使うにはサブクエリ・`OuterRef` が要り、式が重くなる。今の条件は `is_deleted` だけなので、得るものが少ない
- 案 C: `:160` だけ直す（科目管理は触らない）
  - 悪い点: 同じ式が 2 通りになり、科目管理の「問題数」は削除済みを数えたまま。同じ穴を残す

推奨: 案 A。
