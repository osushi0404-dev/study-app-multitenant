# I619 fix 診断メモ（2026-11-24 02:56）

対象: test-gate の Claude の手動テスト No.10 の NG（`docs/tests/open/I619_manual_test.md`）。

## 失敗分解
- 再現手順: パスキーを 1 つ登録し、幅 360px で `/settings` の「パスキー」の欄を開き、行の鉛筆（名前を変える）とごみ箱（削除）のボタンの大きさを測る（Playwright の `boundingBox`）
- 期待値: 押す的が 44×44px 以上（`docs/runbooks/ux-rules.md` §6・計画書 13）
- 実際値: どちらも 40×40px
- ログ・画像: `.evidence/I619/settings-row-360-c-1.png`（手元）。`frontend/src/components/settings/PasskeysCard.tsx:114-119` の `IconButton` に大きさの指定が無い

## 根本原因
- MUI 5 の `IconButton`（size medium）の既定は、アイコン 24px＋上下左右の余白 8px＝40px。ほかのボタン（`Button`）には `minHeight: 44` を付けたが、アイコンだけのボタンに付け忘れた。単体テスト（jsdom）は大きさを測れず、E2E も大きさを確かめていなかった
- セキュリティの観点: 該当なし（押しにくさ・押し間違いの使い勝手の問題。削除は確認のダイアログと本人確認があるので、押し間違いで消えることはない）

## 対応方針（全案＋推奨）
- 案 A（推奨）: 2 つの `IconButton` に `sx={{ width: 44, height: 44 }}` を付ける（今のほかのボタンと同じく、その場で 44px にする）。行の右の余白（`pr: 14`＝112px）は 44＋8＋44＝96px を収める
  - セキュリティ: 影響なし。BP: React 規約 §9（`sx` で変える）・ux-rules §6 どおり。保守: 2 か所・1 行ずつ。副作用: 見た目の円がわずかに大きくなるだけ
- 案 B: `size="large"`（余白 12px・アイコン 28px＝52px）
  - アイコンが大きくなり、ほかの画面のアイコンのボタンと見た目がそろわない
- 案 C: テーマで `MuiIconButton` の最小の大きさを 44px にする（全画面）
  - 根本の直しに近いが、ほかの画面（AppBar・ダイアログの閉じるボタンなど）の見た目が全部変わり、I619 の範囲を大きく超える。後続のイシュー（全画面の押す的の点検）に回すのが妥当

## 影響調査
- 同型のバグ: このイシューで足したアイコンだけのボタンは `PasskeysCard.tsx` の 2 つだけ（`grep IconButton`）。ログイン画面・ダイアログのボタンはすべて `minHeight: 44` 済み（実測で 44px を確かめた）
- 既存の画面のアイコンのボタン（パスワードの表示の切り替え・AppBar など）も 40px の可能性があるが、I619 の前からあり範囲外。retro で後続（全画面の押す的の点検・案 C）にするかを決める
- 足すテスト: E2E（`e2e/tests/passkey.spec.ts`）で、登録した行の鉛筆・ごみ箱のボタンの `boundingBox` が幅・高さとも 44 以上（jsdom では測れないので、実際のブラウザで測る E2E に置く）。失敗注入: 直しを外すと 40 で落ちる
