# I219 修正の診断メモ（close の最終確認の CI 失敗・2026-10-30）

## 失敗分解
- 再現手順: PR #403 の close のコミットの後の CI「Harness Tests」（`bash scripts/claude/tests/run-all.sh`）。手元では `bash scripts/claude/tests/test_i202_ledger_cleanup.sh`
- 期待値: run-all がすべて pass
- 実際値: `run-all: pass=49 fail=1`。`FAIL D3 実物の一覧のどの行も決まった形 expected=yes got=no`
- 原因の行: retro で作った `docs/reviews/backlog/I219.md` の見出しの注記「- F7（計画書の本文の食い違い）は記録の場所の中なので、I219 の retro で直した（ここには載せない）」

## 根本原因
- `test_i202_ledger_cleanup.sh:651-658` の D3 は、一覧のファイルの「`- F` で始まる行」がすべて決まった形（`- F<番号> SEV=… REPRO=… KIND=… FILE=… | … | 一覧に回した理由: …`）かを確かめる。retro で足した注記が「- F7（…」で始まり、指摘の行と見なされた
- retro の手順（`.claude/skills/retro/SKILL.md` 4-0）は「出力の行をそのまま貼る・見出しは I206 と同じ形」と決めていて、注記を足すことは想定していない。決まりの外の書き方をした
- retro の後に run-all を手元で流していなかった（記録の場所だけの変更なので流さなかった）。close の CI で初めて出た
- セキュリティ観点: 該当なし（記録のファイルの書き方の誤り）

## 対応方針（全案＋推奨）
| 案 | 内容 | セキュリティ | BP | 保守性 | リスク・副作用 |
|---|---|---|---|---|---|
| A（推奨） | 注記を「- 」で始まらない形（見出しの説明の文）に書き直す。中身（F7 は retro で直した）は残す | 影響なし | retro の決まりの見出しの形に合わせる | 1 行の書き直し | 無し |
| B | 注記を消す | 影響なし | F7 の扱いが一覧から読めなくなる（レビューの記録には残る） | — | 小 |
| C | D3 の判定を「- F<数字> 」に絞る | 影響なし | 決まりの外の書き方に合わせてテストを緩める | 悪い | 崩れた行を見逃す向きに変わる |

推奨: A。

## 影響調査
- 同型: `docs/reviews/backlog/` のほかのファイルを `grep -E '^- F' | grep -vE <決まった形>` で見ると、崩れた行は I219.md のこの 1 行だけ（直した後に D3 で確かめる）
- 再発防止: 記録の場所だけの変更でも、close の前の CI が捕まえる（今回もそこで止まった）。手戻りは小さいので新しい決まりは足さない
