# I189: issue-bootstrap の採番で同時起票による番号の衝突を防ぐ — 別の作業場所で同時に起票すると同じ番号になる（2026-10-24 に harness-1 の #319 と harness-2 の #318 が両方 I187 になった）。GitHub 登録の直前に同じ番号のタイトルが GitHub にないか確認し、あれば止めて採番し直す

## 関連資料
- 採番スクリプト: `scripts/claude/next-issue-num.sh`（I098 で作った採番の単一権威。詳細は `docs/plans/closed/plan_I098.md`・`docs/runbooks/worktree.md` §8）
- スキル: `.claude/skills/issue-bootstrap/SKILL.md`（step 2 採番・step 4 GitHub 登録）
- 運用: `docs/runbooks/issue-flow.md`
- 発生した実例: #318（harness-2 で起票・I187）と #319（harness-1 で起票・I187 → 手で I188 に付け直し）

## 背景/目的

**背景**: 2026-10-24、harness-1 と harness-2 の 2 つのセッションで、ほぼ同じ時刻（16:47〜16:49 ごろ）に `/issue-bootstrap` が実行され、どちらも I187 を採番した。GitHub には #318 と #319 が両方 `I187:` のタイトルで登録され、ユーザーが GitHub 上で気づいて #319 を手で I188 に付け直した。
**目的**: 別の作業場所で同時に起票しても、同じ番号のイシューが GitHub に登録されないようにする。衝突したときは登録前に止まり、採番し直せるようにする。

### 現状の問題（証拠・再現手順）
- `next-issue-num.sh` は、全 worktree の `docs/issues` 配下のファイル（untracked を含む）と git 履歴から最大値を数えて +1 する。GitHub のイシュータイトルは見ていない
- 2 つのセッションが、相手がイシューファイルを書く前に採番すると、どちらも同じ番号を得る（採番〜ファイル作成〜issue-review〔数分かかる〕〜GitHub 登録の間に時間差があるため、すれ違いが起きやすい）
- 再現手順: 2 つの worktree で、ほぼ同時に `bash scripts/claude/next-issue-num.sh` を実行する → 同じ番号が返る → 両方がそのまま `gh issue create` すると同じ `I###:` のタイトルが 2 件できる

### 根本原因
採番の時点でしか重複を確かめておらず、登録する時点で「その番号がすでに使われていないか」を確かめていない。採番から登録までの間に、別のセッションが同じ番号を使っても気づけない

### 解決方針
GitHub に登録する直前（`/issue-bootstrap` の step 4 の前）に、GitHub の全イシュー（open・closed）に同じ `I###:` で始まるタイトルがないかを確かめる。あれば登録せずに止め、採番し直す（ローカルのイシューファイルと issue-review の記録も新しい番号に付け直す）。確認は決定論的なスクリプトで行い、スキル本文の手順だけに頼らない
- 確認をどこに置くか（`next-issue-num.sh` に GitHub の確認を足す／登録直前の確認用スクリプトを別に作る／両方）: 未定・grill-me で確認（登録直前の確認は必須。採番時にも GitHub を見れば、他の場所で起票されてまだ手元に入っていない番号との衝突も減らせる）
- 衝突したときに自動で採番し直すか、止めてユーザーに知らせるか: 未定・grill-me で確認

## スコープ

- 衝突時の付け直し手順（ローカルのイシューファイル・issue-review の記録・GitHub タイトル）

## 受け入れ条件（Acceptance Criteria）
- [ ] GitHub に同じ `I###:` で始まるタイトルのイシュー（open・closed どちらも）があるとき、`/issue-bootstrap` は GitHub に登録せずに止まる
- [ ] 止まったときに、採番し直す手順（またはそのまま自動で採番し直したこと）が分かる形で表示される
- [ ] 確認はスクリプトで決定論的に行われ、テストで「重複あり → 止まる」「重複なし → 通る」が確かめられている
- [ ] `I18:` と `I188:` のように、番号の一部が一致するだけのタイトルを重複と誤判定しない
- [ ] GitHub に問い合わせられない（ネットワーク・認証のエラー）ときは、黙って通さずに止まる
- [ ] issue-flow.md と issue-bootstrap スキルの記載が新しい手順に合っている
