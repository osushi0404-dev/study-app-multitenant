# I101: docs/issues の open/closed 番号共存の棚卸しと再発防止ゲート — 同一番号が open と closed に別内容で残存し横断チェックを妨げる不整合を解消

## 関連資料
- GitHub Issue: #191
- 発見元: I098（採番権威の堅牢化）の retro（2026-07-05）。是正処置 C1（当初は I042 単体想定 → 起票時スキャンで systematic と判明）。
- 関連: `docs/runbooks/issue-flow.md`（フェーズ4 クローズ処理・ステップ24 の `mv open→closed`）・`.claude/skills/close/`（クローズスキル）
- 関連イシュー: I098（横断採番。content-hash gate を試した際に I042 の open/closed 共存で false-positive し、本問題が表面化）。

## 背景/目的

**背景**: 同一イシュー番号が open/ と closed/ の双方に tracked で残存する不整合（11 番号・I042 は内容差あり）が、I098 の content-hash ゲート試作を false-positive でブロックして表面化した（I098 retro 是正処置 C1・2026-07-05）。
**目的**: 共存 11 番号の棚卸し解消・クローズ処理の除去保証・「open/closed 排他」の決定論ゲート追加により、横断チェックを妨げる不整合の再発を防ぐ。

### 現状の問題（証拠・再現手順）
`docs/issues/` で**同一番号が open/ と closed/ の両方に tracked（コミット済み・origin/develop に存在）**で残存している。起票時（2026-07-05）の全数スキャン結果:

- 共存 **11 番号**: I031・I032・I033・I034・I036・I040・I041・I042・I043・I044・I047
- うち **10 番号は open/closed の内容が同一**（＝クローズ時に open/ の複製が残った）
- **I042 のみ内容が異なる**（open と closed で別内容＝どちらが正本か不明の不整合）
- いずれも `git ls-files` で tracked、`origin/develop` の open/ と closed/ 双方に存在（ローカル untracked ではなく**コミット済みの本体不整合**）

この不整合は横断的な整合性チェックを妨げる。実際 I098 で「同一番号が複数箇所に別内容で存在＝二重採番」を検出する content-hash ゲートを試作した際、I042 の open/closed 共存を誤検出して**全採番がブロック**され、ゲート採用を断念する一因になった。

### 根本原因
**クローズ処理が open/ の複製を確実に除去できていない**。`issue-flow.md` ステップ24 は `mv docs/issues/open/XXX.md docs/issues/closed/`（＝open を除去して closed へ移動）を意図しているが、10 番号が open/closed 同一内容で共存する事実は、**クローズ時に open/ 側を `git rm` し損ねた（コミットに open/ の削除が含まれなかった）**ことを示唆する（要・plan での確定調査）。抽象化: 「ライフサイクル状態遷移（open→closed）で旧状態のアーティファクトを確実に除去する保証（決定論ゲート）がなく、宣言的な `mv` 手順の取りこぼしが蓄積する」という一般問題。加えて、状態不変条件（同一エンティティは open/closed のいずれか一方にのみ存在）を機械検証するゲートが存在しない。

### 解決方針
1. **do（棚卸し・cleanup）**: 全 11 番号の共存を解消する。
   - **内容同一の 10 番号**: closed/ を正本とし、tracked な open/ 複製を `git rm` で除去（closed に同一内容が残るため情報損失なし）。
   - **内容差異の I042**: open と closed の差分を精査し**正本を確定**（通常はクローズ済み＝closed が最終だが、内容差があるため要判断。grill-me/plan で確定）してから一方に統一。
2. **do（根本原因の是正）**: クローズ処理で open/ 側が確実に除去される保証を追加する（`issue-flow.md` のクローズ手順・`close` スキルが `git rm`/`mv` を確実に行う旨の明示、または後述ゲートによる検出）。原因は plan フェーズで確定調査する。
3. **gate（再発防止・決定論）**: 「**同一イシュー番号が open/ と closed/ に同時に存在しない**」ことを検証する決定論チェック（`scripts/claude/tests/` のスクリプト、または close スキル/CI で実走）を追加する。cleanup 完了後に green になることを確認する。

- **有（軽微）**: tracked なイシューファイルの削除（`git rm`）を伴う。ただし削除対象は closed/ に**同一内容が残存**する複製のみ（I042 を除き内容差異ゼロを事前確認済み）で情報損失はなく、git 履歴で復元可能。I042 の統一は内容差異があるため**削除・上書き前にユーザー承認を得る**。大量削除（10+ファイル）に該当するため実施時は対象一覧を提示して承認を得る。
