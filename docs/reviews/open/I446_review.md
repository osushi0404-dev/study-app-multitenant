# I446 レビュー: 問題・科目と本人の記録を扱う全 API の横断の越境テスト

- 関連: docs/issues/open/I446.md / docs/plans/open/plan_I446.md / GitHub #446 / Draft PR #456

## 変更概要
- アプリの全経路（Django の管理画面を除く）を表に載せた横断のテストを足し、他組織・同じ組織の別の利用者・全体共有の番号が存在しない番号と同じ応答で断られること、一覧・集計に他組織・別の利用者の中身が出ないこと、表に無い経路が増えたら落ちることを CI で毎回確かめる
- テストで見つかった越境（計画書の S1〜S6）と、セキュリティ設計レビューで見つけた D1（組織が空の組織管理者）を、1 か所の絞り込みの追加で直す

- 下準備で、他組織の問題への回答を持つ回を進行中にした（1 人 1 つの制約で、終了の経路の確かめが先に 400 で返っていたため・計画変更記録）
- 経路の収集で、DRF が足す HEAD と `<drf_format_suffix:format>` の書き方を除いた（計画変更記録）
- テストの利用者のパスワードを暗号化しない・使わない設定を消した（/simplify・計画変更記録）

## 振り返り

### かんたんなまとめ

#### 良かった点
- 全部の経路を表にして順に呼ぶテストにしたことで、人が洗い出していたら見落としていた越境を 7 件（問題の科目の入力・AI 生成・クイズの回・組織が空の管理者）見つけて直せた（理由: 「経路を足したら表に載るまで落ちる」作りなので、今後の付け忘れも CI で毎回止まる）
- 失敗をわざと入れて、テストが本当に落ちることを確かめた。敵対的レビューで確かめきれなかった 1 項目は、CI で毎回流すテストに置き換えた（理由: 人や実験に頼らず、決定論で守れる形にした）
- 手動テストを Claude が画面で全部行い、人の手を借りずに済んだ

#### 今回の問題への直接の対処
- 境界とは関係ない既存の不具合が 3 つ見つかった。統計の画面の 500、画面からの AI 生成が受け付けられない 415、学習記録の分析の 500 の 3 つ。どれも、その経路を通すテストが無く、誰も気づいていなかった → 統計の画面と AI 生成は新しいイシュー（#459・#460）にした。学習記録の分析は、同じ機能を直す #452 に同梱した
- コードレビューで止めなかった小さな指摘が 9 件残った（テストの確かめの甘さ、クイズの回の読み出しの効率、組織が空のときの二重の守りの比較など）→ 1 件の後続イシュー（#461）にまとめた

#### 同じ問題を次回から防ぐ改善
- 敵対的レビューで「守りを外すとテストが落ちるか」を実験で確かめようとした。ところが実験の環境に python が無く、確かめられないまま 1 周多く回った。計画の段階で、この確かめを実験の項目にしていたのが原因 → 計画の書き方に「守りを外して落ちることの確かめは、最初から CI のテストにする」を足す。計画レビューの観点にも足す。実験の扱いを直す #423 に同梱した
