# I599 fix-loop 診断メモ（2026-11-21 15:55・test-gate の NG）

## 失敗分解
- 再現手順: このブランチ（第 2 版）で、Claude のセッションから `bash scripts/claude/gate-check.sh "I599"` を流す（test-gate の手順 1）
- 期待値: レビュー済みの HEAD で、記録の場所の外にコミットしていない変更が無いので exit 0
- 実際値: `GATE_CHECK: FAIL REASON=dirty`。未追跡として `.bash_profile`・`.bashrc`・`.claude/commands`・`.claude/launch.json`・`.claude/loop.md`・`.claude/output-styles`・`.claude/routines`・`.claude/workflows`・`.claude/worktrees`・`.gitconfig`・`.gitmodules`・`.idea`・`.profile`・`.ripgreprc`・`.vscode`・`.zprofile`・`.zshrc` の 17 件が出る
- ログ: `stat` ではどれも `character special file 1,3`（`/dev/null` と同じ）。`git status` はサンドボックスの中でだけこれらを未追跡に出す

## 根本原因
- 公式のサンドボックス（bubblewrap）は、書き込みを禁じる場所（ホームの設定ファイル・`.claude/` の一部・`.idea` など）を、存在しないパスでも `/dev/null` の bind mount でふさぐ。中から見ると、作業ツリーの最上位にその名前の文字デバイスが現れる
- develop では `bash scripts/claude/*` が外に出る型だったので、gate-check.sh は外で動き、これらは見えなかった。第 2 版で外に出すのを一覧の 16 本だけにしたので、gate-check.sh（一覧に無い。gh・`claude -p` を使わない）は中で動くようになり、ふさぎの印を汚れと数える。第 2 版の影響範囲の洗い出しで、「中で動くようになったスクリプトが、中でだけ見える物を読むか」を見ていなかった
- このままマージすると、すべてのイシューの test-gate・close の gate-check が REASON=dirty で止まる（流れが動かなくなる）
- 同型の調査: 未追跡を数えるほかのスクリプト（`adversarial-review.sh`・`wt-remove.sh`〔一覧にあり外で動く〕・`scripts/claude/hooks/*.py`・`.claude/hooks/*`〔フックはサンドボックスの外で動く〕・`unreviewed.py dirty`〔`code-review.sh` から外で動く〕）は影響を受けない。影響は gate-check.sh だけ
- セキュリティ観点: 秘密の漏れ・権限の昇格は無い。止める側に倒れる失敗

## 対応方針（全案＋推奨）
- 案 A（推奨）: gate-check.sh で、未追跡（`??`）のうち文字デバイスであるもの（`[ -c ]`）を数えない。作業ツリーに文字デバイスを本物の中身として置くことは無く、git は中身を記録できない（追加しても空の扱い）ので、レビュー済みかの判定に関わらない。テスト: `test_i193_official_flow.sh` の G 群に、未追跡の `/dev/null` へのシンボリックリンク（`-c` はリンク先を見る。サンドボックスの外の CI でも作れる）だけなら exit 0、を足す。通常の未追跡ファイルは引き続き 1（既存の G9）。失敗注入: 数えない処理を外した写し（`GC_SCRIPT`）で 1 になる
  - セキュリティ影響: 汚れの見落としは `/dev/null` を指すリンクだけ（中身は空）。BP: 単純な規則（種類だけで決まる）
  - 副作用: 無し（外で動くときも同じ結果）
- 案 B: gate-check.sh を外に出す一覧に足す
  - 外に出すスクリプトを増やす（第 2 版の「外に出すのは gh・`claude -p` が要るものだけ」の方針に反する）。レビュー前の中身があるブランチで test-gate が毎回 `!` を要る。却下
- 案 C: ふさぎの印の名前を表にして除く
  - 公式の版で名前が変わると壊れる。却下

## 影響調査の実施有無と結果
- 実施した: `grep -ln "status --porcelain\|--others\|untracked-files" scripts/claude/*.sh scripts/claude/hooks/*.py .claude/hooks/*` で未追跡を数える全体を洗い出し、それぞれが中・外のどちらで動くかを確かめた（上の根本原因の「同型の調査」）
- git は FIFO を未追跡に出さない（一時のリポジトリで確かめた）ので、テストは `/dev/null` へのシンボリックリンクで作る
