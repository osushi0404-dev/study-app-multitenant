### 実測された主な攻め筋（観点 1）
- 開始: 他組織の科目を文字列・小数・配列・オブジェクトで送る → すべて 400（文言は存在しない ID と同じ）。`subject_id=` など別名 → 科目なしで自組織の問題のみ。同じ Idempotency-Key で科目を変える → 400／422（前の科目を引き継げない）。他ユーザーのキーを使う → 自分の新しいセッションになるだけ。
- 出題・回答: 科目なしで 8 回出題 → 自組織の問題のみ。他組織の問題に数値・文字列・小数で回答 → すべて 404。削除済み → 404。組織なしユーザー → 問題数 0・出題と回答は 404。開始後にユーザーの組織を変える → 404。他ユーザーのセッション → 404。

### 第 1 周の時間切れの原因（第 2 周で判明）
- worktree の見張りが、①ファイルの中身を Docker にパイプで流し込む形 ②波かっこ `{ }` を含む heredoc を「複雑すぎる」として止める。③`docker compose exec ... python /tmp/<file>.py` は許可リストに無く確認画面が出て、バックグラウンドのレビュー役がユーザーの応答待ちで止まる。第 1 周の 3 体はこれらで詰まったとみられる（第 2 周でも観点 3 の実測は ② で止まり、観点 2 は ③ でユーザーの承認を待った）。→ /retro で扱う。
