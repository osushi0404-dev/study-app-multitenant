# I197 fix-loop 診断メモ（2 回目・基本レビュー 2 回目の BLOCKER）

対象: `docs/reviews/I197_code_review_20261026_2124.md` の指摘 1〜10（すべて `scripts/claude/adversarial-review.sh`）

## 失敗分解
| # | 重大度 | 再現手順 | 期待値 | 実際値 |
|---|---|---|---|---|
| 1 | Blocker | 観点の 1 つが時間切れの周（exit 3・`ROUNDS: 0`・`REVIEWED_COMMIT: <HEAD>`）の後に、review-gate が 1 回だけやり直す | やり直しの周も、前の「本当に見た周」と同じ起点からの差分を見る | `review_base()` が最新の記録（`ROUNDS: 0` の周）の `REVIEWED_COMMIT` を起点にするので、差分は記録ファイルだけになり、空の差分で OK が出うる |
| 2 | High | 1 回目の報告が実験案を返した後、締め切りまでの残りが短い（例 20 秒）ところで実験役 → `--resume` | 1 回目の報告（と実験の結果）は判定に残る | `--resume` が時間切れ（124）になると `body.txt` が空になり、観点ごと「報告なし」になる。実験を出した観点ほど失う |
| 3 | Medium | 実験役が `git commit`・`git reset --hard` をする | 作業ツリーの変化と同じく実験を無効にし HIGH | `git status` だけを比べるので、HEAD が動いても見逃す |
| 4 | Medium | スクリプトが途中で止められる（SIGTERM・SIGINT） | 背景の観点と子プロセス（claude・実験役の Bash）も止まる | `trap` は一時フォルダを消すだけ |
| 5 | Medium | 観点 1 の実験役が作業ツリーを変え、その後に観点 2 の実験役が終わる | どの観点が変えたかを決め打ちしない（周全体を無効） | 観点ごとの `dirty` に記録するので、後から比べた観点だけが無効になる（取り違え・取りこぼし） |
| 6 | Medium | 実験のコマンドが非ゼロで終わる（`is_error=true`） | 指摘: 実験必須を満たさない | 「確認済み（実験）」になる |
| 7 | Medium | 2 回目の報告で、扱い済みの id（P1-E1）に別のコマンドを書く | 記録には実際に実行したコマンドが出る | `extract_experiments` が `.cmd` を上書きし、記録のコマンドと実行したコマンドが食い違う |
| 8 | Medium | 比べる相手が無い（`ADV_BASE` が存在しない参照） | 実行できない（exit 2） | `git diff` の失敗の文がそのまま「差分」になり、レビューが走る |
| 9 | Low | 実験のコマンドに行頭の `VERDICT: OK` を含める | 記録に貼るときに無害化 | `.cmd` は無害化せずに貼る（今は最後の行で誤判定しない） |
| 10 | Low | ― | gate-check.sh と記録の探し方を共有 | 写し（計画変更記録 3 で retro に見送り済み） |

ログ: 基本レビューの記録の「コード品質・セキュリティ指摘」の表。指摘 1・2 は組み込み /code-review の指摘で、レビュー役が `review_base()` を読んで確かめている。Claude も該当箇所（`review_base`・`run_perspective` の `claude_log_result ... || : > body.txt`）を読んで同じ動きを確かめた。

## 根本原因
- 1: 「周に数えない記録（`ROUNDS: 0`）」を周回の数え方からは外したのに、見る範囲の起点の決め方からは外していなかった（概念の変更の消費箇所の取りこぼし。plan-writing-rules「概念・セマンティクスの変更も対象」）。
- 2: 締め切りの扱いを「各呼び出しの時間上限＝残り」にしただけで、往復を始める前に「往復を終えるのに足りる時間があるか」を見ていない。さらに、各呼び出しの本文で上書きするので、失敗した最後の呼び出しが前の成功を消す。
- 3・5: 「実験が作業ツリーを変えたか」を、作業ツリーのファイルの変化だけで、観点ごとに見ていた。実験は同じ作業ツリーで並列に動くので、原因の観点は決められない。HEAD・ブランチの移動も同じ「作業ツリーを変えた」に当たる。
- 4: code-review.sh の `kill_tree` の後始末を写していなかった。
- 7: 実験案の取り出しで、既出の id を区別せずにファイルへ書いていた。
- 8: `git diff` の失敗を確かめていなかった。
- 9: 本文は無害化していたが、コマンドの欄を対象から漏らしていた。
- セキュリティ観点: 3 は実験役（auto・Bash）が作業ツリーの外ではなく git の状態を変える操作を見逃す穴（普通の書き方の `git commit` で起きうる）。ほかは判定の偽 OK（1・2・8）と記録の監査性（7・9）。認証・認可・インジェクションの新しい穴は無い。

## 対応方針（全案＋推奨）
- 1:
  - 案 A（推奨）: `review_base()` は `ROUNDS:` が 1 以上（行が無い古い記録は 1 とみなす）の最新の記録の `REVIEWED_COMMIT` を起点にする。`ROUNDS: 0` の記録（報告なしの周・ユーザーの受け入れの記録）は飛ばす。受け入れの記録の後に周を回すことは無い（上限到達後の受け入れ）ので影響しない。
  - 案 B: 報告なしの周では `REVIEWED_COMMIT` を書かない。gate-check がその記録を「行が無い」で落とすので安全側だが、記録の形が周によって変わる。
  - 推奨 A: 周回の数え方と起点の決め方を同じ規則（ROUNDS の値）で揃えられる。
- 2:
  - 案 A（推奨）: 往復を始める前に、残りが `2 × ADV_MIN_STEP`（実験役と続きの 2 回分）以上あるかを見る。足りなければ実験は「締め切り」にして往復しない。さらに、続きの呼び出しが失敗したら、その前の成功した呼び出しの本文で判定する（終わり方は「報告あり（続きは時間切れ）」などと記録し、実験の結果は反映されないので実験必須の項目は 1 回目の報告どおり未検証のまま）。
  - 案 B: 1 回目の本文を保持するだけ。時間切れの往復が無駄に走る。
  - 推奨 A。
- 3・5:
  - 案 A（推奨）: 起動時の HEAD とブランチを控え、各実験役の後に「記録の場所の外のファイルの変化」と「HEAD・ブランチの移動」を見る。変化を見つけたら、観点ではなく周全体のフラグ（`$RUN/dirty`）に書く。判定では、このフラグがあれば全観点の実験を無効（実験必須は未検証）にし、VERDICT は HIGH。全観点の終了後にももう一度見る。消さない・戻さない（従来どおり）。
  - 案 B: 実験を観点ごとに順番に実行して原因を特定する。並列をやめるので遅くなる（10 分の上限に響く）。
  - 推奨 A: 粗く止まる側（fix-loop を過剰にしない・`feedback_fixloop_not_excessive`）。
- 4: 案 A（推奨）: `trap` で、背景の観点の PID に code-review.sh の `kill_tree` を呼んでから一時フォルダを消す（EXIT・INT・TERM）。code-review.sh と同じ後始末。
- 6:
  - 案 A（推奨・指摘を採らない）: 非ゼロで終わったコマンドも「実行した」とし、結果の解釈はレビュー役に任せる。理由: 反証の実験は「拒否されることを確かめる（exit 2 を期待）」形が多く、`is_error=true` を未検証にすると正当な実験が通らなくなる。出力の先頭と `is_error` は記録に残るので、後から監査できる。結果がレビュー役の主張を支えるかは LLM の読みの範囲（層 3）で、決定論で決められない。
  - 案 B: `is_error=true` を「実行したがエラー」として未検証にする。上の理由で誤った未検証が増える。
- 7: 案 A（推奨）: `extract_experiments` は、`.cmd` が既にある id を書き直さず、出力もしない（同じ id で別の中身のときは無視される＝扱い済みのまま）。
- 8: 案 A（推奨）: `git diff --name-status` と `git diff` の終了コードを確かめ、失敗したら `ADVERSARIAL_ERROR: DIFF` を出して exit 2（記録を作らない）。
- 9: 案 A（推奨）: 記録に貼る `.cmd` も `neutralize_machine_lines` を通す。
- 10: 見送り（計画変更記録 3 のとおり retro）。

## 影響調査
- 同型: 「ROUNDS: 0 を数えない」を参照する箇所は `count_rounds`（対応済み）・`review_base`（今回）・review-gate SKILL 3-2 の exit 3 の文（「周に数えない」）。SKILL の文は変更不要（起点の扱いはスクリプトの中）。gate-check.sh は最新の記録の VERDICT を見るだけで、`ROUNDS: 0` の記録が最新なら VERDICT HIGH で落とすので影響しない。
- 他の呼び出し箇所: `review_base` の呼び出しは本体の 1 か所。`extract_experiments` も `run_perspective` の 1 か所。
- 関連機能: 計画書 §4.3 の 5（作業ツリーの比較は観点ごと）と §4.3.1 の実験必須の条件の文を、周全体のフラグ・HEAD の比較に合わせて直す（計画変更記録 4。方式・範囲・受け入れ条件は変えないので計画レビューは通り直さない）。テストは TC-01 に A16（ROUNDS: 0 の後の起点）・A17（往復の前の時間・続きの失敗で前の本文）・A18（HEAD の移動）・A19（ほかの観点の変化で周全体が無効）・A20（git diff の失敗）・A21（扱い済みの id の上書き）・A22（コマンドの無害化）を足し、A1 の判定の要に対応する FG を足す。
