# I197 fix-loop 診断メモ（4 回目・基本レビュー 4 回目の HIGH）

対象: `docs/reviews/I197_code_review_20261026_2347.md` の High 2 件だけ（review-gate ⇄ fix-loop の 4 回目。review-gate の決まりで Medium・Low は retro）

## 失敗分解
| # | 再現手順 | 期待値 | 実際値 |
|---|---|---|---|
| H1 | 観点 3 が時間切れの周（exit 3・`ROUNDS: 0`）で、観点 1 が `NEW_HIGH: 1` を報告。直さずに review-gate が同じ周をやり直す | やり直しの周でも、観点 1 の High は新規に数えられる（VERDICT HIGH） | `PREV_RECORDS`（既知 findings として渡す過去の記録）が `ROUNDS: 0` の記録も含むので、やり直しの周のレビュー役は観点 1 の High を「既知」として数えず、`NEW_HIGH: 0` になりうる |
| H2 | 実験役のコマンドが見張り（PreToolUse）に exit 2 でブロックされる | 「実行していない」（実験必須は未検証） | 指摘: `permission_denials` に入らなければ `ran` と数えうる（未実測） |

## 根本原因
- H1: 「周に数えない記録（ROUNDS: 0）」の扱いを、周回の数え方（count_rounds）と起点（review_base・3 回目で修正）には入れたが、既知 findings の一覧（PREV_RECORDS）には入れていなかった（同じ概念の消費箇所の 3 か所目の取りこぼし）。報告の無い周は「周として成立していない」ので、その周の findings を既知にしてはいけない（修正もレビューもされていない）。
- H2: 実測した（スパイク S5・2026-10-26。scratchpad の `spike/s5.sh`）: 実験役（auto＋承認なし）で見張りが exit 2 でブロックするコマンド（別のワークツリーへの書き込み）を実行させると、`tool_result` は `is_error=true`・本文 `PreToolUse:Bash hook error: [...] [guard] 別 worktree ... への Bash 書込は禁止です` で、**`permission_denials` に入る**。今の claude では `ran` にならない（`claude_log_ran` は 10＝拒否を返す）。ただし、出力の形は claude の版で変わりうるので、二重の守りとして `tool_result` の本文がフックのブロックの形（`PreToolUse:` で始まり `hook error` を含む）なら拒否とみなす。
- セキュリティ観点: H1 は既知扱いによる High の取りこぼし（偽 OK）。H2 は実行していない実験を確認済みとする偽 OK の経路（今は起きないが、形の変化に備える）。

## 対応方針（全案＋推奨）
- H1:
  - 案 A（推奨）: 記録のうち「周に数えたもの（ROUNDS が 1 以上・行が無い古い記録は 1）」を出す関数 `counted_records` を作り、`review_base`（最後のもの）と `PREV_RECORDS`（すべて）の両方がそれを使う。同じ規則を 1 か所にまとめる（基本レビューの Low「記録の走査の重複」もこの範囲だけ解消）。
  - 案 B: PREV_RECORDS の作り方だけを個別に直す。規則が 3 か所に散ったままになる。
  - 推奨 A。
- H2:
  - 案 A（推奨）: `claude_log_ran` で、`tool_result` の本文が `PreToolUse:` で始まり `hook error` を含むときは、`permission_denials` に無くても 10（拒否）を返す。単純な文字列の規則で、実測した形に合わせる。
  - 案 B: `is_error=true` をすべて未検証にする。反証の実験（非ゼロ終了を期待する）が通らなくなる（2 回目で採らない判断済み）。
  - 推奨 A。

## 影響調査
- 同型: `ROUNDS:` を読む箇所は count_rounds・review_base・PREV_RECORDS の 3 か所（gate-check.sh は ROUNDS を読まない）。今回で全部が同じ規則（count_rounds は 0 を足しても変わらないのでそのまま）。
- `claude_log_ran` の呼び出しは adversarial-review.sh の 1 か所。check-permission-prompt.sh は別の判定（承認画面が出るか）で、見張りのブロックは「0＝承認なしで実行」と区別して出力の先頭で見分ける既存の決まりのまま（変えない）。
- テスト: TC-01 に A27（ROUNDS: 0 の記録は既知 findings に渡さない・ROUNDS: 1 の記録は渡す）・L6（`permission_denials` に無いフックのブロックも 10）と、FG-A27・FG-L6 を足す。
