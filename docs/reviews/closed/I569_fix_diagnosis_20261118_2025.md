# I569 修正の診断メモ（fix-loop・2026-11-18）

## 失敗分解
- 起点: close の手順 5.5（`scripts/claude/pr-base-sync.sh final`）で CI の Harness Tests が失敗（PR #582・close のコミット 565d93a1）
- 再現手順: `bash scripts/claude/tests/test_i202_ledger_cleanup.sh`（CI では `bash scripts/claude/tests/run-all.sh` の中）
- 期待値: `D3 実物の一覧のどの行も決まった形` が yes（`docs/reviews/backlog/*.md` の `- F` で始まる行がすべて `BL_FORM` の形）
- 実際値: no（`pass=160 fail=1`）
- ログの要約: run-all は `pass=62 fail=1`。落ちたのは `test_i202_ledger_cleanup.sh` の D3 だけ

## 根本原因
- retro で作った `docs/reviews/backlog/I569.md` に、説明の行 `- F1（Medium・再現なし）はスクリプトの振り分けでは一覧だが、…後続 #583 にした（ここには載せない）` を手で足した。この行が `- F` で始まるため、D3 の検査（`scripts/claude/tests/test_i202_ledger_cleanup.sh:651-658`。`^- F` の行はすべて `- F<番号> SEV=… REPRO=… KIND=… … FILE=… | … | 一覧に回した理由: …` の形）が、崩れた指摘の行として数えた
- なぜ気づかなかったか: retro は記録の場所だけを書く段階で、その後の close までに Harness Tests を手元で流さない（CI が正）。一覧の行の形を確かめる検査があることを、手で行を足すときに見なかった
- セキュリティ: 該当なし（記録の文の形だけ。認証・認可・秘密情報に関係しない）

## 対応方針（全案＋推奨）
| 案 | 内容 | セキュリティ | BP 適合 | 保守性 | リスク・副作用 |
|---|---|---|---|---|---|
| A（推奨） | 説明の行を `- F` で始まらない書き方（`- 台帳の F1（…）は…`）に直す。一覧の先頭の説明の箇条（`- 記録:` などと同じ並び）に置く | 影響なし | 一覧の決まった形（指摘の行だけが `- F` で始まる）に合う | 情報（F1 を #583 へ回した理由）が、後で計画が見る一覧に残る | 記録の 1 行だけ。新しいコードは足さない |
| B | 説明の行を消し、レビュー文書（`docs/reviews/open/I569_review.md` の自律判断の記録）にだけ残す（そこには既に書いてある） | 影響なし | 合う | 一覧を見る計画からは F1 の行き先が見えない | 記録の 1 行だけ |
| C | D3 の検査を、説明の行を見分けるように直す | 影響なし | 検査を弱める方向 | 検査が複雑になる | ハーネスの検査を変えるので、計画の範囲外・レビューのやり直しが大きい。採らない |

推奨: A（記録の 1 行の直しで済み、F1 の行き先が一覧を見る人にも残る）

## 影響調査
- 同型: `docs/reviews/backlog/` のほかのファイルで `- F` で始まり形の崩れた行は無い（CI の D3 は I569.md の 1 行だけを数えた。develop の CI は合格している）
- ほかの呼び出し箇所: 一覧を読むのは `.claude/skills/plan-issue/SKILL.md`「台帳の残りの一覧」の grep（`FILE=<パス> |` で拾う）。説明の行には `FILE=` が無いので、案 A でも拾われない
- 関連機能: このイシューのコード（スクリプト・見張り・フック・スキル）は変えない。review-gate の差分のレビューは記録の場所だけの差分になる
