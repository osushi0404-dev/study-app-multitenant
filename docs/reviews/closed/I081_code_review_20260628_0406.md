### `_SHELL_OPS` の `&&`/`||` 機能性についての検証メモ（指摘なし）

計画書レビューが Warning として挙げた「`shlex.split()` が `&&` を 2 つの `'&'` トークンに分割するため dead entry」の懸念を詳細検証した。

`shlex.split()` の実装は内部で `lex.whitespace_split = True` を設定する（CPython `Lib/shlex.py` の `split()` 関数が明示的に設定）。`whitespace_split=True` 時は空白以外のすべての文字（`&` を含む）がトークンとして連結されるため、`"git push && git checkout -- f"` は `['git', 'push', '&&', 'git', 'checkout', '--', 'f']` と分割され `'&&'` は単一トークンになる。したがって `_SHELL_OPS` の `"&&"` / `"||"` は **機能的に有効**。TC-G11（`&&` 後続の dirty checkout が exit 2）は正しく PASS する。計画書レビューの Warning は `shlex.shlex()` クラス（`whitespace_split=False` がデフォルト）と `shlex.split()` 関数の違いに基づく誤認であった。実装・テスト・結果記録「pass=14 fail=0」は整合的。
