- 診断記録: docs/reviews/I134_fix_diagnosis_20260719_2221.md（案 A=文書側適合で当座対応・ハーネス側根治は本イシューに分離）

## 背景/目的

**背景**: I134 の code-review で、テスト文書に検証スクリプトの全文を参考掲載しただけで omission-lint が「宣言外の隠れゲート」と誤判定して HIGH を返し、差し戻し 1 往復が発生した。また新設した常設チェッカー `check-issue-background.sh` は allowlist（`bash scripts/claude/tests/*.sh` のみ）に入らないため、formal gate として宣言・自動実走できない構造的制約も Medium 指摘として記録された（I134 では文書側の配置変更＝案 A で当座対応し、ハーネス側の根治を本イシューへ分離した）。

**目的**: code-review.sh の機械判定を「正当なパターンを受理できる」形に精緻化する。①omission-lint が『参考掲載のスクリプト全文』と『宣言セクション外の隠れた実行可能ゲート』を区別できる状態、②`scripts/claude/check-*.sh` 型の常設チェッカーを formal gate として宣言・自動実走できる状態、の 2 つを達成し、正当な文書構成・チェッカー運用が誤 HIGH や宣言不能で妨げられないようにする。

### 現状の問題（証拠・再現手順）
1. **omission-lint のスクリプト全文掲載の誤検知（I134 で実発生）**:
   - `omission_lint()`（code-review.sh:209-220）は「`## 決定論ゲート（自動実走）` セクション外の fenced ブロック内」に allowlist パターン（`grep -q`/`grep -L` 等）があると一律 HIGH。fenced ブロックの言語種別や文脈（1 行のコマンド宣言か、`#!/usr/bin/env bash` で始まる複数行のスクリプト本文か）を見ない。
   - 再現: I134_auto_test.md（コミット 19a6322 時点）に TC-03〜06 のスクリプト全文（内部に `grep -q` を含む）を fenced で掲載 → omission-lint: HIGH → FINAL VERDICT: HIGH（LLM レビューは全 AC 実装済み・実装欠陥指摘なし）。
   - plan-review には「スクリプト本文を文書に残せ」という要求（I134 plan-review Warning: TC-03 の実行可能な具体コマンド転記）があり、**「本文を残せ」と「fenced に書くと HIGH」が衝突**する。I134 では全文を計画書側へ移して回避したが、テスト文書単体の自己完結性は下がった。
2. **常設チェッカーが formal gate 宣言不可**:
   - `classify_gate()` の allowlist は `bash scripts/claude/tests/*.sh` のみで、`scripts/claude/` 直下の常設チェッカー（`check-memo-body-paths.sh`・`check-issue-background.sh`）は UNSAFE 分類 → 宣言すると fail-closed で BLOCKER。
   - このため読み取り専用・決定論・高速なチェッカーでも自動実走できず、手動実行＋実施記録の転記に留まる（実行の証跡が実装者の自己申告になる）。tests/ へ移せば宣言可能だが、兄弟チェッカー（check-memo-body-paths.sh）との配置一貫性が壊れる。
3. **ゲート宣言の無警報消失（I134 敵対的レビュー周回1 で実測・追記 2026-07-19）**:
   - 宣言セクション内のゲートコマンドは、①行を `# ` でコメントアウト、②フェンスとコマンド行を 2 スペース字下げ（CommonMark では 3 スペースまで有効なフェンスのため見た目は変わらない）のどちらでも `extract_gate_commands` の抽出が 0 件になり、「(決定論ゲート宣言なし)」＝GATE_VERDICT: OK・omission-lint: OK で**黙って消える**（見出しの改名・降格が omission-lint HIGH で捕捉されるのと対照的に無警報）。
   - 原因: `omission_lint`/`extract_gate_commands` のフェンス正規表現が列 0 の ```` ``` ```` のみを認識し、字下げフェンス・コメントアウト行の消失を検知しない。「以前は宣言があったのに消えた」ことを検知する機構も無い。

4. **常設チェッカー自身の無警報合格（I180 の /plan-issue で実発生・追記 2026-10-21）**:
   - `check-memo-body-paths.sh` は設計確認メモを見出しの**完全一致**（`## 設計確認メモ（/grill-me）`）でしか抽出しない。表記ゆれの見出し（例: `## 設計確認メモ（/plan-issue）`）でメモを書くと抽出 0 件になり、`✅ 設計確認メモにファイルパスの記載なし（検証対象なし）`・exit 0 で**黙って合格**する。I180 ではメモ内の新規パス 2 件が本文と未照合のまま合格し、見出しを標準形に直して初めて検証された。
   - 項目 3 と同じ「抽出 0 件を合格と同一視する」型。本イシューでこのチェッカーを formal gate として宣言可能にする以上、チェッカー自身も fail-closed である必要がある。

### 根本原因
- omission-lint が「fenced ブロック内の allowlist パターン出現」という粗い近似で「隠れゲート」を検出しており、参考掲載（スクリプト本文）と宣言漏れ（単一コマンド）を弁別する情報（fence の言語種別・ブロック構造・マーカー）を使っていない。
- allowlist が「tests/ 配下」というディレクトリ規約のみで、「読み取り専用の常設チェッカー」という正当なカテゴリ（check-*.sh 命名規約・先例 2 件）を受理形に持っていない。

### 解決方針
いずれも fail-closed 原則（不明形は実走しない）を維持したまま受理形を広げる。詳細設計は grill-me で確定するが、候補:
1. **omission-lint の弁別**: 参考掲載と隠れゲートを区別する決定論的規約を導入する（候補: (a) スクリプト全文ブロック（`#!/` 行で始まる fenced）は除外する、(b) 参考掲載用の明示マーカー（例: fence 直前の「参考リスト:」行）を除外条件にする、(c) 言語種別 `text` 等の fence を除外する — いずれも「単一コマンド行だけの bash fence」は引き続き検出対象に残す）。
2. **allowlist の check-*.sh 拡張**: `bash scripts/claude/check-*.sh`（引数付き含む）を ALLOW に追加する（チェーンメタ文字ガード・パストラバーサル拒否は既存のまま適用）。対象チェッカーが読み取り専用であることを担保する規約（命名 check-* = 読み取り専用の宣言）を plan-writing-rules 等に明文化する。
3. **宣言消失の検知**: 決定論ゲートセクションが存在するのに抽出コマンドが 0 件（全行コメントアウト・字下げフェンス等）の場合を fail-closed（HIGH 以上）にする。字下げフェンス（1〜3 スペース）もフェンスとして認識する（候補: `extract_gate_commands`/`omission_lint` のフェンス正規表現を `^[ ]{0,3}```` ``` ```` に拡張＋「セクションあり・抽出 0 件」の警報化）。
4. **check-memo-body-paths.sh の fail-closed 化**: `## 設計確認メモ` で始まる見出しをすべて抽出対象にし、標準形以外の見出しを検知したら exit 1（見出しの是正を促す）にする。「メモ節なし」と「メモにパスなし」を出力上で区別する。
5. 分類の決定論テストを `scripts/claude/tests/` に追加する（①参考掲載ブロック → omission OK、②宣言外の単一コマンド bash fence → HIGH 維持、③`bash scripts/claude/check-*.sh` → ALLOW 実走、④`check-*.sh` を装ったチェーン形 → UNSAFE 維持、⑤コメントアウト/字下げによる宣言消失 → fail-closed、の 5 方向＋失敗注入）。

## スコープ
### 含む
- omission-lint の参考掲載/隠れゲート弁別（fail-closed 維持）
- classify_gate allowlist の check-*.sh 受理追加と読み取り専用規約の明文化
- ゲート宣言の無警報消失の fail-closed 化（セクションあり・抽出 0 件の警報化＋字下げフェンス認識）
- 分類・lint の決定論テスト追加
- check-memo-body-paths.sh の見出し表記ゆれによる無警報合格の fail-closed 化（I180 retro から同梱）
- 既存チェッカー 2 件（check-memo-body-paths.sh・check-issue-background.sh）が新 allowlist で宣言可能になることの確認

### 含まない
- I130 の分類器クォート考慮化そのもの（I130 が担当。本イシューは I130 マージ後に同ファイルへ積む）
- 既存 closed 文書の遡及修正
- チェッカーの tests/ への移動（allowlist 拡張で不要になるのが本イシューの主旨）
