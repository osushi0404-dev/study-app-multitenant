# I094: 決定論テストの false-green 自己検証に decoy 反証を必須化 — 存在検証の部分一致・非近接キーワードによる誤通過を防ぐ

## 関連資料
- GitHub Issue: #180
- 発見元: I092（worktree 運用 runbook 化）の retro（2026-07-02）
- 参考コミット: I092 `8b38c44`（plan-review 指摘で TC-A3 の部分一致・TC-A14 の非近接 grep を是正し decoy で反証）

## 背景/目的

**背景**: I092 の存在検証ゲートで部分一致（`main`⊂`domain`）・非近接キーワード grep による false-green が発生し、plan-issue-review の指摘で初めて検出・是正された（I092 retro・2026-07-02）。
**目的**: 決定論テストの false-green 自己検証に「誤通過を狙った decoy 入力でも NG を確認する」要求を必須化し（do）、plan-reviewer に存在系 TC の偽陰性確認観点を追加する（gate）。

### 現状の問題（証拠・再現手順）
I092 の自動テスト（存在検証の決定論ゲート）で、以下の false-green（対象が壊れても合格しうる見かけのゲート）が発生し、plan-issue-review で初めて検出された:
- **TC-A3**: `grep -Eq 'main'` が**部分一致**のため、`domain`／`remains`／`maintain` 等が本文に在るだけで通過し、「main を使わない警告」の欠落を捕捉できない。
- **TC-A14**: `.env` と `insecure|既定` を**独立した grep**で検証していたため、両キーワードが無関係な別セクションに分散していても通過する。

原因分析: I092 では false-green 自己検証を「対象の**不在**注入（対象を削除/欠くダミー）→ NG 確認」でのみ行い、「**誤通過を狙った decoy 入力**（部分文字列・離れた配置）→ NG 確認」を行っていなかった。是正時（`8b38c44`）に文脈アンカー化・近接一致化し、decoy（`domain` 等・5 行離し）で NG を確認して初めて真に falsifiable になった。

### 根本原因
`plan-writing-rules.md` の「否定・回帰系の決定論テストの自己検証（false-green 禁止）」が、検証手順を「検証対象を一時的に壊した状態（削除/改変した入力・対象を欠いたダミー）」と記すものの、**存在検証で緩いパターン（部分一致・独立した複数キーワード grep）を使う場合に、誤通過を狙う decoy 入力での NG 確認を要求していない**。このため「不在では NG」だけを確認した緩いパターンの存在ゲートが、plausible-but-wrong な入力（部分文字列・分散配置）を取りこぼす。抽象化: 「存在検証の決定論ゲートを不在注入だけで検証し、誤通過（decoy）を検証しない」という一般問題（I092 固有でなく、grep ベースの存在ゲートを書く全イシューで再発しうる）。関連既知原則: 「文字列トークン判定はアンカー/完全一致」（本イシューはこれを**プロセスゲートに組み込む**点が新しい）。

### 解決方針
1. **do**: `docs/runbooks/plan-writing-rules.md` の「否定・回帰系の決定論テストの自己検証（false-green 禁止）」に、「**存在検証で緩いパターン（部分一致・独立した複数キーワード）を使う場合、不在注入に加え、誤通過を狙った decoy 入力（部分文字列・キーワードを離して配置）でも NG を返すことを確認してから採用する**」を追記する。
2. **gate**: `.claude/review-agents/plan-reviewer.md` に「存在系 TC の部分一致・非近接キーワードによる偽陰性（false-green）」を確認する観点を明示する（I092 で機能したレビュー観点の明文化）。
