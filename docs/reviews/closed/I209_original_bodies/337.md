# I201: 手元で流すテストを、変えたファイルから機械的に選ぶ

## 関連資料
- GitHub Issue: #337
- 起点: I197（#332）の retro（予防処置 P1）。記録は `docs/reviews/open/I197_review.md`「## 振り返り」（I197 のマージ後は `docs/reviews/closed/`）
- I197 の再発防止記録: `docs/tests/open/I197_auto_test.md`「再発防止記録（fix-loop 5 回目）」
- 関係する手順: `.claude/skills/implement/SKILL.md`（2) ビルド・テスト）・`.claude/skills/fix-loop/SKILL.md`（6) 決定論のテストを流す）
- 切り出し: CI と手元の道具の同期（shellcheck が手元に無く黙って SKIP された件）は I204（#340）に切り出した（2026-10-27 ユーザーとの対話）

## 背景/目的

**背景**: I197 の作業中、fix-loop の「直したところに関係するテストだけを手元で流す」で、関係するテストを記憶で選び、fix-loop の文章を固定している `test_i185_harness_docs.sh` を取りこぼした。手元では合格に見えて push し、CI の Harness Tests で初めて落ちた（review-gate ⇄ fix-loop の往復が 1 回増えた）。
**目的**: 手元で流すテストの選び方を機械的に決め、取りこぼしで CI で初めて落ちることをなくす。全体（`run-all.sh`）は今までどおり CI に任せる（手元で全体を流しても CI と重なるだけ）。

### 現状の問題（証拠・再現手順）
- fix-loop の手順 6 は「直したところに関係するテストだけを流す」とあるが、選び方が決まっていない（`.claude/skills/fix-loop/SKILL.md`）。implement も同じ

### 根本原因
- implement・fix-loop の「テストを流す」手順に、関係するテストの決定論の選び方が無かった（retro の 5 Whys。手続きの心がけに任せていた）

### 解決方針
- 変えたファイル（`origin/develop...HEAD` と作業ツリーの変更）のファイル名（`code-review.sh`・`SKILL.md` の親フォルダ名など）を、`scripts/claude/tests/` のテストの**本文**から検索し（テストのファイル名との一致ではない。`test_i185_harness_docs.sh` は本文で `fix-loop/SKILL.md` を参照している）、変えたテスト自身も加えて、関係するテストを選んで流すスクリプトを `scripts/claude/` に足し、implement・fix-loop の手順から呼ぶ（I197 の作業中に scratchpad で使った形を元にする）

## 実装対象（既知のもの）
| ファイル | 変更内容 |
|---------|---------|
| `scripts/claude/`（新規スクリプト。名前は計画で確定） | 変えたファイルから関係するテストを選んで流す |
| `.claude/skills/implement/SKILL.md`・`.claude/skills/fix-loop/SKILL.md` | テストを流す手順から新しいスクリプトを呼ぶ |
| `scripts/claude/tests/`（新規・更新） | 新しいスクリプトのテスト（変えたファイルに関係するテストを取りこぼさない・無関係のテストを選ばない） |

## スコープ
### 含む
- 関係するテストの決定論の選び方と、implement・fix-loop からの呼び出し
### 含まない
- CI と手元の道具の同期（I204）
- アプリのテスト（pytest・Jest・E2E）の選び方（CI が流す）

## 関連する品質基準
