## 失敗分解

### F22
- 再現手順: レビュー前の中身が無い状態（develop にマージした後など）で、スキルに書かれた次の呼び出しをそのまま流す
  - `.claude/skills/grill-me/SKILL.md:52` `N=$(bash scripts/claude/issue-source.sh gh-number I###)`
  - `.claude/skills/grill-me/SKILL.md:54` `bash scripts/claude/issue-source.sh body I### > "$DRAFT"`
  - `.claude/skills/issue-bootstrap/SKILL.md:37` `bash scripts/claude/issue-review.sh --file "$DRAFT"`
  - `.claude/skills/plan-issue/SKILL.md:41` `ISSUE_FILE=$(bash scripts/claude/issue-source.sh snapshot "I###") || { …; exit 1; }`
- 期待値: 外で動く必要のある 16 本は、スキルどおりに打てば起動役に付け替わり、外で動く（AC2）
- 実際値: `route()` は `NOT_SIMPLE_RE`（`$`・`>`・`(` など）に当たる形を付け替えない。付け替えが無いので中で動き、gh が鍵を読めない・`claude -p` が API に届かずに失敗する
- ログ: レビュー記録の F22 の再現の欄

### F23
- 再現手順: ルートに `--dangerously-skip-permissions` という名前のファイルを置き、`bash scripts/claude/test-session.sh x [-]-dangerously-skip-permissions` を流す
- 期待値: `test-session.sh` の危ない引数は承認に回る（AC5）
- 実際値: `_test_session_ask` は `-` で始まらない語を位置引数として飛ばすので、`[-]-…` は確かめを通る。`NOT_SIMPLE_RE` に `*?[` が無いので、単体の形として起動役に付け替わり、外の bash が glob を展開して `--dangerously-skip-permissions` が渡る

## 根本原因

- F22: 第 2 版は「単体の形だけを付け替える」という規則にした（`docs/plans/open/plan_I599.md` の方式）。この規則自体は狙いどおりだが、呼び出す側の文書（スキル）を単体の形にそろえる作業を影響範囲に入れていなかった。第 1 版は `bash scripts/claude/*` を外に出す一覧に入れていたので、`$(…)` に包んだ形も（公式の照合のしかたによっては）外に出ていた。第 2 版で一覧から外したので、包んだ形は中で動くようになった。単体の形かどうかを機械で確かめるテストが無かったので、実装中に気づけなかった
- F23: 「単体の形」の定義（`NOT_SIMPLE_RE`）が、シェルが展開する文字のうち glob（`*` `?` `[`）を落としていた。単体の形なら引数は書いたとおりに渡る、という前提が崩れていた
- セキュリティ観点: F22 は安全側に倒れる失敗（外に出ないだけ）で、秘密の漏れ・権限の昇格は無い。F23 は承認の確かめのすり抜け（`--dangerously-skip-permissions` 相当の起動が承認なしで外で動く）。入口は Claude が作業ツリーにファイルを置き、その glob を引数に書くことで、`test-session.sh` が起こす `claude -p` は鍵の読み取り専用の名義で動く（GitHub は読み取りだけ）

## 対応方針（全案＋推奨）

### F22
- 案 A（推奨）: 呼び出す側の文書を単体の形に直す。`$(…)` で受けていた値は、単体で流して出力を読み、次のコマンドには値をそのまま書く。`> "$DRAFT"` は、手順 1 で読んだ本文を Write ツールで下書きに書く形にする（スクリプトにファイルへの書き出しを足さない。外で動くスクリプトが任意の場所に書けるようになるのを避ける）。`"$DRAFT"` は下書きのパスをそのまま書く。あわせて、スキル・サブエージェントの定義に書いた 16 本の呼び出しが、置き換えの後に `route()` で付け替わることを確かめる決定論のテスト（TC-18・失敗注入つき）を足す
  - セキュリティ影響: なし（外に出す形は増えない）。BP: 「単純な規則だけで判定する」（fix-loop 手順 3・I179 retro P1）に合う
  - 保守性: 新しいスキルで包んだ形を書くと TC-18 が落ちる（気づける）
  - 副作用: スキル 3 本の手順の書き方が変わる（Claude が値を読んで次のコマンドに書く 1 手間が増える）
- 案 B: `route()` が `VAR=$(bash scripts/claude/x.sh …)`・`… > file` を読んで中だけを付け替える
  - セキュリティ影響: コマンドの文字列からシェルの動きを読む精密な判定に戻る（第 1 版が収束しなかった原因そのもの）。却下
- 案 C: `bash scripts/claude/*` を外に出す一覧に戻す
  - 第 2 版の方式（既定は中）を崩す。却下

### F23
- 案 A（推奨）: `NOT_SIMPLE_RE` に `*` `?` `[` を足す（glob を含む形は付け替えず中で動く・安全側）。TC に `[-]-…` の形と、`*`・`?` の形を足す（失敗注入: 文字を表から外すと落ちる）
  - セキュリティ影響: すり抜けが無くなる。副作用: `check-permission-prompt.sh bash 'ls *'` のように引数に glob の文字を含む呼び出しは中で動いて失敗する（既に `(`・`$`・`|` を含む形は同じ扱い）。そのときは人が `!` で流す（手順書に 1 行）
- 案 B: 単一引用符の中を除いてから判定する
  - 二重引用符の中の `'` で範囲を取り違え、`$(…)` を隠せる。引用の読み取りは精密な判定になる。却下
- 案 C: `_test_session_ask` で位置引数も表と照らす
  - glob は test-session 以外の引数でも展開される（作業ツリーのファイル名が引数になる）。根を断たない。却下
