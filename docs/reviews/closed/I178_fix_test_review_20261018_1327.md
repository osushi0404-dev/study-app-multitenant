## false-green 評価

**否定・異常系テストが実際に NG になる構造か**を確認した。

- **SHA-256 チェック**: runbook が 1 バイト変われば `actual_sha ≠ RUNBOOK_SHA256` となり確実に exit 1。exit code の向きは「一致=0・不一致=exit 1」で合否基準と一致している。
- **見出し 1 回チェック**: `grep -cxF` で一致行数を数え、`-eq 1` の比較で判定。`n=0`（見出しなし）・`n=2`（重複）のいずれも NG になることを K7（重複注入で exit 1）・既存の開始行なし注入（節が空になり expect_block で NG）で確認している。
- **節の全文比較（expect_block）**: `[ "$actual" = "$expected" ]` の完全一致比較であり、部分一致による誤通過はない。
- **close step 6 の 3 行固定**: `grep -A2 -xF` で取得後に完全一致比較。K6（追加一文を削除→exit 1）で NG になることを確認済み。
- **残余 (E)**: step 5.5〜6 の外に矛盾文を追加しても exit 0 になる。これは診断メモで設計上の残余として明示的に決定・記録されており、false-green ではなく設計の限界として扱う。
- **exit code の向き**: 全チェックで「合格=exit 0・不合格=exit 1」が統一されており逆転はない。

空振り（常に成功するだけのアサーション）の疑いはなく、false-green に該当する構造は見つからない。
