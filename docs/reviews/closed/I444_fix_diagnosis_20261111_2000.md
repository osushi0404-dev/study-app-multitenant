# I444 診断メモ（fix-loop 2）

対象: `docs/reviews/I444_code_review_20261111_1949.md` の止める指摘 F1（前の周から open のまま）。

## 失敗分解
- 再現手順: fix-loop 1 で `docs/tests/open/I444_auto_test.md` の決定論ゲートから `test_guard_corpus_diff.sh` を外して push し、`bash scripts/claude/code-review.sh I444` を流した
- 期待値: F1 が resolved になり FINAL_VERDICT が OK
- 実際値: 決定論ゲートは 8 行すべて exit 0 になったが、「起点の後に記録の場所の外は変わっていない」（`code-review.sh` 1043〜1047 行の `NO_DELTA=1`）ため、レビュー役が呼ばれず台帳が前の周のまま引き継がれ、F1 が open のまま FINAL_VERDICT: HIGH
- ログ: 記録の「コードレビュー [I444]（差分なし）」の節

## 根本原因
- 直接: fix-loop 1 の直しが記録の場所（`docs/tests/`）だけだったので、差分のレビューが「直したものが無い」と扱った（I202 の作り。記録の場所だけの変更ではレビュー役を呼ばない）
- F1 の元の原因（corpus diff をゲートに置いた）のうち、記録の場所の外に残っている部分: `scripts/claude/tests/test_guard_corpus_diff.sh` の冒頭のコメントが「guard_corpus_diff.py を決定論ゲートの許可された形（bash scripts/claude/tests/*.sh）で呼ぶ」と書いている。計画を書くときにこれを読み、ゲートに置いてよいものと受け取った。所要が作業記録の件数に比例して数分かかり、ゲートの 1 行 120 秒に収まらないことが、どこにも書かれていない
- 仕組みの穴（このイシューでは直さない・retro へ）: 止める指摘を記録の場所の直しだけで直したとき、差分のレビューがそれを確かめる手段が無く、止める指摘が閉じない
- セキュリティ観点: 該当なし（コメントの直し）

## 対応方針（全案＋推奨）
### 案 A（推奨）: `test_guard_corpus_diff.sh` の冒頭のコメントを直す
- 内容: 「決定論ゲートの許可された形で呼ぶ」を、「所要が作業記録の件数に比例して数分かかるので、auto_test の決定論ゲート（1 行 120 秒）には置かず、見張りを直したときに手で流して結果を記録する（`danger-ops.md`「見張りを直したら、コミットの前に 3 つのテストを流す」・I444）。作業記録が無い環境（CI）では SKIP」にする
- セキュリティ影響: なし。ベストプラクティス: 誤解の元（コメント）を直す・コードの動きは変えない
- 保守性: 次に見張りを直すイシューが同じ置き方をしない。リスク: なし（コメントだけ）
- この直しは記録の場所の外なので、差分のレビューがレビュー役を呼び、F1 を確かめられる
### 案 B: `code-review.sh` の差分なしの扱いを直す（記録の場所だけの直しでも、止める指摘があればレビュー役を呼ぶ）
- リスク: 共有の仕組みの変更で、このイシューの範囲を越える。I202 の決定論テストの見直しも要る
### 案 C: 止まって人に聞く
- 安全側の選択肢（案 A）があるので当たらない
### 推奨: 案 A（案 B は retro で後続のイシューにする）

## 影響調査
- 同じコメントの写し: `scripts/claude/tests/` の中で「決定論ゲートの許可された形」と書くのは `test_guard_corpus_diff.sh` と `test_guard_bash_oracle.sh`。oracle は速く（ゲートで exit 0・数秒）、直す必要はない
- 呼び出し箇所: `run-all.sh`（全部の test_*.sh を流す。CI には作業記録が無く SKIP で速い。手元では数分かかるが上限は無い）・`danger-ops.md`（手で流す）。動きは変えない
