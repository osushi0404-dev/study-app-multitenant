# I599 fix-loop 診断メモ（2026-11-20 19:10・止める指摘 F7・F8）

記録: `docs/reviews/I599_code_review_20261120_1903.md`

## 失敗分解
- F7（High）: `bash scripts/claude/test-session.sh x >log --permission-mode bypassPermissions`。期待: 承認。実際: `>` で区切りを分けたので、`--permission-mode …` が別の区切り（先頭が `bash` でない）に移り、`_test_session_ask` に渡らない。`bash scripts/claude/tests/stress-repeat.sh 3 2>/dev/null scripts/claude/tests/test_new.sh` も、新しい `test_new.sh` が出発点に入らない
- F8（Medium）: `bash scripts/claude/test-session.sh x --setting-sources user --settings frontend/tsconfig.json`。期待: 承認。実際: 「追跡済みで BASE と同じ」なら何のファイルでも `settings_ok` になり、プロジェクトの設定（見張り・サンドボックス）を読まない子が承認なしで起きる

## 根本原因
- F7: 振り向けの記号を「命令の区切り」と同じに扱った（F1 の直し）。シェルでは振り向けは同じ命令の一部で、記号の直後の 1 語が振り向けの先、その後ろは同じ命令の引数が続く
- F8: 「プロジェクトの設定の代わりになる設定ファイル」を「レビュー済みのファイル」と取り違えた。代わりになるのは `.claude/settings.json`（見張りとサンドボックスを持つ）だけ
- セキュリティ: どちらも守りの無い子・レビュー前のテストを外で動かせる（C8）

## 対応方針（全案＋推奨）
- F7:
  - 案 A（推奨）: 区切りは `;&|()` だけに戻す。`<>` を含む記号の語（`>`・`>>`・`<`・`>&`・`&>` など）は振り向けとして、その語と直後の 1 語（振り向けの先）を引数から除き、同じ区切りを続ける。F1（`a.sh>/dev/null` を 1 語にしない）は、`<>` を区切りの記号の文字に残すことで保つ
  - 案 B: 振り向けを含むコマンドは常に中で動かす。手順書の書き方（振り向けを付けない）では起きにくいが、`2>&1` を付けた普通の呼び出しまで中に回る
- F8:
  - 案 A（推奨）: `--setting-sources` が `project` を含まないときに承認なしで通すのは、`--settings` が `.claude/settings.json` そのもので、BASE と同じときだけ（敵対的レビューの起こし方 `.claude/agents/adversarial-reviewer.md:69` の形）
  - 案 B: `--settings` の中身の JSON を読み、hooks・sandbox を持つかを見る。精密な判定は足さない決まり（fix-loop 手順 3）に反する
- 新しい安全装置の対象: 手元の秘密とサンドボックスの外（GitHub からは戻せない）。判定は語とパスの照合だけ

## 影響調査
- `_segments` の使い先は `_check` だけ。区切りの変更で影響を受けるのは「`bash` の直後の語」と「引数」の取り出し
- F1 の回帰（TC-24）は案 A でも通る（`a.sh>/dev/null` の `>` は区切りの文字として語から切り離され、振り向けとして扱われる）
- `settings_ok` の使い先は `--setting-sources` の確かめだけ
- テスト: TC-24 に F7 の 2 形（振り向けの後ろの引数を見る）を足し、TC-12 に F8 の形を足す。各 FG
