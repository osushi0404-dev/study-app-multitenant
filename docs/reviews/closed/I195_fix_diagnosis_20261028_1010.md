# I195 修正の診断メモ（台帳 F3・2026-10-28）

## 失敗分解
- 起点: コードレビュー `docs/reviews/I195_code_review_20261028_0907.md` の台帳 F3（Medium・再現なし → 一覧に回した）。マージ依頼の後、ユーザーの求めで再評価して再現した。ユーザーの指示（「今直して」）でマージ前に直す（止める指摘の節には無いが、ユーザーの指示による）
- 再現手順: `scripts/claude/tests/test_i193_official_flow.sh` 450 行の `s21_rules_prompt`（`! grep -hE 'Human.*承認画面|承認画面.*Human' "$@" | grep -qvF 'check-permission-prompt.sh'`、`set -uo pipefail` の下）を、違反の行 1 行の後に「Human・承認画面・check-permission-prompt.sh を含む行」を 20000 行続けたファイルに当てる（scratchpad の再現スクリプト）
- 期待値: 違反の行があるので不合格（exit 1）
- 実際値: 200 回中 200 回合格（exit 0）。違反の行 1 行だけの小さいファイルでは 200 回とも不合格（正しい）

## 根本原因
- 後ろの `grep -q` は最初に一致した時点で終わる。前の `grep` がまだ書いている途中ならパイプが閉じて SIGPIPE（終了コード 141）で終わる。`pipefail` の下ではパイプ全体の終了コードが 141（0 以外）になり、先頭の `!` で 0（合格）に反転する
- つまり「違反を見つけたとき」にだけ前のコマンドが異常終了しうる形で、見つけた結果が見逃しに変わる。出力がパイプの容量（64KB）を超えるときに起きる。今の 3 つの文書は小さいので今は起きないが、判定として偽緑になりうる
- セキュリティ: 該当なし（テストの判定。認証・入力・秘密情報に関係しない）

## 対応方針（全案＋推奨）
| 案 | 内容 | 良い点 | 悪い点 |
|---|---|---|---|
| A | 結果を変数に受ける: `hits=$(grep … "$@" \| grep -vF …)`・`[ -z "$hits" ]` | 小さい直し | ファイルが無い・読めないとき、前の grep が失敗しても出力が空で合格になる（fail-open） |
| B（推奨） | パイプをやめて awk 1 回にする: 先にファイルが読めるかを確かめ（読めなければ不合格）、`awk '/Human.*承認画面\|承認画面.*Human/ && !/check-permission-prompt\.sh/ { f = 1 } END { exit f }' "$@"` が 0（違反なし）のときだけ合格 | SIGPIPE が起きない（プロセス 1 つ）。読めないファイルも不合格（fail-closed）。粗く確実 | 1 行が少し長くなる |
| C | `grep -c` で数える（`grep -cvF` は最後まで読むので SIGPIPE が起きない） | 小さい直し | A と同じく、ファイルが読めないときに合格になる |

推奨は B。理由: 反転の元（パイプと `!`）を無くし、読めないときも止める側に倒れる。新しく足すコードも小さい。

## 影響調査（同型のバグ）
- `scripts/claude/` 全体で `! <コマンド> | grep -q…` の形を grep した（`grep -rnE '!\s+[a-z_]+[^|]*\|\s*grep\s+-[a-zA-Z]*q' scripts/claude/ --include=*.sh`）。当たり 3 件:
  - `scripts/claude/check-frontend-evidence.sh:27`（`set -uo pipefail`）: `! printf '%s\n' "$CHANGED" | grep -q '^frontend/src/'`。変更ファイルの一覧の先頭近くに `frontend/src/` があり、一覧が 64KB を超えると（ファイル名で約 2000 件以上）SIGPIPE で「対象外」と誤り、画面確認の記録の判定が飛ばされる。scratchpad の再現スクリプトで 20000 件のときに 100 回中 100 回、2 件のときは 0 回を確かめた。普通の PR の大きさでは起きない。I195 のスコープ外（イシューの「含まない: `check-frontend-evidence.sh` そのものの変更」）なので、このイシューでは直さず、retro で扱う（同じ「判定が実行の条件で反転する」種類として I210 #352 に同梱する案）
  - `scripts/claude/tests/test_posttooluse_check.sh:32`（pipefail あり）: `! printf '%s' "$ERR" | grep -q "$3"`。ERR はフックのエラーメッセージで短く、64KB を超えない。反転しても「期待のメッセージが無い」と誤って不合格になる向き（偽赤）で、見逃しにはならない
  - `scripts/claude/tests/test_auto_test_template_lint.sh:70`（pipefail なし）: pipefail が無いのでパイプの終了コードは後ろの grep のもの。反転は起きない
