## 主要な学び（根本原因分析）

### 事象
本イシューの起点（I071 retro 予防処置）が「対象ファイル: `plan-writing-rules.md`（文書品質ゲート）／`plan-issue/SKILL.md`（転記分）」と**断定形**で記載していたが、実際は文書品質ゲートの実体が `plan-issue/SKILL.md` にのみ存在し、`plan-writing-rules.md` には無かった。誤った所在が I072 のイシュー本文（実装対象テーブル）へそのまま伝播し、grill-me で初めて是正された。

### 理想 vs 実際
| ステージ | 理想 | 実際 |
|---------|------|------|
| retro（予防処置の対象ファイル記載） | grep 未確認の所在は「推定・plan-issue で要実在確認」と明示し、断定しない | 記憶ベースで断定形で記載し、誤った所在がイシューへ伝播 |
| grill-me | コードベース探索で所在の食い違いを検出・是正 | 検出・是正できた（安全網は機能） |

### 5 Whys: retro 予防処置の対象ファイルの誤伝播
- Why1: なぜ I072 イシューの対象ファイルが逆だったか？ → 起点の I071 retro が予防処置の「対象ファイル」を、実体の所在を grep 確認せず記憶ベースで**断定形**で記載したため。
- Why2: なぜ断定形で記載したか？ → retro スキルに「予防処置の対象所在は、未確認なら推定である旨を明示する（または grep 確認する）」という要求がない。
- Why3: なぜその要求がないか？ → retro は根本原因分析と予防策立案に焦点を当て、所在の実在検証は後続の grill-me / plan-issue（参照先実在性検証）に委ねられている。しかし retro の予防処置記載が後続イシューの「実装対象（既知のもの）」の初期値になるため、未確認の所在が断定形のまま伝播する。
- 根本原因（抽象化済み）: **retro で予防処置の「対象ファイル/所在」を記載する際、grep 等で実在確認していない所在を断定形で書くため、未確認の所在が後続イシュー本文へ false-confidence のまま伝播し得る。**
- 抽象化テスト: I072/SKILL/grep を除いても「再発防止策の対象箇所は、未確認なら推定と明示してから記録する」で成立 → 一般化可能。
- 分類: **予防処置**（あらゆる retro で起こり得る）。なお安全網（grill-me / plan-issue の参照先実在性検証）は機能しており、本件の優先度は中。
