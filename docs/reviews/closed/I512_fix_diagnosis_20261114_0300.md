## 根本原因
- 受け入れ条件 AC8（I430 の一覧に F1〜F3 の行がある）を、CI で毎回流す決定論テスト（TC-07）にした。AC8 はこのイシューの中で 1 回確かめれば足りる記録の状態で、後から意図して変わる（一覧は直したら行を消す）
- `docs/runbooks/plan-writing-rules.md`「決定論テストの対象の選び方」の「作らない: 設定ファイルの中身をテストにもう一度書いて照合するもの」「消すのが意図的な変更でしか起きないものの有無」に当たる。計画の段階で、この節に照らして選ばなかった
- セキュリティ: 影響なし

## 対応方針（全案＋推奨）
- 案 A（推奨）: TC-07（と FG-07・FG-07b）をテストのファイルから外す。AC8 は手動テスト（manual_test No.4・Claude が実施）で確かめる。一覧の行の形の確かめは、既存の `test_i202_ledger_cleanup.sh` の D3（実物の一覧のどの行も決まった形）が全一覧に対して毎回行っている（I430.md の新しい行も含む）ので、形の守りは失わない
  - メリット: 将来の罠が消える・決まりに沿う・数行の削除
  - デメリット: 無い（AC8 は今回の 1 回の確かめで足りる）
- 案 B: TC-07 を「行が無ければ合格」にする
  - デメリット: 確かめる意味が無くなる（常に合格）
- 案 C: 残す（台帳 F4 のまま一覧）
  - デメリット: 将来、無関係の PR の CI を止める罠を自分で残す
