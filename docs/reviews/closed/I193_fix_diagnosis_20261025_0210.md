# I193 fix-loop 診断メモ 4（2026-10-25 02:10）

起点: review-gate の基本レビュー 4 回目 `docs/reviews/I193_code_review_20261025_0158.md`（FINAL_VERDICT HIGH・High 2・Medium 5・Low 3）。

範囲: 基本レビューが 4 回続けて HIGH なので、止める条件 3 の安全側（範囲を狭める）として、今回は High 2 件と 1 行で直る Medium 3 件だけを直す。効率の Medium 3 件と Low 3 件は retro に回す（下の「今回直さないもの」）。あわせて review-gate ⇄ fix-loop の繰り返しの上限を足す（上限が無いこと自体が穴）。

## 失敗分解

|---|---|---|---|---|

## 根本原因
- H1: 「PR が無い」と「PR を取れなかった」を区別せず、どちらも「CI を待たない」にしていた（fail-open）
- H2: 段階のスキルの手順で直接打つコマンドが、settings の allow に入っているかを確かめていない（スクリプト経由の `gh pr review` は `Bash(bash scripts/claude/*)` で通るが、手順に直接書いたものは通らない）
- 上限: review-gate ⇄ fix-loop の繰り返しに上限が無い（敵対的レビューだけ 2 周の上限を置いた）
- M1〜M3: 前回直した型の取りこぼし

## 対応方針（全案＋推奨）
- H1: 案 A（推奨）`gh pr view` の失敗と PR が無いことを区別する。`gh pr list --head <今のブランチ> --state open --json number` で引き、gh が失敗したら `CI_WAIT: NO_PR` を出して exit 1。PR が本当に無いときも、CI を確かめられないので同じく exit 1（新しい流れでは /plan-issue が Draft PR を作るので、PR が無いのは異常）。review-gate の終了コード表に NO_PR（原因を直して 1 回やり直し、直せなければ止める）を足す
  - 案 B: PR が無いときは CI 待ちを飛ばす今の形のまま、gh の失敗だけを止める。PR が無い異常を見逃す
- H2: 案 A（推奨）スクリプトにする。`scripts/claude/review-timer.sh <秒>`（sleep するだけ）と `scripts/claude/post-review-comment.sh <記録>`（PR を引いて `gh pr review --comment --body-file`、65,536 文字を超えるときは要約）。`Bash(bash scripts/claude/*)` で承認画面が出ない。review-gate の手順をこの 2 つに置き換える
  - 案 B: settings.json に `Bash(sleep *)`・`Bash(gh pr review *)` を足す。安全装置そのものの変更（止める条件 2）になるので採らない
- 上限: review-gate に「基本レビューが 3 回続けて HIGH 以上（記録の `STAGE_DONE: review-gate NEXT: fix-loop` が続けて 3 行）なら、4 回目からは High・Blocker だけを直し、Medium 以下は retro に回す。5 回続けば止める（止める条件 3）」を足す
- M1: here-string にする
- M2: F10 は一時のリポジトリの記録で確かめる
- M3: test-gate の dirty は「この段階は記録の場所の外をコミットしない。その変更が実装の一部なら `NEXT: fix-loop`（fix-loop が直してコミットし、review-gate に戻す）、この流れで作った一時ファイルなら消す」にする

## 今回直さないもの（retro に回す）
- 記録だけの push のたびに CI 全体が走り直す（効率）
- 組み込みのレビューを CI の確認より先に背景で起動する（NOT_PUSHED などで 2 本分を捨てる。効率）
- gate-check が code-review.sh を丸ごと source している（構成。VERDICT の正規表現が 2 か所）
- Low: gate-check のファイルごとの git の呼び出し回数・その他

## 影響調査
- `PR_NUM` を使うのは code-review.sh だけ（CI 待ちと PR コメント）
- 手順に直接書いたコマンドで allow に無いもの: review-gate の `sleep 900`・`gh pr review`。ほかの段階のスキルの直接のコマンド（`git add`・`git commit`・`git rev-parse`・`bash scripts/claude/*`・`gh pr edit`・`gh pr ready`・`gh issue comment`〔`Bash(gh issue *)`〕）は allow にある。close の `gh pr view … --json isCrossRepository`（`Bash(gh pr view *)`）も allow にある。`gh pr ready` は allow に無い → 直さない。PR の状態を外向きに変える操作で、確認の画面をスクリプトで包んで避けるのは安全装置の回避に近い。出るのは close の 1 回（マージを頼む直前）で、無人の流れの途中を止めるものではない。`sleep` と PR のコメントは、既存のスクリプト（code-review.sh・fix-review-lib.sh）が同じ形で行っている操作なので、スクリプトにそろえる
