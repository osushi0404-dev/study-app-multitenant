# I197 fix-loop 診断メモ（6 回目・台帳の 1 周目の止める指摘 F1〜F4）

対象: `docs/reviews/I197_code_review_20261027_0102.md` の台帳のうち止める指摘（High）F1〜F4。Medium 以下（F5〜F10）は直さない（台帳に残り retro）。

## 失敗分解
| id | 再現手順 | 期待値 | 実際値 |
|---|---|---|---|
| F1 | 台帳に F2（Medium）があり、差分のレビューの入力には止める指摘（F1 だけ）しか出ない。レビュー役が新しい High を「F2」と書く | 新しい High として、FILE から SCOPE を決めて止める | 既存の F2 に合流し、F2 の前の SCOPE（・重大度の扱い）を引き継ぐ。新しい High が outside 扱いで通りうる |
| F2 | 差分の中のファイルの新しい High を `FILE=./scripts/a.sh` や `FILE=scripts/a.sh:12` と書く | 差分の中（delta）として止める | 範囲の一覧と文字が一致せず outside になり通る |
| F3 | 敵対的レビューの続きの呼び出しが exit 0 だが result が success でない（max budget など） | 前の成功した報告で判定する | 本文を空で上書きし、前の報告を失う |
| F4 | 差分のレビューで、レビュー役が FINDING 行を読めない形（表の中・箇条書き）で書き、`VERDICT: HIGH` を出す | 止める（食い違いは止める側） | 差分のレビューは VERDICT 行を合否に使わないので、台帳は前のまま・OK で通りうる |

## 根本原因
- F1: 新しい指摘の番号をレビュー役に振らせ、入力には止める指摘の番号しか見せていない。既存の番号との衝突をスクリプトが見分けていない。
- F2: SCOPE の判定が FILE の文字の完全一致だけで、表記のずれを「外」に倒していた（止めない側に倒れる）。
- F3: 3 回目の修正（続きの失敗で前の報告を消さない）で、「失敗」を終了コードだけで見て、result の subtype を見ていなかった。
- F4: 差分のレビューで VERDICT 行を使わないと決めたとき、「FINDING 行が読めなかった」場合の止める側の扱いを入れていなかった。
- 共通: どれも「判定に迷ったら止めない側に倒れる」経路。§4.8 の方針（止める側に倒す）に揃える。
- セキュリティ観点: どれも偽の OK（止めるべき High が通る）。認可・インジェクションの新しい穴は無い。

## 対応方針（全案＋推奨）
- F1:
  - 案 A（推奨）: スクリプトが見分ける。前の台帳で止める指摘でなかった（＝入力に見せていない）既存の番号が今回使われたら、その行は新しい指摘として、台帳の最大の番号の次に振り直し、SCOPE は FILE から決める。あわせて入力に「台帳の最大の番号」を書く（衝突そのものを減らす）。
  - 案 B: 入力に台帳の全部を見せる。入力が増え、止めない指摘まで見直しの対象に見えて、収束の考え方に反する。
  - 推奨 A。
- F2:
  - 案 A（推奨）: FILE を正規化（先頭の `./` を除く・`:` 以降の行番号を除く）してから範囲と比べる。正規化しても、リポジトリに存在しないパスなら delta（止める側）。outside にするのは「存在するファイルで、範囲に無い」ときだけ。
  - 推奨 A（単純な規則で止める側に倒す）。
- F3: 案 A（推奨）: 続きの呼び出しの「成功」を「exit 0 かつ result が success」にする。そうでなければ前の成功した本文で判定し、直前の往復の実験は「読まれていない」にする（3 回目の扱いと同じ）。
- F4: 案 A（推奨）: 差分のレビューで、code-reviewer の VERDICT 行が HIGH 以上なのに、今回の本文に読める FINDING 行が 1 行も無いときは BLOCKER（食い違いは止める側）。読める FINDING 行がある場合は今までどおり台帳で決める。

## 影響調査
- F1・F2・F4 は code-review.sh の `_LEDGER_PY`（update）と本体の合否の 1 か所ずつ。F3 は adversarial-review.sh の `run_perspective` の 1 か所。
- 同型: SCOPE を決める箇所は update の新しい指摘の分岐だけ。終了コードだけで成功とみなす箇所は adversarial-review.sh の続きの呼び出しだけ（最初の呼び出しも同じ判定にする）。
- テスト: TC-09 に R15（F1: 止める指摘でない既存の番号の再利用は新しい指摘として振り直し・範囲の中なら止める）・R16（F2: `./`・`:行番号` の正規化・存在しないパスは delta）・R14 の 3 周目（F4: FINDING 行なし＋VERDICT HIGH → BLOCKER）、TC-01 に A28（F3: 続きの result が success でないとき前の報告で判定）と、それぞれの FG。
