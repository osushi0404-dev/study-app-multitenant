# I620 修正の診断（fix-loop・2026-11-26 15:20）

起点: test-gate の Claude の手動テスト No.12（`docs/tests/open/I620_manual_test.md`）の NG

## 失敗分解
- 再現: 組織の管理者で `/members` を開き、幅を 360px にする（画面キャプチャ `.evidence/I620/tg-members-360-a-1.png`）
- 期待: 画面の横にはみ出さず、表は表の中で横に流れる（計画 13「幅 360px: 表は `TableContainer` で横に流す」）。押す的は 44px 以上
- 実際: 画面ははみ出さないが、表が表の中で横に流れない。表が 296px の枠に収まるよう列が縮み、ユーザー ID・見出し・ボタンの文字が 1 文字ずつ縦に折り返す（［登録用リンク］64×145・［パスキー］64×99）
- ログ: なし（見た目の問題）

## 根本原因
- MUI の `Table` は既定で `width: 100%`・`table-layout: auto` なので、列は枠に合わせて縮み、文字の折り返しで高さが伸びる。`TableContainer` に `overflowX: 'auto'` を付けても、表の幅が枠を超えない限り横に流れない。表の最小の幅と、折り返さない列の指定が無かった
- jsdom の単体テストは大きさを測れず、E2E も 1280px でしか見ていなかったので、気づけなかった（I619 の No.10 と同じ型）
- セキュリティ: 該当なし（見た目）

## 対応方針（全案＋推奨）
- 案 A（推奨）: 表に最小の幅（`minWidth: 720`）を付けて、狭い画面では `TableContainer` の中で横に流す。操作のボタンは `whiteSpace: 'nowrap'`、ユーザー ID の列以外の列（役割・パスキー・登録用リンク）も折り返さない。E2E に「幅 360px で、表の中のボタンの高さが 44〜56px に収まり、表の枠が横に流れる（`scrollWidth > clientWidth`）」を足す
  - 良い: MUI の推奨の形（横に流れる表）。変更が小さい。計画の 13 のとおり
  - 悪い: 狭い画面では横に流す操作が要る（計画で決めた形）
- 案 B: 狭い画面では表をやめて、1 人 1 枚のカードの並びに切り替える
  - 良い: 横に流さずに読める
  - 悪い: 画面の配置が変わる（ユーザーが了承した案から外れる）・部品が増える
- 案 C: 操作のボタンをアイコンだけにして列を狭くする
  - 悪い: ボタンの文言（了承した案）が変わる・それでも 5 列は 360px に収まらない

## 影響調査
- 同じ型（`TableContainer`＋文字の多い列）: 今回の差分では `MemberManagement.tsx` だけ。既存の画面（`SubjectManagement.tsx`・`UserManagement.tsx` など）の表の 360px の見え方は I620 の範囲外（retro で後続にするか決める）
- 運営の編集画面の欄（`StaffCredentialsCard`）は表を使わず、ボタンが `flexWrap` で折り返すので影響しない
