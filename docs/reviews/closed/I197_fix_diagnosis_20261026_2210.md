# I197 fix-loop 診断メモ（3 回目・基本レビュー 3 回目の HIGH）

対象: `docs/reviews/I197_code_review_20261026_2159.md` の High 1 と、それに直結する Medium 3 件（ほかの Medium 3・Low 2 は見送り。理由は自律判断の記録）

## 失敗分解
| # | 重大度 | 再現手順 | 期待値 | 実際値 |
|---|---|---|---|---|
| H1 | High | 1 回目の報告が `ITEM: V1 RESULT=experiment EXP=P1-E1`＋実験案。実験役が P1-E1 を実行。続き（`--resume`）が時間切れ | レビュー役が結果を読んでいない実験は「実験で確認」にならない（V1 未検証） | 前の本文で判定し、`exp_status` が `ran` なので V1 が「確認済み（実験）」になる（fail-open） |
| M1 | Medium | 実験案の最後の行の後に空行を入れる（`echo hello` の後に空行、その後 `EXPERIMENT_END`） | 実行されたなら「実行した」 | `.cmd` は改行で終わり、実験役への指示は `$(cat …)` で末尾の改行が落ちるので、完全一致が外れ「呼ばれなかった」→ 毎周 HIGH |
| M2 | Medium | レビュー役がツールを 1 回も呼ばずに時間切れ（`last_tool` が `(なし)\t\t\t<秒>`） | 記録の「最後のツール呼び出し」「その結果」「経過」が正しく出る | `IFS=$'\t' read` が連続するタブを 1 つにまとめ、欄がずれる（code-review.sh の BLOCKER の記録・敵対的レビューの記録） |
| M3 | Medium | 実験が `docs/plans/open/plan_I###.md` の一覧や過去の記録を書き換える | 作業ツリーを変えた実験として周全体を無効 | `dirty_outside_records` は記録の場所を除くので、判定の材料の書き換えを見逃す |

## 根本原因
- H1: 2 回目の修正（続きが失敗したら前の本文で判定）で、「前の本文が出した実験案のうち、結果が届いていない実験」を区別しなかった。実験の結果をレビュー役が読んだかどうかは、続きの呼び出しが成功したかで決まる。
- M1: 実験案の取り出しで、末尾の空行を正規化していなかった（実験役に渡す文字列と照合する文字列が違う）。
- M2: 欄の区切りに、bash の IFS で「空白扱い」になるタブを使い、空の欄を許していた。
- M3: 「記録の場所はレビューの後に変えてよい」（gate-check の規則）を、そのまま「実験が変えてよい」に当てはめていた。実験中は、このスクリプト自身も含めて誰もリポジトリに書かないので、記録の場所を除く理由が無い。
- セキュリティ観点: H1 は判定の偽 OK、M3 は判定の材料（一覧・過去の記録）の書き換えの見逃し。どちらも「普通の書き方の事故」（実験が計画書を書き換える・結果を見ずに終わる）で起きうる。

## 対応方針（全案＋推奨）
- H1:
  - 案 A（推奨）: 続きの呼び出しが失敗したら、その往復で実行した実験の状態を `unread`（実行したが結果をレビュー役が読んでいない）に書き換える（`exp_status` に追記し、最後の行を採る）。判定では `ran` だけを「実行した」とみなすので、未検証になる。記録には「実行した（結果は読まれていない）」と出す。
  - 案 B: 続きが失敗した観点を「報告なし」にする。前の報告の findings（NEW_HIGH など）も捨てることになり、見つかった指摘を失う。
  - 推奨 A: 指摘を残しつつ、読まれていない実験だけを無効にできる。
- M1: 案 A（推奨）: `extract_experiments` で、実験案の先頭と末尾の空行を取り除いてから `.cmd` に書く（中の行はそのまま）。
- M2: 案 A（推奨）: `claude_log_last_tool` が空の欄を `-` で埋める（区切りはタブのまま）。呼び出し側の読み方は変えない。
- M3:
  - 案 A（不採用・診断レビュー 1 回目で差し戻し）: `git status --porcelain` の文字列だけを起動時と比べる。起動前から変更済み・未追跡のファイル（作業中の計画書・レビュー記録は普通こうなる）を実験がさらに書き換えても、status の行は同じなので見逃す。
  - 案 A'（推奨）: 起動時に「作業ツリーの状態」を控える。状態 = `git status --porcelain=v1 -z --untracked-files=all --no-renames` の各行と、その行のファイル（消えていないもの）の中身のハッシュ（`git hash-object`）。各実験役の後と全観点の後に同じ方法で取り直して比べ、違えば（記録の場所を含むどのファイルでも）周全体を無効にする。変更の無い追跡済みファイルの書き換えは status の行が増えるので捕まり、起動前から変更済み・未追跡のファイルの上書きはハッシュの違いで捕まる。HEAD・ブランチの比較はそのまま。起動前の「記録の場所の外がきれい」の前提はそのまま。
  - 案 B: 計画書と過去の記録のハッシュだけを比べる。対象を列挙する方式になり、ほかの記録の場所が漏れる。
  - 推奨 A': 「実験中は何も変わらない」を全体で、内容まで確かめる単純な規則（`feedback_local_guard_github_last_line` の単純な規則）。テスト A26 は、計画書が起動時に変更なしの場合と、起動時に既に変更済み（未コミット）の場合の両方を入れる。

## 診断レビュー 1 回目（`I197_fix_diagnosis_review_20261026_2212.md`）の Info への対応
- H1: `unread` にするのは、失敗した続きの直前の往復で実行した id だけ（往復ごとに `last_ids` を控える）
- M1: 空行の除去は、`buf` が空かどうかを見る前に行う（空行だけの実験案は取り出さない）
- M2: `-` で埋めた欄は、記録ではそのまま `-` と出す（`cut -f` 側も `-` を表示するだけで、判定には使わない）
