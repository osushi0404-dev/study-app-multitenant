# I599 fix-loop 診断メモ（2026-11-20 19:25・止める指摘 F11）

記録: `docs/reviews/I599_code_review_20261120_1910.md`

## 失敗分解
- 再現: `python3 .claude/hooks/unreviewed.py check -- 'bash scripts/claude/test-session.sh x $(true) --permission-mode bypassPermissions'`
- 期待: 承認（ask）
- 実際: 書き換えも承認も無い（終了コード 0）。`(`・`)` を命令の区切りにしているので、`$(true)` の後ろの `--permission-mode …` が別の区切りに移り、test-session の引数の確かめに渡らない。bash は `$(true)` を空に展開するので、子に `bypassPermissions` が届く。`<(…)` も同じ

## 根本原因
- F1・F7・F11 は同じ種類: 「シェルの構文（振り向け・置き換え・かっこ）を、自前の語の切り方で読み、その書き方を 1 つずつ足して塞ぐ」方式の限界。シェルの構文は多く、足すたびに別の書き方の取りこぼしや後退が出る（review-gate 3 周で 3 回目）
- セキュリティ: 守りの無い子・レビュー前の中身を外で動かせる（C8）

## 対応方針（全案＋推奨）
- 案 A（推奨・方式の見直し）: 単純な規則に切り替える。`bash scripts/claude/…` に当たるコマンドで、文字に `$`・バッククォート・`(`・`)`・`{`・`}` のどれかがあれば「読み切れない形」として、まとめて中で動かす。`test-session.sh` を含むなら承認にする（中では claude が動かないので）。置き換え・かっこの中身を読もうとしない
  - 影響: 普段の呼び出し（`bash scripts/claude/code-review.sh "I599"`・`--round-limit 3 "I599"`・`issue-source.sh body I599` など）はこれらの文字を含まないので変わらない。含む形（`"$VAR"` を渡すなど）は中で動く（広めに当たっても中で動くだけで害が無い）
- 案 B: `(`・`)` も振り向けと同じく区切らずに読む。`$(…)` の中に別の命令（`;`・`&&`）があると、その後ろの区切りでまた取りこぼす。列挙の続き
- 案 C: シェルの構文を正しく読むライブラリ（bashlex など）を入れる。依存が増え（`.claude/hooks/` は標準ライブラリだけの方針）、見張りの判定の網羅は I430 系で別に扱う範囲
- 新しい安全装置の対象: 手元の秘密とサンドボックスの外（GitHub からは戻せない）。fix-loop 手順 3 の「復旧できない対象にも、精密な判定より単純な規則」に沿う

## 影響調査
- `_segments` の区切りの扱い（`;&|()`・振り向け）は残すが、置き換え・かっこの文字があるコマンドは区切りを読む前に中で動かす（承認にする）ので、区切りの読み違いがあっても外には出ない
- 同型: 引数の取り出し（`EXEC_SUFFIXES`）・test-session の引数の確かめ・出発点の取り出しは、どれも `_segments` の後なので、まとめて守られる
- 既にある TC-07（`bash scripts/claude/$X`・バッククォート）は、この規則でも中で動く
- テスト: TC-26（`$(…)`・`<(…)`・`{ …; }`・`"$VAR"` の形で、test-session は承認・それ以外は中）と FG（規則を外すと不合格）
