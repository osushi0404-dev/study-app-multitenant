## 失敗分解
- F1
  - 再現手順: `psql -hlocalhost -U postgres <<EOF` に `DELETE FROM users;` を続ける。関数単位では `_opt_values(['-hlocalhost','-U','postgres'], ('-c','--command'))`

  - ログ: `pretooluse_guard.py:1874`（まとめ書きの中で、英字だけの並びの後の最初の該当の文字を探す）
- F3
  - 再現手順: `install -t/mnt/c/app/study-app-multitenant/.claude/worktrees/app-1/x /tmp/y`。関数単位では `_write_targets([...])`
  - 期待値: `['/mnt/c/.../app-1/x']`（別ワークツリーへの書き込みとして停止）。コンテナの `install -t/app/dir /tmp/a` は確認
  - 実際値: `[]`（exit 0）。`-t` の値のパスの `study` の d で `install -d` とみなされる
  - ログ: `pretooluse_guard.py:816`（`_has_short(args, "d", "--directory")` が値の付いた語も見る）

## 根本原因
- F1: implement で `_opt_values` を `-vt/x`（cp の付着形）に対応させるとき、「英字だけの並びの後の最初の該当の文字から後ろが値」と一般化した。getopt はどの文字が値を取るかを知っているが、見張りは知らない。そのため、値を取る別の文字（`-h`・`-U`・`-d`）の値が英字で始まると、その中の文字を探す文字と取り違える。変更前は「先頭の文字」か「英字だけの並びの最後の文字」の 2 形だけだったので起きなかった
- F3: `_has_short` は値の付いた語（`-t/…`）の中の文字も「オプションのまとめ書き」と見る。implement で `-t<パス>` を書き先として読めるようにしたので、その値の中の d が `install -d` の判定に当たるようになった
- セキュリティ観点: どちらも見張りの止める側の後退（F1 は破壊的 SQL の停止、F3 は別ワークツリーの停止〔解除不可〕とコンテナの確認）。守る対象: F1 は DB のデータ（手元の開発 DB。GitHub からは戻せないが、手元の開発用で、最後の守りは DB のバックアップと開発用データの作り直し）、F3 は別ワークツリーの未コミットの作業（GitHub から戻せない）。守るのは普通の書き方の事故（`-hlocalhost` も `install -t<パス>` も普通の書き方）

## 対応方針（全案＋推奨）
- **案 A（推奨）: 一般化の範囲を「値が英字以外で始まるとき」に絞る（F1）＋ `install -d` は英字だけの語の中で探す（F3）**
  - F1: `_opt_values` のまとめ書きを、(1) 先頭の文字（`-cX`。変更前と同じ）、(2) 英字だけの並びの最後の文字（`-tAc X`。変更前と同じ）、(3) 英字だけの並びの後の文字で、直後が英字以外（`-vt/x`・`-vt./x`。新しく読む形）の 3 形にする。`-hlocalhost`・`-Ucelery`・`-dfoo` は (3) に当たらない（c・f の直後が英字）
  - F3: `install -d` の判定を、`-` の後が英字だけの語（`-d`・`-vd`）と `--directory` だけで見る。`-t/…` のような値の付いた語は見ない
  - セキュリティ: 止める側に戻る（F1 は変更前と同じ判定に戻り、F3 は値の中の文字で書き先を消さない）。BP: 単純な規則（英字かどうか）だけで、シェルの動きを読む精密な判定は足さない。保守性: 変更は 2 か所の条件だけ。リスク: (3) は `-vtfoo`（値が英字で始まる相対のディレクトリ）を読まない。これは変更前も読んでいなかった形で後退ではなく、別ワークツリーの停止は絶対パス（`/` で始まる）だけが対象なので影響しない。`install -dm755 /x` は `-d` と見なくなるが、書き先は位置引数 2 つ以上のときだけなので `[]` のまま（多く止める側にしか動かない）
- 案 B: `_opt_values` を変更前に戻し、`-vt/x` は `_write_targets` の中だけで読む
  - F1 は確実に直るが、`-t` の付着形の読み方が 2 か所に分かれる（受け入れ条件 4「書き先の見分け方を 1 つに」とずれる）。採らない
- 案 C: コマンドごとに値を取る文字の一覧を持ち、getopt と同じに読む
  - 精密だが、一覧の保守が要り、粗い判定の方針（I179 retro P1・計画の Risk）に反する。採らない
