## false-green 評価
- 主要な修正（H1・H2・M2・M3）は、修正前の版で不合格になることを HEAD 版の取り出し実行で実測済みと記録されている（G14・G15・F11）。この実測により空振りでないと確認できる。
- H1: F11 は、同じ STAGE_DONE 構成で自律判断の記録に 1 行足した前後の STAGE_COUNT が同じことを断言する。`sed -n 3p` による行位置指定は出力順が変わると壊れるが、F2 の断言が順序も固定しており、壊れれば検出できる。S13 は SKILL.md の文言を `grep -qF` で見る。`rc` 経由の exit code 判定で、向きは合格=0 と一致している。
- H2: G14 は、取り込みのみ → 0 と、取り込み後にブランチコードを変更 → 1 の両方向を持つ。G 系の一時リポジトリを feature ブランチ化したことで、「ブランチ自身の変更」が常に空という自明な通過を避けている。既存の G1〜G13 は feature ブランチ化後も同じ期待値で通っている（pass=105 fail=0）。
