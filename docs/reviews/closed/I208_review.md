#### なぜを繰り返す原因分析（P1）
- 理想の状態: implement で、一時フォルダの片付けを含む切り分けのコマンドが承認なしで通る
- Why 1: `rm -rf` が見張りの DANGER_OK で止まった
- Why 2: 見張りは `rm -rf` の宛先が取り消せる場所かを区別しない
- Why 3: 見張りの判定が「操作の種類」で決まり、「消す先の重さ」で決めていない（I200 で絞る対象と同じ根本）
- 一般化: 他のイシューでも一時フォルダの片付けで同じく止まりうる → 予防処置（既存イシューに同梱）

#### 見送り（2.7 の 4 問）
- テストの補助関数で `printf` の `%s` に `\n` を渡した誤り（Q9）: その場のテストで捕まり手戻りなし → 手順を足さない
- 本体の行を引用する FG の置き換え前の文字列が、関数の引数の追加で古くなった: 既存の決定論チェック「FG の写しがすべて作れた」がその場で捕まえた → 手順を足さない
- 計画の `f2_same` の想定が P6 に合わなかった: implement のテストで捕まり、計画変更記録 2 で直した → 手順を足さない
- 記録へ 1 行足す `printf … >>` が、Claude Code のワークツリーの隔離（組み込みの機能）に拒否された: 公式の機能で、Edit で書けば済む → 見送り
- 指示ファイルメンテナンス（plan-reviewer・code-reviewer の観点）: 新しい問題パターンは無い → 見送り
