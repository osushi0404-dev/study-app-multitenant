1. **TC-01 の false-green**
   - 直す前の作りでは、キーに組織が入ります。
   - A で作ったキャッシュは、B での選択解除（B のキーだけ消す）で消えません。
   - A に戻すと「英語」が残り、`assert "英語" not in names` で落ちます。
   - 新しい作りでは、キーが 1 つなので解除でキャッシュが消えます。
   - この結果は、auto_test の「失敗の注入」に実測として記録されています。
   - 次の理由から、テスト自体は有効だと判断しました。
     - `locmem_caches` が `settings.CACHES` を差し替えます。差し替えると Django がキャッシュの設定を読み直します。
     - 全エイリアスが LocMem になるので、キャッシュは実際に通ります。
     - 解除の対象は DB から読み直した `UserSubjectAccess.user` です。その組織は B で、無効化は有効に働きます。
2. **TC-02 の tautology**
   - 直す前の作りでは、TC-02 は通ってしまう可能性があります。
   - 記録の注入は、中間案（キーから組織を外すだけ・絞った後の値を保存）で行われています。
   - 中間案では B で `[]` になり、落ちます。
   - 直す前の作りに対する検出は TC-01 が担っています。役割が分かれていて、問題ありません。
3. **TC-04 の穴**
   - 窓 5 日で (a)〜(f) を手で追いました。日数と本数は、表の期待値（1・2・2・3・2・2 本）と一致します。
     - (b) は窓ちょうどなので、前の窓（空）を読み、2 本で終わります。
     - (f) は窓の外の最初の日が空なので、途切れて 5 日で終わります。
     - (e) は昨日からの連続で、2 本です。
   - 読み足しを外すと、(b)〜(f) は本数の assert で落ちます。(c)・(d) は日数でも落ちます。
   - TC-05 の 365 日は読み足しを外しても通ります。ただし 366 日の行は落ちます。
