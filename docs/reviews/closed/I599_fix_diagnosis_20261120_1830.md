# I599 fix-loop 診断メモ（2026-11-20 18:30・止める指摘 F1・F2・F4）

記録: `docs/reviews/I599_code_review_20261120_1808.md`

## 失敗分解
- F1（High）: 再現 `bash scripts/claude/a.sh>/dev/null`（`a.sh` は新規）。期待: 中で動く。実際: `_segments` の区切りの記号に `<>` が無く、語が `scripts/claude/a.sh>/dev/null` になり、ファイルの一覧に当たらず書き換えない
- F2（High）: 再現 `scripts/claude/evil.tmp`（`.gitignore` が無視する名前）を書き `bash scripts/claude/evil.tmp`。期待: 中で動く。実際: git が無視するファイルは `ls-files` にも `diff` にも出ず、`_reach` で「一覧に無い」として読み飛ばし、書き換えない
- F4（Medium）: 再現 `bash scripts/claude/test-session.sh 'x' --permission-mode bypassPermissions`。期待: 承認を求める。実際: `--permission-mode`・`--setting-sources` の値を見ずに通す

## 根本原因
- F1・F2 は同じ根: 「出発点のパスが git の一覧に無い」ときに、それを「レビュー済み」と同じ扱い（読み飛ばし）にしていた。一覧に無いのに実在するファイルは、レビューを通っていない（追跡もされていない）ものなので、安全側（中で動かす）に倒すべきだった。F1 は語の切り方の誤りで、その状態に入る入口の 1 つ
  - なお F1 の形（振り向けつき）は、手順書（danger-ops.md「外に出すコマンドの書き方」）では外に出す一覧に当たらず中で動く形。ただし公式の一致のしかたに頼らず、判定の側で安全側に倒す
- F4: test-session の許可の表を「引数の名前」だけで作り、値が子のセッションの守り（許可のモード・読む設定の出どころ）を外せることを見ていなかった。`--setting-sources user` は、プロジェクトの設定（見張り・サンドボックス）を読まない子を作れる
- セキュリティ: 3 つとも「レビュー前の中身・守りの無い子をサンドボックスの外で動かせる」穴（C8）

## 対応方針（全案＋推奨）
- F1・F2:
  - 案 A（推奨）: ① `_segments` の区切りに `<>` を足す ② 出発点・たどった先のパスが実在するのに git の一覧（追跡＋追跡していない新規）に無いとき（無視されるファイル・一覧の外）は、変更（レビュー前）として当たりにする。単純な規則で両方を塞ぐ
  - 案 B: `git ls-files --ignored` も読む。無視されるファイルが多い（`.venv` など）と遅く、上限に当たる
  - 案 C: 無視されるファイルを止める（block）。中で動かせば十分で、止めると正当な作業も止まる
- F4:
  - 案 A（推奨）: `--permission-mode` の値は `default`・`manual`・`plan`・`acceptEdits`・`auto` だけ（`bypassPermissions`・`dontAsk` などは承認）。`--setting-sources` は値に `project` を含むか、レビュー済みの `--settings` を一緒に渡すときだけ通す（`.claude/agents/adversarial-reviewer.md:69` の `--setting-sources user --settings .claude/settings.json` の形は通る）
  - 案 B: `--permission-mode`・`--setting-sources` を表から外し、常に承認。敵対的レビューの実験の起こし方（承認なしで動く前提）が止まる
- 新しい安全装置の対象（`danger-ops.md`「GitHub から復旧できる範囲」）: 守る対象は手元の秘密（`.env`・鍵の控え）とサンドボックスの外の書き込みで、GitHub からは戻せないものも含む。最後の守りは auto モードの判定役・許可の設定。判定はパスと値の照合だけ（シェルの動きを読む精密な判定は足さない）

## 影響調査
