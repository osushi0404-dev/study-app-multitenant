# I512 修正の診断（2026-11-14 01:52）

## 失敗分解
- 再現手順: CI の Harness Tests（`bash scripts/claude/tests/run-all.sh`）。単体では `bash scripts/claude/tests/test_pipefail_negated_grep.sh`
- 期待値: `test_pipefail_negated_grep.sh` が exit 0（pipefail のスクリプトに「`!` ＋パイプ＋`grep -q`」の形が無い）
- 実際値: `FAIL G1 scripts/claude の pipefail のスクリプトに、否定とパイプの grep -q の形が無い expected=0 got=1`（pass=9 fail=1）
- ログ: `scripts/claude/tests/test_i512_accepted_risk.sh:171:  && ! grep -E '^- F' "$1" | grep -qvE "$BL_FORM"; }`（CI run 43464302326）

## 根本原因
- implement の commit 時に shellcheck の SC2143（`[ -z "$(grep …)" ]` を `! grep -q` にせよ）に従って、`[ -z "$(grep -E '^- F' "$1" | grep -vE "$BL_FORM")" ]` を `! grep -E … | grep -qvE …` に書き換えた
- `test_i512_accepted_risk.sh` は `set -uo pipefail`。pipefail の下では `grep -q` が先に終わると前の `grep` が SIGPIPE で終わってパイプ全体が 0 以外になり、`!` が反転して「形の崩れた行がある」のに合格しうる（I210 で決めた決まり）。リポジトリの決定論テスト（`test_pipefail_negated_grep.sh`）がこれを正しく捕まえた
- 手元では、変えた文書を読む関係のテストだけを選んで流し、この決まりのテストは「変えたファイルを読むテスト」の選び方（`grep -l code-reviewer.md|retro|…`）に当たらなかった
- セキュリティ: 影響なし（テストの書き方の問題。本体の判定は変わらない）

## 対応方針（全案＋推奨）
- 案 A（推奨）: 件数で判定する。`&& [ "$(grep -E '^- F' "$1" | grep -cvE "$BL_FORM")" -eq 0 ]; }`。パイプの後ろの `grep -c` は入力を最後まで読むので SIGPIPE が起きず、`!` も使わない。SC2143（`-z` と grep の出力の比較）にも当たらない。`test_i202_ledger_cleanup.sh` の `d3_bl` と同じ意味（形の崩れた行が 0 件）
  - メリット: 1 行の書き換え・意味は変わらない・両方の決まり（shellcheck・I210）を満たす
  - デメリット: 無い（`grep -c` は 0 件で exit 1 だが、`$(...)` の中なので判定に影響しない）
- 案 B: 元の `[ -z "$(…)" ]` に戻し、`# shellcheck disable=SC2143` を付ける
  - デメリット: 抑止の印が増える
- 案 C: 形の照合を Python で書く
  - デメリット: 書き換えが大きい

## 影響調査
- 同型: `git grep -n '! grep' -- scripts/claude/tests/test_i512_accepted_risk.sh` で、この 1 か所だけ。ほかの `!` は `yn` などの関数の中で、パイプの後ろに `grep -q` が無い
- この修正のついでに、FG を 1 つ足す: 一時の写しに形の崩れた行（`- F9 SEV=Low FILE=x`）を足すと TC-07 が不合格になること（形の照合が本当に効いていることを確かめる。SIGPIPE で反転すると合格してしまう向きの穴を塞ぐ）
- 関連機能への波及: 無い（テストのファイルだけ）
