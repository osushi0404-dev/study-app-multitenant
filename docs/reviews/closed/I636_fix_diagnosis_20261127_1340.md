# I636 fix-loop 診断メモ（2026-11-27 13:40）

起点: close の後のユーザーの確認の依頼で見直して見つかった、手動テスト No.7 の NG。

## 失敗分解
- 再現手順: 幅 360px でログインする（`e2e_user_a`）。ログイン直後の通知「ログインしました」が出ている間に、上のバーの右側のボタンを見る
- 期待値: 通知が上のバーのどのボタン（左のメニュー・アクセシビリティ設定・テーマの切り替え・ユーザーメニュー）にも重ならない
- 実際値: 通知（x=96〜264・y=16〜61）が「アクセシビリティ設定」のボタン（x≈224〜248）に重なる。通知の上にマウスがあると通知は消えないので、そのボタンを最大 4 秒以上押せない（I636 が直した「ユーザーメニューを押せない」と同じ種類の問題が、別のボタンで残っている）
- ログ: 画面確認の画像 `.evidence/I636/01_login_toast_360.png`・`02_members_360_region_focus.png`（上のバーの並び）。E2E の TC-30 は、通知の枠とユーザーメニューのボタンの枠の重なりだけを確かめていた

## 根本原因
- 通知の置き場所（`frontend/src/App.tsx` の `Toaster`）を「上の中央・左右 64px を空ける」にしたとき、上のバーの右側のボタンを 1 つ（ユーザーメニュー）と数えた。実際は 3 つ（`frontend/src/components/Layout.tsx` の `Toolbar` の `AccessibilityToggleButton`・テーマの切り替え・ユーザーメニュー）あり、幅 360px では通知の幅の中に入る
- 通知は上のバー（`AppBar`・`position="fixed"`）と同じ高さに出るので、横の幅をどう抑えても、ボタンの数と幅の組み合わせしだいで重なりうる（作りとして壊れやすい）
- 確かめ（E2E の TC-30・手動テスト No.3）の相手がユーザーメニューのボタンだけで、上のバーの全体を見ていなかった
- セキュリティの観点: 該当なし（表示の重なり）

## 対応方針（全案＋推奨）
### 案 A（推奨）: 通知を上のバーのすぐ下に出す
- `Toaster` の `containerStyle={{ top: 72 }}`（上のバーの高さ 56px〔幅 600px 未満〕・64px〔それ以上〕より下・8px の余白）。位置は上の中央のまま（ユーザーが選んだ「上の中央」を保つ）
- 最大幅の指定（`min(350px, calc(100vw - 128px))`）は、上のバーと重ならなくなるので外す（react-hot-toast の既定の 350px に戻す）
- セキュリティ影響: なし
- BP 適合: 固定の上のバーの操作を、一時的な表示で塞がない（WCAG 2.2 の 2.4.11 フォーカスが隠れない の考え方にも沿う）
- 保守性: 上のバーにボタンが増えても重ならない（幅の計算に頼らない）
- リスク・副作用: 通知が各画面の一番上の中身（見出しなど）に 4 秒ほど重なる。各画面の一番上の操作（例: メンバー管理の［メンバーを追加］は幅 360px で y≈146〜190）には届かない高さ（72〜117px）。ログインの画面（上のバーが無い）でも、上から 72px に出る
- 確かめ方: E2E（TC-30）で、通知の枠の上端が上のバー（`getByRole('banner')`）の下端より下にあることを確かめる（個々のボタンでなく上のバー全体）。直す前（今の位置）で落ちることを確かめる。手動テスト No.7 を 360px と 1280px で行う

### 案 B: 最大幅を右側の 3 つのボタンを避ける幅にする
- 幅 360px では通知の幅が 60px 程度になり読めない。ボタンが増えるたびに計算し直しになる。採らない

### 案 C: 通知を下の中央に出す
- クイズ管理の［＋］ボタン（右下の固定）と、幅 360px で重なりうる。ユーザーが grill-me で「上の中央」を選んだ判断（右下は［＋］と重なるので選ばない）とも合わない。採らない

### 推奨
案 A。上のバーと縦に分けるので、幅やボタンの数に左右されない。「上の中央」というユーザーの決定も保つ。

## 影響調査（同型バグ・他の呼び出し箇所・関連機能への波及）
1. 同型: 画面の固定の要素（上のバー・クイズ管理の右下の［＋］）と重なりうる一時的な表示は、`Toaster` の 1 か所だけ（MUI の `Snackbar` は使っていない・`grep` で確認）
2. 関連機能: すべての画面の通知の位置が 16px → 72px 下がる。ログインの画面・登録用リンクの画面（上のバーが無い）も同じ位置に出る
3. 計画との関係: `frontend/src/App.tsx` と `e2e/tests/registration-link.spec.ts` は計画の実装対象の中。受け入れ条件 AC12（「通知が上の中央に出て、幅 1280px と 360px のどちらでもユーザーメニューのボタンに重ならず…」）は、ユーザーメニューだけでなく上のバーのどのボタンにも重ならない形に強める（計画変更記録に書く）
4. 敵対的レビュー: 通算 2 周を使い切っている。ユーザーの判断（「マージの前にこの PR で直す」・1 周の延長を含む）で、直した後に `--round-limit 3` で 1 周だけ流す
