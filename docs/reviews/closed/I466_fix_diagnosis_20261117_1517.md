# I466 fix-loop 診断メモ（2026-11-17 15:17）

対象: review-gate の CI 待ちで `CI_WAIT: FAIL`（PR #564・run 44029395707・job 133857388003「E2E Tests (Playwright)」）。コードレビューの止める指摘は無い（CI の失敗で手前で止まった）。

## 失敗分解
- 再現手順: CI の E2E（`npm test`＝`playwright test`）で `e2e/tests/dashboard-layout.spec.ts` を流す
- 期待値: TC-21・TC-23 は `stat-answered-count` が `123456`、TC-22 は `main canvas` が 2 つ、TC-26 は「今日の学習時間」が出た後にアクセシビリティ設定のボタンが上のバーの中にある
- 実際値: 4 件とも、数字のカード・グラフが見つからない（`element(s) not found`・`Received: 0`）。再試行 2 回でも同じ
- ログ: `toHaveText('123456')` … `Error: element(s) not found`（52・75 行）、`toHaveCount(2)` … `Received: 0`（63 行）、TC-26 は 90 行の `waitForNumbers` で「今日の学習時間」が見えない。ほかの 15 件（今回足した「ダッシュボードから苦手を優先のクイズを始められる」を含む）は pass

## 根本原因
- この 4 件は `fixOverview` で `/api/dashboard/overview/` の応答を固定している（14〜29 行の `OVERVIEW_WITH_DATA`）。固定の応答は I473 の契約の 7 つのキーだけで、I466 で足した `weak_difficulties`・`rushed_mistakes` が無い
- 画面は応答の形を `frontend/src/services/dashboard.service.ts` の `isDashboardOverview` で確かめ、欠けたキーを 0 や空で埋めずにエラー（「ダッシュボードの数字を読み込めませんでした」）にする（I473 の決まり）。そのため数字のカード・グラフが出ず、4 件が落ちた
- 本物の API を使う TC-24・TC-25・TC-27 と、今回の苦手を優先の E2E は pass（本物の応答には 2 つのキーがある）。製品の不具合ではなく、E2E の固定の応答が契約の変更に追いついていないこと
- implement で、契約の型を使う単体テストの準備（`Dashboard.test.tsx`・`dashboardAchievements.test.ts`）は直したが、E2E の固定の応答は TypeScript の型（`DashboardOverview`）を使っておらず型の検査で見つからなかった。`grep "recommendations:"` を frontend だけで行い、`e2e/` を探していなかった
- セキュリティ観点: 該当なし（テストの固定データだけ。認証・認可・入力の扱いは変わらない）

## 対応方針（全案＋推奨）
- 案 A（推奨）: `OVERVIEW_WITH_DATA` に `weak_difficulties`・`rushed_mistakes` を足す。値は幅の確かめに意味のあるもの（`weak_difficulties` に 1 件、`rushed_mistakes` に数の入った 1 件）にし、390px で新しい表示（難易度別・急いだ間違いの 1 行）も横にはみ出さないことを同じ TC で確かめる
  - セキュリティ影響: なし／BP: 固定の応答を契約どおりにする（I473 の「形が違えばエラー」の決まりを保つ）／保守性: 変更は 1 か所・数行／副作用: 無し
- 案 B: 画面の形の確かめを緩め、2 つのキーが無ければ空・null とみなす
  - セキュリティ影響: なし／BP: I473 で決めた「欠けたキーを 0 で埋めない」に反する／保守性: 契約のずれを隠す／副作用: 裏側の不具合で欠けたときに気づけない → 採らない
- 案 C: 固定の応答の形を TypeScript の型（`DashboardOverview`）で縛り、次の契約の変更で型の検査が止めるようにする（e2e の tsconfig から `frontend/src/types/api` を読む）
  - BP: 再発防止としては強いが、e2e のパッケージから frontend のソースを読む設定が要り、別の仕組みの変更になる。今回の範囲を超えるので retro で扱う
- 推奨: 案 A。再発防止は「契約のキーを足すときは `e2e/` も含めて固定の応答を grep する」を再発防止記録に書き、型で縛る案 C は retro の判断に回す
