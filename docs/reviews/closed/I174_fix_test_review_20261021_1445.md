## false-green 評価

**否定・異常系テスト（G81〜G87）が実際に NG になる構造かどうか**

- `pw()` ラッパーが PWNED ファイルを削除してから実行し、直後に存在確認する構造になっている。PWNED が生成されると出力に `PWNED:<exit>` が含まれ、期待値（`ASK pwned=no`）とのマッチが外れるため必ず FAIL になる。
- 「修正前の HEAD で同じテストを走らせた場合」の実測値として G81〜G86 が `PWNED:2`（6 件 FAIL）と記録されており、テストが実際に壊れた状態を捕捉できることを実証済み。

**FG-TRUST（false-green 防止・checkout 側）**

- `_git_resolve` を「常に trusted を返す」に sed 置換した破壊版を使い、evil リポジトリの checkout を実行 → PWNED 作成を確認。
- fsmonitor を `-c core.fsmonitor=false` だけで防ごうとしても clean フィルタ攻撃（`filter.pw.clean`）は通過することを実測で実証。場所制限（`_git_loc_trusted`）が唯一の防御であることを確認済みで、保護が load-bearing であることに疑いなし。

**FG-M（false-green 防止・push 側）**

- `_git_loc_dynamic` と `_git_loc_trusted` の両方を無効化した破壊版で `GIT_DIR=$X git push origin` が exit 0 素通しになることを実測。2 条件の両立が回帰防止に必要であることを確認済み。

**空振り懸念なし**：否定系・異常系テストはいずれも「ガードが作動しないと PWNED が生成される → テスト FAIL」という決定論的な構造を持ち、アサーション不足・条件緩めの疑いなし。exit code の向きも `ASK=出力文字列マッチ`・`BLOCK=exit 2` と明確に分離されている。
