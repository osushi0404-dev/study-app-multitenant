# I432 診断メモ（fix-loop）: 最後の確認で Harness Tests が失敗

## 失敗分解
- 再現手順: close のコミット（2f8610ad）を送った後の CI（run 44240970645）の Harness Tests。手元では `bash scripts/claude/tests/test_i202_ledger_cleanup.sh`
- 期待値: `D3 実物の一覧のどの行も決まった形` が yes（`docs/reviews/backlog/*.md` の `- F` で始まる行がすべて決まった形 `- <番号> SEV=… REPRO=… KIND=… SECURITY=… FILE=… | … | 一覧に回した理由: …`）
- 実際値: no（`pass=162 fail=1`）。run-all は `pass=61 fail=1`
- ログ: 失敗したのは `test_i202_ledger_cleanup.sh` の D3 だけ。ほかの CI のジョブ（E2E を含む 7 つ）は合格

## 根本原因
- retro で書いた `docs/reviews/backlog/I432.md` の見出しの部分に、説明の行 `- F4（記録の 2 行のつながり）は review-gate で直したので載せない。…` を足した。この行が `- F` で始まるので、一覧の行として形を確かめられ、決まった形でないため不合格になった
- retro の手順（4-0）は「出力の行をそのまま貼る」で、見出しは `docs/reviews/backlog/I206.md` と同じ形にすることになっている。私が見出しに独自の説明の行を足したことが原因で、手順・テストの不備ではない（テストは正しく止めた）
- review-gate の時点では一覧のファイルはまだ無く（retro で作った）、retro・close は記録の場所だけを書くので手元でハーネスのテストを流さず、close の後の CI で初めて捕まった
- セキュリティ: 該当なし（記録のファイルの形だけ）

## 対応方針（全案＋推奨）
- 案 A（推奨）: 説明の行を `- F` で始まらない形に書き換える（例: `- 載せないもの: F4（…）`）。メリット: 記録の場所の 1 行だけ・見出しの形（I206 と同じ「- 」で始まる説明の行）に合う・F4 を載せない理由は残る。デメリット: なし
- 案 B: 説明の行を消す。メリット: 最小。デメリット: F4 を載せなかった理由が一覧から消える（review の記録には残る）
- 案 C: テスト（D3）を見出しの説明の行を除くように直す。デメリット: 正しく止めたテストを緩めることになり、ハーネスの変更でレビューの範囲も広がる。採らない
- 推奨: 案 A

## 影響調査
- 同型: `grep -n '^- F' docs/reviews/backlog/*.md` で、形の崩れた行がほかに無いかを、直した後の D3（全ファイルを見る）で確かめる
- 他の呼び出し箇所: 一覧を読むのは plan-issue の `grep -rnF -e "FILE=… |"`（`FILE=` で拾う）。説明の行は `FILE=` を持たないので拾われない
- 関連機能への波及: なし（記録のファイルだけ）
