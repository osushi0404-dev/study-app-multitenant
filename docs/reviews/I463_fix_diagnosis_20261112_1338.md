# I463 診断メモ（fix-loop・2026-11-12 13:38）

## 失敗分解
- 再現手順: PR #465 の HEAD 1c862cd7 で CI の Harness Tests（`bash scripts/claude/tests/run-all.sh`）。手元では `bash scripts/claude/tests/run-all.sh scripts/claude/tests/test_i204_tool_sync.sh`
- 期待値: run-all がすべて合格
- 実際値: `test_i204_tool_sync.sh` の S1 が FAIL（`run-all: pass=57 fail=1`）
- ログ（CI run 43154825134 / job 130972199551）:
  ```
  FAIL S1 実物に「道具が無ければ SKIP」の分岐が無い expected=[0] got=[1]
  scripts/claude/tests/test_i463_optspec_help.sh:44: if not shutil.which(cmd):
  ```

## 根本原因
- review-gate で足した `test_i463_optspec_help.sh`（TC-13・表と `--help` の突き合わせ）に、コマンドが無いときに `SKIP` して先へ進む分岐（`if not shutil.which(cmd): print("SKIP …"); continue`）を書いた
- I204 の決まり（`test_i204_tool_sync.sh` の S1）は「テストは道具が無いときに黙って飛ばさない。頼る道具は required-tools.txt で確かめる」。道具が無い環境で合格に見える偽合格を防ぐため。新しいテストを書くときに、この決まりを確かめなかった
- セキュリティ観点: 該当なし（テストの書き方の決まりの違反。見張りの判定には影響しない）。ただし SKIP のまま残すと、道具の無い環境で V1（表の文字の正しさ）の確かめが黙って抜ける偽合格になる

## 対応方針（全案＋推奨）
| 案 | 内容 | セキュリティ | BP | 保守 | リスク・副作用 |
|---|---|---|---|---|---|
| A（推奨） | SKIP の分岐を消す。コマンドが無ければ `subprocess.run` の例外で不合格（飛ばさない）。あわせて、`--help` から値を取る文字を 1 つも読めないとき（`--help` の形が変わった）も不合格にする | 偽合格が無くなる | I204 の決まりどおり | 小さい（数行を消す・足す） | 対象は sed・grep・cp・mv・ln・install（coreutils・grep・sed）と su・flock・script（util-linux）で、どれも OS の基本の道具。CI の ubuntu runner に最初からある（今回の CI でも S1 以外は動いた〔13a の前に S1 で止まっただけ〕） |
| B | A に加えて required-tools.txt に util-linux の行を足す | A と同じ | 一覧で道具を宣言できる | `test_i204_tool_sync.sh` の L1（道具は 7 つ）も直す必要があり、一覧の写しのテストを直す手間が増える | 手元で試したところ L1 が落ちた。基本の道具のために一覧とその写しを 2 か所直すのは、決定論テストの選び方（写しのテストを増やさない）に反する |
| C | テストを run-all から外し、手で流す | V1 の確かめが CI で抜ける | — | — | 敵対的レビューの V1 を決定論で覆う目的に合わない |

推奨: A。粗く確実で、足すものが無い。
