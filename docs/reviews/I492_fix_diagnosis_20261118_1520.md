# I492 診断メモ（fix-loop）: CI の E2E が Playwright を入れる段で失敗

## 失敗分解
- 再現手順: PR #571 の CI（run 44207144182・2026-11-18）の「E2E Tests (Playwright)」
- 期待値: E2E のジョブが Playwright を入れてテストを流し、合格する
- 実際値: 「Install Playwright dependencies」（`npm ci && npx playwright install --with-deps chromium`）で失敗し、テストに入らない。E2E 以外のジョブは合格
- ログの要約: 2026-11-17 午後から `ubuntu-latest` が Ubuntu 26.04 になり、`@playwright/test` 1.59.1 は 26.04 に非対応で、ブラウザの OS の部品を入れられない（I492 の記録 `docs/reviews/open/I492_review.md` の [fix-loop] の行・#432 のコメント 2026-11-18）

## 根本原因
- I492 の変更（古い学習記録の表とコードの削除）ではない。develop の E2E の環境（Playwright 1.59.1・CI の Node.js 18）が、GitHub の実行環境の切り替え（Ubuntu 26.04）に追いついていなかった
- これは I432（#432・PR #575・2026-11-18 マージ・develop b8265798）で直した: E2E の CI の Node.js を 26 に・`@playwright/test` 1.65.1（26.04 に対応）・手元の E2E のイメージ v1.65.1-jammy。PR #575 の CI では Ubuntu 26.04 で E2E 19 件すべて合格
- I492 のブランチは develop の 4c129c3b から分かれていて、I432 の直しを含まない
- セキュリティ: 該当なし（CI の環境の問題。I492 の変更の中身は変えない）

## 対応方針（全案＋推奨）
- 案 A（推奨）: `origin/develop`（b8265798）を I492 のブランチにマージで取り込む。メリット: I432 で直してレビュー・CI を通った変更をそのまま使える・I492 の差分は変えない・食い違いなし（`git merge-tree` で確認）。デメリット: 取り込んだ変更（e2e.yml・e2e の依存・docker-compose.yml のイメージ・手順書・規約の 1 行）がブランチの差分には出ないが、develop 側でレビュー済み
- 案 B: rebase で develop の上に載せ直す。デメリット: 送り済みのコミット（PR #571）の履歴を書き換え、強制の push が要る（危険操作）。採らない
- 案 C: I492 のブランチで同じ直しを別に行う。デメリット: I432 と重複し、develop と食い違う。採らない
- 推奨: 案 A

## 影響調査
- 同型: 同じ時期に develop から分かれて E2E が落ちている他の PR も、develop の取り込みで直る（I492 の範囲外）
- 他の呼び出し箇所: I492 の変更ファイル（backend の学習記録まわり・マイグレーション）と、取り込む変更のファイル（`.github/workflows/e2e.yml`・`e2e/`・`docker-compose.yml` の e2e のイメージ・`docs/runbooks/frontend-verify.md`・`rules/react-coding-standards-integrated.md`）は重ならない
- 関連機能への波及: 取り込みの後、CI の E2E が I492 の変更込みで初めて流れる。I492 の変更で E2E が落ちたら、それは I492 の不具合として次の fix-loop で扱う
