## Blocker 解消に向けた確認事項

**`disable-model-invocation: true` についての補足視点**（実装者向け）:

確認すべき仮説は 2 つ:

**仮説 A**: `disable-model-invocation: true` は「スキル呼び出し時に LLM でユーザーの意図を解釈するステップをスキップし、スキルの指示を直接処理する」という意味。この場合、sections 2/3 の指示も Claude が読んで実行できる（計画の前提が成立）。

**仮説 B**: `disable-model-invocation: true` は「bash block のみ実行し、その後 LLM 処理は一切しない」という意味。この場合、sections 2/3 は無視され、敵対ステージは永遠に自動起動しない（設計全体が機能しない）。

現行 SKILL.md が `disable-model-invocation: true` + `allowed-tools: Bash` のみであることから、現在は「bash 1 コマンド実行して終了」という仮説 B 的な使われ方をしていると見受けられる。新設計で `allowed-tools: Bash, Read, Grep, Glob, Edit, Write, Agent` に拡張するなら、LLM が sections 2/3 を処理して Agent ツールを呼べなければ Read/Edit/Agent を listed に加えても実行されない矛盾が生じる。

計画書を再提出する際は、実機テスト（現セッションで簡易な多ステップ SKILL.md を作り `disable-model-invocation: true` のまま Agent 起動が走るか確認）か、プロジェクト内の知見（他の multi-step スキルがある場合の実績）をエビデンスとして添付することを強く推奨します。
