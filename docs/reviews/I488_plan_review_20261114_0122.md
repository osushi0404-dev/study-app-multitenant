## 観点別の所見
- P1 要件適合性: 問題なし。イシューの設計確認メモとの食い違いはない。`subject_breakdown` を全科目にする点は、計画 9 章で自律判断として記録済み。TC-02・03・04 の日付と数値を自分で検算し、すべて一致した。
  - 90 日の期間は 08-17（月）〜11-14 で、区切りは 13 件。
  - 365 日の期間は 2025-11-15〜2026-11-14 で、区切りは 13 件。
- セキュリティ: 問題なし。
  - 認証は `IsAuthenticated` を明示している。
  - `subject_id` は `OrgSubjectField` で検証する。
  - 4 種類の不正入力が同じ 400 の body になり、TC-07 で固定されている。
  - 読み出しの土台は `_answers(user)` だけで、TC-08・13 が他組織・他人の混入を見ている。
  - 依存の追加はない。
- P4 テスト妥当性: 問題なし。
  - 再発防止として TC-01・02・22 がある。
  - false-green の確かめ手順が 4 件ある。
  - 合否は pytest・Jest の exit code で判定する。
  - 「必ず確かめる項目」は `##` の節で、観点 1〜3・確かめ方「読んで可」のみ。`実験必須` の行はない。
  - 手動テストの Human 行はなく、すべて Claude が実施する。
- P3 データ整合性: 対象外。DB・マイグレーションの変更がない。
- P5 運用性・P8 コスト: 問題なし。ロールバックは revert のみ。`recharts` は残す方針で、依存の変更もない。
- P9 プライバシー: 問題なし。本人の学習データを本人にだけ返し、テナント越境は土台で禁止している。
- Claude Code 指示ファイル: 対象外。
- コマンド衛生・破壊的取り消し: 問題なし。
