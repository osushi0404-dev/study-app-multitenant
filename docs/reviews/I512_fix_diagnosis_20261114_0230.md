# I512 修正の診断（2026-11-14 02:30・retro から）

## 失敗分解
- 起点: コードレビューの台帳 F1（`docs/reviews/I512_code_review_20261114_0153.md`・Medium・REPRO=yes・SECURITY=yes・止めない指摘）。retro で、このイシューの目的（照合は合わなければ今までどおり＝fail-closed・AC5）の穴なので、この PR で直すと決めた（`docs/reviews/open/I512_review.md` 自律判断の記録）
- 再現手順: 計画書の「## 8. Risk & 回避策」に `| R2: a | b | 回避 |` と `| R2: c | d | 受け入れ |` の 2 行を置き、`ACCEPTED=R2` の Medium・再現なし・guard・SECURITY=yes の台帳の行を `ledger_route issue <台帳> <計画書>` で振り分ける
- 期待値: 処遇が食い違う R 番号は受け入れと確かめられないので、今までどおり後続イシュー（理由 `SECURITY=yes・guard の Medium 以上`）
- 実際値: `accepted_risks()` が受け入れの行だけを集めるので R2 が効き、一覧に回る
- もう 1 つ: 8 の節の中の HTML コメント（`<!-- … -->`）の中に `| R1: … | … | 受け入れ |` のような例の行があると、それも受け入れとして読む（雛形の注記に例の行を書いた計画書で起きうる）

## 根本原因
- `accepted_risks()`（`scripts/claude/code-review.sh` の `_LEDGER_PY`）は「最後のセルが受け入れの行」の R 番号を足すだけで、同じ R 番号のほかの行（受け入れでない行）を見ていない。HTML コメントの中かも見ていない
- 計画の TC-05 の照合の失敗の列挙（計画書なし・節なし・行なし・処遇違い・節の外・回避・受け入れない）に「同じ番号の食い違い」と「コメントの中」が無かった
- セキュリティ: 受け入れていない残余リスク（回避と書いた行）が、後続イシュー・最優先から外れて一覧に落ちうる（止める判定は変わらない）

## 対応方針（全案＋推奨）
- 案 A（推奨）: `accepted_risks()` で、受け入れの行の R 番号の集合から、受け入れでない行（処遇の列が受け入れ以外・セルの形が崩れた行を含む）の R 番号の集合を引く。HTML コメントの中の行（`<!--` の行から `-->` の行まで）は読まない。どちらも安全側（効かない向き）にしか倒れない
  - メリット: 数行の変更・既存の振る舞い（重複の無い計画書）は変わらない・単純な規則
  - デメリット: 1 行の中でコメントが開いて閉じる形（`<!-- x --> | R1: …`）は扱わない（普通の書き方では起きない）
- 案 B: 同じ R 番号が 2 行以上あれば、処遇に関係なくその番号を効かせない
  - デメリット: 受け入れの行を 2 つに分けて書いた計画書も効かなくなる（安全側だが過剰）
- 案 C: 重複を見つけたら `--route` を exit 2 で止める
  - デメリット: retro の流れが止まる。照合の失敗は「今までどおり振り分ける」のが決まり（fail-closed は止めることではない）

## 影響調査
- 同型: 計画書の表を読む関数はほかに無い（`grep -n "def accepted_risks\|PLAN_RISK" scripts/claude/code-review.sh` で 1 か所）
- 呼び出し: `route` モードだけ（`accepted_risks(sys.argv[4] …)`）。止める判定・台帳の書き直しは呼ばない
- テスト: `test_i512_accepted_risk.sh` の TC-05 に (9) 同じ R 番号の回避と受け入れ (10) コメントの中の受け入れの行 を足し、引き算・コメントの扱いをそれぞれ外した写しで不合格になる FG を足す。既存の TC-01（R2・R4 が効く）は計画書に重複が無いので変わらない
- 計画: 受け入れ条件 AC5（処遇が受け入れでないときは今までどおり）の範囲の中の直し。方式・範囲・受け入れ条件は変えないので計画レビューはやり直さない（計画変更記録に 1 行）
