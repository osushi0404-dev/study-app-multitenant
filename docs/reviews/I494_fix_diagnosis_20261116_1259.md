# I494 診断メモ（fix-loop 3 回目・マージ依頼の前の BP・UI/UX の見直し）

対象: ユーザーの「BP の観点（UI/UX も）で評価して問題ないか」への見直しで見つけた 2 件（G1・G2）。どちらも動きは変えない。前の組織の割り当て（F2）と、選んだ科目の一覧の読み込みの書き方の不ぞろいは #532 のまま。

## 失敗分解
### G1（チェックボックスのまとまりに名前が無い）
- 再現手順: `/settings` の「学ぶ科目」のカードを画面読み上げ（またはアクセシビリティの木）で見る。`frontend/src/components/settings/LearningSubjectsCard.tsx` の `FormGroup` は名前の無い `div`
- 期待値: チェックボックスのまとまりが「学ぶ科目」という名前のグループとして読まれ、説明文（「ダッシュボード・クイズ・学習統計に出す科目です。最低1つ選んでください」）と、0 件のときの注意（「科目を最低1つ選択してください」）がそのグループに結び付く
- 実際値: 各チェックボックスは科目名だけで読まれ、何の選択か・最低 1 つの決まり・注意が、まとまりと結び付かない
### G2（画面どうしの直接のつながり）
- 再現手順: `frontend/src/components/dashboard/StartQuizCard.tsx:26` が `import { LEARNING_SUBJECTS_ANCHOR } from '../settings/LearningSubjectsCard'` で、送り先 `/settings#...` を自分で組む
- 期待値: 送り先の道筋は 1 か所の定数（規約の `constants/`・`rules/react-coding-standards-integrated.md:97`）にあり、ダッシュボードと設定画面の部品が同じ定数を読む
- 実際値: ダッシュボードの部品が設定画面の表示の部品のモジュールを読み込む（機能どうしの依存）。道筋の文字 `/settings` が別の場所に書かれる

## 根本原因
- G1: 見出し（`Typography`）とチェックボックスのまとまり（`FormGroup`）を見た目でだけ並べ、アクセシビリティの関係（グループの名前・説明）を付けていなかった。I494 の計画の 13 章（アクセシビリティ）が、個々のチェックボックスのラベルと注意の出し方までしか書いていなかった
- G2: カードまで送る目印を、送り先の部品の中に定義した（定数の置き場が無かった）
- セキュリティ: どちらも該当なし（表示とモジュールの置き場だけ）

## 対応方針（全案＋推奨）
### G1
- 案 A（推奨）: 見出しに `id="learning-subjects-heading"`、説明文に `id="learning-subjects-description"`、注意に `id="learning-subjects-error"` を付け、`FormGroup` に `role="group"`・`aria-labelledby` = 見出し・`aria-describedby` = 説明文（注意が出ているときは注意も）を付ける。見た目は変わらない
  - BP: WAI-ARIA のグループの書き方（見える見出しをそのまま名前に使う）。見出しを 2 つ置かない
  - 根本原因が残るか: 取り除く（まとまりと名前・説明の関係を付ける）
- 案 B: `FormControl component="fieldset"` と `FormLabel component="legend"` で囲む
  - BP: MUI の推奨の形だが、見出し「学ぶ科目」と legend が二重になる。legend を見えなくすると見出しと文字が食い違いうる
  - 根本原因が残るか: 取り除くが、見出しの扱いが重なる
- 推奨: 案 A。TC-20b（グループの名前と説明・注意の結び付き）を足す
### G2
- 案 A（推奨）: `frontend/src/constants/routes.ts`（新規）に `LEARNING_SUBJECTS_ANCHOR = 'learning-subjects'` と `LEARNING_SUBJECTS_PATH = '/settings#learning-subjects'` を置き、カードは目印、ダッシュボードは道筋を読む
  - BP: 規約の `constants/`。画面どうしの依存が無くなる
  - 根本原因が残るか: 取り除く
- 案 B: 今のまま（ダッシュボードが設定画面の部品から読む）→ 依存が残る
- 推奨: 案 A。TC-40 の `href` の確かめはそのまま通る
