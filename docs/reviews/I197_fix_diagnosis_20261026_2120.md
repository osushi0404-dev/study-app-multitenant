# I197 fix-loop 診断メモ（1 回目・CI の Harness Tests の失敗）

## 失敗分解
- 再現手順: `/home/tacic/.cache/pre-commit/repoz_4xk138/py_env-python3.12/bin/shellcheck scripts/claude/plan-issue-review.sh scripts/claude/code-review.sh scripts/claude/issue-review.sh scripts/claude/tests/test_review_commit_lifecycle.sh`（`test_review_commit_lifecycle.sh` の TC-C1 と同じ呼び方。CI の Harness Tests の中で動く）
- 期待値: exit 0
- 実際値: exit 1。`scripts/claude/code-review.sh line 464: . "$(dirname "${BASH_SOURCE[0]}")/review-process-lib.sh" — SC1091 (info): Not following: scripts/claude/review-process-lib.sh was not specified as input (see shellcheck -x).`
- ログ: CI run 40319243733 の Harness Tests: `FAIL scripts/claude/tests/test_review_commit_lifecycle.sh` / `FAIL TC-C1-shellcheck (expected success)` / `run-all: pass=39 fail=1`

## 根本原因
- I197 の implement で、code-review.sh の本体に `review-process-lib.sh` の読み込み（`# shellcheck source=scripts/claude/review-process-lib.sh` つき）を足した。shellcheck は `-x` を付けないと、`source=` の指示があっても、引数に渡されていないファイルをたどらず SC1091（info）を出し、終了コード 1 になる。
- TC-C1 は `-x` なしで 4 本だけを渡すので落ちる。commit 時の pre-commit の shellcheck は、ステージした `scripts/` の全ファイル（ライブラリを含む）を一度に渡すので通っていた。
- 手元の run-all で気づけなかったのは、手元に shellcheck が無く TC-C1 が SKIP になるため（CI だけが実行する）。
- セキュリティ観点: 該当なし（静的検査の情報レベルの指摘。挙動・権限・入力の扱いは変わらない）。

## 対応方針（全案＋推奨）
- 案 A（推奨）: 読み込み行の直前に `# shellcheck disable=SC1091` を足す（`source=` の指示は残す）。リポジトリの既存の書き方（`test_i193_official_flow.sh`・`test_i197_adversarial_process.sh` の `# shellcheck disable=SC1091`）と同じ。コメント 1 行で挙動は変わらない。ライブラリ自体は pre-commit・CI の別の検査で shellcheck を通る。
  - セキュリティ影響: なし。BP: shellcheck の公式の抑止の書き方。保守性: 既存と同じ形。リスク: 読み込み先の誤りを shellcheck が見なくなるが、TC-01（test_i197）と test_i193 の C 系が code-review.sh の本体を実際に動かして読み込みを確かめている。
- 案 B: TC-C1 の shellcheck に `-x` を付ける。テスト側の変更で、ほかの 3 本の読み込みの扱いも変わり、範囲が広がる。
- 案 C: ライブラリを読み込まず、code-review.sh に関数を写す。同じ処理が 2 か所になる（/simplify の再利用の指摘に反する）。

## 影響調査
- 同型: I197 で `.` / `source` を足した行は code-review.sh 464 行と adversarial-review.sh の 2 行（`code-review.sh`・`review-process-lib.sh` の読み込み）。adversarial-review.sh は TC-C1 の対象外だが、pre-commit の検査は通っている（ステージで一緒に渡る）。`-x` なしの単体でも同じ指摘が出うるので、同じ `disable=SC1091` を足しておく（同じ案 A の範囲）。
- 他の呼び出し箇所・関連機能: 挙動の変更は無い。gate-check.sh は code-review.sh の関数だけを読み込む（本体の読み込み行には来ない）。
