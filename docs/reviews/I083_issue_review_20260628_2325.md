## 次のアクションの推奨

**`/grill-me` をスキップして `/plan-issue` に進める。**

ただし plan-issue フェーズ開始時に以下を先決することを強く推奨する：

1. **AC 2 の「誤検知ゼロ」定義の確定** — ask（確認プロンプト）を「誤検知」に含むか否かを TC 設計前に一文で明記する。
   - 推奨定義例：「hard block（exit 2）しない = 誤検知なし。ask（exit 0 + プロンプト）は許容。」
2. **block vs ask の振り分け基準の明示** — 動的宛先 push を「常に ask」「常に block」「context で分岐」のどれにするかを実装前に決定する。現制約欄（ask への degrade を含め慎重に）を読む限り「ask」が設計意図に近いと推測されるが、明示がない。
