# I494 診断メモ（fix-loop 2 回目・コードレビューの F1 と、ユーザーと決めた BP・UI/UX の直し）

対象: コードレビュー `docs/reviews/I494_code_review_20261116_1204.md` の止める指摘 F1（Medium・REPRO=yes）。あわせて、ユーザーとの相談（2026-11-16）で「この方針で進めて」と決めた直し（D1〜D4）。台帳の F2〜F6（Low）はこの回では直さない（retro へ）。

## 失敗分解
### F1
- 再現手順: ①設定画面のカードで科目 X にチェックを入れる ②管理者が X を消す ③「学ぶ科目を保存」→ 400「選択された科目の一部が無効です」。`onError` で組織の科目が取り直され、X の行が一覧から消える ④ほかの科目を切り替えて保存しても、`checked` に X の番号が残っているので毎回 400
- 期待値: 取り直した後は、一覧に見えている科目だけで保存でき、成功する
- 実際値: 見えない X の番号を送り続け、画面を読み込み直すまで保存できない
- ログ: `frontend/src/components/settings/LearningSubjectsCard.tsx:62-82`（`currentIds = checked ?? savedIds`・81 行のコメント「currentIds は組織の科目の番号だけ」）

### D1（E2E の探し方・前の fix-loop の直しの置き換え）
- 前の回で `e2e/tests/settings.spec.ts:19` を `{ name: '保存', exact: true }` にした。名前の偶然に頼るので、同じ画面に別の「保存」が増えるとまた落ちる。どのカードの「保存」かが画面の構造に表れていない（画面読み上げでも区別しにくい）
### D2（見出しの段）
- 設定画面の見出しが「設定」= h4、各カード = h6（`variant="h6"` の既定）、I494 のカードだけ h2 で、段が食い違う
### D3（触る前の赤い注意）
- 科目 0 件の人がダッシュボードから来ると、何も触っていないのに「科目を最低1つ選択してください」が赤（`FormHelperText error`）で出る
### D4（見出しの青い枠）
- `#learning-subjects` で来たとき、プログラムで見出しにフォーカスを移すので、太い青い枠（`:focus-visible` の既定）が出る

## 根本原因
- F1: チェックの状態（`checked`）を、組織の科目の一覧と突き合わせずにそのまま使っている。一覧が取り直されて変わることを想定していなかった（`savedIds` は一覧と突き合わせていたが、触った後の `checked` は突き合わせていない）
- D1: 画面に「どの入力のまとまりの保存か」を示す名前が無く、テストが名前の文字列でしか区別できない
- D2: 既存のカードが `Typography` の見た目の段（`variant`）をそのまま見出しの段にしていて、文書の構造の段（`component`）を付けていない
- D3: 「最低 1 つ」の注意を、操作の有無を見ずに 0 件なら出していた
- D4: ボタンではない見出しに、操作できる部品と同じフォーカスの枠を出していた
- セキュリティ: F1 は、見えない番号を送っても裏側が 400 で断る（組織の境界は保たれている）。使えなくなるだけで、漏れ・越境は無い。D1〜D4 は表示とテストだけ

## 対応方針（全案＋推奨）
### F1
- 案 A（推奨）: 表示・保存に使う番号を、毎回いまの組織の科目の一覧と突き合わせる（`currentIds = (checked ?? savedIds).filter((id) => 組織の科目にある)`）。取り直しで消えた番号は自然に外れる
  - BP: 状態を一覧から導く（持っている状態を一覧と食い違わせない）。1 行
  - リスク: 取り直しで消えた科目のチェックが黙って外れる。保存の失敗の表示（「選択された科目の一部が無効です」）は残るので、利用者は一覧を見て選び直せる
- 案 B: 400 のときに `checked` を空に戻す
  - 利用者が選んだほかの科目まで消える。使い勝手が悪い
- 案 C: 400 のときに `setChecked(null)` で保存済みの状態に戻す
  - 選び直した内容が消える。案 A で足りる
- 推奨: 案 A。TC-24b（取り直しで消えた科目を送らず、次の保存が成功する）を足す

### D1
- 案 A（推奨・ユーザーと決めた）: 「学習設定」の `form` に見出しの id を `aria-labelledby` で結ぶ（名前のある form は画面読み上げで飛び先になる。複数の form に名前を付けるのは推奨の書き方）。E2E は `page.getByRole('form', { name: '学習設定' }).getByRole('button', { name: '保存' })`（前の回の `exact: true` を置き換える）
- 案 B: 各カードを `section`（区画）にする → 区画が 5 つ並び、画面読み上げの飛び先の一覧が混む。少なく使うのが推奨なので採らない
- 案 C: ボタンの文言を「学習設定を保存」にする → 画面の文言の変更。今回はしない

### D2
- 推奨: 見た目（`variant`）は変えずに、文書の段（`component`）をそろえる。「設定」= h1、各カード（アカウント情報・学習設定・学ぶ科目・表示設定・通知設定）= h2、「ブラウザ通知の許可状況」= h3

### D3
- 推奨: 赤い注意は「一度触ってから 0 件にしたとき」（`checked !== null && 0 件`）だけ出す。触る前は説明文（「最低1つ選んでください」）だけ。保存ボタンは今どおり 0 件では押せない（決まりは変えない）

### D4
- 推奨: 見出し（`tabIndex={-1}`）の `:focus` の枠を出さない（`'&:focus': { outline: 'none' }`）。フォーカス自体は移すので、キーボードの人はそこから続けられる（ボタンではない見出しの枠を消すのは一般的な作り）
