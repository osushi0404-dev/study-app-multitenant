# I587 修正の診断メモ（fix-loop・2026-11-20 09:30）

対象: `docs/reviews/I587_code_review_20261120_0915.md` の「## 止める指摘」の F8（それ以外の台帳の指摘 F3・F9 は直さない・retro へ）

## 失敗分解

### F8（`backend/problems/views.py` の `MediaAssetContentView`・一覧の絞り込みの仕組みが動く）
- 再現手順: ログインした同じ組織の利用者で `GET /api/media/<自組織の画像の ID>/?ordering=id`
- 期待値: 1 件の配信なので、一覧の並べ替えの値は無視して 200 と画像を返す
- 実際値: `ImproperlyConfigured: Cannot use OrderingFilter on a view which does not have either a 'serializer_class', an overriding 'get_serializer_class' or 'ordering_fields' attribute.`（500）。追加したテスト `test_media_ignores_list_query_params[?ordering=id]` で再現した（`?search=x`・`?page=2` は通る）
- ログ: レビュー役の FINDING F8（REPRO=yes）

## 根本原因

`APIView` から `GenericAPIView` に変えたので、`get_object()` が `filter_queryset()` を通り、全体の設定 `REST_FRAMEWORK['DEFAULT_FILTER_BACKENDS']`（`DjangoFilterBackend`・`SearchFilter`・`OrderingFilter`・`backend/core/settings.py:149-153`）が、このビューにも効くようになった。`OrderingFilter` は並べ替えてよい列を `serializer_class` か `ordering_fields` から決めるが、このビューはどちらも持たないので、`?ordering=` があると設定の誤りとして例外を投げる。1 件を返すビューに、一覧向けの絞り込みの仕組みを効かせる必要は無い。

セキュリティの観点: 500 の本文は `custom_exception_handler` の形で、内部の情報は出ない。組織の境界は越えない（`get_queryset()` の絞り込みはそのまま）。

## 対応方針（全案＋推奨）

- 案 A（推奨）: `MediaAssetContentView` に `filter_backends = []` と `pagination_class = None` を書く。1 件の取り出しに一覧の仕組みを効かせないことを、ビューの属性で明示する（DRF の推奨の書き方）
  - セキュリティ: 変わらない（境界は `get_queryset()`）。規約: §6 の `GenericAPIView` のまま。保守: 2 行。リスク: 無し（このビューは一覧を返さない）
- 案 B: `ordering_fields = []` だけを書く
  - `OrderingFilter` の例外は消えるが、`SearchFilter`・`DjangoFilterBackend` は効いたまま。今は害が無いが、意味の無い仕組みを通し続ける
- 案 C: `APIView` に戻す
  - 規約 §6（`ViewSet`／`GenericAPIView`）から外れる。ユーザーの指示（BP の観点でベストなやり方）に反する

## 影響調査

- 同型のバグ: `GenericAPIView`・`ViewSet` で `serializer_class` も `ordering_fields` も持たないビューがほかにあるか — `grep` で `generics.`・`GenericAPIView` を継承するビューを洗った範囲では（`accounts/views.py` の `UserRegistrationView`・`UserProfileView`・`FieldValidationView` など）、ほかのビューは `serializer_class` を持つ（`OrderingFilter` が例外にならない）。I587 で足したのはこのビューだけ
- 波及: `get_object()` の 404（他の組織・論理削除など）は `filter_queryset()` を通らなくなっても `get_queryset()` で絞られるので変わらない（TC-07）
