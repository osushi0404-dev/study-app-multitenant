# I494 診断メモ（fix-loop・CI の E2E の失敗）

## 失敗分解
- 再現手順: PR #529 の CI「E2E Tests (Playwright)」（run 43795279771）。`e2e/tests/settings.spec.ts` の TC-28（目標時間を保存して、再読み込みの後も同じ値が出る）
- 期待値: 設定画面の「学習設定」の「保存」ボタンを押し、「設定を保存しました」が出る
- 実際値: `locator.click: Error: strict mode violation: getByRole('button', { name: '保存' }) resolved to 2 elements`（1 つ目は「学習設定」の「保存」、2 つ目は I494 で足した「学ぶ科目を保存」）。再試行 2 回とも同じ。ほかの 16 件は通過
- ログ: `e2e/tests/settings.spec.ts:19:50` の `await page.getByRole('button', { name: '保存' }).click();`

## 根本原因
- Playwright の `getByRole` の `name` は、文字列を渡すと**部分一致・大文字小文字を区別しない**のが既定（`exact: true` で完全一致）。既存の E2E は設定画面に「保存」ボタンが 1 つしか無い前提で部分一致で探していた
- I494 で同じ画面に「学ぶ科目を保存」を足したので、部分一致で 2 つに当たった。画面の不具合ではなく、テストの探し方が画面の前提に依っていた
- 実装の段階で、同じ画面の Jest のテスト（Testing Library の `getByRole` は文字列なら既定で完全一致）が通ったので気づかなかった。E2E の探し方の既定が違うことを見ていなかった
- セキュリティ: 該当なし（テストの探し方だけ。認証・認可・入力・表示の変更なし）

## 対応方針（全案＋推奨）
- 案 A（推奨）: `e2e/tests/settings.spec.ts:19` を `getByRole('button', { name: '保存', exact: true })` にする
  - セキュリティ影響: なし
  - BP: Playwright の公式の推奨（同じ名前を含むほかの要素があるときは `exact`）。テストが探すボタンを名前で正確に指す
  - 保守性: 1 行。画面にほかの「◯◯を保存」が増えても壊れない
  - リスク: なし
- 案 B: 「学ぶ科目を保存」を「保存」を含まない名前（例「学ぶ科目を更新」）にする
  - BP: テストの都合で画面の文言を変えることになり、設定画面のほかのカードの「保存」とそろわない
  - 保守性: 将来、別のカードに「◯◯を保存」を足すとまた同じ失敗が出る（根本が残る）
- 案 C: 「学習設定」のカードの中に絞って探す（`page.getByTestId(...)` の中の「保存」）
  - 「学習設定」のカードに目印（`data-testid`）が無く、画面の変更が要る。案 A で足りる
- 推奨: 案 A。テストの探し方の誤りを、その場所で正確な形に直す

## 影響調査の実施有無と結果
- 実施した。`e2e/tests`・`frontend/src` で `name: '保存'` を探した（`grep -rn "name: '保存'" e2e/tests frontend/src`）
  - `e2e/tests/settings.spec.ts:19` だけが部分一致（Playwright）
  - `frontend/src/pages/__tests__/Settings.test.tsx:93`・`:120`・`:142` は Testing Library の `getByRole`（文字列は既定で完全一致）なので、「学ぶ科目を保存」には当たらない。手元で 4 件とも通過済み（implement の記録）
- E2E のほかの `getByRole(..., { name: ... })` で I494 の新しい要素（「学ぶ科目を選ぶ」「学ぶ科目」「再読み込み」）に部分一致で当たりうるもの: 「再読み込み」は E2E のどこでも要素の探し方に使っていない（`grep -rn "再読み込み" e2e/tests` の当たりは `settings.spec.ts:12` のテストの題の文字だけ）。「学ぶ科目」を含む既存の探し方は I494 で足した TC-27 だけ（見出し「学ぶ科目」は設定画面に 1 つ）
