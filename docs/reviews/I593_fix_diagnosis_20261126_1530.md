# I593 fix-loop 診断メモ（review-gate 1 周目 F1）

## 失敗分解
- 再現手順: code-reviewer が、テスト関数を消したファイルについて `FINDING: F3 SEV=Medium STATUS=open FILE=backend/x/tests/test_a.py LINE=200 SECURITY=no STOP=test | … | 再現: TEST_WEAKENING: fewer-tests …` を書く。LINE=200 がブランチの変更の塊（前後 3 行）のどれとも重ならない
- 期待値: 理由の無いテストの弱め（`STOP=test`・再現あり）は、アプリ本体でもハーネスでも必ず止まる（AC4「スクリプトはその指摘で止める」）
- 実際値: `scope_of()`（`scripts/claude/code-review.sh:916`）が `outside` を返し、`blocking()` の `if scope != "delta": return False` で止まらない
- ログ: `docs/reviews/I593_code_review_20261126_1509.md` の F1

## 根本原因
- `STOP=test` を足したとき、`blocking()` の種類ごとの分岐（app・harness）だけを直し、その前にある「差分の中か外か」の判定（`scope_of()`）を見ていなかった。`ac:<番号>` は行に関係なく差分の中と扱う（`:919`）が、`test` には同じ扱いが無い
- テストを弱める差分は、関数ごと消した・数が減ったなど「消えた行」に向く指摘で、HEAD の行番号が変更の塊と重ならないことが普通に起きる（消した位置の前後 3 行を外れる LINE を書くと outside）
- セキュリティ観点: 守りの穴（止まるべき指摘が止まらない＝fail-open）。認証・注入などの新しい露出は無い

## 対応方針（全案＋推奨）
- 案 A（推奨）: `scope_of()` の最初の分岐を `stop.startswith("ac:") or stop == "test" or path == "-"` にし、`STOP=test` を行によらず差分の中と扱う
  - セキュリティ: fail-open を閉じる。偽の止まりは「レビュー役が理由の無いテストの弱めと書いたもの」だけで、計画書に理由を書けば外れる
  - BP・保守性: 既にある `ac:` と同じ形の 1 語の追加。新しい仕組みを足さない
  - リスク: レビュー役が差分の外の古いテストに `STOP=test` を付けると止まる。`TEST_WEAKENING:` はブランチ全体の差分から作るので、正しく使えば差分の外は来ない（定義で `TEST_WEAKENING` の行に対して書くと決めてある）
- 案 B: `blocking()` で `stop == "test"` なら scope を見ずに止める
  - 案 A と効果は同じだが、`scope_of()` と台帳の SCOPE 欄（outside と表示される）が食い違い、記録が読みにくくなる
- 案 C: `STOP=test` の LINE を `TEST_WEAKENING` の行番号に照らして直す
  - 消したファイルや数の減少は HEAD の行が無く、照らす先が無い。複雑で漏れる
- 守る対象は GitHub から復旧できる（ハーネスの判定）。最後の守りは人のマージ。単純な規則（案 A）で足りる

## 影響調査
- 同型: `STOP=` の値で範囲を決めている箇所は `scope_of()` の `ac:` だけ（`grep -n 'startswith("ac:")' scripts/claude/code-review.sh` で `scope_of` と `blocking` の 2 か所）。`blocking()` 側は実装済み
- ほかの呼び出し: `scope_of()` は `ledger_update` の中だけで使う。`--route`（retro の振り分け）は SCOPE を読まないので影響しない
- 関連のテスト: `scripts/claude/tests/test_i593_review_from_base.sh` の TC-09 は LINE=3（塊の中）しか見ていなかった。塊から離れた LINE の行を足し、`scope_of()` の分岐から `test` を外すと落ちる FG を付ける
