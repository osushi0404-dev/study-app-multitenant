# I586 修正の診断メモ（MT-14 の再テストの NG・2026-11-27）

## 失敗分解
- 再現手順: 本人の利用者で http://localhost:<FRONTEND_PORT> にログイン → クイズを始める → 問21 を表示して答える（ユーザーの画面 2 枚・2026-11-27）
- 期待値: 選択肢と解説が読みやすい（MT-14）
- 実際値: ユーザーの言葉: 「まだUIがよくない。まず選択肢が改行した際の2行目以降の開始位置が微妙。2行目以降が選択肢のカタカナのX位置と同じなのは微妙。あとこれはデータの話になるが、解説文に改行がないのが読みづらい。各選択肢ごとの解説文は別行にしたほうが見やすいと思う。」
  1. 選択肢が折り返すと、2 行目が記号（ア）の位置から始まる
  2. 解説が 1 段落で、選択肢ごとの説明が続けて書かれている
- ログ: なし（表示の問題）

## 根本原因
- 1（画面）: 選択肢は記号ごと 1 つの文字列（`ア．RADIUS を…`）で、画面はそのまま 1 つのラベルとして出す（`frontend/src/pages/QuizSession.tsx:554`）。記号と本文が分かれていないので、2 行目を本文の始まりにそろえられない。前回の NG で起票した #645（記号を本文と分けて出す）と同じ原因
- 2（データと画面）: 解説の文を、選択肢ごとの行に分けずに 1 段落で書いた（`.evidence/I586/exam/r06a_db_am2_lv*.md` の「解説」）。さらに、画面は解説の改行を残さない（`QuizSession.tsx:644`・`ProblemPreview.tsx:137` の `Typography` に改行を残す設定が無い）ので、データに改行を入れても 1 段落につながって出る。取り込み（`backend/problems/management/commands/import_problems.py:221-226`）も「**解説**：」の 1 行しか読まない
- セキュリティ: 該当なし（表示する文字の並びだけ。React がエスケープして出す。改行の文字を足すだけ）

## 対応方針＝全案＋推奨
- 案 A（推奨・ユーザーが選んだ）: I586 ではデータだけを直す。25 問の解説を「1 行目: 注記／2 行目: 要点と正解／3 行目から: 選択肢ごとの行（正解の行に「（正解）」）」に書き直す（内容は今の解説と同じ。並べ方だけを変える）。画面の 2 点（選択肢のぶら下げの字下げ・解説の改行を残す設定）は #645 に追記した（2026-11-27・issuecomment-7212630598）
  - DB は `manage.py shell` で 25 問の解説だけを置き換える。25 行の一括更新なので `docs/runbooks/danger-ops.md` の「大量更新」に当たる。**先に控え（`scripts/claude/db-backup.sh`）を取り、ユーザーの承認を得てから行う**（前回の F5 の手順違反を繰り返さない）。計画書の Danger Ops に事前承認の 2 件目として書く
  - Markdown は、取り込みが 1 行しか読まないので、改行入りの版を `.evidence/I586/exam/explanations_v2.json` に置き、Markdown の「解説」も同じ文に直す（続きの行は「**解説**：」の下に書く）。取り込みが続きの行を読まないことは使いにくさの候補と手順書 §11 に書く
  - よい点: #645 が入れば、そのまま選択肢ごとの行で表示される。元に戻すのは控えから同じ置き換えで済む
  - よくない点: #645 が入るまでは、画面では改行が空白 1 つとして出るだけで、見た目はほぼ変わらない。MT-14 の再テストでは、残りは #645 で直すものとして判定してもらう
- 案 B: I586 で画面も直す（解説に改行を残す設定・記号と本文を分けて出す）。I586 の範囲（データの登録と手順書）を超え、#645 と同じ直しを 2 か所で行うことになる。ユーザーが「画面は両方 #645」を選んだので採らない
- 案 C: データも直さず #645 に回す。ユーザーが選んだ範囲（データは I586）と合わないので採らない

## 影響調査の実施有無と結果
- 実施: 書き直した 25 問の解説で、「正解は〇です」と「〇（正解）：」の記号が、どの問題でも Markdown の正解と合うことを機械で確かめた（25 問・食い違い 0）。1 行目は 25 問とも注記
- 同型の問題: 管理画面のプレビュー（`ProblemPreview.tsx:137`）も同じく改行を残さない（#645 のコメントに書いた）。ほかの科目のデータは今は無い
- 波及: 照らし合わせのスクリプト（MT-10）は解説を Markdown と DB で比べているので、改行入りの版（JSON）と比べるように直して流し直す。一覧の一時保存は置き換えの後に消す（`invalidate_problems_cache`）
