# I200 修正の診断メモ（review-gate の CI_WAIT: FAIL・2 回目・2026-10-29）

## 失敗分解
- 再現手順: PR #397（敵対的レビュー 1 周目の対応のコミットの後）の CI「Harness Tests」（`bash scripts/claude/tests/run-all.sh`）
- 期待値: run-all がすべて pass
- 実際値: `run-all: pass=49 fail=1`。不合格は `scripts/claude/tests/test_i200_guard_narrowing.sh` の 1 件
- ログ: `FAIL 03j 別の worktree が無い expected=ok got=SKIP`（Actions の run 40891724690）。ほかの CI はすべて pass

## 根本原因
- 03j（読み解きが例外でも、別 worktree への書き込みの停止を外さない・コードレビューの F1）は、このリポジトリの「ほかの worktree」を `git worktree list` から探して書き先にしていた。手元には app-1 のほかに primary・harness-1・harness-2 があるので通ったが、CI の checkout は worktree が 1 つだけで、見つからないときの分岐が「SKIP」を `ck` に渡して不合格になった
- テストが実行環境（手元の worktree の数）に依存していた。手元で通ったのは環境の差のため
- セキュリティ観点: 該当なし（テストの組み方の誤り。見張りの判定〔停止を読み解きの前に置いた〕は手元で 03j が 2 を返すことで確かめ済み）

## 対応方針（全案＋推奨）
| 案 | 内容 | セキュリティ | BP | 保守性 | リスク・副作用 |
|---|---|---|---|---|---|
| A（推奨） | 一時のディレクトリに主とワークツリーを作り（`git init`・`git worktree add`）、見張りの作業フォルダを主にして、もう一方への書き込みを渡す。`test_pretooluse_worktree_guard.sh` と同じく、どの環境でも同じに確かめる | 影響なし。F1 の守りを CI でも毎回確かめられる | 決定論のテストは環境に依存させない | 一時のディレクトリは trap で消える | 小 |
| B | 別の worktree が無いときは合格として飛ばす | CI では F1 を確かめなくなる | 環境で結果が変わる | 悪い | F1 の後退を CI が捕まえられない |
| C | テストの中でこのリポジトリに一時の worktree を足す | 影響なし | 共有の `.git` の worktree の一覧を書き換える（手元のほかのセッションに影響しうる） | 悪い | 後片付けの失敗で worktree が残る |

推奨: A（実装済み・手元で `pass=75 fail=0`）。

## 影響調査
- 同型（実行環境の worktree の数・名前に依存するテスト）: 今回足した 03j だけ。ほかの I200 のテストは一時のディレクトリか、このリポジトリの中の固定のファイルだけを使う
- 再発防止: テストが環境の何に依存するか（worktree・ネットワーク・ユーザーのホーム）を、足すときに一時のディレクトリで作る形にする。手元で通っても CI で通るとは限らないので、CI の合格を待ってから次に進む（今の流れのまま）
