ログ: 該当なし（画面の表示の食い違い。例外は出ない）

## 根本原因
- F1・F4: 「間違いやすい分野」のカードの出し分けを、科目で絞った値（`has_data`）と、一覧に入る条件（5 問以上）を言わない文言で決めた。カードの中身（全科目・5 問以上）と出し分けの前提がずれている（`Dashboard.tsx:459-463`）
- F2: 達成のお知らせは「その利用者の全体の記録の節目」を祝うものなのに、科目で絞った応答をそのまま判定に使った（`Dashboard.tsx:92-102`）。計画書 4.3 の 10 では「新しいキーで同じ判定をする」とだけ書き、科目の選択との関係を決めていなかった
- F3: 取得を `useCallback` の関数で行い、前の取得を取り消す・古い応答を捨てる仕組みが無い（`Dashboard.tsx:127-136`）。同じ画面の `TodayReviewCard` は `ignore` の印で古い応答を捨てている（`frontend/src/components/TodayReviewCard.tsx:45-55`）のに、そろえていなかった
- セキュリティの観点: どれも本人の自分の数字の表示の食い違いで、他人・他組織のデータは出ない。認証・認可・XSS・機密データの露出には当たらない

## 対応方針（全案＋推奨）

### F1・F4（間違いやすい分野のカード）
- 案 A（推奨）: カードの出し分けを `weak_subjects` の有無を先にする。① 一覧があれば一覧 ② 一覧が空で、科目が「すべて」かつ `has_data=false` なら今の「データがありません。まずは問題を解いてみましょう！」 ③ それ以外は「5 問以上解いた科目のうち、正答率が 70% 未満の科目はありません」（一覧に入る条件を文言に入れて事実と合わせる）
  - セキュリティ: 影響なし。BP: 表示の条件をカードの中身の範囲（全科目）にそろえる。保守: 条件分岐は 3 つのまま。リスク: 文言が 1 つ長くなるだけ
- 案 B: API に全科目の `has_data` を足す
  - 契約（キー）が増え、計画と BE・FE のテストの直しが要る。この食い違いのためだけに契約を変えるのは重い
- 案 C: 科目を選んだときはカードを隠す
  - 設計確認メモ（全科目から出す）に反する

### F2（達成のお知らせ）
- 案 A（推奨）: 科目が「すべて」のときの応答だけでお知らせを判定する（科目で絞った応答では判定しない）
  - セキュリティ: 影響なし。BP: お知らせは全体の節目という意味にそろう。保守: 条件 1 つ。リスク: 科目を選んで開いている間はお知らせが出ないが、全体の節目は「すべて」で開いたときに出るので意味は変わらない
- 案 B: 全科目の数字を API に足す → 契約が増える（F1 の案 B と同じ理由で採らない）

### F3（古い応答）
- 案 A（推奨）: 取得の処理を `useEffect` の中に置き、`TodayReviewCard` と同じ `ignore` の印で、科目を切り替えた後に届いた古い応答（成功・失敗とも）を捨てる。読み込み中の表示の切り替えも、捨てた応答では行わない
  - セキュリティ: 影響なし。BP: React の公式の「effect の中でデータを取得するときの競合の防ぎ方」と同じ形（同じ画面の部品ともそろう）。保守: 今の `useCallback` ＋ `useEffect` の 2 段が 1 段になる。リスク: 小さい
- 案 B: `AbortController` で前のリクエストを取り消す → `apiClient`（axios）に `signal` を通す形にする必要があり、サービスの引数が増える。古い応答を捨てる目的には案 A で足りる

## テスト（直したところを確かめる・失敗の注入つき）
- F1: 科目で絞った `has_data=false` でも `weak_subjects` があれば一覧が出る（`Dashboard.test.tsx`）
- F4: `has_data=true`・`weak_subjects=[]` で「5 問以上解いた科目のうち、正答率が 70% 未満の科目はありません」（TC-25 の文言を直す）
- F2: 科目を選んだ応答（`totals.answered_count=10`）ではお知らせが呼ばれず、「すべて」の同じ応答では呼ばれる
- F3: 科目 5 の応答を遅らせ、「すべて」に切り替えた後に届けても、「すべて」の数字のまま
- 失敗の注入: 各テストを、直す前の条件（`has_data` で先に出し分け・科目で絞った応答で判定・`ignore` なし）に戻すと落ちることを確かめる
