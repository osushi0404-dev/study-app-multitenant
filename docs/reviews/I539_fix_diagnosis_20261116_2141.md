# I539 修正の診断メモ（2026-11-16 21:41）

## 失敗分解
- 再現手順: CI の E2E（`.github/workflows/e2e.yml`・run 43868042699）で `e2e/tests/auth.spec.ts:39`「招待なしの会員登録（I539）」を流す
- 期待値: `/register` で入力して「登録する」を押すと「登録が完了しました。メール認証を行ってからログインしてください。」が出る
- 実際値: 3 回（再試行 2 回を含む）とも 5 秒待っても文が出ない。失敗時の画面キャプチャ（成果物 `playwright-screenshots`）では、パスワード欄に「パスワードは大文字、小文字、数字を含む必要があります」が出て、強さの表示が「✗大文字を含む」。登録の API は呼ばれていない（画面の入力の検証で止まっている）
- ログ: `Error: expect(locator).toBeVisible() failed … getByText('登録が完了しました。…') … element(s) not found`。ほかの 17 本は合格

## 根本原因
- 原因の概要: E2E の新しいテストが、登録のパスワードに CI の `E2E_TEST_PASSWORD` をそのまま使った。CI はこの値を `openssl rand -hex 24`（16 進＝小文字と数字だけ）で毎回作る（`.github/workflows/e2e.yml:24`）ので大文字が無く、登録画面のパスワードの決まり（大文字・小文字・数字・8 文字以上・`frontend/src/pages/Register.tsx` の yup の `matches(/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)/)`）を満たさない
- 手元（Playwright MCP・開発環境）で通ったのは、手元の `e2e/.env.e2e` の値が大文字を含むため。CI と手元で値の形が違うことを見落とした
- これまでの E2E は `E2E_TEST_PASSWORD` をログインにだけ使い（`seed_e2e` が作る利用者）、登録画面の入力の検証を通していなかったので表に出なかった
- アプリの不具合ではない（パスワードの決まりは正しく効いている）
- セキュリティ観点: 認証・認可・入力の検証の欠落ではない（むしろ検証が効いた結果）。直し方で秘密をテストに書き込まないこと（detect-secrets・公開リポジトリ）と、パスワードがログ・成果物に出ないこと（CI は trace を作らない・`playwright.config.ts`）を守る

## 対応方針（全案＋推奨）
- 案 A（推奨）: テストの中で、登録に使うパスワードをその場で作る。`Aa1-` ＋ `crypto.randomBytes(16).toString('hex')`（Node の `crypto`）。大文字・小文字・数字・記号を必ず含み、長さ 36 文字
  - セキュリティ: 秘密を書き込まない（毎回の乱数）。CI の値も手元の値も使わないので、値が表に出る経路が増えない。画面キャプチャのパスワード欄は伏せ字
  - BP: テストが自分の前提（パスワードの決まり）を自分で満たす。環境の値の形に依らない
  - 保守性: 1 行。パスワードの決まりが変わってもこの 1 行を直すだけ
  - リスク: 小さい。ログインもこの値で行う（同じテストの中で作って使う）
- 案 B: CI のパスワードの作り方に大文字を足す（`e2e.yml` を直す）
  - ワークフローの変更は安全装置の変更（止める条件 2）で、GitHub から戻せない例外の範囲。テストだけの都合で触らない。不採用
- 案 C: テストの中で `E2E_TEST_PASSWORD` の先頭に `A` を足して使う
  - 環境の値の形（小文字・数字を含むこと）に依ったまま。手元の値の形が変わると壊れる。案 A より弱い。不採用

## 影響調査
- 同型: `E2E_TEST_PASSWORD` を使う所は `e2e/global-setup.ts`（ログインだけ）・`e2e/tests/auth.spec.ts`（ログインの 2 本と今回の登録）・`backend/accounts/management/commands/seed_e2e.py`（利用者を作るときに Django の `create_user` へ渡すだけで、画面の入力の検証を通らない）。登録画面の入力の検証を通すのは今回の 1 本だけ（`grep -rn E2E_TEST_PASSWORD e2e backend` で確認）
- ほかの呼び出し箇所・関連機能への波及: 無し（アプリのコードは変えない）
- 直すファイル: `e2e/tests/auth.spec.ts` だけ。auto_test の TC-50 に「パスワードはテストの中で作る」を書き足す
