# I444 診断メモ（fix-loop 3・ユーザーの指示で台帳 F3・F4 を直す）

対象: 台帳 `docs/reviews/closed/I444_code_review_20261111_2004.md` の F3・F4（`KIND=guard`・`SEV=Medium`・止めない指摘）。retro で後続 #454 に回したが、マージ依頼の後にユーザーが「マージ前に直す」を選んだ（2026-11-11）。F5（`install -d`・`-vt/app/x`）と作りの改善 2 件は #454 に残す。

## 失敗分解
- 再現手順: 見張りに Bash の JSON を渡す（`test_i444_guard_gaps.sh` の `b` と同じ）
- 期待値: ホストのふだんのプロセス確認 `ps -C node`・`ps -u postgres`・`ps -p 1 -o etime`、環境変数の設定 `declare -x FOO=1` は確認にならない（0）
- 実際値: 4 つとも ASK（「環境変数（秘密情報を含む）の表示」）
- ログ: 台帳 F3・F4、敵対的レビュー `docs/reviews/closed/I444_adversarial_review_20261111_2051.md` の観点 3 の Low

## 根本原因
- I444 の 5-1 で、環境変数の表示の判定をホストとコンテナで 1 か所（`pretooluse_guard.py` の `_cmd_external`）にまとめたとき、コンテナ向けの粗い条件をそのままホストにも当てた
  - F3: `ps` の BSD 形式の e を「- の無い英字だけの引数のどれか」で見ているため、値を取るオプション（`-C`・`-u`・`-o`・`-p` など）の値（`node`・`postgres`・`etime`）にも当たる
  - F4: `export`／`declare`／`typeset` に `-x` があれば確認にしているため、代入（`declare -x FOO=1`）も確認になる。`-x` だけ（引数なし）の形は「引数がすべて - で始まる」の条件でもう確認になるので、`-x` を別に数える必要はない
- 計画時の確かめ（過去の作業コマンドでの比較）にこの形が無かったので見逃した
- セキュリティ観点: 直しは確認を外す方向。外すのは「値を取るオプションの値」と「代入つきの `-x`」だけで、環境変数を表示する形（`ps e`・`ps auxe`・`ps aux e`・`ps -u postgres e`・引数なしの `export`／`declare`／`declare -x`・`declare -p`・`export -p`）は確認のまま。脅威モデルは「事故」

## 対応方針（全案＋推奨）
### 案 A（推奨）: 粗い 2 つの条件の直し
- `ps`: 「英字だけで e を含む引数で、直前の語が - で始まらないもの」（値を取るオプションの直後の値を見ない）。`zip(toks, toks[1:])` で直前の語を見る 1 行の変更
- `export`／`declare`／`typeset`: `-x`・`-px`／`-xp` の数え方から `-x` を外し、`-p`・`-px`・`-xp` だけにする（引数なしは別の条件で確認のまま）
- 写しで確かめた（スクラッチパッドの `g_fix3.py`）: 上の 4 つが 0、表示する形 13 件が ASK のまま。既存の container_guard 788 件・i200 75 件は全件そのまま。`test_i444_guard_gaps.sh` は FG-01 の置き換えの文字列だけ直せば通る
- 副作用: `ps -A e` のように値を取らないオプションの直後の e は見落とす（まれ・粗い判定の範囲。事故の実例なし）
### 案 B: 値を取る `ps` のオプションの一覧を持ち、値を読み飛ばす
- 精密だが一覧の写しが要り、粗い判定の方針（I179・I200）に反する。行数も増える
### 案 C: 環境変数の表示の判定をコンテナだけに戻す
- ホストの `printenv` との一貫性を失う。I444 の計画の決定（判定を 1 か所）を戻すことになり、範囲を越える
### 推奨: 案 A

## 影響調査
- 同型: 環境変数の表示の判定はこの 1 か所だけ（I444 で 1 か所にまとめた）
- テスト: `test_i444_guard_gaps.sh` に、通る形（`ps -C node`・`ps -u postgres`・`ps -p 1 -o etime`・`declare -x FOO=1`）と確認のままの形（`ps -u postgres e`・`declare -x`・`declare -p FOO`）を足し、`ps` の直前の語の条件を外した写しで `ps -C node` が確認になる失敗の注入を足す。FG-01 の置き換えの文字列を新しい条件に合わせる
- 手順書: `danger-ops.md` 3. は代表（`printenv`・コマンドを包まない `env`・引数なしの `export`）と正の関数名だけなので変えない
- 計画書: 5-1 のコード例と計画変更記録を直す。方式（判定を 1 か所・粗い判定）・範囲・受け入れ条件は変えない（計画レビューは通り直さない）
