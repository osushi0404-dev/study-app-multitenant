# I223: GitHub の操作を GitHub App に移したことを記録と仕組みに残し、点検の範囲に GitHub の認証を入れる

## 関連資料

- Draft PR: #414

- 経緯の記録: `docs/reviews/open/I220_review.md`「## 自律判断の記録」（[review-gate の前] の行）

## 設計確認メモ（/grill-me）
- Q: GitHub の MCP（`.mcp.json` の `github`・2025.4.8 版・個人の鍵 `GITHUB_PERSONAL_ACCESS_TOKEN` で動く）をどうするか → A: **外して `gh` だけにする**（ユーザーが「BP の観点で最適なのは？」と質問 → Claude が BP（名義と鍵は 1 つ・長く効く鍵を持たない・使わない道具は置かない）から (a) を推奨 → ユーザーが「それで OK」で確定。スキル・スクリプトはすべて `gh` を使い MCP に頼る所は無い（2026-11-05 に検索で確認）。`.claude/settings.json` の `mcp__github__*` の見張りの登録と `pretooluse_guard.py` の MCP の判定は、安全装置なので触らずに残す（MCP を戻したときにも効く・止めて聞く条件 2 に当てない）。手元の `GITHUB_PERSONAL_ACCESS_TOKEN` の鍵の失効は、誰の鍵かを確かめたうえで手順書に「ユーザーが GitHub の画面で失効させる」と書く）
- Q: `osushi0404-bot`（協力者・write）を協力者から外すか → A: **bot が戻るまで残す**（b）。外すかどうかの判断は、bot が戻った後の片付けで行う
- Q: bot がまだ戻らないとき（PR #404 は 2026-11-05 時点で見えないまま）の片付けの扱い → A: **I223 は待たずに閉じ、片付け（PR #404 を閉じる・古いブランチ `feature/I220-claude-files-issues` を消す・bot を協力者から外すかを決める）はやり残しの一覧（`docs/reviews/backlog/I223.md`）に回す**（a）
- Q: 受け入れ条件の「新しい端末」の範囲 → A: **WSL（Linux）だけ**（a）。Windows 側（デスクトップアプリなど）は対象外

## 背景/目的

**背景**: Claude が GitHub を操作する名義に、人のアカウントの bot（`osushi0404-bot`）を使っていた。2026-10-30 にこの bot が GitHub に停止され、push・PR・イシューの操作が 6 日止まった。停止中は bot が作った PR・イシューが GitHub 上で見えなくなり、I220 の PR は作り直しが要った。停止のきっかけは、短い間のイシューの書き換え・コメント・push の多さと見ている（GitHub からの理由の説明は未着）。2026-11-05 にユーザーの決定で GitHub App（`osushi0404-claude`・組織 `osushi0404-dev` の下・このリポジトリだけに入れた）へ切り替えた。ただし、切り替えの仕組みはリポジトリの外に置いただけで、レビューを通っていない。
**目的**: App への切り替えをリポジトリの仕組みと手順書に残してレビューを通し、別の端末やセッションでも同じ手順で動かせるようにする。あわせて、名義と鍵の仕組みが点検から漏れないようにする。

### 現状の問題（証拠・再現手順）
- リポジトリの外に置いた仕組み（レビューを通っていない）:
  - `~/.local/bin/gh-app-token`: App の秘密の鍵ファイルから 1 時間の鍵を受け取り、控えに置く
  - `~/.local/bin/gh`: `gh` を呼ぶたびに鍵を渡して本物の `gh` を動かす
  - `~/.gitconfig` の credential helper を上の `gh` に差し替え
  - リポジトリの git の作者を `osushi0404-claude[bot]` に変更
- `docs/runbooks/branch-protection-setup.md` に `osushi0404-bot` の記述が残っている
- App の鍵では `gh api user`（ログイン中の人を調べる API）が使えない。頼っている所があるかは未確認（`scripts/claude/`・`.claude/` の検索では見つからなかったが、作業の始めに状態を表示する仕組みなどは未確認）
- これまでの点検（I185 の総点検など）の範囲は、リポジトリの中（スキル・スクリプト・見張り・手順書）だけで、GitHub の認証・鍵・アカウントは入っていなかった

### 根本原因
Claude が GitHub を操作する名義（人の bot アカウント）が、自動化の量を大きく増やした I193 以降も見直されず、どの点検の範囲にも GitHub の認証・鍵・アカウントが入っていなかった。「公式の機能をなるべくそのまま使う」の方針も、スキル・フックにだけ当てはめていた。

### 解決方針
1. 鍵を受け取る仕組みと `gh` の入口をリポジトリ（`scripts/claude/`）に入れ、置き方・設定の手順を手順書に書く（秘密の鍵ファイルはリポジトリに入れない）
2. `branch-protection-setup.md` などの bot 名を App に直す
3. App の鍵で動かない呼び出し（`gh api user` など）が無いかを確かめ、あれば直す
4. 総点検の一覧に「GitHub の認証・鍵・アカウント」を足す
5. 自動化の量を大きく増やす計画で、それを担う名義と鍵の仕組みがその量に合っているかを確かめる観点を、計画の書き方か計画レビュー役に足す（決定論のチェックにできるかは計画で判断）
6. GitHub の MCP を外し、GitHub の操作を `gh`（App の鍵）だけにする（grill-me で確定）。`docs/runbooks/issue-flow.md` の「`gh auth login` で認証済み」の前提も App の仕組みに直す
7. 総点検の一覧は常に置く場所が無い（I185 の計画書の中だけ）ので、手順書に常設の一覧を新しく作る（置き場所は計画で決める）
- 対象の端末は WSL（Linux）だけ（grill-me で確定）
