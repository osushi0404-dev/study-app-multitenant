## 背景/目的

**背景**: I225 で、鍵が画面・記録に出たときの失効をスクリプト `scripts/claude/gh-app/revoke.sh` にし（控えの 2 つの鍵・`--stdin` で控えに無い鍵）、鍵を出す `gh auth status` の書き方を手順書などから締め出す静的な検査（`scripts/claude/tests/test_i223_gh_app.sh` の G10）を足した。レビューで次の残りが指摘された（止める条件には当たらず、I225 では直していない）。
**目的**: 失効の結果の表示が「失効できた」と取り違えないようにし、控えを消すときの競合をなくし、鍵を出す書き方の検査の取りこぼしを減らす。

### 現状の問題（証拠・再現手順）
- **F1（Medium・再現あり・SECURITY=yes）**: `revoke.sh` の `revoke_one`（`scripts/claude/gh-app/revoke.sh:20-25`）は DELETE の結果を見ず、続く読み取りが HTTP 401 なら「失効を確認」とする。一度も有効でなかった鍵（末尾を欠いた・打ち間違い・すでに失効済み）でも成功と表示する。再現: `revoke.sh --stdin` に末尾を欠いた鍵を渡す → 「渡された鍵: 失効を確認しました」・exit 0。本物の鍵は有効なまま残る
- **F5（Low・再現あり・SECURITY=yes）**: 失効の確認の後に控えを `rm -f` で消すまでの間に、並行する `gh` が控えを取り直して書き込むと、失効していない新しい鍵の控えを消す（`revoke.sh:46-52`）
- **F6（Low・再現あり・SECURITY=yes）**: G10 は `gh auth status` の文字列だけを見る。鍵を丸ごと出す `gh auth token` を手順書に書いても通る。`\` で複数行に分けた `--json` 付きの書き方は誤って不合格にする

### 根本原因
- F1: 「無効になった」ことを確かめるときに、「その鍵がもともと有効だった」ことを確かめていない（失効の前に 1 回読んで有効を確かめる段取りが無い）
- F5: 控えの読み・失効・消すまでを 1 つの区切り（排他）にしていない。`gh-app-token` の取り直しにも排他は無い（I223 の台帳 F5 と同じ根）
- F6: 静的な検査の対象を「`auth status` の書き方」に限っていて、「鍵の値を出すコマンド」全体（`auth token`・`--show-token`）を数えていない

### 解決方針
- 確定（設計確認メモ参照）:
  - F1: 失効の前に同じ鍵で読み、成功（有効）を確かめてから DELETE する。前もって 401 なら「もともと無効」と分けて表示する（`--stdin` は exit 1・控えは消して成功扱い）
  - F5: **見送り**（「ふつうの書き方の事故」の範囲外・実害がほぼない）
  - F6: G10 の対象に `gh auth token` を足す。複数行の書き方は行末の `\` をつないでから見る
  - 同梱: backlog の F2・F4、omission-lint を push の前にも流す
- 予防策: レビュー役の観点には足さない。G9 の決定論のテスト（もともと無効な鍵のケース）で守る

### 同梱（I225 マージ後の評価・2026-11-06。grill-me で 3 件とも入れると確定）
- `docs/reviews/backlog/I225.md` の F2（ログインなしのとき置き換えた `auth status` が何も出さず exit 0。Claude が「ログインできている」と取り違える）と F4（`plan-writing-rules.md` に `--strict-mcp-config`・tmux の `PATH`・G7 の記述が無い）。どちらも数行で直る
- 自動テスト文書の決定論ゲートの見出しの検査（omission-lint）を push の前に流す。I225 では見出しの 1 語違いで review-gate を 1 周やり直した（AI のレビュー 1 周分の手戻り）。新しい決まりは足さず、既存の決定論の検査を走らせる時点を前にするだけ
