# I057: ワークフロー改善: plan-issue/SKILL.md・code-reviewer.md に承認ゲートを追加

## 関連資料
- 起点: I055 振り返り（予防処置 P5・P6）
- GitHub Issue: #117
- Draft PR: #118

## 設計確認メモ（/grill-me）
- Q: P5 の「TC」とは何か・適用条件は？ → A: TC = テストケース（`I###_auto_test.md` に記載された個別テスト項目）。「新しい TC を追加したステップがある場合」に限定。文言修正のみのステップ更新は対象外。
- Q: P6 のゲートを置くタイミングは `code-reviewer.md` が最適か？ → A: `/close/SKILL.md` の事前チェックに変更する。理由: レビュー出力時（責務混在）・retro 時（事後）より、/close 実行直前が最も確実に見落としを防げる。`code-reviewer.md` への追記は行わない。

## 背景/目的
I055 の振り返りで 2 件の構造的問題を特定した。

**P5（計画レビュー差し戻し繰り返し）**: 計画書に是正/予防ステップを後追い追加した際、追加したステップの TC を実行せずに plan-review を依頼したため、差し戻しが 3 回発生した。`plan-issue/SKILL.md` の文書品質ゲートに「ステップ追加後の TC 実行確認」がなかったことが根本原因。

**P6（Medium 指摘の追跡漏れ）**: 最終コードレビューで Medium 指摘（`mistake_analysis.py` の implicit string concatenation）が出たが、フロー上いずれのステップにも割り当てられず、/close 直前まで未対応になった。`code-reviewer.md` に「Medium 以上未対応のまま進まない」旨の記載がなかったことが根本原因。

## スコープ
### 含む
- `plan-issue/SKILL.md` の文書品質ゲート（承認ポイント提示前チェックリスト）に以下を追加:
  「新しいテストケース（TC）を追加したステップがある場合、そのTCをすべて実行・記録してから承認ポイントを提示しているか」
- `.claude/skills/close/SKILL.md` の事前チェックに以下を追加:
  「直近のコードレビューで Medium 以上の指摘が未対応のまま残っていないか。未対応の場合は計画書に是正ステップを追記するか、インライン修正を先に完了させること」

### 含まない
- `code-reviewer.md` への変更（grill-me で /close/SKILL.md への追記に変更決定）
- 上記以外のスキルファイル・ルールファイルの変更
- plan-issue-review・grill-me 等への同内容の展開（別イシューで判断）

## 受け入れ条件（Acceptance Criteria）
- [ ] `plan-issue/SKILL.md` の文書品質ゲートに「新しい TC を追加したステップがある場合、実行・記録してから承認ポイントを提示しているか」チェック項目が追加されている
- [ ] `.claude/skills/close/SKILL.md` の事前チェックに「Medium 以上の未対応指摘がないか確認してから /close に進む」旨の記載が追加されている
