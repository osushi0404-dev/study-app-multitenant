## 背景/目的

**背景**: I454 で見張り（`scripts/claude/hooks/pretooluse_guard.py`）のオプションの値の読み方（`_opt_values`）を、くっつけた値（`-vt/x`）も読めるように広げた。review-gate で 2 周続けて「読み方の取り違え」の High が出たため、fix-loop 2 で読み方を 2 段（既定＝変更前と同じ strict／`loose=True`＝まとめ書きの途中からの候補もすべて読む）にし、多く読むほど止める側に倒れる呼び出し元だけが loose を使う形にした。止める指摘は解消したが、止めない指摘（Medium 以下）が台帳と敵対的レビューに残った。
**目的**: 残った指摘を直し、見張りがよくある書き方で誤って確認・停止を出さず、止めるべき形を見落とさない状態にする。あわせて、読み方を変えたときに「止めるべき形の後退」を決定論で見つける仕組みを足す。

### 現状の問題（証拠・再現手順）
（どれも見張りに Bash の JSON を渡して判定だけを見る形で再現できる。`$W` は別ワークツリー）
- F15（Medium・SECURITY=yes）: python の `-c` を loose で読むため、スクリプト名の後ろの引数に含まれる `c` 以降をコードとみなし、実行するスクリプトの中身が読まれなくなる（`_python_code_raw`）
- F16（Medium）: `_sql_of` が loose になり、偽の候補（`-hlocalhost` → `alhost`）が SQL に混ざる。読むだけの `psql -hlocalhost -Ucelery -c 'select 1'` に余計な確認が出る。偽の候補に未解決の置換の印が混ざると、ヒアドキュメントの破壊的 SQL が見えない扱いになる
- F17（Low・SECURITY=yes）: strict 側は先頭と末尾の文字しか読まないので、`psql -Xf/tmp/dump.sql`・`grep -ie. .env` のような途中の文字の付着形を読まない（develop でも元から読めていなかった）
- F2（Medium）: `psql -dprofile_db -c "select 1"` の `-d` の値の `f` を `psql -f` と取り違える誤停止。fix-loop 2 で psql の `-f` を strict に戻したので今は再現しない（grill-me で確認済み。テストで固定して閉じる）
- F4（Medium）: sed の in-place 判定 `_has_short(args, "i")` が `-e's/print/log/'` の式の `i` に当たり、`sed -e's/print/log/' $W/file`（読むだけ）を別ワークツリーへの書き込みとして止める（DANGER_OK でも外れない）
- F6（Medium・敵対的レビューの Medium も同じ）: `_OPT_PATH_RE` は `--rootdir=`・`--confcutdir=` だけを除く。`docker compose exec -T backend pytest --cov=/app/apps` のように `--cov=`・`--cov-config=`・`--ignore=`・`--deselect=` などの読む指定に毎回「/tmp/ 以外への書き込み」の確認が出る
- 敵対的レビューの Medium: `cp -vt/tmp/d $W/a $W/b`（くっつけた `-t` と複数の読み元）で、`-t` の推測が最後の位置引数を書き先に足すため、別ワークツリーから読むだけで停止する（DANGER_OK でも外れない）。離した `cp -t /tmp/d $W/a $W/b` は通るので、形によって結果が食い違う

### 根本原因
- 見張りは、コマンドのどの短いオプションが値を取るかを知らないまま、まとめ書き（`-tAcX`・`-vt/x`）の値を「英字かどうか」で推し量っている。どの読み方を選んでも、どこかの呼び出し元で誤読が残る（F14・F18 も同じ原因）
- I454 の fix-loop 1 は「誤って止める」ケースだけをテストに足し、「止めるべき」ケースの後退（F10〜F12）を見落とした。変更前の見張りと判定を並べて比べる決定論の仕組みが無く、比較表は診断メモで手作業で作った

### 解決方針
（2026-11-12 の grill-me で確定。設計確認メモを参照）
- **案 1 を採る**: 見張りが中を読むコマンド（今の呼び出し元が見ている psql・python・sed・cp・grep など）に「値を取る短いオプションの文字」の表を持たせ、まとめ書きを getopt と同じに分けて読む。表にないコマンドは今の読み方（strict／loose）のまま。止める対象（何を確認・停止にするか）は増やさない
  - 表で直らないもの（F6 の `_OPT_PATH_RE` の読む指定・F16 の偽の候補が置換の印で SQL を隠す扱い）は、同じ方針（読み違いを減らす・止める対象は増やさない）で呼び出し元を直す。具体は計画で決める
- 案 2（個別の直しだけ）・案 3（#430 に吸収）は採らない。I463 は #430 より先に行う
- **予防策を採る**: `scripts/claude/tests/guard_corpus_diff.py` に `--cases <ファイル>` を足し、`scripts/claude/tests/guard_must_stop_cases.txt`（止めるべき形の一覧）を変更前の見張りと作業ツリーの見張りの両方に流して、止める側の判定が減ったものを失敗にする。`docs/runbooks/danger-ops.md`「見張りを直したら、コミットの前に 3 つのテストを流す」に入れる
