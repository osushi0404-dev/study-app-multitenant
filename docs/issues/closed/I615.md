## 背景/目的

**背景**: I599 で「`scripts/claude/` にレビュー前の中身（BASE との差・未追跡・無視されるファイル）があるあいだは、外で動く入口（`OUTSIDE_SCRIPTS` の 16 本）を外で動かさない」にした。そのため、`scripts/claude/` を変えるハーネスのイシューでは、外で動く必要のある入口（コードレビュー・敵対的レビュー・計画レビュー・イシューのレビュー・台帳の振り分けなど）を Claude が起動できず、ユーザーに `! bash scripts/claude/<名前> …` を頼むことになる。I610 では、計画レビュー（途中の変更を `git stash` で退避して回避）・コードレビュー・台帳の振り分けで、人の手か回避が要った。CLAUDE.md の「ユーザーに確認するのは価値判断・取り消せない操作だけ」に反する形で、流れの中に人の手が入っている。
**目的**: スクリプトを変えたブランチでも、外で動く入口を Claude が人の手なしに起動できるようにする。守り（書き換えたスクリプトをレビュー前に外で動かさない）は今と同じに保つ。

### 現状の問題（証拠・再現手順）
- `.claude/hooks/unreviewed.py` の `run` は、`dirty()` が空でないと exit 3 で止まり、`! bash scripts/claude/<名前> …` を頼むよう案内する（`.claude/hooks/unreviewed.py:234-241`）
- 再現: `scripts/claude/` の何かを変えてコミットしたブランチで `bash scripts/claude/code-review.sh I###` → `[unreviewed run] scripts/claude/ にレビュー前の中身がある…` で exit 3
- 1 イシューで 2〜4 回（計画レビュー・コードレビュー〔周ごと〕・敵対的レビュー〔周ごと〕・台帳の振り分け・イシューのレビュー）
- フックの起動役は I610 で「いつも BASE の写し（`git archive $base scripts/claude`・`~/.cache/claude-reviewed-hooks/<BASE>/`）で動かす」にし、同じ守りを人の手なしに満たしている（`.claude/hooks/reviewed-hook.sh`）
- I586（2026-11-22）: `git merge --ff-only origin/develop 2>&1 | tail -2` とつないで流したため外に出ず、中で動いた git が `.claude/hooks/reviewed-hook.sh` を書き換えられずに途中で止まった（HEAD は動かず、ほかのファイルだけ develop の中身に）。途中の状態が「レビュー前の中身がある」に見えて外の入口も止まり、戻す `git checkout --` は見張りが止め、ユーザーに `! git reset --hard origin/develop` を頼んだ

### 根本原因
- I599 は、外で動く入口の守りを「作業ツリーの中身がレビュー済みか」で判定し、レビュー前なら止める形にした。フックの起動役（I610）のように「レビュー済みの写しを動かす」形にしなかったため、守りを保つ代わりに人の手が要る
- 外に出られるかが、コマンドの先頭の形（`excludedCommands` の型）で決まるので、前置き・`|`・`>`・`$(…)` の書き方で黙って中に入り失敗する（I525・I599・I586・この会話の gh の失敗）。git の作業ツリーを書き換える操作では、黙って中に入ると途中で止まって壊れた状態が残る

### 解決方針
- 外で動く入口（`OUTSIDE_SCRIPTS`）は、起動役（`unreviewed.py run`）が BASE の `scripts/claude` の写しから動かす（フックの起動役と同じ写しの作り方・置き場所を共有する）。作業ツリーの中身がレビュー前でも止めない。書き換えたスクリプトは、マージされるまで Claude の起動では外で動かない（守りは今と同じ）
- 写しを作れないとき（BASE を求められない・写しの作成に失敗）は、今と同じく止めて、ユーザーに `!` で流してもらうよう案内する（作業ツリーの版で外に出ない）
- レビューの道具を直したブランチ（流す入口のスクリプト、または、それが呼ぶスクリプト・使うレビュー役の定義が BASE と違う）では、その入口だけ BASE の版を流さず、新しい版をユーザーに `!` で流してもらい、それをその周の正式な結果にする（周ごとに毎回）。Claude がその入口と部品の変更を機械で見分け、頼む・頼まないを決める（見分け方・部品の一覧は計画で全件洗い出す）。関係しない入口は BASE の版で自動
- 写しの作り方を 1 か所にまとめるとき、I610 の F1（`rm -rf "$snap"` してから `mv` する競合）を直す（`rm -rf` をやめ、`mv -T` が失敗したら作った一時の写しだけを消す。途中で壊れた写しの扱いも決める）。F2（`scripts/claude/hooks/sessionstart_context.py:200` の子プロセスに `-I` が無い）も直し、フックの中で python を起こす箇所の `-I` をテストで確かめる
- 写しの入口が作業ツリーのファイル（計画書・記録）を読む前提・作業フォルダ（cwd）・`$0` から相対で他のスクリプトを探す箇所の扱いは、計画で全件洗い出す
- #600（git commit の pre-commit・git のフック・docker compose）は I615 に含めず、別に進める。写しの仕組みは #600 でも使い回せる形にしておく
- 書き方で外に出られなくなる問題は、スキル・手順書の呼び出しを外に出る形だけにそろえ、出力の行き先は `>` でなく引数で受けるなどで減らす（方法は計画で決める）
- 作業ツリーを書き換える git の操作を、つないだ・前置き・`|`・`>` の形で流そうとしたら、見張りが止めて「単独で流して」と案内する（I586 の事例。対象の操作の一覧は計画で決める）。途中で止まったときの戻し方は変えない
