### fix-loop 更新（2026-06-27）— 高リスク保護を `deny` から PreToolUse フックへ
grill-me の (a)（高リスク群を `deny` に追加）は **実機で不成立**と判明（`/test`）。**Claude Code の Edit/Write では、パスが allow と deny の両方に一致すると allow が優先され、deny は上書きしない**（重複 allow 配下の Dockerfile/migrations 等は deny を足しても編集が通る。対照: allow と重複しない `./.env` の deny は実効）。さらに settings `deny` の挙動は自動テストできず fail-open。
→ **方針変更（確定）**: 高リスク群（依存/ロックファイル/`**/migrations/*.py`/init-db.sql/Dockerfile/nginx.conf）の Edit/Write 保護を **PreToolUse フック（`scripts/claude/hooks/pretooluse_guard.py`）** で行う（決定論的・失敗注入でテスト可能・fail-safe）。broad allow は維持（アプリコード無確認）。機密ファイルの `deny` は実効かつ Read も守るため settings 側に据え置き。詳細は計画書「重大な発見」「§4〜§9」。

## 背景/目的

### 現状の問題（証拠・再現手順）
承認済みの実装フェーズに入った後も、`backend/**`・`frontend/**` のソースコードを編集するたびに承諾プロンプトが出る。
- 原因の所在: `.claude/settings.json` の `permissions.allow` で `Write`/`Edit` は `docs/**` のみ許可。コードパスは未許可のため毎回 ask になる。
- 体感: イシュー1件の実装で多数の編集が発生するたびにプロンプトが挟まり、機械的確認のノイズが大きい。

### 根本原因
価値判断（実装してよいか）の承認は「計画承認＋`/implement`」というワークフローゲートで既に取得済みなのに、その後の1ファイルごとのツール権限プロンプトが二重の確認になっている。機械的確認（編集の実行）と価値判断（方針）が権限レイヤーで分離できていなかった。

### 解決方針（案D・fix-loop 確定）
`permissions.allow` にソースコードパス（`Write/Edit(backend/**)`・`Write/Edit(frontend/**)`）と `Bash(bash scripts/claude/*)` を追加し、承認済み実装フェーズ中のアプリコード編集ごとのプロンプトを不要化する（broad allow は維持）。変更が重く価値判断寄りの「高リスク群」（依存マニフェスト/ロックファイル/マイグレーション/init-db.sql/Dockerfile/nginx.conf）の Edit/Write は、**settings `deny` ではなく PreToolUse フック（`pretooluse_guard.py`）が `permissionDecision: "ask"` を返してプロンプト化**する（承認すれば編集可。Edit では `deny` が重複 allow に勝てず・検証不能なため。フックは決定論的・テスト可能・fail-safe）。実装開始の承認ゲート（ワークフロー側）と機密ファイル保護（既存の `.env`/`secrets`/`*.pem`/`*.key` の settings `deny`）は維持する。

## 実装対象（既知のもの）
案D。編集する実ファイルは `.claude/settings.json` と `scripts/claude/hooks/pretooluse_guard.py` の2つ。

| ファイル | 変更内容 |
|---------|---------|
| `.claude/settings.json` (`permissions.allow`) | `Write/Edit(backend/**)`・`Write/Edit(frontend/**)`・`Bash(bash scripts/claude/*)`（維持） |
| `.claude/settings.json` (`permissions.deny`) | 機密ファイル deny（`.env`/`secrets`/`*.pem`/`*.key`）は維持。**実効しない高リスク群 deny（Dockerfile/deps/migrations 等の Edit/Write）は撤去**（フックへ一本化） |
| `.claude/settings.json` (`hooks.PreToolUse`) | `Edit\|Write` マッチャを追加し `pretooluse_guard.py` を呼ぶ |
| `scripts/claude/hooks/pretooluse_guard.py` | Edit/Write の高リスクパス（`(backend\|frontend)/Dockerfile(.dev)?`・`frontend/nginx.conf`・`backend/requirements.*\.txt`・`backend/pyproject.toml`・`frontend/package(-lock)?.json`・`.*/migrations/.*\.py`・`backend/init-db.sql`）に対し `permissionDecision: "ask"` を返す判定を追加（プロンプト化。承認で編集可）。既存の危険 bash の `exit 2` は維持 |

**フックが ask を返す保護対象パターン**（＝編集する実ファイルではなく、フックの判定対象。`pretooluse_guard.py` 内に実装）: `backend/requirements*.txt`・`backend/pyproject.toml`・`frontend/package.json`・`frontend/package-lock.json`・`**/migrations/*.py`・`backend/init-db.sql`・`backend/Dockerfile`・`frontend/Dockerfile`・`frontend/Dockerfile.dev`・`frontend/nginx.conf`。

※ 設計確認メモで言及した `bash scripts/claude/check-memo-body-paths.sh` は本イシューの**編集対象外**（プロンプト挙動の例示として参照しただけ）。

## スコープ
### 含む
- `permissions.allow` へのコードパス追加（`backend/**`・`frontend/**`）＋ `Bash(bash scripts/claude/*)`
- **PreToolUse フックによる高リスク群 Edit/Write のブロック**（`pretooluse_guard.py` ＋ `hooks.PreToolUse` の `Edit|Write` 登録）
- 実効しない高リスク群 `deny`（settings 側）の撤去
### 含まない

- 既存の機密ファイル `deny`（`.env`/`secrets/**`/`*.pem`/`*.key`）の変更（現状維持）
- ワークフローの承認ゲート（`/plan-issue`・`/implement`）の変更
- ファイル閲覧時の Bash 使用方針（Read ツール優先は別途運用で対応）
