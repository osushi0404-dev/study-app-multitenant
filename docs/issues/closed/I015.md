# I015: /code-review・/plan-issue-review スキルへのレビュー観点追加と /issue-bootstrap 採番バグ修正

## 関連資料
- .claude/skills/code-review/SKILL.md
- .claude/skills/plan-issue/SKILL.md
- .claude/skills/issue-bootstrap/SKILL.md

## 背景/目的
- 現状の `/code-review` は受け入れ条件との照合・ロジック品質確認のみで、セキュリティや業界標準のベストプラクティス観点が欠けている
- 計画書・テスト文書のレビューフェーズが存在しないため、設計上のセキュリティ漏れや非推奨パターンが計画段階でチェックされない
- `/plan-issue` に埋め込まず、`/code-review` の命名規則に準じた `/plan-issue-review` を独立スキルとして新設することで責務を分離する
- レビュー品質を底上げし、「実装後に発覚するセキュリティ・設計問題」を計画段階・実装レビュー段階で潰す
- `/issue-bootstrap` の採番スクリプトで `printf "%d"` が `014` 等の0埋め数値を8進数として解釈し、正しい次番号を算出できないバグが存在する（例: 014→12と解釈→次番号が013になる）

## スコープ
### 含む
- `/code-review` SKILL.md に「ベストプラクティス・セキュリティ・モダン開発観点」レビューステップを追加
- `/plan-issue-review` スキルを新規作成（計画書・テスト文書を同3観点でレビュー）
- `/plan-issue` SKILL.md の末尾に「次のステップ: `/plan-issue-review`」の案内を追加
- `CLAUDE.md` のスキル一覧に `/plan-issue-review` を追加（`/plan-issue` と `/implement` の間）
- `docs/runbooks/workflow.md` のフロー・スキル一覧・フェーズ移行テーブルに `/plan-issue-review` を追加、ワークフロースキルリストに `/retro` を追加（欠落していた）
- `docs/runbooks/issue-flow.md` のフロー図・フェーズ2詳細に `/plan-issue-review` ステップを追加、フロー図に retro フェーズを追加（欠落していた）
- `/issue-bootstrap` SKILL.md の採番スクリプトを修正し、0埋め数値を常に10進数として扱うように変更

### 含まない
- `/plan-issue` のレビューロジック自体への変更（生成フローは変えない）
- 他のスキル（/implement, /test 等）への変更
- コーディング規約ファイル（rules/）の変更

## 受け入れ条件（Acceptance Criteria）
- [ ] `/code-review` の手順にベストプラクティス・セキュリティ・モダン開発観点のチェック項目が追加されている
- [ ] `/plan-issue-review` スキルが新規作成され、計画書・テスト文書を同3観点でレビューする手順が含まれている
- [ ] `/plan-issue-review` でレビュー NG の場合に計画書修正→再実行のフローが明記されている
- [ ] 各観点のチェック項目が具体的で（例：「N+1クエリ」「認証漏れ」「OWASP Top 10」等）、曖昧でない
- [ ] `/plan-issue` の末尾に `/plan-issue-review` への案内が追加されている
- [ ] `CLAUDE.md` のスキル一覧に `/plan-issue-review` が追加されている
- [ ] `docs/runbooks/workflow.md` のフロー・スキル一覧・フェーズ移行テーブルに `/plan-issue-review` が追加されている
- [ ] `docs/runbooks/workflow.md` のワークフロースキルリストに `/retro` が追加されている
- [ ] `docs/runbooks/issue-flow.md` のフロー図・フェーズ2詳細に `/plan-issue-review` ステップが追加されている
- [ ] `docs/runbooks/issue-flow.md` のフロー図に retro フェーズ（test OK → retro/close）が追加されている
- [ ] 既存の手順フローを壊していない（ステップ番号の整合性、STOP条件等）
- [ ] `/issue-bootstrap` の採番スクリプトで `I014` の次が `I015` と正しく算出される（8進数誤解釈が修正されている）
