## 背景/目的

**背景**: I599 で「`scripts/claude/` のスクリプトは既定でサンドボックスの中・外に出すのは起動役（`python3 .claude/hooks/unreviewed.py run`）を通る 16 本だけ」にした。レビューで止めなかった指摘のうち、再現のある High・Medium が 2 件残った。あわせて、外から中へ移ったスクリプトの中で、サンドボックスの中で書けない場所に書くものが見つかった。
**目的**: 下の 3 つを塞ぎ、「外と中の境目を動かしたときに、動いた側のスクリプトを確かめる」手順を決まりにする。

### 現状の問題（証拠・再現手順）
1. F24（High・SECURITY=yes・`.claude/hooks/reviewed-hook.sh`）: フックの起動役は、作業ツリーのフックを `python3 "$root/$rel"` で動かす（`-I` なし）。変更の確かめは差分と未追跡だけで、git が無視するファイルを数えない。そのため `scripts/claude/hooks/` に置いた `json.pyc` のような無視されるファイルが、フック（サンドボックスの外）の `import json` で読み込まれうる。
2. F30（Medium・`scripts/claude/gate-check.sh`）: I599 で、未追跡の文字デバイス（サンドボックスのふさぎの印）を数えないようにした。この判定の `[ -c "$p" ]` はシンボリックリンクをたどるので、`/dev/null` を指す未追跡のリンクも、どの深さでも汚れとして数えない。テスト（`scripts/claude/tests/test_i193_official_flow.sh` の G9b）も、リンクで印を作るので、この見逃しを正しい動きとして固定している（一覧の F31）。
3. 中で書けない場所: `scripts/claude/tests/run-all.sh` はサンドボックスの中で uv がキャッシュ（`~/.cache/uv`）に書けず exit 2 になる（`test_i193_official_flow.sh` の F9 の 3 件が手元で落ちる。CI では起きない）。I599 の前は `bash scripts/claude/*` が外に出る型だったので起きなかった。

### 根本原因
- I599 の影響範囲の洗い出しは「外に出す必要があるか（gh・`claude -p` を使うか）」だけを見ていた。外から中へ移ったスクリプトについて、(a) 中でだけ見える物（ふさぎの印）を読まないか、(b) 中で書けない場所（キャッシュなど）に書かないか、を確かめる手順が無かった（gate-check の汚れの誤検出は test-gate で、run-all の失敗は fix-loop で見つかった）。
- F24 は、フックの起動役の「変更があるか」の判定が、起動役（`.claude/hooks/unreviewed.py`）の「レビュー前の中身」（差分・未追跡・無視されるファイル）と食い違っている。

### 解決方針
- F24: フックの起動役の「変更があるか」を、起動役（`unreviewed.py`）と同じく無視されるファイルまで数え、あわせてフックを起こす `python3` すべてに `-I` を付ける（設計確認メモ）。
- F30: 数えないのは「シンボリックリンクでない文字デバイス」に絞る（`[ -c "$p" ] && [ ! -L "$p" ]`）。G9b は、リンクは汚れとして数える（→ 1）向きに直す。本物の文字デバイスは判定の差し替えで確かめる。
- 中で書けない場所: `run-all.sh` で、`UV_CACHE_DIR` が指定されておらず既定の置き場に書けないときだけ、`$TMPDIR` の下に向ける（設計確認メモ）。
- 予防: `docs/runbooks/plan-writing-rules.md` に、「外に出す型・外で動くスクリプトの一覧を変えるイシューでは、中へ移るスクリプトごとに、中でだけ見える物を読まないか・中で書けない場所に書かないかを、サンドボックスの中で 1 回流して確かめる」手順を足す。
