# I011: Service Worker・PWA コンポーネントを完全撤去

## 背景/目的
- `pwa.service.ts` が `NODE_ENV` に関係なく Service Worker を登録しており、dev 環境でキャッシュした古いバンドルが返ってくる
- HMR が機能せず、ソース変更がブラウザに反映されない問題が発生した
- 調査の結果、SW 実装に以下の根本的な問題が見つかった：
  - `CACHE_NAME = 'learning-app-v1'` が固定のため、更新後も古いキャッシュが残る
  - 静的キャッシュ URL（`/static/js/bundle.js` 等）が CRA 本番ビルドのハッシュ付きファイル名と一致せず、pre-cache が機能しない
  - Cache First 戦略により、一度キャッシュされると再ビルドしても古い JS が返る
- SW はセキュリティ機構ではなく、モダン Web のデフォルトでもない（CRA/Next.js/Vite はいずれも標準では含まない）
- 現時点で PWA / オフライン利用 / プッシュ通知の要件は未確定
- 要件が固まった時点で Workbox 等で正しく実装する方針とし、今は撤去する

## スコープ
### 含む
- `public/sw.js` の削除
- `frontend/src/services/pwa.service.ts` の削除
- `frontend/src/components/PWA/` 配下 4 ファイルの削除（`PWAProvider` / `InstallPrompt` / `OfflineIndicator` / `UpdateNotifier`）
- `frontend/src/App.tsx` から PWA 関連の import・コンポーネント使用箇所を削除

### 含まない
- `public/manifest.json` の変更（PWA マニフェストは残す）
- `public/index.html` の変更
- 将来の Workbox 導入

## 受け入れ条件（Acceptance Criteria）
- [ ] dev 環境（`npm start`）で SW が登録されない
- [ ] ソースファイルを変更してコンテナ再起動後、ブラウザリロードで最新コードが即時反映される
- [ ] アプリが正常に起動し、既存機能（ログイン・問題管理・科目管理等）に影響がない
- [ ] `npm run build` がエラーなく完了する
- [ ] TypeScript エラーなし

## 影響範囲（想定）
- Backend: なし
- Frontend: 削除 5 ファイル + 修正 1 ファイル（`App.tsx`）
- DB: なし
- Config/Infra: なし
