## 背景/目的

**背景**: CI（GitHub の `ubuntu-latest`。入っている道具と版は GitHub が決め、時期で変わる）と手元（WSL。人が入れたもの次第）で、ハーネスのテストが頼る道具を揃える仕組みが無い。どちらを正とするかもどこにも書いていない。I197 では、CI には最初から入っている shellcheck が手元に無く、テストがそれを黙って SKIP して手元では「合格」に見え、CI で初めて落ちた。
**目的**: ハーネスのテストが頼る道具と版を 1 か所の一覧で正とし、CI と手元の両方をそれに従わせる。今の食い違いを揃え（現時点の同期）、CI に道具を足す・変えるときも一覧を書き換えれば手元の確認が自動で追従する（CI 変更時の同期）ようにする。

### 現状の問題（証拠・再現手順）
- 手元に shellcheck が無い WSL で `bash scripts/claude/tests/run-all.sh` を流すと、TC-C1 が SKIP になり全体は合格に見える。CI では shellcheck があるので落ちうる（I197 の CI run で発生）
- python の版（CI は 3.11）・PyYAML・git などの道具の前提も、手元で確かめていない
- CI に新しい道具を足しても、手元に知らせる仕組みが無い

### 根本原因
- テストが頼る道具と版の「正」が無く、CI と手元がそれぞれ別の出どころ（GitHub の環境・人の手）から道具を得ている。テストは「無ければ飛ばす」で食い違いを隠す

### 解決方針
- (a) ハーネスのテストが頼る道具の一覧を 1 か所に書く（置き場所・形は計画で決める。例: `scripts/claude/tests/` の中の一覧ファイル）。版は、pre-commit が持つ道具（shellcheck など）は一覧に書かず「pre-commit 経由（版は `.pre-commit-config.yaml`）」と参照するだけにする（版の決め先を 1 か所に保つ）。それ以外（python の版・PyYAML など）は一覧に版を書く
- (b) 確かめるのは `run-all.sh` の冒頭の 1 か所（CI の Harness Tests も手元も同じ `run-all.sh` を流すので、同じ確認が両方で走る）。足りなければその場で不合格にして、どれが足りないか・どう入れるかを出す。CI の `ci.yml` は一覧の道具を入れる役（pre-commit の導入を含む）だけを持つ。個々のテストの「無ければ SKIP して合格」の分岐はやめる
- (c) 版を固定できる道具（shellcheck など）は、CI でも手元でも pre-commit 経由で `.pre-commit-config.yaml` に固定した同じ版を使う
- (d) CI 変更時の同期: CI に道具を足すときは一覧を書き換える形にし、一覧と CI のワークフローが食い違っていないかを確かめるテストを置く（確かめ方は計画で決める）
- 採らないもの: コンテナで手元と CI をまったく同じにする形（devcontainer など）。食い違うのは一部の道具だけで、重さに見合わない
- 一覧に入れる道具の範囲はハーネスのテストだけ（grill-me で確定）。一覧に入る道具: python3（版は「3.11 以上」）・PyYAML・git・shellcheck（pre-commit 経由）・docker compose
- python の版をぴったり揃えるのは別イシュー（grill-me で確定）。本イシューでは下限「3.11 以上」を確かめるだけ

- [ ] ハーネスのテストが頼る道具と版の一覧が 1 か所にある
- [ ] 手元でテストの最初に一覧を確かめ、足りなければ不合格にしてどれが足りないかを出すことを、ハーネステストで固定している（例: shellcheck が無い環境で TC-C1 が黙って合格にならない）
- [ ] 個々のテストに「道具が無ければ SKIP して合格」の分岐が残っていない（shellcheck の TC-C1・docker compose の `test_compose_ports.sh` を含む）

- [ ] 既存のハーネステスト（`bash scripts/claude/tests/run-all.sh`）・CI がすべて pass する

## 制約・引き継ぎ情報
- pre-commit の shellcheck は `~/.cache/pre-commit/` の仮想環境に入る。bin ごと PATH に足すと、そこの python3（PyYAML なし）が先に使われる（I197 で発生）。shellcheck だけを使う形にする
- `.github/workflows/` を変える場合は、PR を出した時点で secrets 付きで動くので、`docs/runbooks/review-rules.md`「GitHub から復旧できない変更のレビュー観点」に沿う
