# I053: Django migration 依存ルールを ultimate_django_coding_standards.md に追記する

## 関連資料
- 起因: I050 振り返り（予防処置 #1）
- GitHub Issue: #108
- Draft PR: #111

## 設計確認メモ（/grill-me）
- Q: `rules/ultimate_django_coding_standards.md` にマイグレーション専用セクションが存在しないが、どこに追記するか → A: Section 4「モデル設計」内に `### マイグレーション` サブセクションを新設する（co-location 原則・Django 業界標準・バイブコーディングでの発見容易性を根拠として案A を採用）

## 背景/目的
- I050 で `problems/0004` が `accounts/0010`（Organization の再作成 migration）への依存を欠落させていたことが判明した
- 根本原因は「FK を追加する migration の依存先ルール」が明文化されていなかったこと
- 具体的には「参照先テーブルを後の migration で DROP→CREATE 再作成している場合、FK 追加 migration はその再作成 migration にも依存しなければならない」というルールが存在しなかった
- このルールを `rules/ultimate_django_coding_standards.md` に追記することで、同様のミスを将来の migration 作成時に防ぐ

## スコープ
### 含む
- `rules/ultimate_django_coding_standards.md` の migration セクションに、FK 追加 migration の依存ルールを追記する
  - 追記内容: 参照先テーブルが後の migration で再作成（DELETE → CREATE）されている場合、FK 追加 migration はその再作成 migration も `dependencies` に含めること

### 含まない
- `problems/0004` の変更（I050 で対応済み）
- `accounts/0021` の条件付き変換ロジックの変更
- migration の squash

## 受け入れ条件（Acceptance Criteria）
