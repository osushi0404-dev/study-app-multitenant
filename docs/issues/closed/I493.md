## 背景/目的

**背景**: ダッシュボードの数字が 0 のままだった不具合（I473）の根本原因の 1 つは、画面の型（`frontend/src/services/types.ts`）と API の応答が別々に書かれ、ずれを機械で見つける仕組みが無かったことだった。I473 では応答の形をシリアライザ（`backend/dashboard/serializers.py` の `OverviewSerializer`）で固定し、画面では手書きの型と手書きの形の確かめ（`frontend/src/services/dashboard.service.ts` の `isDashboardOverview`）で受けた。同じ形を 3 か所に書いている。統計画面（#488）も同じ作りの直しを控えている。
**目的**: API の仕様書（OpenAPI のスキーマ）をシリアライザから作り、画面の型をそこから自動で作る。API の形を変えて型を作り直し忘れたら、CI で止まるようにする。

### 現状の問題（証拠・再現手順）
- `backend/requirements*.txt` に OpenAPI のスキーマを作る道具が無い（2026-11-13 に grep で確認。`drf-spectacular`・`drf-yasg` とも無し）。`frontend/package.json` にも型を作る道具が無い
- 画面の型は手書き（`frontend/src/services/types.ts` に 25・`frontend/src/types/quiz.ts` に 9 の `interface`/`type`）。API を変えても型は変わらず、ずれは実行時まで分からない（I473 の不具合の形）
- I473 のダッシュボードは、型（`types.ts` の `DashboardOverview`）・形の確かめ（`isDashboardOverview`）・シリアライザの 3 か所に同じ形を書いている

### 根本原因
- 画面と API の受け渡しの形に「正」となる 1 つの定義が無く、両側が独立に書かれている。ずれを見つける決定論の確かめも無い
- I473 でシリアライザが形を固定しても、画面の側がそれに追従する仕組みが無い（手で写している）

### 解決方針
- バックエンド: シリアライザから OpenAPI のスキーマを作る道具を入れる（候補は `drf-spectacular`。DRF の公式ドキュメントが案内している）。どの道具・版にするかは計画で決める（公開から 2 週間以上たった版・`pip-audit` で high/critical なし）
- フロントエンド: スキーマから TS の型を作る道具を入れる（候補は `openapi-typescript`）。作った型はリポジトリに入れる
- CI: スキーマと型を作り直し、リポジトリの中身と違えば落とす（作り直し忘れを止める決定論の確かめ・失敗の注入つき）
- 移行の範囲: 今回はダッシュボードの overview（I473 で形を固定済み）だけ置き換える。残りは触る画面のイシューで順に置き換え、別イシュー（#496）で追いかける（grill-me で確定）
- 形の確かめ（`isDashboardOverview` のような実行時の確かめ）を残すか、作った型から作るかは計画で決める
- スキーマを見る画面（Swagger UI など）は出さない（開発環境・本番とも。grill-me で確定）
- 型を作る道具は、画面の本体とは別の置き場で TypeScript 5 で動かす（画面は TypeScript 4.9.5 のまま。grill-me の調べで確定）
