# I024: frontend Docker 開発環境で新規ファイル追加時に webpack キャッシュが失効しない問題の根本対処

## 関連資料
- I019 振り返り（2026-04-03）: 新規ファイル `apiError.ts` 追加後にコンテナ内 TS キャッシュが古く TS2307 エラーが発生した

## 背景/目的
- Docker 開発環境（`docker-compose up frontend`）で新規ファイルを追加した場合、コンテナ内の webpack/TypeScript コンパイルキャッシュ（`node_modules/.cache`）が失効せず、`TS2307: Cannot find module` エラーが発生することがある
- 現状の回避策は手動での `docker-compose exec frontend rm -rf /app/node_modules/.cache` + restart であり、原因がわかりにくく開発体験を損ねる
- コンテナ起動時またはファイル追加検知時にキャッシュを適切に無効化する仕組みを整備する

## スコープ
### 含む
- 根本原因の調査（Windows/WSL ファイルシステム上の inotify/polling と TS キャッシュ失効の関係）
- 恒久対処の実装（例: エントリポイントスクリプトでキャッシュクリア、または webpack 設定で新規ファイル検知を改善）
- `docs/runbooks/common-commands.md` へ暫定回避手順の追記（対処完了まで）

### 含まない
- React → Vite 等、フレームワーク全体の移行
- その他の Docker 設定変更

## 受け入れ条件（Acceptance Criteria）
- [ ] 新規 `.ts` / `.tsx` ファイルをホスト側に追加した後、コンテナを再起動せずに（または自動再起動で）TS2307 エラーが発生しないこと
- [ ] または、コンテナ起動時に自動でキャッシュがクリアされ、手動操作が不要になること
- [ ] `common-commands.md` に暫定回避手順が記載されている

## 影響範囲（想定）
- Backend: なし
- Frontend: `Dockerfile.dev`、`docker-compose.yml`（frontend サービス）、または webpack 設定
- DB: なし
- Config/Infra: Docker 開発環境のみ
