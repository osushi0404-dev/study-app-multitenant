## 背景/目的

**背景**: I463 で、見張り（`scripts/claude/hooks/pretooluse_guard.py`）に「値を取る短いオプションの文字」の表（`_OPTSPEC`）と getopt と同じ読み方（`_getopt`）を入れ、まとめ書きの読み違いを直した。レビューで、表に入っていない値付きのオプションと、表を使わずに手で探している箇所が 3 つ残った（どれも I463 の前からある取りこぼしで、I463 による後退ではない）。
**目的**: 秘密情報の表示・強制 push の取りこぼしになる 3 つの読み残しを、I463 の表の方式のまま直す。「止める対象は増やさない」は、確認・停止にするコマンドの種類（規則）を増やさない意味で、離して書けば今も確認・停止になる形を、くっつけた形でも同じ判定にする（読み違いの修正）のは含む。その結果の誤った確認の増加は、作業記録での判定比較の 1% 以内で見る。

### 現状の問題（証拠・再現手順）
（見張りに Bash の JSON を渡して判定だけを見る形で再現できる）
- F2（Low・SECURITY=yes）: su の表に `-C`／`--session-command` が無い。`su -C 'git push --force origin develop'` が通る（`-c` と同じく中のコマンドを読むべき）。手元の util-linux 2.39 の `su --help` には `-C` が無いが、版によってはある（`pretooluse_guard.py` の `_OPTSPEC["su"]`・`_expand` の su）
- F3（Low・SECURITY=yes）: 秘密のファイルを探す `paths`（`_cmd_external`）が `-` で始まらない語だけなので、`grep -f.env x`・`grep --file=.env x`（パターンを .env から読む）の .env を落とし、確認にならない。離した `grep -f .env x` は確認になる
- F7（Low・SECURITY=yes）: `_cmd_external` の python の `first`（スクリプト名の探し方）が表を使わない。`curl x | python3 --check-hash-based-pycs default` で値の語をスクリプト名と読み、「パイプで流し込むコード」の確認が出ない。I463 の F1 と同じ原因の残り

### 根本原因
- I463 は表を入れたが、`_cmd_external` の 2 か所（秘密のファイルを探す `paths`・python の `first`）は止める側を減らさないために手書きのまま残した（I463 の計画書 9.・/simplify の見送り）。値の付着形（`-f.env`・`--file=.env`）は、位置引数だけでも `-` で始まらない語だけでも拾えない
- 表は手元の `--help` から作ったので、版によって増えるオプション（su の `-C`）が入らない

### 解決方針
未定・grill-me で確認。候補:
- F3: `paths` に、表で読んだファイルを値に取るオプション（grep の `-f`／`--file` など）の値も足す（今の `-` で始まらない語は残し、止める側を減らさない）
- F7: `first` を `_getopt("python", …)` の位置引数にする。I463 で見送った理由（`python3 -c "$X" | …` で新しく確認が出る）の扱いを計画で決める
- F2: su の表に `-C` と `--session-command` を足し、`_expand` の su が両方の値を読む。I463 の TC-13（表と `--help` の突き合わせ）が版の違いで落ちないよう、`--help` に無い文字の扱いを決める
