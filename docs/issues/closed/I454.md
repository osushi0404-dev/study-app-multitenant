## 背景/目的

**背景**: I444 で、見張り（`scripts/claude/hooks/pretooluse_guard.py`）の「環境変数をまとめて表示する形」の判定をホストとコンテナで 1 か所（`_cmd_external`）にまとめ、コンテナ内の書き先（`_ctr_write_targets`）に `-t`・`--target-directory`・`mv` の移動元を足し、許可リスト（`_container_safe`）を「危ない語が当たっても通す形」だけに縮めた。レビューで見張りの Medium の指摘と作りの改善が残り、マージ前の追加の直し（ps・declare の誤検出）で F10 の後退が出た。見張りの Medium は GitHub から復旧できない例外に関わるので、一覧ではなくイシューにする（retro の決まり）。
**目的**: 環境変数の表示を確認に戻し（F10）、普通のホストの操作に余計な確認を出さず、手元のファイルへの書き込みの取りこぼしを粗い判定のまま減らす。

### 現状の問題（証拠・再現手順）
1. **`ps -A e` の後退（F10・最優先・SECURITY=yes）**: I444 のマージ前の直しで、`ps` の BSD 形式の e は「直前の語が - で始まらない、英字だけで e を含む引数」だけを見るようにした。そのため、値を取らないフラグの直後の e（`ps -A e`・`ps -ef e`）が確認にならない（直しの前は確認になっていた）
2. **書き先の取りこぼし（F5）**: コンテナ内の、値をくっつけた `cp -vt/app/x /tmp/y`・`cp -t/app/x /tmp/y`（`_opt_values` が読めない形）が確認にならない
3. **通す形が書き込みの判定ごと飛ばす作り**: `_analyze` は `_container_safe` が True なら `_container_risky`（語と書き込み先）を呼ばない。そのため、通す形の分岐ごとに書き込みの除外（`--fix`・`--basetemp`・`ruff format --check`・psql の `-o`・`sort -o` など）を抱えていて、抱え漏れは素通りする（例: `docker compose exec -T backend pytest --junitxml=/app/r.xml -k x` が通る。I444 の前からそう）
4. **書き先の抽出が 3 つに分かれている**: `_bash_write_targets`（別ワークツリーへの書き込みの停止）・`_record_writes`・`_ctr_write_targets` が別々の見分け方で、I444 の後は差が広がった（例: `_bash_write_targets` は `-t` の完全一致だけで `--target-directory=` を見ない）
- （I444 で直したので外したもの: ホストの `ps -C node`・`ps -u postgres`・`ps -p 1 -o etime`・`declare -x FOO=1` の誤検出〔台帳 F3・F4〕）

### 根本原因
- 1: 値を取るオプションの値を読み飛ばす判定を「直前の語が - で始まる」で近似したため、値を取らないフラグの後ろも値とみなした
- 2: 書き先を「最後の位置引数」と「`_opt_values` で読める `-t`」の 2 つの形でしか見ていない
- 3: 許可リストの役目を「危ない語が当たっても通す形」に変えたのに、作りは「通す形なら書き込みの判定も飛ばす」のまま（語の理由と書き込みの理由を分けていない）
- 4: 書き先の見分け方を共通の関数にしていない

### 解決方針
- 1: `ps` の値を取るオプション（`-C`・`-u`・`-U`・`-o`・`-p`・`-G`・`-g`・`-O`・`-t`・`-q`・`--sort` 等）の直後だけを値として読み飛ばし、それ以外の英字だけで e を含む引数は確認にする。具体の一覧と書き方は計画で決める。粗い判定にとどめる（I179 の教訓）
- 2・4: 書き先を出す共通の関数を 1 つ作り、`_bash_write_targets`・`_record_writes`・`_ctr_write_targets` がそれを使う。`-t` に値をくっつけた形（`-t/x`・`-vt/x`）と `--target-directory=` を読む。`install -d` は書き先にしない（ディレクトリを作るだけ）。別ワークツリーへの書き込みの停止（exit 2）は、`install`・`ln`・`rsync` の書き先・`--target-directory=`・くっつけた `-t`・`mv` の移動元に広がる（設計確認メモのとおり）
- 3: `_container_risky` を「語の理由」と「書き込みの理由」に分け、`_container_safe` は語の理由だけを打ち消す。/tmp/ 以外への書き込みは常に見る（通す形の分岐ごとの書き込みの除外を減らせる）
- 見張りに判定を足すときの決まり（#430 で手順書に入れる: 公式で表せないかを先に書く・事故の実例を書く・意図的な回避の指摘は一覧へ）に従う
