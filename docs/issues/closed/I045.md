## 関連資料
- 提案ドキュメント: docs/proposals/review_perspective_framework.md（P3・P5・P8 の詳細確認項目）
- GitHub Issue: #94

## 背景/目的
I043（停止条件・重大度・高リスク判定）・I044（/security-review 新設）でレビューの「構造」を整備した。
次のステップとして、レビューの「観点の網羅性」を8観点フレームワークに整合させる。

現行の `/plan-issue-review` および `/code-review` には、以下の3観点がゼロカバーである:
- **P3（データ整合性・変更安全性）**: DB制約・トランザクション・マイグレーション安全性
- **P5（運用性・障害対応性）**: 構造化ログ・タイムアウト・フォールバック・Feature Flag
- **P8（コスト・保守負荷）**: インフラコスト・属人化リスク・維持コスト

これらを両スキルに追加し、設計・実装段階でゼロカバー観点の問題を検出できるようにする。

## スコープ
### 含む
- `/plan-issue-review` に P3・P5・P8 の確認項目を追加する
- `/code-review` に P3・P5・P8 の確認項目を追加する
- 重大度定義（Blocker/High/Medium/Low）は既存定義を踏襲する

### 含まない
- P1・P2・P4・P6・P7 の補完（→ I046）
- `/plan-issue`・`/grill-me`・`/implement` の上流スキル更新（→ I047）
- 新スキルの新設

## 受け入れ条件（Acceptance Criteria）
- [ ] `/plan-issue-review` の確認項目に P3・P5・P8 の観点が追加されている
- [ ] `/code-review` の確認項目に P3・P5・P8 の観点が追加されている
- [ ] 各観点の「対象スキル」（設計段階 / 実装段階）が proposals の記載と一致している
- [ ] 既存の Blocker/High/Medium/Low 重大度定義と整合している
- [ ] 追加した確認項目が既存の観点と重複していない（P2・P6・P7との境界が明確）
