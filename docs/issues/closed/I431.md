## 背景/目的

**背景**: I166 でクイズの経路（開始・出題・回答・結果）の組織境界を塞いだ。その敵対的レビューで、クイズとは別の学習記録の API から、他組織の問題文・解説・選択肢が取得できることを実測で確認した。I166 以前からある別の経路で、I166 の差分とは無関係のため、I166 の範囲外として別イシューにした（ユーザー決定 2026-10-25「別イシューで最優先」）。
**目的**: 学習記録の API（`/api/study/` 配下）とダッシュボードの API で、ユーザーの組織の科目・問題だけを扱うようにし、他組織の問題文・正解・解説・科目名が取得できない状態にする。直した経路ごとに、越境を拒否することを回帰テストで固定する（問題・科目を扱う全 API の横断のテストは #446）。

### 現状の問題（証拠・再現手順）
1. **間隔反復のカード作成（実測済み・High）**: `POST /api/study/spaced-repetition/create_card/` は、`backend/studylogs/views.py:446` で問題を `Problem.objects.get(id=problem_id, is_deleted=False)` で取得し、組織を照合しない。返却は `SpacedRepetitionCardSerializer`（`backend/studylogs/serializers.py:111-112` で `ProblemSerializer` を入れ子で使う）。
   - 再現（I166 の延長周で実測・ロールバック付きの実験）: 組織 A の一般ユーザーが組織 B の問題 ID を送ると 201。応答に組織 B の問題文・解説・選択肢（`is_correct` を除く）・作成者 ID が入る。作ったカードはカードの一覧 `GET /api/study/sr-cards/` と復習対象 `GET /api/study/spaced-repetition/due_cards/` からも読み出せる。正解の印は出ないが、解説から正解が分かる。
2. **適応的な問題選択（静的読解・今は別の不具合で隠れている）**: `POST /api/study/adaptive-learning/select_problems/` は、科目を指定しないと全組織の問題を対象にする（`backend/studylogs/adaptive_selection.py:293-316`）。習熟度の計算の `Subject.objects.all()`（同 170 行目）も組織で絞らない。
   - 今は difficulty の型の不具合（`Field 'difficulty' expected a number but got 'easy'`）で 500 になり、問題を返さない（I166 の延長周で実測）。この不具合を直すと、組織 B の問題が返り始める。
3. **同じ型の取得の候補（未特定・計画で全件確認）**: 組織で絞らずに `Problem.objects` / `Subject.objects` を使っている箇所が、ほかにもある。
   - `backend/studylogs/services.py:62`（新しく学ぶカードの候補。`is_active=True` で絞っているが、Problem モデルに `is_active` の欄は無いため、今は動いていない可能性がある）
   - `backend/studylogs/mistake_analysis.py:241`（間違いの分析で `Subject.objects.all()`）
   - `backend/studylogs/tasks.py:202`（非同期処理で `Subject.objects.get(id=subject_id)`）
   - `backend/dashboard/views.py:291,313`（おすすめの問題数を `Problem.objects.filter(subject_id=..., is_active=True)` で数える。`is_active` の欄が無い点も同じ）
   - `backend/studylogs/serializers.py` の `StudyLogSerializer.subject`（学習記録の作成で、科目を主キーで受け付ける。他組織の科目を指定でき、応答の `subject_name` で他組織の科目名が見える可能性）

### 根本原因
境界の判定（ユーザーの組織の科目・問題）が 1 か所に無く、各ビュー・サービスが `Problem.objects` / `Subject.objects` をそのまま使っている。I166 でクイズの経路は `QuizService` に集めたが、学習記録・ダッシュボードの経路は対象外だった。加えて、境界の不備を直すときに「対象のモデルを返す全経路」を機械的に確かめる仕組み（横断のテスト）が無く、設計確認と計画での洗い出しに頼っていた（I166 の /retro の予防処置 3）。

### 解決方針
- 境界の判定の置き場所を決め、学習記録・ダッシュボードの経路もそれを通す。I166 の `QuizService.available_subjects` / `available_problems` を共通の場所へ移して使い回す方向で、置き場所は計画で決める（技術の選択）。
- 対象は、残るすべての経路（`/api/study/` の下の全部と `dashboard` の全ビュー）。画面から呼ばれていない経路も、アドレスを直接打てば呼べるため塞ぐ。何も消さず、止めもしない（grill-me 確定 2026-11-11）。
- 他組織の問題・科目の ID は、存在しない ID と同じ応答で断る（I166 と同じ考え方。404 か 400 かは API の種類ごとに計画で決める）。
- 上の「同じ型の取得の候補」を計画の段階で全件調べ、組織の境界を越えるものはすべて塞ぐ。動いていない（`is_active` の欄が無い等）経路も、境界は塞ぐ。動くように直すことや消すことは、このイシューではしない（I452）。
- 適応的な問題選択の difficulty の型の不具合（500）は、このイシューでは直さない（I452 で直す）。問題を選ぶ部分（候補の取得・科目の取得）を直接テストして、他組織の問題・科目が入らないことを固定する。こうしておけば、I452 で型の不具合を直しても漏れは表に出ない。
- 新しく作るのを防ぐだけでなく、既に作られた他組織の問題のカードや学習記録も、一覧・復習対象などの読み出しから外す（作成を塞いでも、既にあるデータから問題文・解説が読めてしまうため。安全側の選択として Claude が決定・2026-11-11 の 2 回目の grill-me）。データそのものは消さない（消す必要が出たら Danger Ops として計画で承認を取る）。
- 横断の越境テストは #446 で扱う。このイシューでは、直した経路ごとの回帰テスト（他組織の ID と存在しない ID の応答の比較）を書く

- 学習記録 API（`/api/study/` 配下）とダッシュボード API の、他組織の問題・科目の取得・作成・参照の是正

## 受け入れ条件（Acceptance Criteria）
- [ ] 他組織の問題 ID で間隔反復のカードを作ると、存在しない問題 ID と同一の応答（ステータスと本文）で拒否され、カードが作られず、問題文・解説・選択肢が返らない
- [ ] 適応的な問題選択（科目の指定あり・なし）で、他組織の問題・科目が返らない。difficulty の型の不具合は直さない（grill-me 確定）ので、API はエラーのままで他組織の問題も返らないことを確かめる。加えて、問題を選ぶ部分（候補の取得・科目の取得）を直接テストし、自組織の問題・科目だけが対象になることを固定する（I452 で型を直した後も漏れないため）
- [ ] 「同じ型の取得の候補」すべてについて、調査結果と扱い（塞いだ・動いていない経路も境界は塞いだ）が計画書に記録され、越境するものが塞がれている
- [ ] 直した経路（間隔反復のカード作成・適応的な問題選択・「同じ型の取得の候補」のうち塞いだもの）ごとに、他組織の ID と存在しない ID で同一の応答になることを確かめる回帰テストがある
