## 背景/目的

**背景**: I591 で、外の資料（公式ブログ）とハーネスを突き合わせたところ、レビュー役とレビューの決まりを変える PR が、変えた後のレビュー役と決まりで審査される作りになっていることが分かった。I615 の後も、入口・レビュー役の定義を変えたブランチでは人が `!` で新しい版を流すので、変えた後の審査役が自分を審査する点は残っている。
**目的**: 判定の仕組み（レビュー役の定義・レビューの決まり・判定のスクリプト・テスト）を変える PR が、変更前の基準で審査されるか、少なくとも必ず強い審査（高リスク扱い）になる状態にする。

### 現状の問題（証拠・再現手順）
- レビュー役は作業ツリー（＝PR のブランチ）の定義を読む: `scripts/claude/fix-review-lib.sh:69`（`.claude/agents/${agent_name}.md` を確かめて `claude -p --agent` で起動）・`scripts/claude/code-review.sh:1108`・`scripts/claude/plan-issue-review.sh:99`。I615 で入口は BASE の写しで動くが、入口・部品・定義を変えたブランチでは 75 で止まり、人が新しい版を流す（`.claude/hooks/unreviewed.py`）
- 決定論の高リスク判定 `path_risk_trigger()`（`scripts/claude/code-review.sh:309`〜`318`）の集合は「GitHub から復旧できない例外」（`.github/*`・`.pre-commit-config.yaml`・`.secrets.baseline`・見張り・`.claude/settings*.json`）だけで、`.claude/agents/`・`.claude/skills/`・`scripts/claude/`（見張りを除く）・`docs/runbooks/review-rules.md` は入っていない
- LLM の高リスク判定（`.claude/agents/plan-reviewer.md:220`）では拾われることがあるが、決まった扱いではない
- テストを消す・スキップする・弱めて緑にする変更を確かめる観点が、レビュー役の定義に無い（`.claude/agents/code-reviewer.md`・`.claude/agents/adversarial-reviewer.md` に該当の記述なし）
- 最後の守りは人のマージ（ブランチ保護で bot はマージできない）。公開リポジトリなので、この節には穴の種類と場所だけを書き、回避の手順は書かない

### 根本原因
構造の原因: 審査する側（レビュー役の定義・レビューの決まり・判定のスクリプト・テスト）が、審査される PR と同じブランチから読まれ、審査の基準と審査される物が分かれていない。

放置された経緯: `path_risk_trigger()` は I086（決定論の高リスク判定）・I197（GitHub から復旧できない例外に絞った）で入り、集合は「GitHub から戻せないもの」で選ばれた。「判定の仕組みそのものが変わる」ことは、選ぶ考えに入っていなかった。

### 解決方針
設計確認メモの確定値で行う（ユーザーの委任で確定・2026-11-26）:
- (1) 審査する側はいつも BASE の写しで動かす: レビューを流すスクリプトは写しの版、レビュー役の定義（`.claude/agents/*.md`）とレビューの決まり（`docs/runbooks/review-rules.md`）も写しの版を使う。新しい審査役が効くのはマージの後。新しい版の正しさは CI の決定論のテストで確かめる
- (2) 変更前の版で動かせないとき（ブランチのスキルが写しの入口に無い引数を使うなど。判定の条件は計画で決める）だけ、今の 75 → `!` に戻し、その PR は必ず高リスクにする
- (3) 審査の段階のスキル（`.claude/skills/review-gate/`・`.claude/skills/test-gate/`・`.claude/skills/fix-loop/`・`.claude/skills/plan-review/`）を変えた PR は `path_risk_trigger()` で必ず高リスクにする。ほかのスキルは高リスクにしない
- (4) テストを弱める差分（テストファイルの削除・テスト関数や確かめの行の削除・`skip`・`xfail`・`.only`・`.skip`・`todo`・`fixme` の追加）を決定論で拾い、レビュー役の入力と記録に必ず載せる。計画書に理由の無いものはレビュー役が Blocker にする。高リスクにはしない
