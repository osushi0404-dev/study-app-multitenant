## 背景/目的

**背景**: I468 で、敵対的レビューの通算 2 周の上限を使い切った後に develop の取り込みで差分が出たため、ユーザーの承認で 1 周延長した。review-gate の手順どおり `ADV_ROUND_LIMIT=3 bash scripts/claude/adversarial-review.sh I468` を Claude の Bash で起動すると、2 回続けて `ADVERSARIAL_ERROR: DIRTY` で止まった（作業ツリーは実際にはきれい）。ユーザーが入力欄の `!` で同じコマンドを流すと通り、3 周目は OK だった。

**目的**: ユーザーが延長を承認したとき、Claude が手順どおりに延長の周を起動でき、ユーザーに `!` でコマンドを打ってもらう必要が無くなる。

### 現状の問題（証拠・再現手順）
- `.claude/settings.json` の `sandbox.excludedCommands` は `bash scripts/claude/*` の形をサンドボックスの外で動かす。前に環境変数を付けた `ADV_ROUND_LIMIT=3 bash scripts/claude/...` はこの形に当たらず、サンドボックスの中で動く
- サンドボックスの中では、書き込みを止める場所（`.bashrc`・`.gitconfig`・`.idea`・`.claude/hooks` など）に中身の無い装置ファイルが差し込まれる。`adversarial-review.sh` の作業ツリーの確かめ（`git status --porcelain=v1 -z --untracked-files=all`）がそれを未追跡の変更として数え、`ADVERSARIAL_ERROR: DIRTY` で止まる
- 延長の値を受け取る手段は環境変数 `ADV_ROUND_LIMIT` だけ（`scripts/claude/adversarial-review.sh:31`）。Claude の Bash は環境を持ち越さないので、前に付ける以外の渡し方が無い
- 再現: Claude の Bash で `ADV_ROUND_LIMIT=3 bash scripts/claude/adversarial-review.sh I###`（上限を使い切ったイシュー）→ DIRTY。同じコマンドを `!` で流すと通る

### 根本原因
1. **前置きの形が外に出ない**: 延長の渡し方（環境変数の前置き・I197）と、サンドボックスの外に出す形の一覧（`excludedCommands`・I430）が突き合わされていない。延長は上限に達したときだけ使う珍しい道筋で、決定論のテストでも実際の起動でも通っていなかった
2. **確かめがサンドボックスの差し込みを区別しない**: `adversarial-review.sh` の作業ツリーの確かめは、サンドボックスの外で動く前提で作られた（`bash scripts/claude/*` は外に出る）。サンドボックスの中で動いたときに見える装置ファイル（I468 で `ls -la` で確かめた: `.bashrc`・`.gitconfig`・`.idea` が文字デバイス `1, 3`〔/dev/null と同じ〕・所有者 nobody）を、本物の未追跡のファイルと区別しない。DIRTY で報告されたのは `.bash_profile`・`.bashrc`・`.claude/commands`・`.claude/hooks`・`.claude/launch.json`・`.claude/loop.md`・`.claude/output-styles`・`.claude/routines`・`.claude/workflows`・`.claude/worktrees`・`.gitconfig`・`.gitmodules`・`.idea`・`.profile`・`.ripgreprc`・`.vscode`・`.zprofile`・`.zshrc`（どれも Claude Code のサンドボックスが書き込みを止める場所）

### 解決方針
- 未定・grill-me で確認（技術の選択は計画で決める）。候補: (a) スクリプトに延長を受け取る引数（例 `--round-limit 3`）を足し、手順を `bash scripts/claude/adversarial-review.sh --round-limit 3 I###` にする（`excludedCommands` の形のまま外に出る）(b) `excludedCommands` に前置きの形を足す (c) 作業ツリーの確かめで、サンドボックスが差し込む装置ファイル（文字デバイス）を数えない。(b) はサンドボックスの設定（安全装置）の変更になるので採らない方向。(a) は根本原因 1 を、(c) は根本原因 2 を直す。(c) は、確かめを緩める向き（本物の未追跡のファイルを見逃さないか）の検討が要るので、(a) を第一候補にし、(c) を併用するかは計画で決める。(a) のときの、引数と環境変数 `ADV_ROUND_LIMIT` の両方があるときの優先と、環境変数を残すか（後方互換）も計画で決める
- どの案でも、承認の無い延長を防ぐ今の形（ユーザーの承認のときだけ）は変えない
