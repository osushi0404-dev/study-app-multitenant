- 対象: `.claude/skills/close/SKILL.md`（主）。review スクリプト（code-review/plan-issue-review/issue-review）は**案A では保存先を変更しない**

## 設計確認メモ（/grill-me）
- Q1: ライフサイクル方式 → A: **案A**。review スクリプトの保存先（`docs/reviews/` 直下）は**変更しない**。`/close` に「当該 issue の `docs/reviews/I${NUM}_*_review_*.md` を `closed/` へ `git mv` する」処理を追加し、`/close` を回収係にする。採用理由: レビュー投稿フローを壊さず、**I062（同じ review スクリプトの判定/ `find_file` を改修）と同一ファイルを触らず衝突しない**・リスク最小。
  - 定常状態: 直下＝今 open な issue の進行中記録のみ／`closed/`＝クローズ済み issue の監査記録アーカイブ。`IXXX_review.md`（ライフサイクルファイル）は従来どおり `open/`→`closed/`、timestamped 監査記録は `直下`→`closed/`。経路は違うがクローズ後は両方 `closed/` に揃う。
- Q2: 既存52件の遡及整理 → A: **closed 済み issue（I054〜I061）の記録のみ一度きり `git mv` で `closed/` へ**。今 open の I062〜I065 の記録は対象外（各 `/close` 時に回収）。
- Q3: plan→review 相対リンクの扱い → A: **含める**。`/close` が記録を `closed/` へ移動する際、plan 内の `## レビュー結果` リンク `../../reviews/<basename>` を `../../reviews/closed/<basename>` に更新する（`plan-issue-review.sh:73-74` が貼るリンク。移動でリンク切れさせない）。
- スコープ外確認: `open/` に残る古い `IXXX_review.md`（I013 等のライフサイクルファイル移動漏れ）は**別問題**で I065 の対象外（timestamped 監査記録に限定）。

## 背景/目的

### 現状の問題（証拠・再現手順）
レビュースクリプトが生成する timestamped 監査記録が `docs/reviews/` **直下に無制限に蓄積**し、issue クローズ後も整理されない。
- 保存先（スクリプト実装）: `code-review.sh:9` `REVIEW_FILE="docs/reviews/${ISSUE}_code_review_${TIMESTAMP}.md"` / `plan-issue-review.sh:9` 同形式 / `issue-review.sh:14` 同形式。いずれも `docs/reviews/` 直下（`open/`・`closed/` ではない）。
- `/close`（`close/SKILL.md`）が移動するのは `docs/reviews/open/I${NUM}_*.md` のみ。**直下の timestamped 記録は移動対象外**で据え置かれる。
- 結果（実測）: `ls docs/reviews/*.md | wc -l` = **52件**が直下に堆積（例: `I054_code_review_…`、`I055_*` が複数世代）。issue がクローズ済みでも残り続け、ディレクトリが見通し悪化。

### 根本原因
- レビュー監査記録に**ライフサイクル管理が無い**。スクリプトが `open/closed` の外（直下）へ保存し、`/close` もそれらを対象にしないため、「作りっぱなし」になる。`IXXX_review.md`（open→closed 管理あり）と扱いが非対称。

### 解決方針（案A で確定・設計確認メモ参照）
直下蓄積を解消し、`/close` を回収係にして issue 単位でライフサイクル管理する（**review スクリプトは触らない**）:
1. `.claude/skills/close/SKILL.md` に「当該 issue の `docs/reviews/I${NUM}_*_review_*.md` を `closed/` へ `git mv`」を追加。
2. 同 close 手順に「plan 内の `## レビュー結果` リンク `../../reviews/<basename>` → `../../reviews/closed/<basename>` への更新」を追加（Q3・リンク切れ防止）。
3. 遡及整理（一度きり）: **closed 済み issue（I054〜I061）の直下記録のみ `git mv` で `closed/` へ**（Q2）。件数が多いので一括処理＋移動前後の件数一致を確認。
4. open 中の I062〜I065 の記録は据え置き（各 `/close` 時に回収）。
