# I004: 移管用フォルダの資材をリポジトリに配置

## 背景/目的
- **大命題: 学習アプリをデバッグモードでエラーなく起動できる状態にする**
- `移管用/` フォルダに格納された既存プロジェクトの資材（バックエンド・フロントエンド・設定ファイル等）をリポジトリのルートに正しく配置する
- 移管ファイル一覧（`移管用/移管ファイル一覧.md`）に従い、配置すべきファイル・ディレクトリを漏れなく反映する

## スコープ
### 含む
- `移管用/` 配下の以下資材をリポジトリルートへ配置
  - `CLAUDE.md`（既存と差分を確認・統合）
  - `README.md`
  - `docker-compose.yml`
  - `.gitignore`
  - `rules/`
  - `docs/`（既存と差分を確認・統合）
  - `dev_diary/`
  - `answer/`
  - `backend/`（Dockerfile, manage.py, requirements.txt, .env.example, init-db.sql, アプリケーション各ディレクトリ, media/）
  - `frontend/`（Dockerfile, Dockerfile.dev, nginx.conf, package.json, package-lock.json, tsconfig.json, public/, src/）
  - `nginx/`

### 含まない
- `backend/logs/`（Django起動時に自動生成）
- `backend/staticfiles/`（collectstatic で生成）
- `backend/celerybeat-schedule`
- `backend/organization_backup.json`
- `frontend/node_modules/`
- `frontend/build/`
- `backup_*.sql`
- `push_to_github.sh` / `.github_push.sh`
- `test_registration.py`
- `学習アプリ.code-workspace`
- `.claude/`（移管先で再作成済み）
- `get-docker.sh`
- `backend/.env`（`.env.example` からの再設定が必要）

## 受け入れ条件（Acceptance Criteria）
- [ ] **【主目的】学習アプリがデバッグモードでエラーなく起動できる**（`docker-compose up -d` 後、backend・frontend・db・nginx・redis 全コンテナが正常稼働）
  - Claude: コンテナ起動ログ・`docker-compose ps`・Django ログにエラーがないことを確認
  - ユーザー: ブラウザでアプリにアクセスし、画面が正常に表示されることを確認
- [ ] DB データが正常にリストアされ、テーブルが存在する（`\dt` で確認）
- [ ] 移管ファイル一覧（✅）に記載された全ファイル・ディレクトリがリポジトリルートに存在する
- [ ] 移管しない（❌）ファイルがコミットに含まれていない（`backup_migration.sql` も含む）
- [ ] `backend/.env` がリポジトリに含まれていない（`.env.example` のみ）
- [ ] 既存の `docs/`・`CLAUDE.md` と移管資材の差分が確認・統合されている

## 影響範囲（想定）
- Backend: `backend/` 全体を新規追加
- Frontend: `frontend/` 全体を新規追加
- DB: `backup_migration.sql`（移管用フォルダ配置済み）を移管先の PostgreSQL にリストア
- Config/Infra: `docker-compose.yml`, `nginx/`, `.gitignore` を追加
