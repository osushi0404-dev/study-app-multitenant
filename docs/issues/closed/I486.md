## 背景/目的

**背景**: I228 で、敵対的レビューの実験がアプリのテストを流せず空振りする問題（I431・I446・I452・I455 の 4 回連続）に、(1) レビュー役への「`docker compose exec -T backend …` で流す」案内、(2) 出力が「コマンドが見つからない」形だけの実験を「実行した」に数えない判定（`exp_not_executable`）、(3) review-gate §3-1 の「アプリを変えたイシューは起動の前に `docker compose up -d backend`」の手順、を入れた。(3) は Claude が手順書を読んで判断する手続きで、(2) は出力の形を並べる判定なので、どちらも決定論として弱い。
**目的**: 実験の環境（コンテナ）が整っているかと、空振りの見分けを、スクリプトの決定論にする。手順書の判断に頼らず、整っていない周を走らせない（止める側に倒す）。

### 現状の問題（証拠・再現手順）
1. コンテナの確かめが手順書頼み（台帳 F6・F7・F8）: `.claude/skills/review-gate/SKILL.md` §3-1 は「アプリ（`backend/`）を変えたイシューでは `docker compose up -d backend`」と書くだけで、変えたかの判断は Claude、失敗したとき（ワークツリー間のポートの衝突など）の分岐は無い。起こし損ねると、敵対的レビューは起動し、案内どおりの実験も `service "backend" is not running` で全部空振りして 1 周を失う。`--build` が無いので、依存を変えたイシューでは古いイメージのままになりうる
2. 空振りの見分けが形の列挙（台帳 F2）: `scripts/claude/adversarial-review.sh` の `exp_not_executable` は、出力の全行が決まった形（`<コマンド>: command not found` など）のときだけ「実行できなかった」にする。載っていない形（`sh: 1: python: not found`）や、別の行が混ざる出力（`…; echo "exit=$?"`）は「実行した」に数えられる
3. 言い直しの案内の不足（台帳 F1）: noexec の結果を返すとき「言い直す」とだけ伝え、新しい実験の id を使うよう案内していない。同じ id で出し直した案は、扱い済みの id として黙って捨てられる（`scripts/claude/adversarial-review.sh` の `run_perspective()` の「まだ扱っていない実験案だけを実行する」行）

### 根本原因
1. 実験の前提（コンテナが動いている）の確かめを、決定論のスクリプトでなく手順書の手続きに置いた（I228 の計画で範囲を守って手順書にした）
2. 「実行できなかった」を、出力の文字の形という後から付ける判定で見分けている（前提が整っていれば空振りはそもそも起きない）

### 解決方針
- 1: `scripts/claude/adversarial-review.sh` の起動時（レビュー役を呼ぶ前）に、見る範囲の変更ファイル（`$RUN/files.txt`）に `backend/` があれば、backend のコンテナが動いているかを決定論で確かめる。動いていなければ起こすか、起動せずに止める（`ADVERSARIAL_ERROR:` の新しい値）。どちらにするか・`--build` の要否は計画で決める（未定・技術。起こすなら失敗時は止める側）。review-gate §3-1 の手順はスクリプトに置き換えて消す
- 2: 前提を 1 で保証したうえで、空振りの見分けを粗く確実な形にする（例: 出力のどこかに見つからない形の行があれば `noexec`。取りすぎは未検証＝止める側に倒れる）。形を足す列挙を続けない
- 計画で決めること（技術）: 起こすか止めるか・`--build` の要否・起こすときの待ち時間と 1 周 10 分の上限との関係（待ちは締め切りの外で行う）・粗い判定の具体の条件と取りすぎの許容・`backend/` 以外の変更でアプリのテストを流す実験が出たときの扱い
- 3: noexec を返すときに「新しい id（`P<観点>-E<次の番号>`）で出し直す」と案内する
- 決定論のテスト（失敗の注入つき）を `scripts/claude/tests/test_i197_adversarial_process.sh` に足す。docker はテストの中で差し替える（実物を起動しない）
