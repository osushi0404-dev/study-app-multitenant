## 背景/目的

**背景**: 2026-10-23 に djangorestframework 3.18.0 の脆弱性 3 件（CVE-2026-114136・114137・114138）が公開された。CI の `Backend Lint & Security` ジョブは `pip-audit -r requirements.txt` で既知の脆弱性があると失敗し、このジョブは develop/main の必須チェックなので、develop 宛ての PR がすべてマージできなくなっている（I182 の PR #308 で発見。I182 の変更とは無関係）。
**目的**: djangorestframework を修正版 3.18.2 に上げ、`pip-audit` を通して develop 宛ての PR の CI を緑に戻す。アプリの動作（API・認証・テスト）は変えない。

### 現状の問題（証拠・再現手順）
CI run 39856491985（PR #308）の `Backend Lint & Security` → `pip-audit` の出力:
```
Found 3 known vulnerabilities in 1 package
Name                Version ID              Fix Versions
------------------- ------- --------------- ------------
djangorestframework 3.18.0  CVE-2026-114138 3.18.2
djangorestframework 3.18.0  CVE-2026-114136 3.18.2
djangorestframework 3.18.0  CVE-2026-114137 3.18.2
##[error]Process completed with exit code 1.
```
- 固定箇所: `backend/requirements.txt` 2 行目 `djangorestframework==3.18.0`（3 行目 `djangorestframework-simplejwt==5.5.1` が依存する）
- 同じ run のほかの必須チェック（Backend Tests・Frontend Type Check・Frontend Lint & Security・Frontend Tests）と E2E は成功

### 根本原因
- 依存をバージョン固定しているため、公開後の脆弱性は手で上げるまで残る。
- PR ゲートの `pip-audit` が「新しく持ち込んだ脆弱性」ではなく「既存の全脆弱性」で失敗する作りのため、無関係な PR まで止まる（根本の是正は I152）。

### 解決方針
`backend/requirements.txt` の `djangorestframework==3.18.0` を `==3.18.2`（パッチ版・修正版）に変える。`djangorestframework-simplejwt==5.5.1` との互換を確かめ、backend のテスト（pytest）・`pip-audit`・E2E が通ることを確認する。backend のイメージは `requirements.txt` を COPY してインストールする（`backend/Dockerfile` 18〜19 行目）ので、手元はイメージの作り直しが要る。
