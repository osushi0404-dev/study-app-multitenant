## 背景/目的

**背景**: 2026-11-13 に、確かめ用の利用者（2 科目・複数の曜日に解答）で `/dashboard` を開いて確かめた。曜日ごとの学習時間・科目の絞り込み・直近 7 日より前の除外・1 問 300 秒の上限・苦手とおすすめは、すべて期待どおりに出た。一方で、次の 3 つが分かった。
**目的**: 「曜日ごとと週全体の学習状況」が、科目を選んでも選ばなくても誤解なく読める画面にする。あわせて、毎回変わる確かめ用のデータと、その期待値を出す手順を用意する（決め打ちの値を出していても気づける）。

### 現状の問題（証拠・再現手順）
確認方法: 開発の環境で `verify_i487@example.com` でログインし `/dashboard` を開く（2026-11-13・Playwright MCP。画面キャプチャは app-1 のワークツリーの `.evidence/I487/scenario-*-1440.png`・git に入れない）
1. **科目を選ぶと、目標の残りが科目だけの分で出る**: 今日の全科目の合計は 10 分（目標 30 分）なのに、「確かめ数学」を選ぶと「今日の目標達成まであと25分です」「目標: 30分 (16%)」になる（正しくは、あと 20 分・33%）。`frontend/src/components/dashboard/StartQuizCard.tsx`（目標の 1 行）と `frontend/src/components/dashboard/DashboardStatCards.tsx`（進み具合のバー）が、選んだ科目の応答の `today.study_seconds` を使っている
2. **推移のグラフが曲線**: `frontend/src/components/dashboard/DashboardCharts.tsx` の折れ線（`tension: 0.4`）。月曜 0 分・火曜 6 分のような日ごとの値の間が、なめらかに続いて見える
3. **曜日ごとの解答数・正答率と、週全体の合計が出ていない**: 応答の `last_7_days` には日ごとの `answered_count`・`correct_count` があるのに、画面は学習時間だけを出す。数字のカードは「今日」と「全期間」で、直近 7 日の合計は無い

### 根本原因
- 1: 目標（1 日全体）と、科目で絞った数字（選んだ科目の分）を、同じ応答の同じ値で出している。I487 で目標を設定に従わせたとき、科目の選択との関係を決めていなかった
- 2・3: I473・I487 は「数字が正しく出る」「状態ごとに誤解なく出る」を範囲にしていて、週の見せ方（グラフの種類・合計）は決めていなかった

### 解決方針
- 1: 目標の計算に使う「今日の全科目の学習時間」を、科目を選んでいても取る。科目を選んでいる間も「すべて」の overview を React Query で読む（同じキーのキャッシュを使い回すので、多くの場合は通信が増えない・API は変えない）。目標の行に「全科目」と添える。「すべて」の取得が失敗・読み込み中のときは、目標の行と進み具合を出さない（仮の値で埋めない・I487 と同じ）
- 2: 推移を棒グラフ（Chart.js の `Bar`）にする。縦軸は 0 から・整数の目盛り（I487 と同じ）。今の `DashboardCharts.tsx` の chart.js の登録の中で行い、統計画面と共通の部品は作らない（共通化は #516）
- 3: 棒の tooltip に「学習時間・解答数・正答率」。グラフの見出しの下に「直近 7 日の合計: ◯分・◯問・正答率◯%」。どちらも `last_7_days` から画面で計算する（裏側は変えない）。学習時間は 60 分以上も「◯分」で出す（ダッシュボードの中の単位をそろえる）。答えが 0 件の日・期間は正答率を「—」。データ無し（`has_data` が偽）のときは今どおり「まだ記録がありません」で、合計の行も出さない
- 確かめ用のデータ: 管理コマンドを足す（グラフ・合計・目標の直しを、いつでも実際のデータで確かめるために要るので、同じイシューに入れる）。専用の組織（slug `verify-i487-org`）・利用者（`verify_i487@example.com`）・科目（slug `verify-i487-math`・`verify-i487-english`。数は計画で決める）・問題を「無ければ作る」。解答は今日（`timezone.localdate`）を基準に、次のように作る:
  - 毎回乱数で決める: どの日にどの科目を何問解くか・正解か・解いた時間
  - 毎回必ず入れる境目: 直近 7 日より前の日の解答（範囲の外）・300 秒を超える解答（300 秒で数える）・直近 7 日の中で解答の無い日・今日の解答
  - 乱数の種を出力する。`--seed <数>` で同じデータを作り直せる（おかしな表示を見つけたときに同じ場面で調べ直す）
  - 作り直し（既定）: この利用者のクイズのセッションと解答だけを消してから作る（ほかの利用者のデータには触らない）。今あるデータ（2026-11-13 に手で作ったもの）も同じ slug・メールなので、このコマンドがそのまま引き継ぐ
  - 画面からクイズを解けるよう、科目ごとに問題を複数（数は計画で決める）作る
- 期待値の出力: 作った解答の一覧から、ダッシュボードの集計（`dashboard/selectors.py`）を**使わずに**数える。全科目と科目ごとに、今日の学習時間（分）と解答数・直近 7 日の日ごとの学習時間（分）と解答数と正解数・直近 7 日の合計（分・問・正答率）・全期間の解答数と正答率・連続日数を、画面の表記（分の切り捨て・正答率の整数 % の四捨五入・答えが無ければ「—」）で出す
- `DEBUG` が偽なら何も作らずに止まる。パスワードは引数（環境変数から渡す・`seed_e2e` と同じ形）。Playwright MCP からログインできるよう、秘密の名前（`--secrets`）で入力できる値にする（渡し方は計画で決める。値は会話にもファイルにも書かない）
- 確かめの手順（`docs/runbooks/frontend-verify.md` に「確かめ用のデータ」の節を足す）:
  1. 管理コマンドで、過去の分を乱数で作り直す（期待値と種が出る）
  2. 確かめ用の利用者でログインし、ダッシュボードの「すべて」と科目ごとの値を期待値と見比べる
  3. Playwright MCP で、画面からクイズを何問か解く（今日の分を足す）
  4. ダッシュボードに戻り、今日の学習時間・解答数と直近 7 日の合計が、解いた分だけ増えたかを見る（解いた時間は画面の操作の時間なので、分は解いた問題の時間の合計の範囲で増える）
