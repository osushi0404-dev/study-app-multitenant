# I069: レビュー記録（timestamped review）の commit ライフサイクル根治 — 未追跡のまま close で git mv 失敗

- **Q: どの案を採用するか（案A/A'/B）** → **A: 案A ＋ 案A' ＋ 案B（保険）を併用。**
  - `plan-issue-review.sh` / `code-review.sh` = **案A**: review ファイル**1点のみ**を path-scoped で `git add`→`git commit`（他の index・作業ツリーに触れない）。**auto-push しない**（後続フロー/close が push）。

- **スコープ修正**: issue-review 記録の回収を **close（案B）に集約**するため、当初案の `.claude/skills/plan-issue/SKILL.md`（plan-issue で回収）は**実装対象から除外**。
- **テスト方針**: 案A は一時 git fixture（使い捨て repo）でスクリプトが review ファイルを commit することを検証。close 案B は未追跡 I### 記録を回収し scoped ゲートを壊さないことを検証。TDD（新規の振る舞い＝スクリプトの commit 副作用）を適用。

## 背景/目的

### 現状の問題（証拠・再現手順）
`/close` の step 1 が timestamped レビュー記録を `git mv` で `closed/` へ回収する際、その記録ファイルが**未追跡（untracked）**だと `fatal: not under version control` で失敗する。

再現（I067 close 実行時に実際に発生）:
```
$ git mv docs/reviews/I067_code_review_20260618_1906.md docs/reviews/closed/
fatal: not under version control, source=docs/reviews/I067_code_review_20260618_1906.md, ...
```
- `docs/reviews/I067_{plan,code}_review_*.md` が未追跡のままだった（issue_review も同様になり得る）。
- 暫定対処として close 実行中に手動で `git add`→`git mv` し回収して完走させた。

### 根本原因
- `scripts/claude/plan-issue-review.sh` / `code-review.sh` は timestamped 記録ファイルを**書く（`> file`）が commit しない**。
- 従来は `/close` の **旧 broad `git add`** が偶然これら未追跡ファイルを拾って commit していたため、close 時点では追跡済みで `git mv` が成立していた（＝broad add の副次効果に暗黙依存）。
- I067 で `/close` を **scoped `git add -u`＋決定論ゲート**（未追跡を構造的に除外＝正しい挙動）へ変更した結果、broad add の副次効果が消え、**潜在していた「レビュー記録が未追跡のまま」という問題が顕在化**した。
- 一般化: **生成物（レビュー記録）の commit 責任が誰にも明示的に割り当てられておらず、broad add という曖昧な経路に依存していた**。

### 解決方針
**案A（理想・推奨）= 生産者がコミットする**: レビュー記録を生成するスクリプト自身が、書いた直後にその1ファイルを commit する（artifact は生産者がコミットする原則。決定論的で broad add 依存を断つ）。
- ただし **issue-review は実行タイミングが特殊**: `/issue-bootstrap` 中に走り、その時点のブランチが **develop の場合がある**。develop へ直接 commit するのは禁止のため、issue-review 記録に案A をそのまま適用できない。
  - 対応案A': issue-review 記録は commit せず未追跡のまま残し、当該イシューの `/plan-issue` 初コミット（feature ブランチ）で issue ファイルと共に拾う。または close 側で I### スコープの未追跡 review を明示 add（案B）でフォロー。
  - plan-issue-review / code-review は **feature ブランチ上で走る**ため案A をそのまま適用可。
**案B（フォールバック）= close が拾う**: `/close` が I### スコープの未追跡 timestamped review を明示 `git add` してから `git mv` する（close/SKILL.md）。scoped staging/ゲートの方針は維持しつつ、未追跡 review だけは明示対象に含める。

**採用確定（/grill-me 2026-06-19）**: 「plan-issue-review・code-review＝案A（review ファイル1点を path-scoped commit・auto-push なし）、issue-review＝案A'（commit せず・develop 直 commit 回避）、close＝案B（未追跡 I### レビュー記録の単一回収点）」。issue-review 記録の回収は close に集約するため plan-issue 側の変更は不要。設計確認メモ参照。
