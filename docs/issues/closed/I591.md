## 背景/目的

**背景**: 2026-11-20 の会話で、ユーザーから「グラフエンジニアリング（Claude の設計手法）」について聞かれ、調べた。作業を「点（ノード＝ひとまとまりの作業。サブエージェント・スクリプト・人の承認）」と「線（エッジ＝順番と結果の受け渡し）」の図として設計し、関係ない作業は同時に流す・検証役を分ける・機械的な処理はスクリプトに任せる・NG のときの戻り先を決める、という考え方。ユーザーから「うちのハーネスに取り入れられるところがあるか検討・調査する」イシューの起票を頼まれた。起票の後、ユーザーから確かめてほしい資料（上の「関連資料」・検証の考え方やサブエージェントの使いどころを含む）を渡された。
**目的**: 今のハーネス（イシュー → 計画 → 計画レビュー → 実装 → review-gate → test-gate → retro → close）を、この考え方と渡された資料で見直し、取り入れる価値があるところ・無いところを根拠つきで一覧にする。取り入れる案は別イシューとして起票する（このイシューでは仕組みを変えない）。

### 現状の問題（証拠・再現手順）
- 不具合ではなく、改善の余地の調査。
- 今の段階はほぼ一本道で順に進む（`docs/runbooks/workflow.md`）。同時に流しているのは、敵対的レビューの 3 観点（`scripts/claude/adversarial-review.sh:7`・`.claude/skills/review-gate/SKILL.md:50`）と、組み込みの /code-review と /security-review（`scripts/claude/code-review.sh:1177`〜`1226`）。
- 検証役の分離（plan-reviewer・code-reviewer・adversarial-reviewer・fix-diagnosis-reviewer・issue-reviewer）、決定論の判定（`scripts/claude/gate-check.sh` など）、NG のときの戻り先（fix-loop → review-gate）はすでにある。どこまでがすでに満たしていて、どこに差があるかは整理されていない。
- `.claude/workflows/` は空で、Workflow ツール（`parallel()`・`pipeline()`）は使っていない。
- 予備の検討（このイシューのコメント・2026-11-20）で、判定の仕組みを判定される変更が書き換えられる穴（A）が見つかった（上の設計確認メモ）。

### 根本原因
未特定・調査で確認（不具合ではないため、「なぜ今の形なのか」を各段階の経緯（過去のイシュー・retro）から確かめる）。

### 解決方針
1. 外部の解説と渡された資料から考え方の要点（同時に流す・検証役の分離・検証のやり方・決定論の処理・戻り先・状態の受け渡し・モデルの使い分け・サブエージェントに分けるか戻すか）を抜き出し、Claude Code の公式ドキュメント（サブエージェント・Workflow）で仕様を確かめる
2. 今のハーネスの段階・レビュー役・スクリプトを点と線の図に書き出す（図は記録ファイルに Mermaid などで残す）
3. 要点ごとに「すでに満たしている／差がある／取り入れない」を、根拠（`ファイル:行`・過去のイシュー）つきで表にする
4. 差があるものは、効果（待ち時間・見落とし・費用）と危険（費用の増加・同時に動くことでの書き込みの衝突・サンドボックスや見張りとの相性・決まりが増えること）を比べて採否を決める。設計確認メモで決まったもの（A・終了報告・回数の上限・B）はその答えに従う
5. 採るものは別イシューとして起票し、このイシューには番号を書く。少なくとも次を起票する: A（ハーネスの次の最優先・I547 より先）／終了報告に「今回の確かめで見ていないこと」を足す／B（レビュー役を試す問題集を毎回のレビューで流す）
