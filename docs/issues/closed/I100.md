## 背景/目的

### 現状の問題（証拠・再現手順）
`docs/tests/templates/auto_test_template.md` の先頭は「実行コマンド（例）:」に続く fenced ` ```bash ` ブロックになっている。スクリプト系イシューがこのブロックに**テスト実行コマンド**（例: `bash scripts/claude/tests/test_xxx.sh`）を書くと、`/code-review`（`code-review.sh`）の `omission_lint()` が **HIGH** を返す。

- `omission_lint()`（`code-review.sh` l.153-166）は「`## 決定論ゲート（自動実走）` セクションの**外側**の fenced ` ```bash `/` ```sh ` ブロック内に allowlist ゲートパターンがある」と HIGH を出す設計。
- allowlist パターン: `bash scripts/claude/tests/*.sh`・`grep -[qL]`・`python3 -m json.tool`・`bash -n `・`python3 -m py_compile`。
- テンプレ既定の先頭ブロックは heavy 例（`docker compose exec ...`）なので単体では発火しないが、**利用者が自然にそこへテスト実行コマンド（allowlist パターン）を書く**と、決定論ゲートセクションにも同じコマンドを正しく宣言していても、**先頭ブロックが「ゲート宣言漏れ」として HIGH を誤発火**する。I098 では実際に発生し、`d22822d` でインライン化して解消した（毎回の `/code-review` で `omission-lint: HIGH` が注入される永続ノイズになるため）。

### 根本原因
**テンプレートの構造が lint（omission-lint）の制約と非整合**。テンプレの先頭「実行コマンド（例）:」ブロックは「そこにテスト実行コマンドを書く」ことを自然に誘導するが、omission-lint は「決定論ゲートセクション外の fenced bash に allowlist コマンドがあると宣言漏れ＝HIGH」とみなす。両者が食い違うため、**テンプレ通りに書くと lint 違反になる**。抽象化: 「lint/ゲートの制約とテンプレートの構造が非整合で、テンプレの既定に沿って書くと lint 違反を誘発する」という一般問題（omission-lint 対象の他テンプレでも再発しうる）。

### 解決方針
`auto_test_template.md` の先頭「実行コマンド（例）:」節に**ガイド（HTML コメント）を追加**し、allowlist ゲートコマンドは必ず「## 決定論ゲート（自動実走）」セクションに書くよう明示する。先頭ブロックは heavy 実行例（`docker`/`npm` 等・非 allowlist）のみに留めるか、インラインコード（fenced でない backtick）で書く旨を案内する。

- **do**: `auto_test_template.md` の先頭ブロック直前/直後に HTML コメントを追加:
  「allowlist ゲートコマンド（`bash scripts/…/tests/*.sh`・`grep -[qL]`・`python3 -m json.tool`・`bash -n`・`python3 -m py_compile`）はこの先頭 fenced ブロックに書かない（`code-review.sh` の omission-lint が『決定論ゲート宣言漏れ』として HIGH を誤発火する）。決定論ゲートとして実走させたいコマンドは必ず『## 決定論ゲート（自動実走）』セクションに書く。ここは `docker`/`npm` 等の heavy 実行例のみ、または省略。」
