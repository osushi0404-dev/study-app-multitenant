## 背景/目的

**背景**: 破壊的なマイグレーション（列の削除など）の前に、開発の DB の控えを取る決まりがある（計画書の Danger Ops の手順）。I587（2026-11-19）と I590（2026-11-20）で、計画どおり `bash scripts/db_backup.sh` を流すと、2 回とも止まった。どちらも、Claude が手で `docker compose exec -T db pg_dump …` を流す回り道でしのいだ。I587 の retro で #538 に同梱したが手つかずのまま、翌日に同じ所で再発した。
**目的**: Claude が危険操作の前に、手順書どおりの 1 つのコマンドで、確かな控え（空でない・途中で切れていない）を取れるようにする。失敗したときは控えのファイルを残さず、はっきり止まる。手順書にその取り方を書き、動かない古い呼び方が計画・手順書に戻らないようにする。

### 現状の問題（証拠・再現手順）
1. Claude（Bash ツール）から `bash scripts/db_backup.sh` を流すと、`open <ワークツリー>/.env: permission denied` で止まる（I590・2026-11-20、I587・2026-11-19 も同じ）
2. 止まっても、空の `backup_<日時>.sql`（0 バイト）が作業フォルダに残る。`scripts/db_backup.sh:11` が `> "$OUTPUT"` で先にファイルを作るため。後で見た人が控えがあると勘違いしうる
3. 回り道（`docker compose exec -T db pg_dump -f /tmp/…` → `docker compose cp`）は手順書に無く、コンテナの中に DB の中身の写しが残る
4. `docs/runbooks/danger-ops.md` は危険操作の承認の決まりを持つが、その前の控えを Claude がどう取るかを書いていない

### 根本原因
- Claude のコマンドは原則サンドボックスの中で動く。外で動くのは `.claude/settings.json` の `sandbox.excludedCommands`（`docker *`・`docker-compose *`・`gh *`・`git *`・`bash scripts/claude/*`）だけ。`scripts/db_backup.sh` は `scripts/claude/` の外なので、中の `docker compose` がサンドボックスの中で動く（外に出すかは Bash ツールに渡した 1 回の呼び出しの頭で決まる。親の `bash scripts/db_backup.sh` が一覧に当たらずサンドボックスの中で動くので、その子の `docker compose` も中で動く。Claude が直接打つ `docker compose exec …` は頭が `docker *` に当たるので外で動き、回り道ができてしまう）
- サンドボックスは秘密を守るため `.env` の読み取りを禁じている（`.claude/settings.json` の `Read(**/.env)` の deny。正しい守り）。`docker compose` は起動時に `.env` を読むので止まる
- `scripts/db_backup.sh` は I005 で人が使う道具として作ったもの（サンドボックスより前）で、Claude から流す前提が無い。手順書にも Claude 向けの控えの取り方が無いため、計画が I587 の手順を写し、計画レビューも止められなかった

### 解決方針
- Claude が流せる控えの入口を `scripts/claude/` に置く（例: `scripts/claude/db-backup.sh <名前>`）。`bash scripts/claude/*` はサンドボックスの外で動くので、中の `docker compose` が `.env` を読める。サンドボックスの設定（`.claude/settings.json`）は変えない
- 入口は、一時のファイルに書き、`pg_dump` の終了コード・大きさ・最後の行（`-- PostgreSQL database dump complete`）を確かめてから正式の名前に移す。どれかが駄目なら一時のファイルを消して非 0 で止まる。出力は作業フォルダの `backup_*.sql`（`.gitignore` 済み）
- `scripts/db_backup.sh`（人が使う）も空のファイルを残さないようにする（入口と処理を共有するか、同じ確かめを入れるかは計画で決める）
- `docs/runbooks/danger-ops.md` に「破壊的な DB の操作の前の控えは入口で取る」節を足す
- 計画書・手順書が Claude の手順として `bash scripts/db_backup.sh` を書いたら止める決定論のテストを足すかは、計画で決める（`docs/runbooks/plan-writing-rules.md`「決定論テストの対象の選び方」に照らす）
- 新しいスクリプトはサンドボックスの外で動くので、外で動いてよい中身か（`docker compose exec -T db pg_dump` と作業フォルダへの書き込みだけ）をレビューで見る（`docs/runbooks/danger-ops.md:31`）
