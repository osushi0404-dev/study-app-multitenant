## 背景/目的

**背景**: I211 で python の版を 3.12.3 に揃え直した差分（`.python-version`・`pyproject.toml`・`uv.lock`。CI の設定を含むブランチなので高リスク）を review-gate に通した。1 回目は組み込みの `/security-review` が動かず（基盤の失敗）、手順どおり `FINAL_VERDICT: HIGH` になった。手順どおり 1 回だけやり直したところ、スクリプトは失敗した回の記録の `REVIEWED_COMMIT` を差分の起点にし、「起点の後に記録の場所の外は変わっていない（範囲のファイル 0 本）」と判断して、レビュー役も `/security-review` も呼ばずに台帳を引き継ぎ、`FINAL_VERDICT: OK` を出した。`gate-check.sh` もこの記録で通った。I211 では Claude が気づいて `/security-review` を直接実行して補った（指摘なし）。
**目的**: レビューが失敗した回（HIGH・BLOCKER・組み込みのレビューが動かなかった回）の後のやり直しで、その回が見るはずだった差分を必ず見直す。セキュリティレビューを一度も通らない変更が test-gate に進む道を無くす。

### 現状の問題（証拠・再現手順）
- `review_mode()`（`scripts/claude/code-review.sh:494-506`）は、台帳のある最新の記録（`LEDGER_ROUND:` がある記録）の `REVIEWED_COMMIT` が HEAD の祖先なら差分のレビューにする。記録の `VERDICT`／`FINAL_VERDICT`／`OFFICIAL_SECURITY` は見ていない
- 1 回目の記録（`OFFICIAL_SECURITY: FAILED`・HIGH）にも `LEDGER_ROUND:` と `REVIEWED_COMMIT:` が書かれるため、やり直しの起点になる
- 再現（I211）: 高リスクのブランチで、組み込みの `/security-review` が動かない回を作る → 記録が commit される → やり直す → 「差分のレビュー（台帳の 3 周目・範囲のファイル 0 本）」「レビュー役は呼ばずに台帳を引き継ぎます」→ `FINAL_VERDICT: OK`

### 根本原因
差分のレビューの起点を「最後にレビューした場所」で選んでいて、「最後に合格した場所」で選んでいない。失敗した回の記録も「見た」ことになり、その回が見るはずだった差分が、やり直しの範囲から外れる。

### 解決方針
- 差分のレビューの起点にするのは、`VERDICT: OK`（台帳の結論が合格）で、高リスクなら組み込みの `/security-review` が動いた（`OFFICIAL_SECURITY: FAILED` が無い）記録だけにする。HIGH・BLOCKER・FAILED の記録は起点にしない（その前の合格した記録から差分を取る。合格した記録が無ければ全体のレビュー）
- 台帳（指摘の番号・状態）の引き継ぎは今までどおり（起点の選び方だけを変える）
- 決定論のテストで固定する（失敗した記録を最新に置いた写しで、差分の範囲が前の合格した記録から取られること。失敗注入: 失敗した記録の後に記録の場所の外の変更が無くても、範囲が 0 本にならない）
- `gate-check.sh` が失敗した回の後の「範囲 0 本・OK」の記録で通らないかも確かめる（必要なら同じ考え方で直す）。詳細は計画で決める

## 受け入れ条件（Acceptance Criteria）
- [ ] 最新の記録が見終えていない回（組み込みの `/security-review` が動かなかった〔`OFFICIAL_SECURITY: FAILED`〕・レビュー役の出力が壊れていた）のとき、やり直しの差分のレビューは、その前の見終えた記録（無ければ全体）を起点にする（2026-11-08・計画の段階のユーザーの判断「ループエンジニアリング、ハーネスエンジニアリングのベストプラクティスと開発をサクサク進めるという観点で問題ないやり方を選択して」を受けて、「HIGH・BLOCKER の回すべて」から狭めた。台帳に止める指摘が残って HIGH になった回は見終えているので起点にしてよい。理由は plan_I212.md §9）
- [ ] その結果、失敗した回の後に記録の場所の外の変更が無くても、失敗した回が見るはずだった差分をレビュー役と（高リスクなら）組み込みの `/security-review` が見る
- [ ] 上の 2 点を、失敗注入つきの決定論のテストで固定している（失敗した記録を起点にする前の形に戻すとテストが落ちる）
- [ ] 失敗が続いた場合（失敗した記録が 2 つ以上続く）も、遡って最後の合格した記録を起点にする（テストで固定）
- [ ] `gate-check.sh` が、失敗した回の後に「範囲 0 本」で出た OK の記録だけでは通さない（失敗した回が見るはずだった差分を見た記録が要る）ことをテストで固定している（計画で `gate-check.sh` を直す必要が無いと分かったら、その理由を計画書に書き、テストだけ足す）
- [ ] 台帳（指摘の番号・状態）は、起点にした記録ではなく最新の台帳のある記録から引き継ぐ（I206 の番号の合流を壊さない。どの記録から引き継ぐかを計画書に明記する）
- [ ] 見終えたかの判定に使う欄（計画で `REVIEW_COMPLETE:` の行を足すと決めた）と、欄が無い古い記録の扱いを計画書に明記する
- 同梱 3・5（敵対的レビューの「確認済み」の引き継ぎ・締め切りで実験が走らない）は、計画で別イシューに切り出すと決めた（retro で起票。plan_I212.md §9）
- [ ] 合格した記録の後のやり直し（今までの差分のレビュー）の動きは変わらない（既存のテストが通る）
- [ ] 既存のハーネステスト（`bash scripts/claude/tests/run-all.sh`）・CI がすべて pass する
