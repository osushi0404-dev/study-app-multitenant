# I054: サブエージェントレビューと差し戻しファースト原則の導入

## 関連資料
- 提案書: docs/proposals/subagent_review_architecture_proposal.md
- GitHub Issue: #112
- Draft PR: #113

## 設計確認メモ（/grill-me）
- Q: I054.md のスコープが提案書最終版と乖離している。計画書作成前に更新するか → A: 計画書作成前にイシューファイルを更新する
- Q: `gh pr review` による GitHub PR コメント投稿を I054 に含めるか → A: 含める。親エージェントが `$(cat [ファイルパス])` 経由で投稿する（`--body` への内容直書き禁止）
- Q: サブエージェントのモデルを指定するか → A: `claude-sonnet-4-6`（品質優先）

## 背景/目的
- 同一コンテキストでのレビューは確証バイアスを生む。設計議論に参加した Claude が「自分が合意した設計」をレビューすると、問題を見つける動機よりも検証する動機が強くなる
- レビュアーが曖昧な記述を文脈で補完して通過させており、実装フェーズで解釈がぶれてバグを生む
- コンテキスト分離（サブエージェント）と差し戻しファースト原則を組み合わせることで、批判的・否定的視点でのレビューと明確な仕様に基づく実装を実現する

## スコープ
### 含む
- `/plan-issue-review/SKILL.md`: read-only サブエージェント起動（Agent ツール）・親エージェントによる verbatim ファイル保存・`cat` 経由での GitHub PR コメント投稿・フロントマター変更（`disable-model-invocation: false`、`allowed-tools` に `Agent, Edit, Bash` を追加）
- `/code-review/SKILL.md`: 同上
- `.claude/review-agents/plan-reviewer.md`: 新規作成（計画書レビュー指示ファイル。XML デリミタ・IDOR/DEFAULT_PERMISSION_CLASSES チェック・3段階重大度等）
- `.claude/review-agents/code-reviewer.md`: 新規作成（コードレビュー指示ファイル。同上 + `@transaction.atomic`・AI 生成コード固有チェック・pip-audit 確認）
- `docs/reviews/`: 新規ディレクトリ作成（レビュー結果独立ファイルの保存先）
- `/grill-me/SKILL.md`: 抽象的な回答が返ってきた場合に具体値を引き出す「具体化追求ルール」の追加
- `/plan-issue/SKILL.md`: 承認ポイント提示前の文書品質ゲート（API・権限・エラー・DB・テスト期待値の具体性チェック）の追加
- `retro/SKILL.md`: 指示ファイルのメンテナンス確認項目追加
- `docs/tests/templates/auto_test_template.md`: 具体性ガイドのコメント追加
- `docs/tests/templates/manual_test_template.md`: 具体性ガイドのコメント追加

### 含まない
- `/test/SKILL.md` の変更: テストケース具体性は plan-issue-review の差し戻しファーストで担保するため不要
- `/security-review` スキルへのサブエージェント導入: 別途検討
- CI/CD 自動トリガー（PR 作成時の自動レビュー実行）: 別イシューで対応
- 既存テストケース文書・計画書の遡及修正

## 受け入れ条件（Acceptance Criteria）
- [ ] `/plan-issue-review` 実行時にサブエージェントが起動され、コンテキストゼロ・read-only（Edit なし）の状態でレビューが行われる
- [ ] サブエージェントは構造化テキストのみを親エージェントへ返却する（ファイルへの直接書き込みなし）
- [ ] 親エージェントがサブエージェントの出力を verbatim で `docs/reviews/I{番号}_{type}_{YYYYMMDD_HHMM}.md` に保存する
- [ ] 親エージェントが `$(cat [ファイルパス])` 経由で `gh pr review` を実行し GitHub PR にレビュー結果を投稿する（`--body` への内容直書き禁止）
- [ ] サブエージェントは「曖昧な記述を発見した場合は差し戻す（推測しない）」差し戻しファースト原則に従って動作する
- [ ] 差し戻し時は 3 段階重大度（Blocker/Warning/Info）のテーブル形式で出力される（差し戻しトリガーは Blocker のみ）※ plan-reviewer のみ。code-reviewer は既存 code-review の慣行に合わせ Blocker/High/Medium/Low の 4 段階を維持（意図的設計）
- [ ] `/code-review` 実行時にも同様のサブエージェントが起動される
- [ ] `.claude/review-agents/plan-reviewer.md` が作成され、XML デリミタによるプロンプトインジェクション対策・IDOR チェック・DEFAULT_PERMISSION_CLASSES チェック等が含まれる
- [ ] `.claude/review-agents/code-reviewer.md` が作成され、上記に加えて `@transaction.atomic`・AI 生成コード固有チェック・pip-audit 確認が含まれる
- [ ] サブエージェントのモデルは `claude-sonnet-4-6` を使用する
- [ ] `/grill-me` で抽象的な回答を受け取った場合、具体値が出るまで追加質問が行われる
- [ ] `/plan-issue` の承認ポイント提示前に、計画書・テスト文書の具体性ゲートが自動実行される
- [ ] `retro/SKILL.md` に指示ファイルのメンテナンス確認項目が追加されている
- [ ] テストテンプレートに具体性ガイドのコメントが追加されている
- [ ] 各スキルの Claude Code ベストプラクティス（allowed-tools 最小権限・argument-hint 等）が維持されている

## 影響範囲（想定）

- Frontend: なし
- DB: なし
- Config/Infra: なし（`.claude/skills/` 配下のスキルファイルのみ）
