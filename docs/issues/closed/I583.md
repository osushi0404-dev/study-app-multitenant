## 背景/目的

**背景**: I569 で、イシューの番号を 3 桁以上受け付けるようにし、そのテストを足した。テストは「まだ無い番号」の例として `I1000` を本物のリポジトリのまま使い、`gate-check.sh`・`adversarial-review.sh`・`check-manual-test-executor.sh` が「記録が無いので別の理由で止まる」ことに頼っている。GitHub の番号は約 1 か月で #1000 に届く見込みで、#1000 のブランチでは記録が本当にできる
**目的**: テストが本物のリポジトリの「まだ無いはず」の状態に頼らず、どの番号のイシューのブランチで流しても同じ結果になる。番号の確かめを通ったことを、期待する止まり方まで確かめる

### 現状の問題（証拠・再現手順）
- `scripts/claude/tests/test_i569_issue_number_digits.sh` の TC-03（`adversarial-review.sh I1000`）は、イシューファイルと計画書が無いので `ADVERSARIAL_ERROR: FILES` で止まる前提。I1000 のブランチで `docs/issues/open/I1000.md` と `docs/plans/open/plan_I1000.md` ができると、FILES で止まらず、CI や手元の `run-all.sh` から本物の敵対的レビュー（別プロセスの `claude -p`）を起動しうる。TC-03 も落ちる
- TC-02（`gate-check.sh I1000`）・TC-05（`check-manual-test-executor.sh I1000`）も本物の I1000 の記録を読みに行く
- TC-02・TC-05 の「I1000 は番号の確かめを通る」は、出力に「使い方」が無いことしか見ていない。確かめに着く前に別の理由（読み込みの失敗など）で終わっても合格になる
- 再現: まだ起きていない（#1000 が無いため）。推測: I1000 のブランチで run-all.sh を流すと TC-03 が本物のレビューを起動する

### 根本原因
テストが、本物のリポジトリにまだ無いデータ（番号の記録）に頼って「ほかの理由で止まる」ことを使っていた。時間がたつと現れるデータを「無い」前提にする書き方を、計画レビュー・実装のどちらの段階でも確かめていなかった（I569 のコードレビューで初めて指摘された）

### 解決方針
- 番号の確かめを通るかを見るテスト（TC-02・TC-03・TC-05）は、本物のリポジトリではなく一時の git リポジトリ（対象のスクリプトと読み込むライブラリだけを写したもの）で流す。スクリプトは `git rev-parse --show-toplevel` に移るので、一時のリポジトリの中で起動すれば本物の記録を読まない。具体の組み方（写すファイル・`GATE_CHECK_LIB` などの差し替えの使い方）は計画で決める
- 「通る」の確かめを、期待する止まり方（例: `GATE_CHECK: FAIL REASON=missing`・`ADVERSARIAL_ERROR: FILES`・手動テスト文書が無いときの文言）まで見る形にする
- 失敗の注入: 一時のリポジトリに I1000 の記録を置いたときにも本物のレビュー役を起動しない（`claude` を起動する前に止まる、または起動の道具を差し替える）ことを確かめる。方式は未定・計画で決める
