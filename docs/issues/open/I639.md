## 背景/目的

**背景**: 流れの入口と出口に、文章の決まりでは防げない穴が 2 つある。
1. **入口**: `/grill-me`・`/plan-issue` はイシューの本文だけを読む（`scripts/claude/issue-source.sh` の `body`・`snapshot`）。新しいイシューへの同梱・訂正は `gh issue comment` で行うので、コメントの中身が計画の入力に入らない。2 回起きた: I546 で I545 から引き継いだ 1 項目がコメントにだけあった／I591 が I593 の本文の誤った見立てをコメントで訂正したが、I593 の計画に入らないおそれがあった（手で /grill-me I593 から始めて避けた）
2. **出口**: 計画書で「別イシュー」「後続」と決めた項目を、起票しないまま close まで進んだ（I466: 表の削除を別イシューにすると決めたが起票せず、マージ前の見直しで気づいて #492 に同梱）。retro は台帳の残りを振り分けるが、計画で自分で決めた「後でやる」は対象外

**目的**: コメントを流れの入力に入れ、計画の「別イシュー」に番号が付いているかを決定論で確かめる。

### 現状の問題（証拠・再現手順）
- 入口: `grep -n comments scripts/claude/issue-source.sh` が 0 件（2026-11-27 時点）。コメントが付いたイシュー（例: #547 に 10 件）で `bash scripts/claude/issue-source.sh body I547` を流すと、コメントの中身が出ない
- 出口: retro のスキル（`.claude/skills/retro/SKILL.md`）に計画書の「別イシュー」の行を確かめる手順・スクリプトが無い。記録: `docs/reviews/closed/I466_review.md` の「## 振り返り」・`docs/reviews/closed/I591_review.md` の「## 振り返り」

### 根本原因
- 入口: 同梱・訂正の置き場所（コメント）と、流れが読む場所（本文）が違う
- 出口: 計画で決めた「後でやる」に番号が付いているかを確かめる工程が無い

### 解決方針
1. 入口: `scripts/claude/issue-source.sh` の `body`・`snapshot` が、イシューのコメント（日時と本文）を本文の後ろに付けて出す。手元のイシューファイル（I427 未満）は今までどおり。文章の決まりより決定論の直しを優先する（I591 の retro の案）
2. 出口: 計画書の「別イシュー」「後続」を含み `#番号` を含まない行を拾うスクリプトを `scripts/claude/` に足し、retro の手順から呼ぶ。0 件でなければ起票か同梱をしてから進む。拾い方（語・節の範囲）と誤検出の扱いは計画で決める
3. 外で動く入口を足す・変えるときは `.claude/hooks/unreviewed.py` の `OUTSIDE_SCRIPTS` と `docs/runbooks/plan-writing-rules.md`「外と中の境目を動かす計画」に従う
