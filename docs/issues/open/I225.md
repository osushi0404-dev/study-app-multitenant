  - 手順書・スキル・エージェント・スクリプト・open のテスト文書に `--json` なしの `gh auth status` が書かれたら落ちる静的な検査を `scripts/claude/tests/test_i223_gh_app.sh` に足す（closed の記録は対象外）。※計画で対象を手順書・スキル・エージェント・ハーネスのスクリプト・テンプレートに絞った（open のテスト文書を含む個々のイシューの記録は外す。理由は plan_I225.md §9）

## 背景/目的

**背景**: I223 で、Claude が GitHub を操作する名義を GitHub App にし、テスト用のセッション（`claude -p`・tmux の中の `claude`）には読み取りだけの鍵（`GH_APP_READONLY=1`）を渡すようにした。I223 の test-gate で、手順書どおり `gh auth status` を流したところ、App の新しい形式の長い鍵（書き込みのできる 1 時間の鍵）の大部分が画面と会話の記録に出た（`gh` は鍵の最後の部分しか伏せない）。その鍵はすぐに失効させ、手順書の確かめ方は `gh auth status --json …`（要る欄だけを取り出す）に直した。ただし、レビューで次の残りが指摘された（止める条件には当たらず、I223 では直していない）。
**目的**: 鍵が画面に出る書き方を決定論で締め出し、出てしまったときの手順を正しくし、テスト用のセッションが読み取りだけの鍵を迂回する抜け道を塞ぐ。

### 現状の問題（証拠・再現手順）
- **F15（SECURITY=yes）**: `--json` なしの `gh auth status` が鍵の大部分を出す問題を、手順書の決まりだけで防いでいる。見張り（`scripts/claude/hooks/pretooluse_guard.py`）が確認にしているのは `gh auth status -t`・`gh auth token` だけ（`scripts/claude/tests/test_pretooluse_container_guard.sh` の S23・S35）。手順書・スキルに書き戻されると再発しうる
- **F13（Medium・再現あり・SECURITY=yes）**: `docs/runbooks/github-app-setup.md`「5.」の「鍵が出たときの失効手順」`gh api -X DELETE installation/token` は、そのとき入口（`scripts/claude/gh-app/gh`）が渡す鍵を失効させるので、漏れた鍵と同じとは限らない（テスト用のセッションで漏れた読み取りだけの鍵・期限間際に取り直された鍵）。消す控えも `~/.cache/github-app/token` だけで `token-readonly` が抜けている。再現: 読み取りだけの鍵が画面に出た後、通常のシェルで手順を流すと、書き込みの鍵が失効し、漏れた鍵は有効なまま残る
- **F14（Medium・再現あり）**: `docs/runbooks/harness-audit.md` の「手元に残る古い鍵」の行の点検コマンドが、表の中の `\|` のせいでそのままコピーすると jq の構文エラーになる。`GH_APP_READONLY` があると `GH_APP_DISABLE=1` が無視され、保存されたログインを見られない。`.tokenSource` が抜けていて、環境変数の鍵と保存されたログインを区別できない
- **F7（SECURITY=yes）**: `scripts/claude/` の `claude -p` の起動に `--strict-mcp-config` が無い。ワークツリーのセッションは元のリポジトリの `.mcp.json`（develop のまま GitHub の MCP がある）を読む（I223 の M-06 ② で観測）。手元に PAT が残っていると、MCP 経由の書き込みが読み取りだけの鍵を迂回しうる
- **F9（SECURITY=yes）**: `scripts/claude/tui-capture.sh` で、tmux サーバーが先に立っていて、その `PATH` に `~/.local/bin` が無いと、中の `claude` の `gh` が入口を通らない（入口を通らなければ App の鍵自体は渡らないが、本物の `gh` に保存されたログインが有効なら、そちらで書き込める）

### 根本原因
鍵・秘密を扱う手順の確かめ方を決めるときに、そのコマンドが秘密を画面に出すかを確かめる段取りが無く、見張りも一部の書き方しか確認にしていない。テスト用のセッションの守り（読み取りだけの鍵）は `gh` の入口を通ることを前提にしていて、入口を通らない経路（MCP・本物の `gh`・別の `PATH`）を数えていない。

### 解決方針
- F15（確定）: 入口 `scripts/claude/gh-app/gh` で、`--json`・`-t`/`--show-token` なしの `gh auth status` を、鍵の欄を出さない `--json` の表示に置き換える（断らない・置き換えたことを標準エラーに 1 行）。あわせて、手順書・スキル・エージェント・ハーネスのスクリプト・テンプレートに `--json` なし（または `-t`/`--show-token` 付き）の `gh auth status` が書かれたら落ちる静的な検査を `scripts/claude/tests/test_i223_gh_app.sh` に足す。見張り `pretooluse_guard.py` は変えない
- F13（確定）: 失効の手順を、漏れた鍵そのものを `GH_TOKEN` に入れて `DELETE /installation/token` する形にし、`token`・`token-readonly` の両方の控えを消す手順にする
- F14（確定）: 点検コマンドを表の外のコードブロックに出し、`GH_APP_READONLY` を外して流す形・`.tokenSource` を足した形にする
- F7（確定）: `scripts/claude/` の `claude -p` の起動に `--strict-mcp-config`（MCP が要る判定では `--mcp-config` で必要なものだけ）を足す。既存のテスト（`test_check_permission_prompt.sh` Q18 など）は維持する
- F9（確定）: `tui-capture.sh` の tmux 起動に `-e PATH=…` を足し、入口の `gh` を必ず通す
- 予防策（確定）: 新しい決まりは足さず、F15 の入口の置き換えと静的な検査（決定論のチェック）で代える
