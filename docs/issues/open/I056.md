# I056: ワークフロー改善 - ツール導入時の事前実行義務化とコードレビュー基準精密化

## 関連資料
- I055 振り返り（予防処置 P1・P2）: docs/plans/closed/plan_I055.md（予定）
- GitHub Issue: #116

## 背景/目的

I055（pre-commit 静的チェック・npm audit・pip-audit CI 追加）の振り返りで以下の2つの予防処置が特定された。

**P1: lint/audit/scan 系ツール導入時の副作用ファイルが計画外変更になる問題**
- I055 では pip-audit 導入後に Pillow CVE が、ESLint `--max-warnings 0` 導入後に Login.tsx・QuizManagement.tsx が計画外変更となった
- 根本原因: 計画書作成前の事前調査ルールに「既存コードを検査するツールを実際に実行する」義務がなかった
- `plan-writing-rules.md` の事前計測セクションが lint ツールのみを想定しており、audit/scan 系が抜けていた

**P2: コードレビューでテスト結果欄が空白であることが Medium 指摘される問題**
- フローの順序は `/implement → /code-review → /test` であり、/code-review 時点でテスト結果欄が空白なのは正常状態
- しかしコードレビュー subagent がフロー順序を知らず、空白を「テスト未実施」と判断して Medium 指摘した
- 根本原因: code-reviewer.md に「CI pass かつテスト結果空白 = /test 実施前の正常状態」という条件付き基準がなかった

## スコープ
### 含む
- `docs/runbooks/plan-writing-rules.md`: 事前調査セクションを拡張し「lint/audit/scan 系ツール導入イシューでは計画前にツールを実際に実行して副作用ファイルを列挙する」という**ツール非依存の原則**を追加
- `.claude/review-agents/code-reviewer.md`: 「CI 全ジョブ pass かつテスト結果欄空白 → /test 実施前の正常状態として Low 以下で扱う。CI 未 pass またはテスト結果空白かつ CI 状況不明 → 従来通り Medium 以上」という条件付き基準を追加

### 含まない
- 特定ツール名（pip-audit・npm audit・mypy 等）の列挙（原則として書くことで将来のツール追加にも自動適用）
- フロー順序の変更（/implement → /code-review → /test の順は維持）

## 受け入れ条件（Acceptance Criteria）
- [ ] `plan-writing-rules.md` の事前調査セクションに「lint/audit/scan 系ツールを導入するイシューでは、そのツールを計画書作成前に実際に実行し、検出された問題・修正必要ファイルを計画書に列挙する」という原則が追加されている
- [ ] `code-reviewer.md` に「CI 全ジョブ pass かつテスト結果欄が空白の場合は /test 実施前の正常状態として Low 以下で扱う」という条件付き基準が追加されている
- [ ] 既存のレビュー観点・事前調査ルールが壊れていないこと（既存文書との整合性）
