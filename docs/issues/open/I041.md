# I041: 計画書の実装手順に垂直スライス・依存関係ルールを追加する

## 関連資料
- 参考記事: https://x.com/L_go_mrk/status/2040032952818729206（PRD to Issues スキルの解説）
- GitHub Issue: #85
- Draft PR: #87

## 設計確認メモ（/grill-me）
- Q: 例示の技術スタックはプロジェクト固有か汎用的か？ → A: 汎用的（DB/API/UI）でよい
- Q: 各プロジェクトで正確に適用できるようにするにはどうするか？ → A: 汎用原則の直後に「プロジェクトの技術スタックに合わせて読み替える」旨の注記1行を添える（例: Django+DRF+React の場合は DB/API/UI = model/viewset/React component）

## 背景/目的
現在の計画書「実装手順（ステップ）」はフリーフォーマットに近く、
タスクの切り方・順序付けの原則が明示されていない。

記事の「PRD to Issues」の設計原則を `plan-writing-rules.md` に取り込むことで、
計画書の実装手順を体系的に構造化し、未知リスクの早期発見と並行作業の明示を促す。

## スコープ
### 含む
- `docs/runbooks/plan-writing-rules.md` の「実装手順」セクションへの以下の原則追記
  - 垂直スライス原則: 特定レイヤーだけ横に広げず、全レイヤーを薄く縦に貫通する単位でステップを切る
  - 未知リスク先行原則: 実現可能性が不確かなもの（新外部サービス連携等）を最初のステップに置く
  - 依存関係の明示: 「ステップ3はステップ1完了が前提」等のブロッキング関係を明記する

### 含まない
- スキルファイルの変更
- 既存計画書の遡及修正

## 受け入れ条件（Acceptance Criteria）
- [ ] `plan-writing-rules.md` の実装手順セクションに3原則が追記されている
- [ ] 各原則に具体例が記載されており、適用判断ができる
- [ ] `/plan-issue` スキル実行時に Claude が自然にこの原則に従った手順を生成できる
