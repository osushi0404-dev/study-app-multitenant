# I052: webpack proxy を設定してローカル Docker E2E テストを可能にする

## 関連資料
- 起因: I049 振り返り（予防処置 #2）
- GitHub Issue: #106

## 背景/目的
- I049 で導入した Playwright E2E テストはローカル Docker 環境で実行できない
- 原因: React アプリが `REACT_APP_API_BASE_URL || 'http://localhost:8000'` をデフォルト URL として
  使用しており、Playwright コンテナ内の Chromium からは `localhost:8000` に到達できない
  （`localhost` がコンテナ自身のループバックに解決されるため）
- CI（GitHub Actions ホスト上で Playwright を直接実行）では問題なく動作するが、
  開発者がローカルで E2E を実行できない状態は開発体験・デバッグ効率を損なう
- webpack `devServer.proxy` を設定し、フロントエンドがバックエンドへのリクエストを
  相対パス（`/api/...`）でプロキシできるようにすることで解決する

## スコープ
### 含む
- `frontend/` の webpack 開発サーバーに proxy 設定を追加
  （例: `/api` → `http://backend:8000`）
- `docker-compose.yml` の `e2e` サービス環境変数を
  `BASE_URL=http://frontend:3000` のみに簡略化（API URL をハードコードしない）
- ローカル E2E 実行手順の更新（`common-commands.md`）
- 既存の CI E2E（`e2e.yml`）がこの変更で引き続き動作することの確認

### 含まない
- E2E テストケースそのものの変更
- 本番 Nginx のプロキシ設定変更

## 受け入れ条件（Acceptance Criteria）
- [ ] `docker compose --profile e2e run --rm e2e` でローカル Docker E2E テストが全件 pass する
- [ ] CI E2E テストが引き続き pass する
- [ ] React アプリからバックエンドへのリクエストが `/api/` 相対パス経由で動作する
  （`http://localhost:8000` への絶対 URL 依存を除去）

## 影響範囲（想定）
- Backend: なし
- Frontend: webpack 設定（`devServer.proxy`）の追加
- DB: なし
- Config/Infra: `docker-compose.yml`（e2e サービス環境変数の整理）

## Danger Ops（有/無）
- 無
