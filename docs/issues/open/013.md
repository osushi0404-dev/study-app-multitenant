# I013: GitHub Actions CI パイプライン導入

## 関連資料
- 設計検討会話（2026-03-27）: 実装レビューフロー改善の議論
  - /implement 細分化・コードレビュースキル新設の前提インフラとして位置づけ
  - 参照: feature/I012 ブランチ上でのやり取り

## 背景/目的

**背景**: 品質ゲートが Claude Code の自己チェックのみに依存しており、実装者が自分のコードを自分でレビューする客観性の低さ・実行漏れの検知不能・Policy as Code の不在という問題があった（2026-03-27 の実装レビューフロー改善議論から）。
**目的**: GitHub Actions を導入して PR 作成時に機械的・客観的な品質ゲートを設け、将来の /implement 細分化（/code-review スキル新設）の基盤を整える。

現在 CI/CD が未整備（.github/ ディレクトリなし）。
品質ゲートが Claude Code の自己チェックのみに依存しており以下の問題がある：

- 実装者（Claude）が自分のコードを自分でレビューするため客観性が低い
- lint / 型チェック / テストの実行漏れがあっても検知できない
- 「Policy as Code」が存在せず品質保証がプロセス依存になっている

GitHub Actions を導入し、PR 作成時に機械的・客観的な品質ゲートを設ける。
これにより将来の /implement 細分化（/code-review スキル新設）の基盤を整える。

## スコープ
### 含む
- `.github/workflows/ci.yml` 作成
- バックエンド: flake8（lint）+ mypy（型チェック）+ pytest（自動テスト）
- フロントエンド: eslint（lint）+ tsc（型チェック）+ jest（自動テスト）
- セキュリティスキャン: bandit（Python）+ eslint-plugin-security（JS/TS）
- PR 作成 / push をトリガーに自動実行
- Claude Code から `gh pr checks` で結果確認できること

### 含まない
- CD（デプロイ自動化）
- E2E テスト（Playwright 等）
- /implement スキルの分割（別イシューで対応予定）
- /code-review スキルの新設（別イシューで対応予定）

## 受け入れ条件（Acceptance Criteria）
- [ ] PR を作成すると GitHub Actions が自動起動する
- [ ] バックエンド lint / 型チェック / pytest が CI 上で通過する
- [ ] フロントエンド lint / 型チェック / jest が CI 上で通過する
- [ ] セキュリティスキャン（bandit / eslint-plugin-security）が実行される
- [ ] `gh pr checks <PR番号>` で Claude Code から結果を確認できる
- [ ] 既存のテストが CI 上で全て通過する

## 影響範囲（想定）
- Backend: CI 設定のみ（プロダクションコード変更なし）
- Frontend: CI 設定のみ（プロダクションコード変更なし）
- DB: なし
- Config/Infra: `.github/workflows/ci.yml` 追加、依存パッケージ確認
