# I043: レビュースキルに停止条件・重大度区分・高リスク判定を追加する

## 関連資料
- 提案資料: docs/proposals/review_design_proposal.md
- GitHub Issue: #90

## 背景/目的

現行のレビュースキル（`/plan-issue-review`・`/code-review`・`/test`）には以下の構造的な欠如がある。

- **停止条件が未定義**: 「何があったら次工程へ進めないか」がスキルに書かれておらず、Claude の判断任せになっている。同じ問題でも OK/NG の判断がぶれる。
- **指摘の重大度区分がない**: 「NG」の一語では修正必須なのか推奨なのかが不明瞭。
- **高リスク判定の出力がない**: `/plan-issue-review` がセキュリティ観点を含むが、「この変更が高リスクかどうか」を判定・出力する仕組みがなく、後続の深掘りレビューへの接続ができていない。
- **`/grill-me` の観点が設計曖昧点に限定されている**: 「実装する価値があるか」「既存方針との衝突」を確認する観点がない。

これらを整備することで、レビューの判断基準を明確化し、フローの安定性を高める。

## スコープ
### 含む
- `/plan-issue-review` に停止条件・重大度区分・高リスク判定を追加
- `/code-review` に停止条件・重大度区分を追加
- `/test` に停止条件を明示（現行実装の整理・明文化）
- `/grill-me` に「実装する価値があるか」「既存方針との衝突」の確認観点を追加

### 含まない
- `/security-review` スキルの新設（別イシューで対応）
- 既存スキル以外のファイル変更

## 受け入れ条件（Acceptance Criteria）

- [ ] `/plan-issue-review` の出力に重大度区分（Blocker/High/Medium/Low）の列が含まれる
- [ ] `/plan-issue-review` に「Blocker が残っている場合は STOP し `/implement` を案内しない」ことが明記されている
- [ ] `/plan-issue-review` の出力に「高リスク判定: Yes/No・該当条件・推奨アクション」が含まれる
- [ ] 高リスク条件（認証・認可変更、マルチテナント境界、ファイルアップロード等）が `/plan-issue-review` に定義されている
- [ ] `/code-review` の出力に重大度区分の列が含まれる
- [ ] `/code-review` に「Blocker が残っている場合は STOP し `/test` を案内しない」ことが明記されている
- [ ] `/test` に「自動テスト失敗時・手動テスト NG 時は次工程を案内しない」ことが明記されている（現行ロジックの明文化）
- [ ] `/grill-me` の質問観点に「実装する価値があるか」「既存方針との衝突」が追加されている
