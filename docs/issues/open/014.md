# I014: /implement 細分化・/code-review スキル新設

## 関連資料
- I013 イシューファイル（docs/issues/open/013.md）: CI 導入時に「別イシューで対応予定」として明記
- I013 振り返り（2026-03-27）: 実装完了後に CI → コードレビュー → 自動テスト の順で進む希望フローを確認

## 背景/目的
現在の `/implement` スキルは「実装 → 自動テスト → push → CI 確認 → 手動テスト」を一括実行する。
これにより、コードレビュー（要件面の確認）が自動テスト実行より後になっておらず、
CI を活用した以下の希望フローが実現できていない：

```
/implement（実装のみ）→ push → GitHub Actions CI → /code-review → /test（自動テスト）
```

このイシューで `/implement` を細分化し `/code-review` スキルを新設することで、
「CI が通ってからコードレビュー、コードレビュー OK なら自動テスト」という品質ゲートフローを実現する。

## スコープ
### 含む
- `/implement` スキルを「実装 + push」のみに絞り込む（自動テスト実行を切り出す）
- `/code-review I###` スキルを新設する（要件面・受け入れ条件のコードレビュー）
- `/test I###` スキル（または既存スキルへの統合）で自動テストを実行する
- `workflow.md` のフロー定義を新フローに更新する

### 含まない
- CD（デプロイ自動化）
- E2E テスト導入
- `/plan-issue` `/fix-loop` `/close` 等の他スキルの変更

## 受け入れ条件（Acceptance Criteria）
- [ ] `/implement I###` を実行すると実装と push のみ行い、自動テストは実行しない
- [ ] `/code-review I###` を実行すると要件面のレビュー（受け入れ条件との照合）を実施する
- [ ] `/code-review` の後に自動テストを実行するスキル・手順が存在する
- [ ] `workflow.md` のフローが `implement → CI → code-review → test → fix-loop or close` に更新されている
- [ ] 既存の `/fix-loop` `/close` スキルが新フローと整合している

## 影響範囲（想定）
- Backend: なし
- Frontend: なし
- DB: なし
- Config/Infra: `.claude/skills/implement/SKILL.md` 変更、`.claude/skills/code-review/SKILL.md` 新規作成、`docs/runbooks/workflow.md` 更新
