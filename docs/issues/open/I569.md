## 背景/目的

**背景**: I221 からイシューの番号は GitHub の番号（#427 → I427）になり、桁数に上限が無い。一方、流れを動かすスクリプトの多くは番号を 3 桁（`I` の後に数字ちょうど 3 つ）だけ受け付ける。GitHub の番号は 2026-11-17 に #563 まで来ていて、11-08 の #427 から 9 日で約 136 番増えた（1 日に約 15 番）。この速さなら約 1 か月で #1000 に届く（推測）
**目的**: I1000 以上のイシューでも、流れ（plan-issue → … → close）と見張り・開始時の文脈が今と同じに動く

### 現状の問題（証拠・再現手順）
番号を 3 桁だけ受け付ける場所（2026-11-17 に grep で確認・2026-11-18 の grill-me で grep し直して同じ 8 か所）:
- `scripts/claude/flow-stage.sh:11`（`^I[0-9]{3}$`）: 次の段階を返せず exit 2 → `/proceed` が止まる
- `scripts/claude/gate-check.sh:17`: test-gate・close の関所が止まる
- `scripts/claude/adversarial-review.sh:490`: 敵対的レビューが動かない
- `scripts/claude/check-frontend-evidence.sh:15`・`scripts/claude/check-manual-test-executor.sh:18`: test-gate・plan-issue の確かめが止まる
- `.claude/skills/close/SKILL.md:47`（`^[0-9]{3}$`）: close が止まる
- `scripts/claude/hooks/pretooluse_guard.py:2780`（`\.evidence/I[0-9]{3}/`）: 画面の確かめの書き先（`.evidence/I1000/`）を見張りが許可の対象と認めない（推測: 承認画面が出る）
- `scripts/claude/hooks/sessionstart_context.py:28`（`\b(I[0-9]{3})\b`）: I1000 の PR の題から番号を取れない（`\b` があるので I100 とも読まない。開始時の文脈の 1 行が欠けるだけ・推測）
- 手順書: `docs/runbooks/workflow.md`「ブランチ戦略」・`.claude/skills/plan-issue/SKILL.md` のブランチ名の「イシュー番号3桁」（I546 で手順書側は「I＋GitHub の番号」に直す）
- すでに 3 桁以上を受け付ける場所（直さない・形をそろえる手本）: `scripts/claude/issue-source.sh:27`（`^I[0-9]{3,}$`）・`scripts/claude/check-memo-body-paths.sh:30`・`scripts/claude/code-review.sh:1039`（`^I[0-9]+$`）

再現（2026-11-18 に実行して確認済み）: `bash scripts/claude/flow-stage.sh I1000` が「⛔ 使い方: scripts/claude/flow-stage.sh I###（受け取った値: 'I1000'）」で exit 2 になる

### 根本原因
I221 で番号の振り方を GitHub の番号に変えたとき、番号を受け付ける判定の消費箇所（スクリプト・フック・スキル）を全件そろえなかった（`issue-source.sh` など一部だけ `{3,}` にした）。

### 解決方針
- 番号を受け付ける判定を `^I[0-9]{3,}$`（close の SKILL は `^[0-9]{3,}$`）にそろえる。見張りとフックの正規表現も同じに（見張りの変更はユーザー了承済み・設計確認メモ。桁数だけを広げ、保存先の範囲・ファイル名の制限は変えない）
- 判定の正を 1 か所（例: 共通の小さな関数・定数）に寄せるか、全件を直してテストで固定するかは計画で Claude が決める（ユーザーの方針: 再発を断つ根治を優先。漏れた構造上の原因は、判定が各スクリプトに散らばっていること。再発を断つなら 1 か所に寄せるか、AC 3 の grep を CI の決定論ゲートにする）
- 実装対象の表は 2026-11-18 の grep し直しで確定（追加なし）。計画では実装の直前に同じ grep をもう一度流して差分が無いことを確かめる
- テスト: 各スクリプトに I1000 を渡して通ること・`I12`・`I1a` などは今までどおり断ることを確かめる（失敗の注入つき）
