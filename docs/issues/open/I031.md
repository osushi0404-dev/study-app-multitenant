# I031: issue-flow.md の採番ロジックを issue-bootstrap スキルの実装に統一

## 関連資料
- docs/proposals/I026_ai_dev_improvement_proposal.md（改善案 C）
- GitHub Issue: #69
- Draft PR: #70

## 背景/目的
- `docs/runbooks/issue-flow.md` に記載されている採番ロジックが `issue-bootstrap` スキルの実装と乖離している
- docs 記載: 「ローカル最大番号 + GitHub issue 件数 + 1」
- スキル実装: 「FS最大値 と git履歴最大値の大きい方 + 1」
- 乖離が続くと、Claude が docs を参照して採番した場合にスキルと異なる番号を算出し、番号衝突・欠番が生じるリスクがある
- また I039 のクローズ時に `docs/tests/open/` にテストファイルが残留しており、`close` スキルのコメントが auto/manual 両ファイルを処理していることを明示していないため改善が必要

## スコープ
### 含む
- `docs/runbooks/issue-flow.md` の採番ロジック説明をスキル実装に合わせて修正（3箇所）
- 旧ロジック（ローカル最大 + GitHub件数 + 1）の記述を削除
- `docs/tests/open/I039_auto_test.md`・`I039_manual_test.md` を `docs/tests/closed/` へ移動（残留ファイルの後片付け）
- `.claude/skills/close/SKILL.md` の `# テストケース` コメントを auto/manual 両ファイルを移動する旨に改善

### 含まない
- `issue-bootstrap` スキル本体の変更
- `close` スキルのロジック変更（コメント改善のみ）

## 受け入れ条件（Acceptance Criteria）
- [ ] `issue-flow.md` の採番ロジックが `issue-bootstrap` スキルの実装（FS最大値・git履歴最大値の大きい方 + 1）と一致している
- [ ] GitHub issue 件数を参照する旧ロジックの記述が削除されている
- [ ] `docs/tests/open/` に I039 のテストファイルが残っていない
- [ ] `close/SKILL.md` の `# テストケース` コメントが auto/manual 両ファイルを移動することを明示している

## 影響範囲（想定）
- Backend: なし
- Frontend: なし
- DB: なし
- Config/Infra: `docs/runbooks/issue-flow.md`・`.claude/skills/close/SKILL.md`・`docs/tests/open/`
