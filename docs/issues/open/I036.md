# I036: workflow.md の /retro 必須化

## 関連資料
- docs/proposals/I026_ai_dev_improvement_proposal.md（改善案 E）
- GitHub Issue: #80
- Draft PR: #83

## 背景/目的

**背景**: workflow.md で /retro が「任意」扱いのため省略され得る状態で、振り返り不実施による問題蓄積・同じ失敗の繰り返しリスクがあった（I026 改善提案 E）。
**目的**: /retro をテスト OK 後の必須セレモニーに変更し、継続的改善サイクルを確立する。

- `docs/runbooks/workflow.md` で `/retro` が「任意」扱いのため、テスト OK 後に省略されるケースがある可能性がある
- 振り返りを実施しないと問題が蓄積し、同じ失敗が繰り返されるリスクがある
- アジャイル・モダン開発のベストプラクティス（Scrum レトロスペクティブ、Google SRE ポストモーテム文化等）では振り返りは必須セレモニーとして位置づけられている
- 「必須（テスト OK 後は必ず実施）」に変更して継続的改善サイクルを確立する

## スコープ
### 含む
- `docs/runbooks/workflow.md` の `/retro` の扱いを「任意」→「必須（テスト OK 後は必ず実施）」に変更
- CLAUDE.md のスキル説明の `/retro` 箇所も同様に更新（必要な場合）

### 含まない
- `/retro` スキル本体の変更

## 受け入れ条件（Acceptance Criteria）

- [ ] フロー step 7 とスキル呼び出し表の両方で必須である旨が明確になっている
