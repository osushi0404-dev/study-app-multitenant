# I050: migration チェーンの型不整合を修正し CI フレッシュ DB で migrate を通す

## 関連資料
- 発見元: I049 E2E CI 調査（PR #103）
- 詳細調査: code-review I049 にて確認
- GitHub Issue: #104

## 設計確認メモ（調査結果）

### 不整合の全体像

| migration | 操作 | 問題 |
|-----------|------|------|
| `accounts/0009` | Organization を **UUID** pk で作成 | 初期定義 |
| `accounts/0012` | `organizations.id` → `organization_id` にリネーム + `organizations_id_seq` をリネーム | UUID に sequence は存在しないため、sequence rename は CI（フレッシュ DB）で失敗する可能性がある |
| `problems/0004` | Subject.organization FK 追加（参照先 pk が UUID のため `problems_subject.organization_id` = **UUID**） | FK 型は参照先 pk に追従 |
| `accounts/0021` | `problems_subject.organization_id`（UUID）→ `organizations(id)` の FK 制約を再追加 | integer と UUID の型不一致 → `ProgrammingError` |

### 現行モデル定義（正解）
- `accounts/models.py`: `Organization.id = models.AutoField(primary_key=True)` → **integer**
- `problems/models.py`: `Subject.organization` → FK to Organization → `problems_subject.organization_id` は **integer** が正しい

### ローカルで動く理由
既存の `postgres_data` named volume に migration が適用済み（手動操作含む）で整合した状態が既に作られている。CI は毎回フレッシュ DB のため不整合が顕在化する。

## 背景/目的
- I049（E2E CI 基盤）で CI がフレッシュ DB に対して `python manage.py migrate` を実行したところ migration チェーンの型不整合が判明した
- 現行の migration チェーンはローカルの永続 DB 上では動作するが、CI（毎回フレッシュ DB）では `accounts/0021` の FK 制約再追加で `ProgrammingError` が発生し migrate が完了しない
- この問題が解消されない限り I049 の E2E CI（および将来の CI フレッシュ実行全般）がブロックされる

## スコープ
### 含む
- migration チェーンを修正し、フレッシュ DB で `python manage.py migrate` が完走すること
- migration 修正後に既存ローカル DB（既に migrate 完了済み）でも `migrate` が冪等に動作すること（追加 migration は "already applied" として skip される）

### 含まない
- モデル定義の変更（`Organization.id` は `AutoField` のまま）
- データの移行（CI はフレッシュ DB のみ対象）
- migration の squash（今回は最小限の修正のみ）

## 受け入れ条件（Acceptance Criteria）
- [ ] フレッシュ DB（`postgres_data` volume を持たない環境）で `python manage.py migrate` がエラーなく完走する
- [ ] 既存ローカル DB（migration 適用済み）で `python manage.py migrate` を実行しても追加変更なく正常終了する
- [ ] I049 の E2E CI（`docker compose up -d --wait db backend frontend`）でバックエンドが `healthy` になる

## 影響範囲（想定）
- Backend: `accounts/migrations/` または `problems/migrations/` に修正用 migration 追加
- Frontend: なし
- DB: migration の修正のみ。既存データへの変更なし
- Config/Infra: なし

## Danger Ops（有/無）
- 有
- 内容: migration の変更は DB スキーマに影響する可能性がある
- 承認: `danger-approved` + `DANGER_OK=1` が必要
- ロールバック: 追加した migration を revert し `migrate` を再実行する
