## 背景/目的

**背景**: I166 の敵対的レビューで、クイズの回答の応答が `problem.explanation_image.url` を呼んでいるのに、`explanation_image` が文字列の欄（ファイル名）であることが指摘された。組織の境界とは無関係で、I166 以前からある不具合のため、別イシューにした（ユーザーが 2026-10-26 に起票を指示）。I452（2026-11-12）で回答の処理を変えた後も残っている。
**目的**: 解説画像がある問題にクイズで回答しても、エラーにならず、結果と解説（画像を含む）が表示されるようにする。新しい形式で登録した解説画像・問題の画像も、クイズで問題管理のプレビューと同じ見え方で表示されるようにする。回帰テストで固定する。

### 現状の問題（証拠・再現手順）
- 再現（2026-10-26・ロールバック付きの実験）: 問題の `explanation_image` にファイル名（例 `sample.png`）を入れて、その問題にクイズで正解の回答を送る → `POST /api/quiz/<id>/submit_answer/` が **500**（`AttributeError: 'str' object has no attribute 'url'`）。2026-11-12 の develop でも同じ書き方が `backend/problems/views.py:988` に残っている
- 500 になる時点で、回答の保存（QuizAnswer）・セッションの集計（`completed_problems`・`correct_answers`）・I452 で足した復習の予定（間隔反復のカードと復習記録）の更新は済んでいる。I452 でこれらを `transaction.atomic()` の 1 つにまとめたが、応答の組み立てはその外（`views.py:985-` の `return Response(...)`）にある。画面には結果が返らないのに、回答と復習の予定は記録される
- 開発用データ（primary の dev DB・2026-10-26・読み取りのみ）: 古い形式の解説画像（`explanation_image` に値がある未削除の問題）は 0 件（今は 500 は起きていない）。新しい形式（MediaAsset・`ProblemMediaAsset` の `usage_kind='explanation'`）の解説画像は 1 件ある
- 回答後の解説の表示（`QuizSession.tsx:621-650`）は、応答の `explanation_image`（古い形式）だけを使う。新しい形式の解説画像（`explanation_images`）は回答の応答に含まれず、クイズの画面のコードにも使う箇所が無い。新しい形式で登録した解説画像は、クイズで回答しても表示されない
- （2026-11-12 の読み比べで追記）設計確認メモの「両方の解説画像を出す」と「問題管理のプレビューと同じ見え方」は、今のプレビューの作りと食い違う。プレビュー（`ProblemPreview.tsx:78-86`）は **新しい形式が 1 枚以上あれば新しい形式だけを出し、古い形式は出さない**（新しい形式が無いときだけ古い形式）。→ 2026-11-12 の /grill-me でプレビューと同じ（新しい形式を優先）に確定
- （同）「画像の並べ方・拡大は今の解説画像と同じ」と「プレビューと同じ見え方」も食い違う。今のクイズの解説画像は 1 枚を横幅いっぱい（`maxWidth: 100%`）で出す。プレビューは `ImageList` で最大 3 列・高さ最大 300 で並べる。どちらも、クリックで `ImageModal` に拡大する点は同じ。また URL の付け方が違う（クイズは `REACT_APP_API_BASE_URL` を前に付けるだけ・プレビューは `getMediaUrl()`＝絶対 URL ならそのまま）。新しい形式の URL（`MediaAsset.get_url()`・`models.py:407`）は今は `/media/...` の相対パス → /grill-me でプレビューと同じ並べ方・`getMediaUrl()` に確定
- （同）プレビューは解説画像を、解説文があるときだけ出す（`ProblemPreview.tsx:193-207`）。クイズは解説文か解説画像のどちらかがあれば解説の枠を出す（`QuizSession.tsx:621`） → /grill-me でクイズの動き（画像だけでも出す）を残すに確定
- （同・本文に無かった事実）次の問題の応答（`views.py:898`・`ProblemDisplaySerializer`）には新しい形式の問題画像（`question_images`）が入っているが、クイズの画面（`QuizSession.tsx:494-509`）は古い形式の `question_image` だけを出す。新しい形式で登録した問題画像も、クイズでは表示されない（同じ種類の抜け）。→ /grill-me で I472 に含めると確定

### 根本原因
`submit_answer` の応答だけが、`Problem.explanation_image` を FileField のように扱っている（`.url` を呼ぶ）。他の経路（`ProblemSerializer`・`ProblemDisplaySerializer`）は、文字列から URL を作る `get_explanation_image_url()` を使っている。解説画像の URL の作り方が 1 か所にまとまっておらず、回答の応答で書き間違えた。また、回答の応答を作る前に回答の保存を済ませているので、応答の組み立てで失敗すると「保存されたのに 500」になる。

### 解決方針
- 回答の応答の解説画像の URL を、他の経路と同じ作り方（`get_explanation_image_url()`）にする
- 新しい形式の解説画像（`explanation_images`）を回答の応答に含め、回答後の解説に表示する（設計確認メモで確定）。応答の作り方は `ProblemDisplaySerializer` の `get_explanation_images` にそろえる。画面での選び方（新しい形式があれば新しい形式だけ・無ければ古い形式）と並べ方は問題管理のプレビュー（`ProblemPreview.tsx`）と同じにする。ただし解説文が無くても解説画像があれば解説の枠を出す（設計確認メモ・2026-11-12）
- クイズの問題文の画像も、新しい形式（`question_images`・次の問題の応答に入っている）を同じ選び方・並べ方で出す（設計確認メモ・2026-11-12）。プレビューと同じ選び方・並べ方を問題文と解説の両方で使うので、共通にする作り（部品に切り出すか、プレビューと共有するか）は計画で決める
- 応答の組み立てで失敗したときに「保存されたのに 500」にならないよう、応答に使う値を保存の前に組み立てるか、組み立てまでを I452 のトランザクションの中に入れるかは、計画で決める
- 回帰テスト: 古い形式の解説画像がある問題に回答すると 200 で、応答の `explanation_image` が `get_explanation_image_url()` と同じ URL になる。新しい形式の画像が応答に含まれる。画面のテストで、解説画像（新しい形式があれば新しい形式だけ・無ければ古い形式・解説文が無くても出る）と問題文の画像（同じ選び方）が表示される
