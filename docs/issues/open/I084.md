## 設計確認メモ（/grill-me）
判断基準＝検証階層（①手続き＜**②決定論ゲート**＜③敵対的検証）と目標運用モデル（レビュー不要でも false-green を出さないハーネス）。理想・根治を基準に各論点を確定。

- Q: 抽出方式は (a) 機械可読セクション規約 / (b) ヒューリスティック抽出 のどちらか → A: **ハイブリッド確定**。実走対象は (a) の機械可読『決定論ゲート』セクション（実行コマンドの fenced ブロック列）に**列挙されたコマンドのみ**（誤抽出ゼロ・実行契約を明示）。加えて (b) を **omission-lint** として併設し、宣言セクション外にゲート相当行を検出した場合に surface（宣言漏れ由来 false-green の再発経路を閉じる）。実行は宣言のみで決定論を保ち、(b) は非実行の lint に限定。〔**この 1 巡目の「記録付き警告」表現は後続で更新済み**: 2 巡目で **HIGH として VERDICT へ反映**に格上げ／3 巡目でトリガーを**副作用なし allowlist のゲートパターン行のみ**（heavy/deferred・散文裸語は非検出）に厳格化。最終仕様は下記「追補（2/3 巡目）」を正とする。〕
- Q: code-review が実走する決定論ゲートの範囲は（heavy テストを含むか） → A: **副作用なし allowlist ∩ 宣言ゲートのみ**。実走＝`scripts/claude/tests/*.sh`（temp repo）・`grep`・`python3 -m json.tool`・`python3` 構文チェック・`check-*.sh` 等の副作用なし読み取り系に限る。宣言されていても heavy（pytest/Jest/E2E・`docker compose ...`）は**実走せず「/test に委譲」と記録**（`/test` の所掌・Docker/DB 依存で低速）。破壊的コマンドは positive allowlist 不一致で**恒久的に実走しない**（AC の安全境界を allowlist で担保）。
- Q: 決定論ゲートに FAIL があった場合の VERDICT 反映は → A: **`code-review.sh` が最終 VERDICT を BLOCKER へ決定論的に上書き**（LLM 出力に依存しない）。実装＝`final = max(gate_verdict, llm_verdict)`（BLOCKER>HIGH>OK）で、LLM 文脈への事前注入（叙述整合）＋最終 VERDICT 行の事後上書き（決定論の要）を両建て。証跡（コマンド＋exit code）を記録／PR コメントへ注入。検証済み決定論 FAIL は「修正推奨(High)」でなく確定不合格のため BLOCKER が意味論的に正しく、HIGH ルーティングの将来変更にも堅牢。
- Q: ゲートが実行自体できなかった場合（スクリプト不在・`python3` 未検出等）の扱いは → A: **fail-closed（BLOCKER 扱い）**。起動不能＝「検証できていない」ため OK にせず BLOCKER・証跡記録。Q2 で heavy/破壊系を除外済みのため残る allowlist コマンド（bash/grep/python3/json.tool）は `/test` が回る dev 環境で常に起動可能＝誤ブロックを生まない。heavy の「/test へ委譲」は FAIL でなく deferred 記録（別バケット）。

### 追補（2巡目・二次的論点を理想基準で確定）
- Q: omission-lint（宣言セクション外のゲート検出）は VERDICT に影響するか、純 advisory か → A: **VERDICT に反映（HIGH・単層）**。純 advisory は「宣言漏れ→未実走→false-green」を人間の警告読解に委ね①手続きへ退化するため不可。lint の走査対象は**構造化シグナルに限定**（宣言セクション外の fenced ```bash/```sh ブロック、または `scripts/claude/tests/*.sh`（bash 実行）・`python3 -m json.tool`・`grep -q … <file>` 等の実行可能ゲートパターン行）。該当検出時は **HIGH の finding を記録し `final = max(gate_FAIL=BLOCKER, omission=HIGH, llm)` へ反映**。散文中の裸の語（"grep" 等）は走査対象外＝誤検知抑制の二層は不要（単層が最適）。未実走ゲートは「確定不合格(BLOCKER)」でなく「probable omission」のため意味論的に **HIGH** が正しく、code-review.sh は HIGH も `/fix-loop` へ誘導し `/test` に到達させないため穴は塞げる。作者は「宣言」または「非ゲート注記」で安価に解消。
- Q: 既存 open イシューの `auto_test.md`（宣言セクション無し）への移行スコープは → A: **前進のみ＋自己ドッグフーディング**。一括バックフィルはしない（mid-flight 成果物の後追い改変＝scope creep）。未移行イシューは code-review 到達時に omission-lint（HIGH）が発火し JIT 移行を促す＝自己強制。**I084 自身の `auto_test.md`（plan-issue で新規作成）は新セクションで宣言し契約を end-to-end 実証（ドッグフーディング）**。
- Q: 宣言セクションの厳密フォーマットは → A: 見出し **`## 決定論ゲート（自動実走）`**（固定・greppable）＋直後の単一 fenced ```bash ブロック。**非空・非コメント行 1 行＝1 ゲートコマンド**（`#` コメント・空行は無視）。パーサは当該見出し配下の fenced ブロック内行のみ抽出。omission-lint はこの見出し**外**の構造化シグナルを対象とする。

### 追補（3巡目・omission-lint のトリガー精度）
- Q: omission-lint のトリガーは fenced ```bash ブロック全般か、ゲートパターン行のみか → A: **副作用なし allowlist のゲートパターン行のみ**（`scripts/claude/tests/*.sh`（bash 実行）・`grep -q … <file>`・`python3 -m json.tool`・構文チェック等）が宣言セクション外に現れた場合に限り HIGH。**heavy/deferred（pytest/Jest/E2E・docker・npm）のみを含むブロックや例示は omission とみなさない**（定義上ゲートでない＝Q2 で /test 委譲確定済み。fenced bash ブロック全般をトリガーにすると `auto_test.md` テンプレートの例示 heavy ブロックを自傷的に HIGH 誤検知する）。lint の検出集合＝実走 allowlist と同一パターンに揃え、「実走すべきなのに未宣言のゲート」だけを HIGH にする。
- Q: 宣言ゲートがハングした場合の実行境界は → A: 各ゲート実走を `timeout`（既定 **120s**）で束ね、超過は「実行不能」扱い＝**fail-closed で BLOCKER**（Q4 と一貫）。具体秒数・実装は plan-issue で確定。

### 追補（plan-issue・実装粒度の確定 / plan_I084.md 準拠）
- **a. allowlist の具体化**: 「構文チェック等」を `bash -n` / `python3 -m py_compile` として具体化し allowlist に含める（副作用なし・読み取り系）。allowlist 全体＝`scripts/claude/tests/*.sh`（bash 実行） / `grep`（`-q` 存在・`-L` 不在）/ `python3 -m json.tool` / `bash -n` / `python3 -m py_compile`。
- **b. classify_gate は HEAVY を先頭コマンド anchored 判定（部分一致にしない）**: heavy 判定を部分一致にすると `grep -q "npm test done" build.log`（引数に heavy 語を含む正当な grep ゲート）が HEAVY 誤判定で**実走されず沈黙スキップ＝false-negative（gate 取りこぼし）**になる。先頭トークン（`docker`/`npm`/`pytest`/`manage.py test` 等）で判定してこれを防ぐ。判定順＝HEAVY(anchored)→allowlist(チェーンメタ文字ガード付き)ALLOW→UNSAFE。
- **c. UNSAFE な宣言ゲートも fail-closed BLOCKER**: allowlist 不一致・チェーン系の宣言ゲートは実走せず、検証不能として VERDICT を OK にしない（Q4「実行不能」の一貫拡張＋破壊/注入コマンド混入の loud signal）。
- **d. doc-sync ゲートは plain grep で存在/不在を表現**: 存在＝`grep -q 文言 file`（exit0=合格）、**不在＝`grep -L 文言 file`**（file が文言を含まないとき exit0＝合格・含むと exit1）。`!`/`grep -v`＋チェーンを使わず allowlist に収める。I080 の本質（禁止パターンの**不在**検証）はこの `grep -L` 形で忠実に固定する（AC4・TC-DOC3/4）。

## 背景/目的

### 現状の問題（証拠・再現手順）
`/code-review`（`scripts/claude/code-review.sh`）は単発の `claude -p`（tools=`Read,Grep,Glob`）でレビューする。
決定論的に判定できるゲート（`auto_test.md` が指定するテストスクリプト・doc-sync grep・lint 等）まで、
スクリプトが**実走せず LLM の読解に委ねている**ため、実行していないのに「PASS」と断定し得る。

**実証（I080）**: code-review 記録 `docs/reviews/I080_code_review_20260629_0101.md` は AC#11 で
「TC-DOC1〜3 PASS」と記載したが、実際には **TC-DOC3 が FAIL**（`claude-code-structure.md` の限界注記に
イシュー番号 `I083` を混入させ、規約「追加行にイシュー番号なし」に抵触）していた。次工程 `/test` が
当該 grep を**実走して初めて検出**（コミット `2c85f27` で修正）。レビューが決定論ゲートを実走していれば
code-review 段階で捕捉できた＝false-green（緑に見えて実は赤）。

### 根本原因
レビュー自動化が**決定論で判定可能な結果を、実行でなく推論で報告**している。LLM は Grep/Read ツールを
持つが実行を強制されておらず、決定論ゲートの「実 exit code」を判定の根拠にしていない。
検証の階層（①手続き＜②決定論ゲート＜③敵対的検証）のうち、②を①に退化させている。

### 解決方針
`code-review.sh`（または共有 review-lib）が、`auto_test.md` が指定する決定論ゲートを
**スクリプト自身で実走**し、実 exit code／pass-fail を `claude -p` のレビュー文脈に**証跡として注入**する。
決定論ゲートに FAIL があれば VERDICT を OK にしない（NG/Blocker 側へ倒す）。`code-reviewer.md` には
「決定論ゲートは注入済みの実結果を使い、読解で PASS と断定しない」を明記する。

> **抽出方式（grill-me で確定＝ハイブリッド）**: `auto_test.md` は自由記述の Markdown のため抽出方式を確定した。
> **実走対象は (a) の機械可読『決定論ゲート』セクション（実行コマンドのコードブロック列）に列挙されたコマンドのみ**
> （`auto_test.md` テンプレートに当該セクションを規約化）。加えて (b) を **omission-lint** として併設し、本文の他所に
> **副作用なし allowlist のゲートパターン行**（`scripts/claude/tests/*.sh`（bash 実行）・`grep -q … <file>`・`python3 -m json.tool` 等）を
> 宣言セクション**外**に検出した場合は **HIGH の finding として VERDICT に反映**（単層・散文の裸語や heavy/deferred のみのブロックは
> 走査対象外＝定義上ゲートでない heavy の誤検知を避けつつ宣言漏れ由来 false-green の再発経路を閉じる）。
> 実行は宣言セクションのみで決定論を保ち、(b) は非実行の lint（判定への反映は HIGH 上限）に限定。宣言セクションは
> 見出し `## 決定論ゲート（自動実走）`＋単一 fenced ```bash ブロック（非空・非コメント行 1 行＝1 コマンド）で規約化する。
> 実走は副作用なし allowlist（`scripts/claude/tests/*.sh`・`grep`・`python3 -m json.tool`・構文チェック等）に絞り、
> heavy（pytest/Jest/E2E・`docker compose`）は「/test に委譲」と記録、破壊的コマンドは allowlist 不一致で恒久的に実走しない。
> FAIL または実行不能があれば `code-review.sh` が最終 VERDICT を **BLOCKER** へ決定論的に上書きする（fail-closed）。
> 判定合成は `final = max(gate_FAIL=BLOCKER, omission=HIGH, llm)`（BLOCKER>HIGH>OK）。既存 open イシューへの一括
> バックフィルは行わず前進のみ（未移行分は omission-lint が JIT 移行を促す）。**I084 自身の auto_test.md は新セクションで
> 宣言しドッグフーディングする**。
