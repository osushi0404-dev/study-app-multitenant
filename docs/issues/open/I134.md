## 背景/目的

**背景**: I132 のイシュー本文で、`## 背景/目的` セクションに小見出し 3 つ（現状の問題・根本原因・解決方針）だけが書かれ、肝心の「背景」「目的」そのものが記載されないままレビューを通過し、ユーザー指摘で発覚した。原因はテンプレート側にあり、`issue_template.md` の `## 背景/目的` にはセクション名に対応する記述欄（プレースホルダ）が存在しないため、テンプレートを埋めるだけでは背景・目的が書かれない構造になっている。

**目的**: テンプレートに `**背景**:` / `**目的**:` のプレースホルダ行を追加し、イシュー起票時に背景・目的の記述が構造的に促されるようにする（テンプレート埋め＝抜けなし、の状態にする）。

### 現状の問題（証拠・再現手順）
`docs/issues/templates/issue_template.md` の `## 背景/目的` セクション（6〜15 行目）:

```markdown
## 背景/目的

### 現状の問題（証拠・再現手順）
（具体的な症状・エラー・動作。…）

### 根本原因
（なぜ起きているか。…）

### 解決方針
（どのアプローチか・なぜそのアプローチか。…）
```

- セクション見出しは「背景/目的」だが、配下は問題・原因・方針の 3 小見出しのみで、**背景（経緯）と目的（達成したい状態）を書く欄がない**。
- 実際に I132 で抜けが発生した（テンプレート通りに埋めても背景・目的が書かれない）。issue-review（自己完結度レビュー）も小見出し単位の記入有無を見るため検出できなかった。

### 根本原因
テンプレートの `## 背景/目的` 直下にプレースホルダ行がなく、記入者（Claude 含む）が小見出しだけを埋めて完了と判断する構造になっているため。

### 解決方針
`issue_template.md` の `## 背景/目的` 直下（`### 現状の問題` の前）に以下のプレースホルダ 2 行を追加する:

```markdown
**背景**: （このイシューに至った経緯。どの作業・レビュー・指摘から生まれたか）
**目的**: （このイシューで達成したい状態。何がどうなれば成功か）
```

あわせて、既存 open イシュー全件に同ラベル 2 行を追記して形式統一する（旧値 sweep。I130 の「旧値 sweep」と同型の是正。/grill-me の点検実走で「抜けがあれば少数」ではなく実質ほぼ全件が対象と確定）:
- 現行テンプレ型（小見出し 3 つのみ）: 背景・目的を書き起こしてラベル 2 行を追記
- 旧形式（013, I031〜I047 の 12 件・見出し直下に文章あり）: 既存文章を要約してラベル 2 行化（既存文章は保持）
- 完了判定は grep による機械検証（wt-harness の `docs/issues/open/*.md` 全件にラベル 2 行が存在すること）で締める
- GitHub open 全件（計画時 41 件・検証実行時点の全件を対象とし新規発生分は同手順で追補）の本文を wt-harness セッションから再同期する。隣の worktree（study-app-multitenant）にのみ存在するローカルファイルはトラック境界ルールにより本セッションから編集せず、計画書に反映手順（スクリプト）を記載して引き継ぐ
