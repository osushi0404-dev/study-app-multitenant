## 背景/目的

**背景**: I166 でクイズの経路、#431 で学習記録・ダッシュボードの経路の組織境界を塞ぐ。どちらも、境界の不備を見つけるのは設計確認と計画での洗い出しに頼っており、「問題・科目を返す全経路」を機械で確かめる仕組みがない。新しい API が増えたとき、組織の絞り込みを忘れても CI では気づけない。
**目的**: 問題・科目と本人の記録を扱うすべての API に他組織の ID（本人の記録では同じ組織の別の利用者の ID も）を送り、存在しない ID と同じく拒否されることを 1 本の横断のテストで確かめ、CI で毎回回す。番号を受け取らない一覧・集計では、他組織・別の利用者の中身が出ないことを確かめる。テストが扱っていない新しい経路が増えたら、テストが落ちて気づけるようにする。

### 現状の問題（証拠・再現手順）
- 組織境界のテストは、経路ごとの個別のテスト（I166 のクイズ、#431 の学習記録）しかない
- `backend/studylogs`・`backend/dashboard` には、#431 の前はテストが 1 本もない
- studylogs だけでも `@action` が 27 個あり、`create_card` のように本文の `problem_id` で ID を受け取るものが多い（2026-11-10 の点検）

### 根本原因
- 組織での絞り込みが、各ビュー・サービスの手書き（`get_queryset` や `Problem.objects.get(...)` に条件を書く）で、共通の仕組みで強制されていない。ID の入口も、URL・`@action` の本文の `problem_id`・一覧の絞り込みの引数などばらばらで、書き忘れが起きやすい
- そのうえ、境界の不備を直すときに「対象のモデルを返す全経路」を機械的に確かめる仕組みがない（I166 の /retro の予防処置 3）。洗い出しは設計確認と計画に頼っている

### 解決方針
- URL の一覧（`django.urls.get_resolver`）から、`api/` の下の全経路（メソッド別）を集める
- 全経路を表に載せ、各経路を「確かめる」か「対象外（理由を書く）」に分ける。「確かめる」経路には「どの引数に番号を入れるか」「期待する応答（存在しない ID と同じ）」「本人の記録か（同じ組織の別の利用者の番号も試すか）」を書く（自動で集められるのは経路だけで、引数と期待値は経路ごとに書く必要がある）
- 集めた経路と表を突き合わせ、表に載っていない経路があればテストが落ちる作りにする（洗い出し漏れを機械で止める・fail-closed）
- 番号を受け取らない一覧・集計の経路は、他組織と同じ組織の別の利用者にデータを置いた状態で呼び、応答に他組織・別の利用者の問題文・解説・選択肢・科目名・ID が出てこないことを確かめる
- 今は壊れている経路（#452 の difficulty の型・`is_active`）は、#452 の番号を書いた `xfail(strict=True)` にする（直ったら印を外す）
- 応答は、他組織の ID と存在しない ID のときのステータスと本文を比べる。本文の中の ID・URL は伏せてから比べる（I166 のテストと同じ）。作成（POST）や一覧の絞り込みの引数のように、404 ではなく 400 や空の一覧になる経路は、表に「期待する応答」をその経路ごとに書き、他組織の ID でも存在しない ID と同じになることを確かめる。問題文・解説・選択肢・科目名が返らないことも確かめる
- 対象の範囲: クイズ（I166 で直し済み）・学習記録・ダッシュボード・統計など、問題・科目を扱う API すべて。クイズも表に載せる（直すのは I166 で済んでいるが、回帰を防ぐため）。問題・科目以外の記録（学習記録・目標・復習カード・復習の記録・クイズの回など）も含める（設計確認で確定）。境界は 2 種類: 他組織の番号（全部の対象）と、同じ組織の別の利用者の番号（本人の記録だけ。組織で共有する問題・科目は対象外）

## スコープ
### 含む
- `api/` の下の全経路を載せた表による横断の越境テスト（CI で毎回実行）。対象は問題・科目と、本人の記録（学習記録・目標・復習カード・復習の記録・クイズの回など）。他組織の番号と、本人の記録では同じ組織の別の利用者の番号を試す

- 表に載っていない新しい経路を検出する仕組み
- テストで見つかった越境があれば、その修正（1 経路の絞り込みの追加で済むものは同梱。境界の判定の置き場所を変えるなど複数のファイルにまたがるものは、別イシューにし、そのテストは別イシューの番号を書いて一時的に `xfail` にする）
### 含まない
- #431 で済ませた学習記録・ダッシュボードの経路の修正と、その個別の回帰テスト（このテストで新しく見つかった越境の修正は「含む」の扱い）

- 公開の科目一覧（`subjects/public/`）と運用者用の利用者管理（`admin/users/`）の仕様の変更（表では理由付きの対象外）
