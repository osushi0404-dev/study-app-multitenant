# I015: /code-review・/plan-issue スキルへのレビュー観点追加と /issue-bootstrap 採番バグ修正

## 関連資料
- .claude/skills/code-review/SKILL.md
- .claude/skills/plan-issue/SKILL.md
- .claude/skills/issue-bootstrap/SKILL.md

## 背景/目的
- 現状の `/code-review` は受け入れ条件との照合・ロジック品質確認のみで、セキュリティや業界標準のベストプラクティス観点が欠けている
- 現状の `/plan-issue` は計画書・テスト文書を生成するが、生成後のセルフレビューフェーズがなく、設計上のセキュリティ漏れや非推奨パターンが計画書に混入するリスクがある
- レビュー品質を底上げし、「実装後に発覚するセキュリティ・設計問題」を計画段階・レビュー段階で潰す
- `/issue-bootstrap` の採番スクリプトで `printf "%d"` が `014` 等の0埋め数値を8進数として解釈し、正しい次番号を算出できないバグが存在する（例: 014→12と解釈→次番号が013になる）

## スコープ
### 含む
- `/code-review` SKILL.md に「ベストプラクティス・セキュリティ・モダン開発観点」レビューステップを追加
- `/plan-issue` SKILL.md に生成ドキュメントに対するセルフレビューフェーズを追加（同3観点）
- `/issue-bootstrap` SKILL.md の採番スクリプトを修正し、0埋め数値を常に10進数として扱うように変更

### 含まない
- 他のスキル（/implement, /test 等）への変更
- コーディング規約ファイル（rules/）の変更
- 既存の受け入れ条件照合ロジックの変更

## 受け入れ条件（Acceptance Criteria）
- [ ] `/code-review` の手順にベストプラクティス・セキュリティ・モダン開発観点のチェック項目が追加されている
- [ ] `/plan-issue` の手順に、生成ドキュメントへのセルフレビューフェーズ（同3観点）が追加されている
- [ ] `/plan-issue` のセルフレビューで問題が見つかった場合、承認ポイント提示前に修正する旨が明記されている
- [ ] 各観点のチェック項目が具体的で（例：「N+1クエリ」「認証漏れ」「OWASP Top 10」等）、曖昧でない
- [ ] 既存の手順フローを壊していない（ステップ番号の整合性、STOP条件等）
- [ ] `/issue-bootstrap` の採番スクリプトで `I014` の次が `I015` と正しく算出される（8進数誤解釈が修正されている）

## 影響範囲（想定）
- Backend: なし
- Frontend: なし
- DB: なし
- Config/Infra: なし（スキルファイルのみ変更）

## Danger Ops（有/無）
- 無
