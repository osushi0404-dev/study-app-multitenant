## 設計確認メモ（/grill-me）
- Q: 選び直す欄をどこに置くか → A: 設定画面（`frontend/src/pages/Settings.tsx`）の中に「学ぶ科目」のカードを足す。自分の組織の科目をチェックボックスで並べ、カードの「保存」ボタンで保存する。左のメニューは増やさない
- Q: 全部外して 0 件にできるか → A: できない。最低 1 つは必須（会員登録の `subject_ids` の `min_length=1`・`backend/accounts/serializers.py:32-40` と同じ決まり）。画面は 0 件では保存できず「科目を最低1つ選択してください」を出し、API も 0 件を 400 で断る
- Q: ダッシュボードで科目が 0 件の人への案内をどう分けるか → A: 組織に科目があるかで分ける。組織に科目がある（利用者が選んでいないだけ）→「学ぶ科目を選ぶ」ボタンで設定画面の「学ぶ科目」のカードへ。組織に科目が 1 つも無い → 今の「組織の管理者に科目の登録を依頼してください」のまま
- Q: 科目を外したとき、その科目の過去の記録の見え方 → A: 今の作りのまま「選んだ科目だけ出す」。外した科目は学習統計の科目別の欄（`backend/studylogs/views.py:257-259`）・ダッシュボードのおすすめ（`backend/dashboard/selectors.py:158`）に出なくなる。記録は消さず、選び直せばまた出る
- 自己解決（コードを読んで確定）: 価値は「割り当てを書く API・画面が無く、0 件の人が行き止まり」で明確・代わりの手段なし。費用は既存の `UserSubjectAccess` を使い DB の変更なしで小さい。既存方針とは、組織の境界を `SubjectService` と同じく DB の条件で掛け、キャッシュは `user_subjects_cache_key` を消すことでそろう。`backend/problems/permissions.py` の `AccessPermissionChecker` はどこからも使われておらず、外しても問題を解く権限には影響しない。管理者（`role=admin`）も自分の学ぶ科目として同じカードを使える（他人への割り当てはスコープ外のまま）。ツールの出力で完了基準が決まるイシューではない

## 背景/目的

**背景**: 利用者がどの科目を学ぶか（`UserSubjectAccess`・`backend/problems/models.py:277`）は、会員登録のとき（`backend/accounts/serializers.py:32`・`:98-114` の `subject_ids`）にしか作れない。後から追加・変更する画面も API も無い。ダッシュボードの「学習を開始」のカードは、科目が 0 件のとき「組織の管理者に科目の登録を依頼してください」と案内するが（`frontend/src/components/dashboard/StartQuizCard.tsx:84-88`・#487）、組織に科目があって利用者が選んでいないだけの場合も同じ案内になり、利用者が自分で直せない。設定画面（`frontend/src/pages/Settings.tsx`）に科目の欄は無い。管理者向けの `/subject-management` は組織の科目を作る画面で、利用者への割り当てはできない。
**目的**: 一般ユーザーが、会員登録の後でも、自分の組織の科目から学ぶ科目を選び直せるようにする。科目が 0 件の人が行き止まりにならないようにする。

### 現状の問題（証拠・再現手順）
1. 科目が 0 件の一般ユーザー（dev 環境の `e2e_user_c`・組織 A）でログインし `/dashboard` を開くと、「学習を開始」のカードに「組織の管理者に科目の登録を依頼してください」が出て、「クイズを始める」は押せない。組織 A には科目があるのに、利用者が自分で選ぶ手段が無い。`/settings` を開いても科目の欄は無い
2. 割り当てを読む API は `GET /api/.../user/subjects/`（`backend/problems/urls.py:13`・`backend/api/views/user_subjects.py`）だけで、書く API が無い
3. 会員登録の後に学びたい科目が増えた・減ったときに、利用者が自分で変えられない（組織の管理者にも割り当ての画面が無い）

### 根本原因
- 科目の割り当てを「会員登録のときに 1 回だけ決めるもの」として作り、その後の変更を設計していない

### 解決方針
- 設定画面（`frontend/src/pages/Settings.tsx`）に「学ぶ科目」のカードを足し、自分の組織の科目をチェックボックスで選んで「保存」で書き換える（左のメニューは増やさない）。書き換えの API を足す
- 最低 1 つは必須。0 件の保存は画面で止めて「科目を最低1つ選択してください」を出し、API も 400 で断る
- 選べるのは自分の組織の科目だけ（組織の境界は、`SubjectService.get_user_selected_subjects`・`backend/core/subject_service.py:112` と同じく DB の条件で掛ける）
- 変更したら、利用者の科目のキャッシュ（`user_subjects_cache_key`・`backend/core/subject_service.py:20`）が確実に消えること。今は `backend/problems/signals.py` の post_save / post_delete で消しているが、`bulk_create` では post_save が呼ばれないので、書き方に合わせて確かめる。画面側も、保存の後にダッシュボード・クイズが使う科目の一覧（`frontend/src/hooks/useUserSubjects.ts`）を古いまま出さない
- 外した科目は、今の作りのまま学習統計の科目別の欄・ダッシュボードのおすすめに出なくなる（記録は消さない。選び直せばまた出る）
- ダッシュボードの「学習を開始」のカード（`frontend/src/components/dashboard/StartQuizCard.tsx`）の科目 0 件の案内を、組織に科目があるかで分ける。組織に科目がある →「学ぶ科目を選ぶ」ボタンで設定画面の「学ぶ科目」のカードへ。組織に科目が 1 つも無い → 今の「組織の管理者に科目の登録を依頼してください」のまま

## 実装対象（既知のもの）
| ファイル | 変更内容 |
|---------|---------|
| `backend/api/views/user_subjects.py`・`backend/problems/urls.py` | 利用者の科目の割り当てを書き換える API（自組織の科目だけ・最低 1 つ。方式は計画で決める） |
| `backend/problems/signals.py` または書き換えの処理 | 書き換えの後に利用者の科目のキャッシュを消す |
| `frontend/src/services/subjectService.ts` | 書き換えの API を呼ぶ関数 |
| `frontend/src/pages/Settings.tsx` | 「学ぶ科目」のカード（組織の科目のチェックボックス・保存・最低 1 つの検証・保存の失敗の表示） |
| `frontend/src/hooks/useUserSubjects.ts` | 保存の後に利用者の科目の一覧を読み直す（古い一覧を出さない） |
| `frontend/src/components/dashboard/StartQuizCard.tsx` | 科目 0 件の案内を、組織に科目があれば「学ぶ科目を選ぶ」ボタン（設定画面へ）、無ければ今の案内に分ける |
| テスト（`backend/` の API テスト・`frontend/` の画面のテスト） | 他組織の科目を選べないこと・0 件を断ること・キャッシュが消えること・保存して読み戻せること・0 件の案内の分かれ方 |

## スコープ
### 含む
- 一般ユーザー（管理者も自分の分は同じ）が自分の科目を選び直す設定画面のカードと API
- 他組織の科目を選べないこと・0 件にできないことの確認（テストで固定）
- ダッシュボードの「科目 0 件」の案内を、組織に科目があるかで分け、ある場合は設定画面への導線にする
### 含まない
- 組織の管理者がほかの利用者に科目を割り当てる画面
- 組織の科目そのものの作成・編集（既存の `/subject-management`）
- 会員登録の画面の科目の選び方の変更
- 外した科目の過去の記録を学習統計に出し続ける変更（今の「選んだ科目だけ出す」のまま）

## 関連する品質基準
- C1 学習効果 — 学びたい科目をいつでも選べ、科目が無くて学習を始められない状態をなくす
- C7 フェールセーフ — 保存の失敗を画面に出し、選んだ内容が消えたように見えないようにする

## 受け入れ条件（Acceptance Criteria）
- [ ] 一般ユーザーが、会員登録の後に、設定画面の「学ぶ科目」のカードで自分の組織の科目を追加・解除でき、保存した内容がダッシュボード・クイズの科目の選択に反映される（キャッシュが残って古い一覧が出ない）
- [ ] 他組織の科目の ID を送っても割り当てられない（API テストで固定）
- [ ] 科目を 0 件にして保存できない（画面は「科目を最低1つ選択してください」を出し、API は 400 で断る。API テストで固定）
- [ ] 保存の失敗が画面に出る
- [ ] ダッシュボードで科目が 0 件の人に、組織に科目があれば「学ぶ科目を選ぶ」ボタン（設定画面の「学ぶ科目」のカードへ）が出る。組織に科目が 1 つも無ければ「組織の管理者に科目の登録を依頼してください」が出る
- [ ] 既存の機能に退行が無い（既存のテスト・E2E が通る）

## 影響範囲（想定）
- Backend: 利用者の科目の割り当てを書き換える API・キャッシュの無効化
- Frontend: `Settings.tsx` の「学ぶ科目」のカード・`subjectService.ts`・`useUserSubjects.ts`・`StartQuizCard.tsx` の案内
- 変えないもの（意図的除外）: `backend/problems/permissions.py`（どこからも使われていない・問題を解く権限に影響しない）・`backend/studylogs/views.py`・`backend/dashboard/selectors.py`（外した科目を出さない今の作りのまま）・`backend/accounts/serializers.py`（会員登録は変えない）
