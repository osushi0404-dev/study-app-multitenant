## 背景/目的

### 現状の問題（証拠・再現手順）
- `docs/tests/templates/auto_test_template.md` の冒頭に「実行コマンド（例）:」として fenced ```bash ブロックの例示がある。
- 一方、omission-lint（I084）は `## 決定論ゲート（自動実走）` セクション**外**の fenced ```bash にゲート系コマンド（`bash scripts/claude/tests/*.sh` 等）があると HIGH を返す仕様。
- テンプレートを素直に踏襲して冒頭ブロックに専用テストスクリプトを書くと、**正しく作った文書が機械チェックで誤 HIGH になる**。I109 で実際に発生し、code-review 初回 NG →文書構造の手直し 1 往復が発生した。
- 再現手順: auto_test.md の冒頭「実行コマンド:」fenced ブロックに `bash scripts/claude/tests/test_*.sh` を記載して `/code-review` を実行 → omission-lint: HIGH。

### 根本原因
- omission-lint（I084）導入時に、その lint が参照するテンプレート（auto_test_template.md）の既存例示部分との整合を同時監査する手順がなく、テンプレート冒頭の fenced 例示が lint パターンと衝突したまま残った（I109 retro の 5 Whys で特定）。

### 解決方針
- テンプレート冒頭の「実行コマンド（例）:」fenced ブロックを**インラインコード列挙に変更**する（`docker compose exec backend python manage.py test` / `docker compose exec frontend npm test` をバッククォート表記で残し、「結果:」欄は現状維持。冒頭から fenced ```bash ブロックを構造的に排除）。fenced ```bash のゲート系コマンドは `## 決定論ゲート（自動実走）` セクションのみに置く構造にする。
- テンプレート冒頭に「ゲート系コマンドは『## 決定論ゲート（自動実走）』セクションに書く（セクション外に書くと omission-lint が HIGH を出す）」の**誘導注記**を追加する。allowlist パターンの列挙は既存のゲートセクション内コメント1箇所に集約し、冒頭には複製しない（code-review.sh 変更時の乖離ポイントを増やさない）。
- gate 層は既存の omission-lint に加え、恒久テストスクリプト `scripts/claude/tests/test_auto_test_template_lint.sh` を新規作成して担保する（是正後テンプレ OK・罠注入で HIGH の decoy 反証・完成文書 OK の3点検証。将来テンプレに fenced 例示が復活する退行も検知）。
