## 背景/目的

**背景**: I473 で、ダッシュボードの数字の出どころをクイズの答えの記録（`QuizAnswer`）に 1 本化し、あわせて #467 の引き継ぎ（科目のキャッシュのキー・学習記録を閉じる範囲）を直した。レビュー（コードレビュー 2 回・敵対的レビュー 1 周）で、止める指摘には当たらない Low の指摘が残った。どれも計画の範囲の外の境界（組織の移動・長い利用期間・並列実行・境界値）にある。
**目的**: 残った 5 件（F5・F8・F7・F6・B1）を直す（または直さない理由を決める）。あわせて、`QuizAnswer` の読み出しを組織の境界の見張りに入れるかを決める。

### 現状の問題（証拠・再現手順）
1. **F5 科目のキャッシュの消し残し**（`backend/problems/signals.py` の `_invalidate_user_subjects_cache`）: 無効化するキーを、利用者の今の `organization_id` だけで作る（キーの関数は `backend/core/subject_service.py` の `user_subjects_cache_key`）。再現: 組織 A でキャッシュを作る → 組織 B へ移る → 科目の選択を外す（B のキーだけ消える）→ 期限内に A へ戻ると、外した科目が A のキャッシュから返る。読む側は DB で組織を絞るので他組織の科目は出ない（漏れではない）
2. **F8 旧組織の進行中の学習記録が残る**（`backend/studylogs/views.py` の `StudyLogViewSet.create`）: I473 で、閉じる対象を `StudyLog.objects.for_user(user)`（自組織の科目・科目なし）に絞った。再現: 組織 A の科目で記録を始めたまま組織 B へ移り、B で記録を作っても、A の記録が `is_active=True` のまま残る
3. **F7 連続日数の読み出しに上限が無い**（`backend/dashboard/selectors.py` の `_current_streak`）: 答えのある日付を全期間から読む。行数は利用期間（日数）に比例する（1 年で最大約 365 行）。クエリの本数は増えない（I473 の TC-12 で 9 本に固定）
4. **F6 E2E の解答数の比べ方**（`e2e/tests/quiz-session.spec.ts` の「クイズに答えると、ダッシュボードの解答問題数が 1 増える」）: 共有ユーザー（`e2e_user_a`）の全期間の解答数が、前の値 + 1 になることを厳密に比べる。`e2e/playwright.config.ts` は workers を決めておらず、別の spec が同じユーザーで同時に答えると +2 になって落ちうる（I473 の CI では通った）
5. **B1 学習時間の上限の境界値のテストが無い**（`backend/dashboard/tests/test_I473_overview.py` の `test_values_and_seconds_cap`）: 1 問 300 秒の上限を 400 秒の答えだけで確かめていて、ちょうど 300 秒・301 秒が無い
6. **Q1（検討）** `QuizAnswer` は、I455 の「組織で絞らずに読むなら理由のコメントを書く」見張り（`backend/studylogs/tests/test_I455_org_scoped_querysets.py:253-298`。対象は `OrgScopedQuerySet` を持つモデル）の対象外。I473 では `backend/dashboard/selectors.py` の `_answers()` の 1 か所で絞る作りにして守っている（I473 の design-security-review の Medium の必須条件）

### 根本原因
- I473 の計画は「ダッシュボードの数字」と「#467 の引き継ぎ 3 件」の範囲で書き、組織を移る利用者・長い利用期間・E2E の並列実行を前提に入れていなかった。レビューでは止める重さに当たらず、台帳に残った
- Q1 は、組織の境界の見張りが「`OrgScopedQuerySet` を持つモデル」だけを対象にしていて、利用者を経由して持ち主が決まるモデル（`QuizAnswer` は `session__user`）を見ていないこと

### 解決方針
- F5: キャッシュのキーから組織を外し、組織の境界は読む側の DB の条件だけに頼る（設計確認メモ参照）。I473 でキーに組織を入れた理由（#467 の引き継ぎ 3「キャッシュのキーに組織が無い」）は、中身が科目の番号だけで境界を DB で掛けるため、キーから外しても崩れない。計画でこの前提をテストで固定する
- F8: 直さない（`StudyLog` は画面から書かれず、#492 で API・表ごと消す）。理由を計画書に記録する
- F7: 見え方は変えずに正確に数え、読み出しの行数を作り方で抑える（窓の日数・方式は計画で決める）
- F6: 比べ方を「1 以上増える」にするか、この spec だけ別のユーザーを使うか。技術的な選択なので計画で決める
- B1: ちょうど 300 秒・301 秒の答えを足す（期待値は 300・300）
- Q1: `QuizAnswer` の読み出しを見張りの対象に足す方向で、方式は計画で決める（足さないと決めるなら理由を記録）
