## 背景/目的

**背景**: ダッシュボードは数字が 0 になる不具合（#473）とは別に、画面の作りの面でも、初めての人・スマホの人・データが無い人にとって使いにくい状態にある。2026-11-13 に dev 環境（develop と同じ内容）を Playwright MCP で開き、デスクトップ幅（1440px）とスマホ幅（390px）、科目ありの管理者（`e2e_user_a`）と科目なしの一般ユーザー（`e2e_user_c`）で確かめた。
**目的**: ダッシュボードを「開いたら次に何をすればよいかが分かり、スマホでも崩れず、データが無い・読み込み中・失敗のどの状態でも誤解を生まない」画面にする。

### 現状の問題（証拠・再現手順）
確認方法: dev 環境で下のアカウントでログインし `/dashboard` を開く（2026-11-13・Playwright MCP）。
1. **スマホ幅でダッシュボードだけ横にはみ出す（最優先）**: 幅 390px では、中身が画面幅の約 2 倍（全体のキャプチャで約 808px）に広がる。挨拶文が途中で切れ、「今日の復習」の「復習を始める」ボタンが画面の外に出る。同じ幅の設定画面（`/settings`）でははみ出さない。共通の枠 `frontend/src/components/Layout.tsx:219-225` の `component="main"` は、`md` 以上でしか幅を指定しておらず、`minWidth: 0` も無い。そのため、ダッシュボードの中の広い要素（Chart.js の canvas など）に押されて広がっている疑いがある（原因は推定。計画で特定する）
2. **データが無いときの誤表示**: 正答率のドーナツグラフが赤一色になり、「不正解 100%」に見える（`frontend/src/pages/Dashboard.tsx:242-251`）。週の学習時間のグラフは、目盛り 0〜1.0 の空の枠だけが出る（`Dashboard.tsx:229-240`）。数字のカードも「0分・0日・0・0%」が並ぶだけで、データが無いのか本当に 0 なのか分からない
3. **科目を持たない人の行き止まり**: 科目が 0 件の一般ユーザー（`e2e_user_c`）が「クイズを始める」を押すと、数秒で消えるお知らせ（toast）が出るだけ（`Dashboard.tsx:184-188`）。「間違いやすい分野」のカードは「まずは問題を解いてみましょう！」と誘うのに、科目を登録する画面へのリンクが無い
4. **科目の切り替えで画面全体がちらつく**: 科目を切り替えるたびに、画面全体が「ダッシュボードを読み込み中...」に置き換わる（`Dashboard.tsx:206-212`）。科目のセレクタも付け直されるため、ブラウザのコンソールに MUI の警告（選択肢に無い値 `2` を渡している）が出る。初回表示で `GET /api/dashboard/overview/` が 2 回呼ばれる
5. **目標時間が 60 分で固定**: ダッシュボードは「目標: 60分」と書いてあるが（`Dashboard.tsx:111`・`:312-316`・`:416`）、設定画面には「1日の学習目標時間（分）」の入力欄（`frontend/src/pages/Settings.tsx:258`・`daily_study_goal`）がある。設定を変えてもダッシュボードに反映されない
6. **主な行動が下の方にある**: デスクトップ幅（1440×900）で、「クイズを始める」ボタンは数字のカードと大きなグラフの下にあり、最初の画面に入らない。スマホ幅では、さらに 4 枚のカードと 2 つのグラフの下になる
7. **達成のお知らせの記録がユーザーで分かれていない**: `localStorage` のキー `lastHighAccuracyNotification`・`lastDailyGoalNotification`（`Dashboard.tsx:101-106`・`:115-120`）に、ユーザーの区別が無い。同じブラウザで別のユーザーに切り替えると、お知らせが出ない・取り違える
8. **読み込み中・失敗の表示が弱い**: 読み込み中は文字だけで、スケルトン（形だけの仮表示）が無い。取得に失敗したときは toast だけで、画面は読み込み中の文字のまま止まり、再試行のボタンが無い（`Dashboard.tsx:153-158`・`:206-212`）
9. （小）アクセシビリティ設定の丸いボタン（画面右下に固定）が、デスクトップでは正答率のグラフに、スマホでは数字のカードに重なる

### 根本原因
- ダッシュボードの画面が「データがある前提」で作られていて、データ無し・科目無し・読み込み中・失敗の状態を設計していない（#473 の、防御的な既定値で 0 を埋める作りと同じ根）
- 狭い画面での確認と、画面確認の E2E が無い（`Dashboard.test.tsx` も E2E も無い・#473 の記載）
- 1 のはみ出しの技術的な原因は未特定（上の推定を計画で確かめる）

### 解決方針
- #473 で入った API 契約（`has_data` など）を使って、「データ無し」の表示を作る。数字のカードとグラフ 2 つは残し、それぞれの中に「まだ記録がありません」と出す（赤いドーナツ・空のグラフの枠は出さない。設計確認メモ）。科目を選んでその科目の解答が 0 件のときの「間違いやすい分野」は「この科目はまだ解答がありません。まずは問題を解いてみましょう！」にする
- 状態（読み込み中・失敗・データ無し・科目無し）ごとの表示を作る。読み込み中はスケルトンにし、画面全体を置き換えない。失敗したら再試行ボタンを出す
- 並び順（上から）: 挨拶（1 行）→ 科目の選択（画面全体の絞り込み）→「クイズを始める」と「今日の復習」を横並び（スマホでは縦）→ 数字のカード 4 枚 → グラフ 2 つ → 間違いやすい分野・おすすめ（見出しに「（全科目）」）→「統計を見る」（一番下の小さなリンク）。科目を選んでいるときの「クイズを始める」はダイアログを出さずにその科目で始める（2 回目の設計確認メモ）
- 選んだ科目の解答が 0 件なら、「間違いやすい分野」のカードの一番上に案内を出し、その下に全科目の一覧も出す
- 答えが 0 件のときの推移のグラフの縦軸がマイナスにならないようにする（最小 0）
- 科目が 0 件の人には、画面の中に「科目がまだ登録されていません。組織の管理者に科目の登録を依頼してください」を出す（リンクなし・toast だけにしない）。自分で科目を選べる画面は #494 で作り、そちらで行き先を差し替える
- 目標時間は設定の `daily_study_goal_minutes`（裏側の項目名・既定 30 分）を使う。設定画面（`Settings.tsx`）の項目名 `daily_study_goal` を裏側にそろえる
- 達成のお知らせの記録の `localStorage` のキーにユーザーを含める。連続日数の節目は同じ連続の間に 1 回だけ（途切れた後に再び届いたらもう一度）、解答数の節目は越えた中で一番大きい未表示の節目を 1 回だけ、正答率 95%・目標時間の達成は 1 日 1 回にする。お知らせの判定は取得の effect の依存から外す（I473 F11）
- `Dashboard.tsx` を、取得と状態のフック（例: `useDashboardOverview(subjectId)`）と表示の部品に分ける。型は #493 で生成したものを使う
- スマホ幅のはみ出しは、原因を特定して共通の枠か部品の側で直す。スマホ幅の E2E（またはスナップショットではない幅の検査）で再発を止める。#473 は済んでいるので PR は分けない
