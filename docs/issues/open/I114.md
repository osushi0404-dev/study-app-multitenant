# I114: /retro スキルの対ユーザー説明・確認出力を平易化（記録ファイルは詳細維持／専門用語・内部記号を平易な言葉に置換し、経緯・理由は残す）

## 関連資料
- GitHub Issue: #212
- 発見経緯: I104 の `/retro`（2026-07-15）で、ユーザーから「振り返りスキルで出力されるものが全体的にわかりにくい」と指摘。さらに平易化した出力に対し「簡略化しすぎ・経緯など必要情報まで削っている」と再指摘があり、"短く"ではなく"平易かつ必要情報は保つ"が求められていることが判明。

## 設計確認メモ（/grill-me）
- Q: 詳細版（内部管理用の表）はどこに残すか（現状 retro は記録ファイルを作らず、詳細はチャットにしか存在しない。記録ファイル新設 or チャット併記） → A: **チャット併記（案B）**。retro に記録ファイル作成ステップは追加しない。対話では「平易版 → 詳細版の表」の順に両方提示する。
- Q: 5 Whys の途中経過（Why 1→2→…の連鎖）をチャットに出すか → A: **出す（案B）**。経過の提示は維持し、専門用語・内部記号のみ平易な言葉に置換する。
- （自己解決）手順4/5 のコマンド名（`/issue-bootstrap` `/plan-issue` 等）と a/b/c の選択肢記号は、ユーザーが入力に使うため平易化の対象外として残す。説明文のみ平易化する。
- （自己解決）平易版ルールは原則の文章だけでなく、具体的な文例（変換前→変換後）つきで SKILL.md に明記する（「簡略化しすぎ」の再発防止・既存手順との粒度パリティ）。

## 背景/目的

### 現状の問題（証拠・再現手順）
`/retro`（`.claude/skills/retro/SKILL.md`）の**ユーザーへの説明・確認の出力**が分かりにくい。

具体的には SKILL.md 手順3の報告フォーマット・手順2.5 の 5 Whys 提示・手順4/5 の確認ガイドが、**内部用の専門用語・記号をそのままユーザーに提示**している:
- 「是正処置（Corrective）／予防処置（Preventive）」「5 Whys」「抽象化テスト」等の方法論用語
- 「C1」「P1」等の内部識別記号（表の # 列）
- 表形式に「根本原因／対象ファイル」等の内部管理列がそのまま並ぶ

再現手順:
1. 任意のイシューで `/retro I###` を実行する。
2. 手順3の報告・手順4/5 の確認が、上記の専門用語・記号を含んだまま提示される。
3. コンテキストを持たないユーザーには「結局どういうことか・何を選べばよいか」が読み取りにくい。

一方で、単純に短く要約すると**経緯・理由・判断根拠などの必要情報まで欠落**する失敗も起きた（I104 retro の同一セッションで実証）。つまり「用語をやさしく」と「情報を削る」が混同されている。

### 根本原因
retro SKILL.md が **「記録用の詳細フォーマット」と「ユーザーへの説明・確認フォーマット」を分離していない**。内部管理用の用語・記号・列構成を対ユーザー出力にそのまま流用しているため、①専門用語で分かりにくい／②それを避けようとすると情報を削ってしまう、という二律背反が起きる。対ユーザー出力の「平易さ」と「情報の完全性」を両立させる明示ルールが SKILL.md に無い。

### 解決方針
SKILL.md に**「対ユーザー要約（平易版）」の提示ルールを、記録フォーマットとは別に定義**する。原則:
- (a) 専門用語・内部記号は**平易な言葉に置換**する（省略ではない。例: 「予防処置」→「同じ問題を次回から防ぐ改善」、内部記号 C1/P1 は使わずに内容で示す）。
- (b) 各項目に**「何が・なぜ（経緯／理由）」を一言添える**。過度な要約で経緯・判断根拠を削ることを禁止する。
- (c) **記録ファイル（`docs/reviews/` 等）は現状の詳細フォーマットを維持**する（監査・引き継ぎのため）。＝「資料は詳細・対話は平易」を分離する。
- (d) 対話では**平易版を先に提示し、その後に詳細版（既存の内部管理フォーマットの表）を併記**する。retro への記録ファイル作成ステップの新設は行わない（/grill-me で確定）。
- (e) 5 Whys は**経過（Why の連鎖）の提示を維持**し、専門用語・内部記号のみ平易な言葉に置換する（分析ロジック自体は変更しない）。
- (f) コマンド名（`/issue-bootstrap` 等）と選択肢記号（a/b/c）はユーザーの入力に必要なため**平易化の対象外**とし、説明文のみ平易化する。

## スコープ
### 含む
- `/retro` の**対ユーザー説明・確認出力**を平易化するルールの SKILL.md への追加
- 「専門用語・記号は平易な言葉に置換」「経緯・理由は残す（過度な要約禁止）」「記録ファイルは詳細維持」の明文化
- 「平易版 → 詳細版の表」の併記順の明文化と、平易化の具体的な文例（変換前→変換後）の記載
### 含まない
- 記録ファイル（`docs/reviews/` 等）のフォーマット変更（詳細のまま維持）
- retro への記録ファイル作成ステップの新設（詳細版は対話内の併記で残す。/grill-me で確定）
- retro 以外のスキルの対ユーザー出力の平易化（必要なら別イシュー。ただし本イシューで確立した原則を横展開の雛形にしてよい）
- retro の分析ロジック（観点・5 Whys の内部手続き）自体の変更
