# I081: Bash 実行作法を規約化（allowlist 単体コマンド徹底・複合/パイプ禁止・未コミットファイルの安全な取り消し）

## 関連資料
- GitHub Issue: #161
- 起点: I079 振り返り（retro）の予防処置 P2・P4
- 関連: I079 対応中、複合コマンド・パイプ（`| tail`・`; echo "exit=$?"`・`&&`・inline heredoc）による承諾プロンプト多発、および `git checkout -- <file>` で未コミット実装を消失した事象
- 関連メモ（運用）: feedback_atomic_allowlisted_commands / feedback_use_read_tool_not_bash_for_files（個人記憶だが canonical 規約化が本イシューの目的）

## 設計確認メモ（/grill-me）
- Q: 複合/パイプは「禁止」か「原則単体・必要時許容」か → A: **原則 allowlist 単体コマンド**。検証目的で複合/パイプが本質的に必要な場合のみ許容し、その際プロンプトが出ることを受容（完全禁止ではなく「原則禁止・例外明示」）。
- Q: `git checkout/restore <file>` の取り消し規約は DANGER_OK ゲートか注意か → A: **注意ガイドライン**（毎回ゲート化はしない＝通常の revert を妨げない）。`danger-ops.md` の Git 項目に注記。
- Q: checkout のデータ消失をフックでも機械防止するか → A: **(B) する**。ただし **対象ファイルに未コミット変更がある場合の `git checkout/restore <file>` のみ** ブロック（`DANGER_OK=1` で迂回可）。clean なファイルの revert は素通し。複合/パイプの機械ブロックは引き続き非採用（正当用途があるため）。

### 設計確認メモ 第2回（フック検出ロジックの確定）
- Q: 「未コミット変更あり」の検出範囲はどのステータスか → A: **(a) ワークツリー変更（unstaged の `M`）のみを block 対象**。`git status --porcelain <path>` の worktree 列（2文字目）が変更を示す場合に block。**untracked（`??`）は対象外**（checkout/restore は消さない）。**`git restore --staged <file>`（index のみ・ワークツリー非消失）は素通し**。
- Q: `git checkout` のブランチ切替とファイル復元の判別ロジックは → A: **(b)**。`--` セパレータがある場合はその後ろを pathspec とみなす（`git checkout -- f.py` / `git checkout <branch> -- f.py`）。加えて `--` 無しでも**引数が実在し dirty なファイルパスに解決できる場合は復元扱いで判定**（`git checkout f.py` 形の消失も防ぐ）。それ以外の bare 引数はブランチ扱いで素通し。`git restore` は常にファイル指向のため無条件に判定対象。
- Q: 全体 pathspec（`git checkout .` / `git restore .` / `git restore -- .`）の扱いは → A: **いずれかのファイルが dirty なら block**（I079 の実消失に最も近いケースのため）。`git checkout -b` / `git switch` は素通し。
- Q: テストの false-green 検証方法は → A: **決定論シェルテスト**（`scripts/claude/tests/` に追加）で、(a) dirty ファイルへの checkout/restore が block（exit 2）、(b) clean ファイル・ブランチ切替が素通し（exit 0）の両方を確認。配置先・命名は既存テスト規約に合わせる。

## 背景/目的

### 現状の問題（証拠・再現手順）
1. **承諾プロンプト多発**: `.claude/settings.json` の allow は具体的な単体コマンド形（例 `git push -u origin *`・`bash scripts/claude/*`・`python3 -m json.tool *`）で定義されている。これに対しエージェントが `git push ... 2>&1 | tail -2`・`bash ...; echo "exit=$?"`・`sed ...; for ... head`・`python3 - <<PY` のように**複合化/パイプ/inline heredoc で束ねる**と、コマンド全体がどの単一 allow にも一致せず、より広い ask（例 `git push *`）にマッチして毎回プロンプトになる。I079 では同種が繰り返し発生し「承諾が多い」体感の主因になった。
2. **未コミット変更の消失**: 一時的なファイル内変更（テスト注入のコメント等）の取り消しに `git checkout/restore <file>` を使うと、**同ファイルの未コミット変更がすべて HEAD に戻され消失**する。I079 ではこれでフック実装（未コミット）を一度失い再実装した。

### 根本原因
エージェントのシェル実行作法（単体 allowlist コマンドで実行する／破壊的な取り消しを避ける）が **canonical なルール（runbook）として明文化されておらず**、個人記憶（feedback メモ）依存で生成時に抑止できていなかった。

### 解決方針
`docs/runbooks/common-commands.md` に実行作法（原則 allowlist 単体コマンド・必要時の複合は例外許容）を明文化、`danger-ops.md` に `git checkout/restore <file>` のデータ消失注意を追記し、レビュー観点（`.claude/review-agents/*.md`）に gate を追加する。さらに **`pretooluse_guard.py` に「対象ファイルに未コミット変更がある場合の `git checkout/restore <file>` を `DANGER_OK=1` 無しでは block」する判定を追加**（データ消失の機械防止）。複合/パイプの機械ブロックは非採用（正当用途のため規約＋レビューで担保）。

## スコープ
### 含む
- 上記 runbook への実行作法の明文化（原則単体・例外許容）
- レビューエージェントへの gate 観点追加
- `pretooluse_guard.py` への「未コミット変更（unstaged worktree 変更）ファイルへの `git checkout/restore` を DANGER_OK 無しで block」判定＋決定論テスト（dirty→block(exit2) / clean・ブランチ切替→素通し(exit0) の両方確認＝false-green でない）
### 含まない
- `.claude/settings.json` の permissions 変更（allowlist の拡張は I079/I080 の範疇）
- フック（pretooluse_guard.py）での**コマンド複合/パイプ**の機械ブロック（パイプは正当用途があり強制ブロックは逆効果のため非採用。retro で評価済み）。フックで防止するのは checkout のデータ消失のみ
