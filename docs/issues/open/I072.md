# I072: 否定・回帰系の決定論テストの false-green を検出するゲートを文書品質ゲート・P4観点に追加する

## 関連資料
- GitHub Issue: #148
- 発生源: I071 retro（`docs/reviews/I071_retro_20260621.md` 予防処置 #1・#2）
- 既存の近接ゲート: `docs/runbooks/plan-writing-rules.md`「文書品質ゲート」の項目「lint / 静的解析ツールの異常系テストがある場合、インプットコードを対象ツールで実際に実行し非ゼロ終了することを確認済みか」
- 既存の近接観点: `.claude/review-agents/plan-reviewer.md` P4「CLI フラグ…のフラグの振る舞い自体を検証するテストケースがあるか（文字列一致確認だけでは不十分）」
- 目標運用モデル: 検証は ①手続き < ②決定論ゲート < ③敵対的検証（false-green は「見かけ上のゲート・実体は手続き未満」）

## 設計確認メモ（/grill-me）
**grill-me I072 で確定（2026-06-21）。**

- **Q1（do層の配置先）→ A: 両方に置く（根治）。** 調査の結果、**「文書品質ゲート」チェックリスト（lint 異常系項目を含む）の実体は `.claude/skills/plan-issue/SKILL.md`（L169）にのみ存在し、`docs/runbooks/plan-writing-rules.md` には無い**ことが判明（当初イシューの「plan-writing-rules が正本／SKILL は転記分」という前提は逆だった）。よって do層は次の2箇所に置く: ①`plan-writing-rules.md` の TC ルール群（「検証コマンドを書かない」等の近く）に**一般原則を新規追加**して runbook を正本化する、②`.claude/skills/plan-issue/SKILL.md` の既存 lint 異常系項目（L169）を**一般形へ更新**して強制チェックとする。両者は粒度パリティを保つ。
- **Q2（do層チェックの対象範囲）→ A（既定で決定）: 否定・不在・回帰・無改変を検証する決定論 TC を中核**とし、文言は「**失敗条件を注入して実際に不合格（NG）になることを確認**」とする。全 TC 一律ではなく false-green リスク階級に焦点を当てる（同語反復な肯定アサーション＝常時真も同一文言で捕捉される）。

## 背景/目的

### 現状の問題（証拠・再現手順）
決定論的な合否判定テスト（grep ベースの TC 等）のうち、**否定・不在・回帰・無改変を検証するアサーション**が、検証対象が壊れても合格（OK）を返す **false-green** 状態のまま提出されることがある。

I071 で実際に発生した2例（plan-reviewer が指摘・後に修正済み）:
- `grep -q 'VERDICT: <BLOCKER\|HIGHRISK\|OK>'` … BRE で `\|` が OR となり「HIGHRISK」部分一致で常に通過（テンプレート行が改変されても検出できない）。
- `for n in ...; do grep -q ... || { echo NG; break; }; done; echo OK` … break 後も末尾 `echo OK` が無条件実行され、見出しが削除されても OK を返す。

これらは「正常時に OK を返す」ことだけ確認され、「**異常時に NG を返す**」ことが未検証だった。現行ゲートは正常系の期待値記載は要求するが、否定・回帰系 TC に対し失敗注入での不合格確認を要求していない。

### 根本原因
（I071 retro で特定）決定論的な合否判定 TC（特に否定・不在・回帰アサーション）について、**失敗条件を注入して実際に不合格を出すことを検証する**、という要求がゲートに一般化された形で存在しない。既存ゲート（`plan-issue/SKILL.md` の文書品質ゲート）は「lint / 静的解析ツールの異常系」という特定ケースにのみ異常系実行を求めており、grep / 存在否定 / 無改変確認など一般の決定論 TC へ一般化されていない。加えて、この原則は `plan-writing-rules.md`（計画書・テスト文書の書き方の正本）には記載が無く、SKILL の checklist のみに留まっている。

### 解決方針
do（提出前の自己検証）と gate（レビューでの捕捉）の2層で再発を防ぐ。do層は **runbook（正本）＋ SKILL（強制チェック）の両方**に置く（grill-me Q1 で確定）。
- **(do層・正本)** `plan-writing-rules.md` の TC ルール群に**一般原則を新規追加**: 「否定・不在・回帰・無改変を検証する決定論 TC は、失敗条件を注入して実際に不合格（NG）になることを確認してから採用する（false-green の禁止）」。
- **(do層・強制チェック)** `plan-issue/SKILL.md` の文書品質ゲートの既存 lint 異常系項目（L169）を**一般形へ更新**し、lint 異常系をその特例として包含する。
- **(gate層)** review-agent（plan-reviewer・code-reviewer）の P4 テスト妥当性観点に「合否判定 TC（否定・回帰・不在アサーション）が失敗条件で実際に不合格を出すか（常時 OK の false-green でないか）」を追加。
- 文言は I071 固有語（grep・P9 等）を含まない一般形で記述する。
