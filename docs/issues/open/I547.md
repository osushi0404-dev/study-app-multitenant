## 背景/目的

**背景**: レビュー役（計画・コード・敵対的・診断・イシューのレビュー）への指示は、Claude が実際に従う文章で、作業の質を直接決める。イシューごとの振り返りで継ぎ足されてきた。今の公式の書き方（Claude Code のサブエージェントの書き方、Anthropic のプロンプトの書き方の推奨）に照らした全体の見直しはしていない。振り返りからの観点の追加の案も、このイシューに 8 件溜まっている（下の「同梱」）。
**目的**: `.claude/agents/` の 5 つのレビュー役の指示を、今の時点で BP として「あるべき状態」にする。
1. **最新化**: Claude Code のサブエージェントの今の公式の書き方（前置きの項目・道具の指定・モデルの指定など）と、Anthropic のプロンプトの書き方の推奨に照らして直す
2. **漏れ**: レビュー役の観点に足りないもの（このリポジトリで過去にすり抜けたバグ・指摘の種類）を足す
3. **最適化**: レビュー役間の重複・矛盾・冗長な指示を整理し、手順書（`docs/runbooks/`）・規約（`rules/`）と二重に書いている内容は正の置き場所を 1 つにする

### 根本原因
- 公式の書き方（サブエージェント・プロンプト）の変化に気づいて指示に戻す工程が無い
- 同じ決まりをレビュー役と手順書・規約のどちらに書くか（正の置き場所）が決まっておらず、振り返りのたびに近い場所へ継ぎ足している
- 全体を通した見直しをしていないので、継ぎ足しの重複・矛盾が残る

### 解決方針
1. 5 つのレビュー役の全部について、公式の文書（Claude Code のサブエージェントの書き方・Anthropic のプロンプトの書き方）に照らして点検し、ファイルごと・節ごとに「そのまま／直す／消す／足す」と根拠を表にする
2. 観点の漏れは、上の「同梱」の A・B・D・E・F と、このリポジトリで過去にレビューをすり抜けたバグ・指摘の種類（`docs/reviews/closed/` の retro・`bug` ラベルのイシュー）から洗い出す。足す観点には、すり抜けた実例を根拠として添える
3. 正の置き場所: 決まり（何をしてよい・いけない・条件）は手順書・規約に置き、レビュー役は「何を見て、どう判定するか」と参照を持つ。写しは参照に置き換える（同梱 C）。手順書・規約側に追記が要るなら本イシューで足す（I545・I546 は閉じている。同梱 E・F・H の 1 文ずつ）
4. 公式の機能で置き換えられる手作りの仕組みは #427 に回す（本イシューでは書き換えない）
5. 今のモデルで要らなくなった部品は「外す候補」として表に挙げるだけにし、実際に外すのは #594 で測ってから（同梱 H）
6. 指示を増やすことが目的ではない。足すのは「気づきにくく被害が大きい」ものに限り、足す分だけ重複・冗長を刈る（同梱 G）
7. 点検して問題が無かったものは「そのまま」と記録して終える
