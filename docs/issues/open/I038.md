# I038: retro スキル改善: 5 Whys 導入・予防処置フロー整備

## 関連資料
- I029 retro 議論（2026-04-08）: 個別事象にとどまらない根本原因分析と予防処置の抽象化が必要
- GitHub Issue: #64
- Draft PR: #65

## 背景/目的
- 現在の `/retro` スキルは「成果・プロセス・技術」のカテゴリ表と改善案テーブルを出力するが、改善案が個別事象にしか適用できないものにとどまりやすい
- 根本原因を掘り下げる手法（5 Whys 等）がなく、表面的な再発防止策になりがち
- 是正処置（今回限りの修正）と予防処置（ルール・仕組みの変更）が混在していて、予防処置を issue → plan という正規フローで対応する仕組みがない

## スコープ
### 含む
- `/retro` SKILL.md に 5 Whys ステップを追加（各改善項目に対して根本原因を深掘り）
- 是正処置（corrective）と予防処置（preventive）を別テーブルに分離
- 予防処置がある場合、`/issue-bootstrap` → `/plan-issue` の正規フローを経由するルールを明記
- ドキュメント更新（workflow.md / issue-flow.md）が必要な場合は plan-issue を使うルールを明記
- 資料更新内容の提示・承認を必須化（スキル内に承認ゲートを追加）

### 含まない
- `/retro` 以外のスキル変更
- issue-bootstrap / plan-issue の責務変更（I037 で対応）

## 受け入れ条件（Acceptance Criteria）
- [ ] `/retro` を実行すると各改善候補に対して 5 Whys（少なくとも 3 回以上の Why）が提示される
- [ ] 是正処置と予防処置が別テーブルで明示される
- [ ] 予防処置に「issue 化」または「ルール・ドキュメント更新」が含まれる場合、`/issue-bootstrap` 実行を促すガイドが表示される
- [ ] 資料更新内容（SKILL.md の変更案等）を提示してユーザー承認を得てから書き込む

- Frontend: なし
- DB: なし
- Config/Infra: `.claude/skills/retro/SKILL.md`
