## 背景/目的

**背景**: I587 で、問題・解説の画像をファイル（`backend/media`）から DB（`MediaAssetContent`）に移した。I590・I602 で残りを片付けた。app-1 では移行 0024〜0027 がすべて流れ、`backend/media` も画像用の保存領域も無い。一方、ほかのワークツリーは確かめていなかった（2026-11-20 時点でコンテナが止まっている）。
**目的**: すべてのワークツリーで、古い画像ファイルと移行前の DB を残さない状態にする。primary は画像の移行を安全に終えて画像が画面に出る状態にし、harness-1・harness-2 は DB（と画像ファイル）を捨てて作り直せる状態にし、study はファイルを消す。

- 各 DB で 0024〜0027 が流れたかは未確認（コンテナが止まっているため）
- backend のコンテナは起動のたびに `migrate` を流す（`docker-compose.yml` の backend の `command`）。そのため、次にそのワークツリーで develop を取り込んでアプリを起動すると、控えを取らないまま次の移行が流れる:
  - 0025: ファイルがある画像は DB に移す。ファイルの無い画像の行と紐づけは消す（ファイルそのものは消さない）
  - 0026: 問題の古い画像の列に値があれば止まる
  - 0027: 科目の `image_directory` に値があれば止まる（止まると backend が起動しない）

### 根本原因
- I587 の計画で、移行の確かめと片付けを app-1 だけで行い、ほかのワークツリーの DB とファイルは「未確認」のまま受け入れた（R6）。ワークツリーごとに DB とファイルが別であることを、片付けの範囲に入れていなかった
- 0025 はファイルを DB に移すが、元のファイルを消さない（戻すとき〔`write_back_media_files`〕のために残す設計）。消す工程が別に要る

### 解決方針
I605 1 本で、primary → harness-1 → harness-2 → study の順に回る。それぞれのワークツリーのセッションで行う（別のワークツリーには書き込めない・`docs/runbooks/worktree.md` §9）。結果は I605 の記録にまとめる。

**primary（丁寧に移す）**: 次の順で進める。
1. 控え: DB だけを起こし（`docker compose up -d --wait db`）、`bash scripts/claude/db-backup.sh I605_before_primary` で控えを取る。backend は起こさない（起こすと控えの前に移行が流れる）
2. 確かめ: 流す前に、`image_directory` に値のある科目・古い画像の列に値のある問題・ファイルの無い画像の行の件数を数える（backend を起こさずに数える。候補: DB だけを起こした状態で `docker compose exec -T db psql -U postgres -d learning_app -c "SELECT …"`。確定は計画で決める）。消える行・止まる移行が分かったら、人の承認を得る
3. 移行: backend を起こして移行を流す。0026・0027 で止まったら、手順書（`docs/runbooks/backend-check.md` §4）どおりに値を空にして流し直す（人の承認の後）。`migrate` の出力の `I587 media: moved=… already=… deleted_assets=… deleted_links=…` を記録する
4. 確かめ: 画像のある問題を画面で開き、画像が出ることを確かめる。移した件数が、ファイルの数と合うことを確かめる
5. ファイルを消す: 4 が済んだら、primary の `backend/media` を消す（人の承認の後）
6. 控えを消す: 5 の後に、1 の控えを消す（控えは移行の前の写しで、画像の中身を含まない。5 の後は控えから画像を戻せないので、残す意味が無い。`docs/runbooks/danger-ops.md` の決まりどおり早めに消す）。控えを消すと移行の前の DB に戻す手段も無くなるので、5 の承認のときにそのことも伝える

**harness-1・harness-2（捨てて作り直す）**: コンテナを止めたまま、DB の保存領域（`harness-1_postgres_data`・`harness-2_postgres_data`）を消す。harness-2 は `backend/media` も消す（harness-1 は元から無い）。人の承認の後・控えは取らない。移行・画面の確かめはしない。次にそのワークツリーで develop を取り込んで起動したとき、空の DB に全部の移行が流れる（develop の取り込みは待たない）。

**study（ファイルを消すだけ）**: DB が無いので DB の手順は無い。`backend/media` の 18 個の一覧を記録に残し、確かめを増やさずに消す（人の承認の後）。

- 記録は、このイシューの計画で作るテスト文書（`docs/tests/`）にワークツリーごとの行で残す

## Danger Ops（有/無）
- 有
- 何を: primary の開発の DB で 0025（ファイルの無い画像の行と紐づけの削除）・0026／0027（列の削除）を流す。止まったときは値を空にする（UPDATE）。harness-1・harness-2 の DB の保存領域を消す。各ワークツリーの `backend/media` のファイルを消す
