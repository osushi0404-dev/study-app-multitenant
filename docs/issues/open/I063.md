## 背景/目的

### 現状の問題（証拠・再現手順）
ワークフローの3ステージに、後工程で初めて顕在化する見落としを生む検証ギャップがある:

1. **implement 完了時にコミット・push 検証がない（→ 空 diff で後工程が破綻）**: 実装内容が作業ツリーに存在するだけで「実装済み」と扱われ、ブランチ未コミットのまま `/code-review` へ渡ると `git diff origin/develop...HEAD` が空になり、レビューが「未実装/Blocker」と判定する。
   - 実害例: I060 で D1〜D15 が作業ツリーにあるだけで未コミットのまま code-review に進み、空 diff Blocker になった（人手でコミットして救済）。
2. **ドキュメント整合系イシューで参照先の実在性を全件機械検証していない（→ 不在パス参照の取りこぼし）**: 棚卸し・整合系の計画がエージェント読解中心で、文書内のパス/ファイル/ディレクトリ参照が実在するかを `test -f`/`ls` で全件検証していない。
   - 実害例: I060 で実在しないディレクトリ `in_progress/` への参照（複数 runbook）を初回計画 D1〜D15 で取りこぼし、D16 として後追いになった。
3. **grill-me が scope/AC を左右する scan/lint ツールを実行せず概算で AC を確定（→ 達成不可 AC）**: 個別バージョン照会（`npm view` 等）だけで設計値を決め、ツール全体の依存固着・修正可否を把握しないまま完了基準を確定してしまう。
   - 実害例: I061 で grill-me が「監査 high ゼロ」を AC に設定したが、`npm audit --json` を plan で実行したところ react-scripts 固着で達成不可と判明し AC を覆した。
4. **grill-me が設計確認メモを*追記*するだけで、確定した決定と矛盾する既存セクションを整合させない（→ イシュー内に矛盾が残る）**: grill-me の手順4は「`## 設計確認メモ` をイシューに追記する」のみで、決定に伴って `解決方針`/`スコープ`/`実装対象`/`AC` を整合更新する手順がない。結果、本文に grill 前の「どちらか／併用（未確定）」表現が残り、メモ（確定）と矛盾する。コンテキストを持たない担当者が本文を読むと方式未決と誤読し得る。
   - 実害例: I062 で grill-me 後、設計確認メモは確定値だったが `解決方針`/`スコープ` が「(a)/(b) どちらか」「上記3ファイル」のまま残り、別途手作業で整合を取った。
5. **grill-me が GitHub イシュー本文を同期しない（→ GitHub とローカルが乖離）**: grill-me の手順4はローカル issue ファイルのみ更新し、`gh issue edit` で GitHub 本文を更新しない。GitHub 本文は `/issue-bootstrap` 時点のスナップショットで固定され、grill-me の決定（メモ・整合）が GitHub に反映されない。
   - 実害例: I062/I063 で grill-me 後、GitHub #128/#129 が作成時のままだったため手作業で `gh issue edit` 同期した。

### 根本原因
- 各スキルの**完了/着手条件が「中間成果（編集・ビルド pass・概算）」止まりで、最終的に効く検証（git 反映・参照実在性・ツール実行結果）を必須ステップに含めていない**。後工程に検証を委ねているため、手戻りコストが大きいステージで初めて顕在化する。

### 解決方針
スキルの該当ステップに、機械的に実行可能な検証を**必須ステップ**として追加する（行動指針でなく手順として明記）:
1. **implement 完了検証（失敗時ハード STOP・Q1）**: 完了宣言の前に「`git diff origin/develop...HEAD --name-only` に意図した変更ファイルが現れること」を確認する手順を手順3〜4間に追加。現れない場合は**完了案内を出さず停止**して未コミット/未 push の可能性を報告する。
2. **ドキュメント参照実在性検証（Q3: plan-writing-rules.md に配置）**: `plan-writing-rules.md`「計画書作成前の事前調査（必須）」に「文書内のパス/ファイル/ディレクトリ参照を抽出し `test -f`/`ls` で実在性を全件検証する」手順を追加（`plan-issue/SKILL.md` には入れない）。
3. **grill-me ツール実行**: grill-me の必須確認に「scope/AC が lint/audit/scan/型チェック等ツールの出力で決まるイシューでは、概算でなく対象ツールを実際に実行して全件分類し、達成可能な完了基準を確定してから AC を記録する」観点を追加。
4. **grill-me 本文整合**: grill-me の手順4（設計確認メモの追記）に「**追記した決定値と矛盾する既存セクション（解決方針・スコープ・実装対象・受け入れ条件）を同じ決定値に整合更新する**」手順を追加する（`plan-writing-rules.md` の「ルール変更時に関連ファイルを同時更新する」不変条件を、イシュー本文内のセクション間にも適用する）。
5. **grill-me GitHub 同期**: grill-me の手順4の末尾に「**本文整合の後、`gh issue edit <GitHub#> --body "$(cat docs/issues/open/IXXX.md)"` で GitHub イシュー本文をローカルと同期する。`gh` 不可環境では skip（非ブロック・警告のみ）**」を追加する。
