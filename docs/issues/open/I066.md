## 背景/目的

### 現状の問題（証拠・再現手順）

1. **高リスク判定の“保険”経路が常に空振り（silent・最も危険）**
   - `scripts/claude/plan-issue-review.sh` の高リスク検出 `grep -qiE "高リスク判定.*Yes"` は**行単位**マッチだが、レビュー出力は `## 高リスク判定`（見出し行）と `判定: Yes`/`No`（本文行）が**別行**構成。
   - 証拠: 実出力 `docs/reviews/I062_plan_review_20260616_0055.md` で 17行目 `## 高リスク判定` / 18行目 `判定: No`。`grep -c '高リスク判定.*Yes'` = **0**。
   - 影響: 真に高リスクな計画でも `/security-review` 案内が出ず `/implement` 直行する（スクリプトは正常終了し「✅ /implement」と表示するため気づけない）。
   - 注: I062（#133）で `VERDICT: HIGHRISK` 一次判定を導入したため**新形式レビューは救済済み**。本イシューは**固定判定行が無い場合の保険経路**を多行対応にして二段構えを完成させる。

2. **生成レビュー成果物が close でアーカイブされない（systemic）**
   - `code-review.sh` / `plan-issue-review.sh` は `REVIEW_FILE="docs/reviews/${ISSUE}_..._${TIMESTAMP}.md"`（**flat 直下**）に保存。一方 `/close`（`.claude/skills/close`）step1 は `docs/reviews/open/` のみ closed へ移動する。
   - 証拠: flat 直下に dated review が **60件**堆積、`docs/reviews/closed/` の dated review は **0件**（`ls docs/reviews/closed/*_code_review_*.md *_plan_review_*.md` = 0）。I062 でも6件が flat 残留、closed へ移ったのは雛形 `I062_review.md` のみ。
   - 「生成物の保存先（flat）」「close の回収対象（open/）」「`find_file` の探索先（open/closed）」が三者不整合。

3. **plan-issue-review.sh が再実行ごとに計画書へ「## レビュー結果」を重複追記（非冪等）**
   - 証拠: `docs/plans/closed/plan_I062.md` の 293/296/299 行目に**3つの重複**「## レビュー結果」セクション（plan-review を3回実行したため）。

### 根本原因
- ワークフロー・スクリプトの**分岐・検出ロジックが一度もテストで検証されていない**ため、行単位 grep の多行ミスマッチ（dead branch）や、保存先と回収先の不整合が長期間 silent に放置された。
- I062 で code/plan-review 判定はユニットテストで守られるようになったが、**高リスク保険・close のアーカイブ・追記冪等性は未カバー**。

### 解決方針（詳細は grill-me で確定）
1. 高リスク保険判定を**多行対応**にする（`## 高リスク判定` ブロック内の `判定: Yes` を `awk` 範囲指定 or `grep -A` で検出）。VERDICT 一次経路は I062 実装済みのため保険のみ補修。
2. レビュー成果物の保存先と回収を整合させる。**方針候補（grill-me で1つ選定）**:
   - (a) スクリプトの保存先を `docs/reviews/open/` に変更し、`/close` の既存 `docs/reviews/open/` 回収に乗せる
   - (b) 保存先は flat のまま、`/close` step1 に flat dated review（`docs/reviews/${ISSUE}_*_review_*.md`）の closed 回収を追加する
   - 既存60件の堆積整理方針（一括移動するか・対象範囲）も併せて決定（**大量 move のため Danger Ops 確認対象**）。
3. `plan-issue-review.sh` の計画書追記を**冪等化**（既存「## レビュー結果」セクションがあれば追記でなく当該行を追加/置換、もしくは重複ヘッダを作らない）。
4. 上記分岐を I062 の source ガード＋`test_review_verdict.sh` 系**ユニットテストで固定**（多行高リスク検出・冪等追記・close 回収の回帰）。
