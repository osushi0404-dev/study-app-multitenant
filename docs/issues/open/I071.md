# I071: レビュー観点に P9(プライバシー・コンプライアンス)を追加し設計思想 C2 を検知可能にする

## 設計確認メモ（/grill-me）
**判定基準＝「最適・理想」。grill-me I071 で確定（2026-06-20）。**

- **Q1（P9 として「学習効果」を観点化するか）→ A: 観点化しない（含めない）。** 学習効果(C1)は開発・レビュー時点で検証できる性質のものではなく、**リリース後の学習成果・KPI（定着率・正答率・継続率）の計測で経験的に検証すべき領域**。よってレビュー観点(P)として持たない。これは**ギャップではなく意図的な設計判断**。→ 整理: **設計思想の全基準が必ずレビュー観点に1対1対応するわけではない**（C1 は運用・計測で品質担保し、レビュー観点は持たない）。
- **Q2（プライバシー/コンプラの観点番号）→ A: P9。** 学習効果を観点化しないため新規観点は1つ。P8 の次の **P9＝プライバシー・コンプライアンス**として確定（当初案「P9学習効果・P10プライバシー」から変更）。
- **Q3（P9 と P2 の境界・高リスク接続）→ A: OK。** **P2＝「攻撃者を防ぐ」**（認証認可・脆弱性・技術的テナント境界防御）。**P9＝「正常稼働時でも適法・適正に扱う」**（同意取得・保持期間・削除権・**未成年データ配慮**・データ所有権＝学校/企業が管理者・目的外利用禁止・ポリシー面のテナント分離）。**P9 のうち未成年データ・個人情報の越境は I043 の高リスク判定に接続**し `/security-review`（I044）の対象に含める。

## 背景/目的

### 現状の問題（証拠・再現手順）
設計思想（`learning_app_quality_criteria.md` の C1〜C8）のうち、**C2(プライバシー/コンプライアンス) に対応するレビュー観点 P が存在しない**。

- `review_perspective_framework.md` の観点は P1〜P8。設計思想文書 §6 の C↔P 対応表でも、対応が付くのは C4↔P1・C8↔P2・C7↔P5・C3↔P6 の4組のみで、**C2 は対応 P が空欄**。
- そのため plan-reviewer / code-reviewer（`### P〇.` 観点でレビュー）が、**C2 の違反（同意なき個人情報利用・保持期間超過・削除権の無視・未成年データ配慮漏れ・ポリシー面のテナント混在等）を構造的に検知できない**。
- なお C1(学習効果) も対応 P がないが、これは本イシューで**意図的に観点化しない**と確定（設計確認メモ Q1）。本イシューが扱うのは C2 のみ。

### 根本原因
レビュー観点フレームワーク（P1〜P8）は I043〜I046 で整備されたが、その後に策定した設計思想（C1〜C8）の C2 が**観点側に反映されていない**。設計思想とレビュー観点が同期しておらず、レビューが C2 をカバーできていない。

### 解決方針
レビュー観点フレームワークに **P9 プライバシー・コンプライアンス**を新設し、C2 を検知可能にする。
- **P9 の確認項目**（C2 対応）: 同意取得・保持期間・削除権（データ主体の権利）・未成年データ配慮・データ所有権（学校/企業が管理者）・目的外利用禁止・ポリシー面のテナント分離（横断データ混在の禁止）。
- **P2 との境界を明記**: P2＝「攻撃者を防ぐ」、P9＝「正常稼働時でも適法・適正に扱う」。二重チェック・抜けを防ぐ。
- **高リスク接続**: P9 のうち未成年データ・個人情報の越境は I043 の高リスク判定に接続し `/security-review`（I044）対象とする。
- **学習効果(C1) は観点化しない**ことを設計思想文書 §6 と framework に明記（意図的・開発時検証不能・KPI 計測で担保）。
- P9 を**消費箇所（review-agents・plan-issue/implement スキル）に全件反映**する（`plan-writing-rules.md` の「消費箇所の全件列挙」を適用）。
