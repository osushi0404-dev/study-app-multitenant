# I044: /security-review スキルを新設する（高リスク変更の実装前セキュリティ深掘り）

## 関連資料
- 提案資料: docs/proposals/review_design_proposal.md
- 先行イシュー: I043（高リスク判定の出力追加）
- GitHub Issue: #91
- Draft PR: #93

## 背景/目的

**背景**: セキュリティ確認が /plan-issue-review の表層チェックと実装後の /code-review の 2 点しかなく、高リスク変更を設計レベルで実装前に深掘りする仕組みが無かった（提案資料 review_design_proposal.md・先行 I043 の高リスク判定出力が前提）。
**目的**: /security-review スキルを新設し、高リスク判定 Yes の変更に対して /implement 前にセキュリティ設計・攻撃シナリオの深掘りレビューが実行される状態にする。

現行フローでは、セキュリティの確認が `/plan-issue-review`（表層チェック）と `/code-review`（実装後）の2点にしか存在しない。

- `/plan-issue-review` は「認可要件が計画書に明示されているか」等の表層チェックに留まる。
- `/code-review` は実装後のため、設計上の問題を発見してもコスト高なリワークが発生する。

認証・認可変更、マルチテナント境界変更、外部公開API追加など高リスク変更では、**実装前に設計レベルで深掘りする**ことで事故を防ぐ必要がある。

`/security-review` を新設し、`/plan-issue-review` での高リスク判定 Yes 時に `/implement` 前に実行するスキルとして追加する。セキュリティ設計レビューと攻撃シナリオレビューを1スキルに統合する。

## スコープ
### 含む
- `/security-review` スキルの新設（`.claude/skills/security-review/SKILL.md`）
- セキュリティ設計観点（設計上の重大リスク・実装上の禁止事項・必須の防御条件）
- 攻撃シナリオ観点（入口・想定権限・想定操作・守るべき条件・自動テスト化対象・残余リスク）
- レビュー結果を計画書の `## セキュリティレビュー結果` セクションに追記する手順
- Blocker が残っている場合は次工程（`/implement`）へ進まない停止条件
- `/retro` スキルに「残余リスクの処遇決定」と「設計ルール昇格の検討」観点を追加
- `docs/runbooks/workflow.md` の高リスク変更フローに `/security-review` を追記

### 含まない
- plan_*.md テンプレートの変更（`## セキュリティレビュー結果` セクションの追加は `/security-review` スキルの手順内で指示する）
- 既存イシューへの遡及適用

## 受け入れ条件（Acceptance Criteria）

- [ ] `.claude/skills/security-review/SKILL.md` が存在する
- [ ] スキルの入力として計画書・イシュー・権限モデル・DB変更案を読む手順が含まれる
- [ ] セキュリティ設計観点の出力（設計上の重大リスク・実装上の禁止事項・必須の防御条件）が定義されている
- [ ] 攻撃シナリオ観点の出力（入口・想定権限・想定操作・守るべき条件・自動テスト化対象・手動確認対象・残余リスク）が定義されている
- [ ] 出力に重大度区分（Blocker/High/Medium/Low）の列が含まれる
- [ ] Blocker が残っている場合は STOP し `/implement` を案内しない停止条件が明記されている
- [ ] レビュー結果を計画書末尾の `## セキュリティレビュー結果` セクションに追記する手順が含まれる
- [ ] `/retro` の振り返り観点に「残余リスクの処遇（High以上はイシュー化・Medium以下は任意）」が追加されている
- [ ] `/retro` の振り返り観点に「今回の security-review の発見を設計ルールに昇格できるか」が追加されている
- [ ] `docs/runbooks/workflow.md` のフロー説明に「高リスク判定 Yes の場合は `/security-review` を実行」が追記されている
- [ ] スキルファイルが Claude Code ベストプラクティスに準拠している（allowed-tools 最小権限・disable-model-invocation・argument-hint・description・500行以内）
