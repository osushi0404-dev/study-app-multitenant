## 設計確認メモ（/grill-me）
- Q: オフセット機構の実装方式 → A: 直下 `.env`（gitignore 済み・compose が変数展開に自動読込）方式を採用。`docker-compose.override.yml` 方式は不採用。責務分担＝テンプレは `docker-compose.yml`／確定値は worktree 直下 `.env`／割当は `scripts/claude/wt-new.sh`。
- Q: 変数化する対象サービス → A: db/redis/backend/frontend の 4 サービス。nginx（80/443）は production profile で既定 up 対象外かつ並行 dev に不要なため対象外（本番同時起動を支援する誤解回避・消費者不在）。
- Q: ポート変数の持たせ方 → A: `DB_PORT`/`REDIS_PORT`/`BACKEND_PORT`/`FRONTEND_PORT` の 4 個別変数、既定＝現行値（5432/6379/8000/3000）。`${}` が算術不可のため一括 offset 変数は採らずサービスごとの完全ポート値を持つ。
- Q: オフセットの割り当てと wt-new 連携 → A: `scripts/claude/wt-new.sh` に `--port-offset N` を追加。未指定時は `git worktree list` で既存 `.env` を走査し空きオフセット=max+STEP(10) を自動割当。衝突時は fail（決定論ゲート）。確定ポートを直下 `.env` に生成・表示。port=base+offset。
- Q: 同時 up 非衝突（AC#2）の検証方法 → A: 決定論テスト①=wt-new のオフセット/衝突ロジック（docker 不要・常時実行）＋②=`docker compose config` レンダリングで publish ポート重複なしを assert（docker 無しは skip）。手動 2 worktree 同時 up は任意スモーク。完了ゲートは決定論テスト①②。
- 自己解決: frontend↔backend は docker 内部ネットワーク（`frontend/src/setupProxy.js` の `BACKEND_URL=http://backend:8000`・`REACT_APP_API_BASE_URL` 空）で接続するためホスト publish ポートのオフセットで壊れない → `frontend/.env.*`・`frontend/src/setupProxy.js` は変更不要。e2e も内部ネットワークのため影響なし。
- Q(2回目): `COMPOSE_PROJECT_NAME` を生成 `.env` に書くか → A: 書かない。既定（ディレクトリ名）で既にコンテナ/volume が分離され AC#3 を満たすため。`wt-new.sh` は設定せず、既存の §5C（global export 警告）で foot-gun を防ぐ方針を維持。
- 検証(2回目・docker compose v5.1.0 実走): throwaway compose で `docker compose config` が **daemon 無しでレンダリング**し、変数未設定＝現行ポート／直下 `.env` の `BACKEND_PORT=8010` で published が 8010 に変わる（`.env` は compose ファイルのディレクトリ＝worktree root から読込）ことを確認 → **AC#2/#5・決定論テスト② は達成可能**と確定。

## 背景/目的

### 現状の問題（証拠・再現手順）
worktree ごとにコンテナ・named volume は分離されるが、**ホストのポートは共有**される。`docker-compose.yml` の db/redis/backend/frontend（および production profile の nginx）は**固定のホストポート**を publish している（`ports:` がハードコード）。

- 固定ポート: db 5432 / redis 6379 / backend 8000 / frontend 3000（`worktree.md` §6 の表と `docker-compose.yml` の実査で一致）。
- 再現: 2 つの worktree で同時に `docker compose up` すると、これらのポートが衝突して片方が起動に失敗する。
- 現状の回避（§6）: 「同時に up せず 1 スタックずつ」「切り替え時は使わない方を `docker compose down`」という**人手規律**。§6 自身が「同時起動が必要なら compose override でポートと `COMPOSE_PROJECT_NAME` を変える／ただしポートは環境変数でテンプレート化されておらず compose 編集が要るため本 runbook の対象外・別イシューで仕組み化する」と繰り越している。

### 根本原因
`docker-compose.yml` のホストポートが**環境変数でテンプレート化されておらず**、worktree ごとにオフセットできない。このため worktree の本来の狙い（複数トラックの**並行**作業）が「編集は並行できるが**スタックの同時起動・同時テストはできない**」という形で制約される。

### 解決方針（/grill-me 確定）
ポートを環境変数化し、worktree ごとに**直下 `.env`（gitignore 済み・非共有）**で分離することで**同時 up を可能**にする（`COMPOSE_PROJECT_NAME` によるコンテナ/volume 分離は既存で機能しているため、残る衝突点＝ポートを解消する）。責務分担＝**テンプレート構造は `docker-compose.yml`／確定ポート値は worktree ごとの直下 `.env`／割当ロジックは `wt-new.sh`**。compose override ファイル方式は採らない。
1. `docker-compose.yml` の db/redis/backend/frontend のホストポートを `${DB_PORT:-5432}` `${REDIS_PORT:-6379}` `${BACKEND_PORT:-8000}` `${FRONTEND_PORT:-3000}` の**既定値付き環境変数**に置き換える（既定値＝現行値＝後方互換。`${}` は算術不可のため一括 offset ではなくサービスごとの完全ポート値変数とする。nginx は対象外）。
2. worktree ごとの直下 `.env` に確定ポートを持たせる。人間が扱う「オフセット」は `wt-new.sh` の 1 ノブに集約し、`.env` には展開後の確定値を明示。追跡ファイル `.env.example` に 4 変数・既定値・オフセット規約を記載して非 wt-new 起動でも自己文書化する。
3. `wt-new.sh` を改修し、`git worktree list` で既存 worktree の `.env` を走査して空きオフセット（STEP=10）を**自動割当**（未指定時）。`--port-offset N` で明示上書き可。割当先が既存と衝突する場合は **fail（決定論ゲート）**。生成した確定ポートを直下 `.env` に書き出し表示。
4. `worktree.md` §6 を「同時起動可能」に更新し、`common-commands.md` にポート変数・同時 up 手順を追記。

## スコープ
### 含む
- `docker-compose.yml` の db/redis/backend/frontend ホストポートの環境変数化（既定値＝現行値で後方互換）と `.env.example` 追加。
- worktree ごとのポートオフセット運用の定義（直下 `.env`）と runbook 反映。
- `wt-new.sh` への自動オフセット割当・衝突 fail（決定論ゲート）・`.env` 生成の実装。
- 同時 up がポート衝突しないことの決定論テスト（①ロジック②`docker compose config` レンダリング）と任意の手動スモーク。

### 含まない
- コンテナ内部ポートの変更（内部は固定のまま・ホスト publish のみ可変化）。
- nginx（80/443・production profile）のポート変数化および本番同時起動対応（並行 dev に不要・消費者不在）。
- compose override ファイル（`docker-compose.override.yml`）方式（直下 `.env` 方式を採用）。
- `frontend/.env.*` / `frontend/src/setupProxy.js` の変更（docker 内部ネットワーク接続のため不要）。
- サービスディスカバリ/リバースプロキシ導入等の大掛かりな構成変更。

## 影響範囲（想定）
- Backend: なし（アプリコード不変・ホスト publish ポートのみ）
- Frontend: dev サーバの publish ポート可変化（内部は不変）。`frontend/.env.*`・`frontend/src/setupProxy.js` は変更不要（docker 内部ネットワーク `backend:8000` へプロキシするためホスト publish ポート非依存）
- DB: なし（接続ポートは環境変数経由・既定は現行）
- Config/Infra: `docker-compose.yml`・`.env.example`（新規）・`scripts/claude/wt-new.sh`・`scripts/claude/tests`・`docs/runbooks/worktree.md`・`docs/runbooks/common-commands.md`
