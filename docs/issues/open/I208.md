# I208: 台帳の残りの振り分けと一覧の行をスクリプトが出すようにし、テストを実物の一覧に依存させない

## 関連資料

- 起点: I207（#346・PR #347）の retro（手順 4-0「台帳の残り」・retro からの起票）
- 指摘: `docs/reviews/closed/I207_code_review_20261027_1942.md` の台帳の F2（Medium・ハーネス）。同じ記録の一覧 `docs/reviews/backlog/I207.md` の F1・F5・F8
- 振り分けの今の決まり: `.claude/skills/retro/SKILL.md` 4-0（I207 で追加した `grep -E` / `grep -vE` の 2 本）・一覧を見る決まり: `.claude/skills/plan-issue/SKILL.md`「台帳の残りの一覧」

- テスト: `scripts/claude/tests/test_i202_ledger_cleanup.sh` の I207 の節（D1〜D3）

## 設計確認メモ（/grill-me）

## 背景/目的

**背景**: I207 で、retro の手順 4-0 に、台帳の残りを重さで「後続イシュー」と「軽い指摘の一覧」に分ける正規表現を手順書に書き、Claude が流す形にした。I207 の retro で初めて使ったとき、F2 の行は要約の中に `KIND=app` という文字があるため、欄の値（`KIND=harness`・`REPRO=no`）に反して後続イシュー側に振り分けられた（このイシュー自身がその結果）。さらに、一覧に書く `FILE=` は台帳の行に無いので、Claude が過去の記録の FINDING 行を手でたどって拾う（振り直した番号では取り違える・I207 一覧の F5）。I207 のテスト D2・D3 は実物の一覧（`docs/reviews/backlog/I206.md`）の行数を確かめるので、一覧の決まりどおり「同梱して直した行を消す」と CI が落ちる（I207 一覧の F8）
**目的**: ①振り分けと一覧の行を、台帳と同じスクリプトが欄の値から決定論で出す（手順書の正規表現と手作業をなくす）②一覧を使う通常の手順でテストが落ちないようにする

### 現状の問題（証拠・再現手順）
- 取り違え: `docs/reviews/closed/I207_code_review_20261027_1942.md` の LEDGER 行の F2 に、retro 4-0 の `grep -E` を当てると当たる（後続イシュー側）。欄だけで決めれば一覧側
- ファイル名: LEDGER 行（`code-review.sh` の `ledger_line`）に `FILE=` の欄が無い。retro は FINDING 行をたどって拾い、見つからなければ `FILE=-`。`FILE=-` の行は plan-issue の `grep -F "FILE=<パス>"` に当たらず残り続ける（I207 一覧の F4）
- テスト: `test_i202_ledger_cleanup.sh` の D3 `d3_bl` は `docs/reviews/backlog/I206.md` に F3〜F6 の 4 行があることを確かめる。I206 の F4・F5 を同梱して一覧から消すと不合格になる
- guard: guard（GitHub から復旧できない例外のファイル）の High で再現なしの行は、今の振り分けでは一覧に落ちる。止める判定（`blocking()`）は guard では再現を問わないので扱いが食い違う（I207 一覧の F1）

### 根本原因
- I207 の計画（4.2・9）で「大きな自作のコードを足さない」を優先し、振り分けをスクリプトにせず手順書の正規表現にした。台帳の欄を読む仕組み（`_LEDGER_PY`）が既にあるのに、別の場所（手順書）で行を文字列として読み直したため、欄と要約の区別・ファイル名の持ち方・止める判定との整合が手作業に残った
- テストで実物の記録を入力にした（I207 の D2・D3）。実物の一覧は使うたびに変わるものなので、テストの入力にすると通常の運用で落ちる

### 解決方針
1. 台帳の行に `FILE=` の欄を持たせる（新しい指摘のときに FINDING 行の `FILE=` を入れ、既にある行の書き直しでは前の値のまま）。前の形（FILE の欄の無い行）も読める（足りないときは `FILE=-`）
2. `_LEDGER_PY` に振り分けのモードを足し、台帳の残り（`is_rest()`）の行ごとに、後続イシューか一覧かと、一覧に書く 1 行（`- <番号> SEV=… REPRO=… KIND=… FILE=… | <要約> | 一覧に回した理由: …`）を出す。判定は欄の値だけで行う（要約は見ない）: 後続イシューは「再現のある Medium 以上」「`SECURITY=yes`」「`KIND=app`」「`KIND=guard` の Medium 以上（再現を問わない）」のどれか
3. retro の手順 4-0 は、そのモードの出力を使う（後続イシュー側はまとめて起票か同梱、一覧側は出力の行を `docs/reviews/backlog/<起点>.md` に貼る）。手順書の正規表現と、FINDING 行をたどる手作業は消す
4. テスト D1〜D3 は、テスト用の写し（一時のファイル）で確かめる形にし、実物の一覧・記録の行数に依存させない。実物の一覧については「形が正しいこと」（どの行も決まった形か）だけを確かめる
5. 細かい関数名・出力の形・既存の台帳の行の扱いは計画で Claude が決める
