# I061: フロントエンド依存脆弱性の是正（npm audit critical/high 解消）

## 関連資料
- GitHub Issue: #126
- 起点: I060 PR #125 の CI `Frontend Lint & Security` が `npm audit --audit-level=critical --omit=dev` で失敗
- 失敗ログ: GitHub Actions run 27460841957 / job 81174187408（2026-06-13）
- 直接の契機: 2026-06-13 に `shell-quote` の critical advisory が表面化。`frontend/package-lock.json` は develop と同一のため develop ベースの全 PR が同様に失敗する状態
- 影響: I060 を含む develop ベースの全 PR が CI 緑にできない

## 設計確認メモ（/grill-me）
- Q: 対応スコープ（critical のみ vs critical+high） → A: **B＝critical + high 全11件**を対応する。具体修正値（grill-me のコード調査で確定）:
  - overrides 拡張（既存 `nth-check`/`postcss` に追加）: `shell-quote` `^1.8.4`（critical 解消）/ `serialize-javascript` `^7.0.5` / `underscore` `^1.13.8` / `@babel/plugin-transform-modules-systemjs` `^7.29.7` / `fast-uri` `^3.1.2`（※4.0.0 メジャーは不要・3.1.2 で解消、ajv 経由のビルド時依存）
  - 直接依存更新: `axios` を `^1.6.7` → `^1.17.0`（脆弱範囲 ≤1.15.2 を回避。1.x 内で非破壊。利用6ファイル `services/api.ts` `services/auth.service.ts` `services/dashboard.service.ts` `services/quiz.service.ts` `pages/PasswordReset.tsx` `pages/Settings.tsx` をスモークテスト）
  - `npm audit fix --force`・`react-scripts` のメジャー更新は**使わない**（`--force` は `react-scripts@0.0.0` 破壊を伴うため）
- Q: 完了基準（AC）の監査レベル → A: **`npm audit --audit-level=high --omit=dev` が exit 0**（high+critical ともゼロ）を計画完了の合否基準にする。scope B 適用後に達成可能。なお CI ワークフローの監査閾値（現行 `--audit-level=critical`）自体の変更は本イシュー対象外（必要なら別フォローイシューで `high` への引き上げを検討）。
- Q: moderate / low（計18件）の扱い → A: **`--force` 不要で直せるものは moderate/low も含めて全部直す**（例: `ws`、overrides/`npm audit fix` で解消可能なもの）。**`--force` 必須の `react-scripts` 由来（`uuid`/`sockjs`/`webpack-dev-server` 等＝dev/build 時のみ使用）は本イシューでは risk-accept** し、根拠（react-scripts メジャー更新が必要・ランタイム外）を計画書に記録する。`react-scripts` のメジャー更新は別イシュー。

## 背景/目的

### 現状の問題（証拠・再現手順）
`cd frontend && npm audit --audit-level=critical --omit=dev` が exit 非0。
CI ログ上のサマリ: **30 件（low 9 / moderate 9 / high 11 / critical 1）**。
`--audit-level=critical` のため critical 1 件で hard fail する。

high/critical 対象（CI ログ抜粋）:
- **critical**: `shell-quote` 1.1.0–1.8.3（推移的: react-scripts → workbox 系）
- high: `axios` 1.0.0–1.15.2 / `serialize-javascript` ≤7.0.4 / `underscore` ≤1.13.7 / `@babel/plugin-transform-modules-systemjs` 7.12.0–7.29.0 / `fast-uri` ≤3.1.1（CI ログ抜粋の代表例。high 全11件の完全な内訳は解決方針 step 1 の `npm audit` 実行で確定し計画書に列挙する）

再現:
```bash
cd frontend && npm audit --audit-level=critical --omit=dev; echo "exit=$?"
```

### 根本原因
`frontend/package-lock.json` に脆弱版（例: `shell-quote@1.8.3`）が固定されたまま、新規 advisory が公開されたため。多くが `react-scripts` 経由の推移的依存で、トップレベルからの直接更新が効きにくい。`axios` は直接依存の可能性が高く、更新時に API クライアントの動作確認が必要。

### 解決方針
1. `cd frontend && npm audit` で現状を確定する
2. `npm audit fix`（非 `--force`）で解消できる範囲を適用する
3. `--force`・メジャー更新が必要なもの（`axios` 等の直接依存）は、ビルド・テスト・E2E への影響を確認しながら個別対応する
4. react-scripts 経由で直接更新できない推移的依存は `package.json` の `overrides` で非脆弱版に固定するか、リスク受容を根拠付きで記録する
5. `npm audit --audit-level=critical --omit=dev` が exit 0 になることを確認する

## スコープ
### 含む
- `frontend` の依存更新による npm audit **critical + high 全件**の是正（設計確認メモ #1=B）
- `--force` 不要で解消できる moderate/low（例: `ws`）の是正（設計確認メモ #3）
- 既存フロントテスト・型チェック・ビルド・E2E がグリーンであることの確認
- 直接依存（axios）更新時の呼び出し箇所（6ファイル）の互換性スモークテスト

### 含まない
- 新機能追加・UI/挙動の変更
- backend 依存（pip）の監査（必要なら別イシュー）
- CI ワークフローの audit 閾値ポリシー自体の変更（現行 `--audit-level=critical` のまま。`high` 引き上げは別フォロー候補）
- `--force`（`react-scripts` 破壊）が必要な moderate/low の是正（`uuid`/`sockjs`/`webpack-dev-server` 等は risk-accept・根拠を計画書に記録）
- `react-scripts` のメジャー更新（別イシュー）
