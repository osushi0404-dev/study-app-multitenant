## 背景/目的

**背景**: I151（Django 5.2 更新）の敵対的レビューで、クイズの経路に組織のチェックが無く、他組織の科目・問題を出題させられることが見つかった。I151 以前からある不具合（I151 起因ではない）のため、I151 の範囲外として別イシュー化した。E2E の `tenant_isolation` シナリオは科目・問題の一覧／作成の経路だけを担保しており、クイズの経路は含まない。
**目的**: クイズの全経路（開始・出題・回答・結果）で、ユーザーが利用してよい科目・問題だけを扱うようにし、他組織の問題文・正解・解説が取得できない状態にする。回帰テストで固定する。

### 現状の問題（証拠・再現手順）
`backend/problems/views.py` の `QuizSessionViewSet`（808 行〜）:
1. **開始（`create`・820 行）**: リクエストの `subject`（ID）を、組織・利用権限のチェックなしにそのまま保存する（`serializer.save(user=request.user)`）。`QuizSessionSerializer` の `subject` は通常の主キー指定で、組織で絞っていない（`backend/problems/serializers.py:306`）。
2. **出題（`next_problem`・848 行 → `QuizService.get_next_problem`・`backend/problems/services/quiz_service.py:30-34`）**: `session.subject` の問題をそのまま返す。**`subject` を指定しない（空の）セッションでは、全組織の全問題から出題される**（絞り込みが無い）。
3. **回答（`submit_answer`・876 行）**: `problem_id` を `Problem.objects.get(id=problem_id, is_deleted=False)` で取得し、組織もセッションの科目も照合しない。応答に **正解の選択肢（`correct_choices`）と解説（`explanation`・`explanation_image`）** を含めて返す（945〜957 行）。

再現手順（想定・`/plan-issue` で実測して確定する）:
- 組織 A のユーザーで `POST /api/quiz/`（または開始 API）に組織 B の科目 ID を送る → 201 でセッションができる → `next_problem` で組織 B の問題文が返る
- 科目なしでセッションを作る → `next_problem` で任意の組織の問題が返る
- 任意の `problem_id`（他組織）で `submit_answer` → 正解と解説が返る

### 根本原因
クイズの ViewSet と QuizService が、ほかの科目・問題の API（`organization_id` を照合している）と違い、組織の境界を確かめる共通の仕組みを通っていない。境界のチェックが各ビューに個別に書かれていて、クイズの経路で書き漏れた。利用可否の判定単位は「ユーザーの組織」で確定（設計確認メモ）。

### 解決方針（設計確認メモで確定）
- **利用してよい範囲は「ユーザーの組織の科目・問題」**（`Subject.organization_id` / `Problem.subject__organization_id` を `user.organization_id` と照合。判定はキャッシュを通さない）。クイズの経路の絞り込みを `QuizService` に寄せ、ビューとシリアライザはそれを使う。
- **開始**: `QuizSessionSerializer.subject` の受け付けをユーザーの組織の科目に限定し、他組織の科目は存在しない ID と同一の 400 で拒否する（セッションを作らない）。
- **科目なしのセッションは残し**、開始時の `total_problems`・出題・回答をユーザーの組織の問題に限定する。現状の「全組織の全問題」は廃止する。
- **回答**: 問題が「ユーザーの組織の問題」かつ「セッションに科目があればその科目の問題」であることを照合し、外れていれば存在しない問題と同一の 404 で拒否する（回答を保存せず、正解・解説を返さない）。
- **出題**（`QuizService.get_next_problem`）も、常にセッション所有者の組織で絞る（多層防御）。
- 既存の問題作成・更新の 403 は変えない。

## スコープ
### 含む
- クイズの開始・出題・回答・終了・結果取得の全経路での組織境界の担保
- 科目なしセッションの扱いの是正
- 越境・科目なし・他組織の問題への回答を拒否する回帰テスト
- 既存の dev DB に、他組織の問題で作られたセッション・回答が残っているかの調査（grill-me で実測済み・0 件。結果を記録する）

### 含まない
- クイズのセッションが二重に作られる既存不具合（I158・#275）
- ダッシュボードの集計にクイズ回答が反映されない件（I151 手動 No.7 の既存不具合 #2。ダッシュボード改善時に対応）
- 組織内の権限（ロール）や登録時に選んだ科目（`UserSubjectAccess`）による科目の出し分け（必要なら別イシュー）
- 既存の問題作成・更新の越境拒否（403）を 404 に揃えること
- E2E の `tenant_isolation` シナリオへのクイズ経路の追加
