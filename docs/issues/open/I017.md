# I017: 科目管理画面UX刷新（一覧テーブル化・追加モーダル・詳細ページ）

## 関連資料
- なし

## 背景/目的
- 現在の科目管理画面（SubjectManagement.tsx）は最小構成（一覧表示＋追加のみ）で、UXが粗削り
- 今後 CRUD 機能を追加することを見据え、テーブル化・詳細ページ導入により拡張しやすい土台を整える

## スコープ
### 含む
- 一覧画面のテーブル化（科目名・説明・問題数・登録日・操作列）
- 科目の追加モーダル（科目名＋説明フィールド）
- 科目の詳細参照ページ（/subject-management/:id）
- 編集・削除ボタンの配置（UIのみ・disabled、機能は別イシューで対応）
- Subject の description フィールドを一覧・詳細に表示（既存フィールド、マイグレーション不要）

### 含まない
- 編集機能の実装（別イシューで対応）
- 削除機能の実装（別イシューで対応）
- is_deleted フラグの追加・論理削除対応（別イシューで対応）
- 論理削除に伴う問題フィルタ対応（別イシューで対応）
- 科目の並び替え
- 科目の検索・フィルタ
- ユーザーごとの科目閲覧権限管理

## 受け入れ条件（Acceptance Criteria）
- [ ] 科目一覧がテーブル形式で表示される（科目名・説明・問題数・登録日・操作）
- [ ] 「科目を追加」ボタンからモーダルで科目を追加できる（科目名は必須、説明は任意）
- [ ] 各行に編集・削除ボタンが表示される（disabled 状態）
- [ ] 各行の詳細ボタン（または科目名クリック）で詳細ページへ遷移できる
- [ ] 詳細ページ（/subject-management/:id）に科目名・説明・問題数・登録日・更新日が表示される
- [ ] 詳細ページに編集ボタンが表示される（disabled 状態）
- [ ] 詳細ページから一覧に戻れる

## 影響範囲（想定）
- Backend: SubjectViewSet の list に problem_count・description を含める（既存フィールド）、detail エンドポイント確認
- Frontend: SubjectManagement.tsx（全面刷新）、新規 SubjectDetail.tsx 追加、App.tsx（ルート追加）
- DB: なし（description は既存フィールド）
- Config/Infra: なし

## Danger Ops（有/無）
- 無
