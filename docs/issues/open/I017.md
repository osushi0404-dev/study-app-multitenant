# I017: 科目管理画面UX刷新（一覧テーブル化・CRUD・詳細ページ）

## 関連資料
- なし

## 背景/目的
- 現在の科目管理画面（SubjectManagement.tsx）は最小構成（一覧表示＋追加のみ）で、編集・削除・詳細参照の機能がない
- 今後 CRUD 機能を追加することを見据え、UI/UX を刷新して拡張しやすい土台を整える

## スコープ
### 含む
- 一覧画面のテーブル化（科目名・説明・問題数・登録日・操作列）
- 科目の追加モーダル（科目名＋説明フィールド）
- 科目の編集モーダル（科目名＋説明フィールド）
- 科目の削除（論理削除）＋確認ダイアログ
- 科目の詳細参照ページ（/subject-management/:id）
- Subject モデルへの description フィールド追加（バックエンド）
- 論理削除（is_deleted フラグ）対応（バックエンド）
- 論理削除された科目に紐づく問題を表示・出題・統計から除外

### 含まない
- 削除済み科目の復元機能
- 科目の並び替え
- 科目の検索・フィルタ
- ユーザーごとの科目閲覧権限管理

## 受け入れ条件（Acceptance Criteria）
- [ ] 科目一覧がテーブル形式で表示される（科目名・説明・問題数・登録日・操作）
- [ ] 「科目を追加」ボタンからモーダルで科目を追加できる（科目名は必須、説明は任意）
- [ ] 各行の編集ボタンからモーダルで科目名・説明を編集できる
- [ ] 各行の削除ボタンから確認ダイアログを経て論理削除できる
- [ ] 削除時ダイアログに「紐づく N 件の問題が非表示になる」旨の警告が表示される
- [ ] 論理削除された科目は管理画面の一覧に表示されない
- [ ] 論理削除された科目に紐づく問題は問題管理・クイズ出題・統計フィルタから除外される
- [ ] 詳細ページ（/subject-management/:id）に科目名・説明・問題数・登録日・更新日が表示される
- [ ] 詳細ページに「編集」ボタンがあり、編集モーダルを開ける
- [ ] 詳細ページから一覧に戻れる

## 影響範囲（想定）
- Backend: Subject モデル（description, is_deleted フィールド追加）、API エンドポイント（CRUD 追加・論理削除対応）、問題取得クエリへの is_deleted フィルタ適用
- Frontend: SubjectManagement.tsx（全面刷新）、新規 SubjectDetail.tsx 追加、App.tsx（ルート追加）
- DB: subjects テーブルに description, is_deleted カラム追加（マイグレーション）
- Config/Infra: なし

## Danger Ops（有/無）
- 有（DBマイグレーション）
- 有の場合: subjects テーブルへのカラム追加（description, is_deleted）。既存データへの影響は追加のみで破壊的変更なし。ロールバックはマイグレーション reverse で対応。
