## 背景/目的

**背景**: 学習アプリとして「とりあえず使える」状態かを、画面を通しで操作して確かめた。ログイン画面の「アカウントをお持ちでない方はこちら」（`/register`・組織の指定なし）から登録すると、2 段目の科目選びで止まり、登録を完了できなかった。
**目的**: 招待リンクを持たない人でも、会員登録を最後まで終えて、自分の科目・問題を作ってクイズを解き始められる状態にする。

### 現状の問題（証拠・再現手順）
1. ログアウトした状態で `/login` を開き、「アカウントをお持ちでない方はこちら」を押す（`/register` に移る）
2. メールアドレス・ユーザーID・パスワードを入れて「登録して次へ」を押す
3. 2 段目に「この組織には利用可能な科目がありません。管理者にお問い合わせください。」と出て、「登録を完了」が押せないまま
4. この時点で利用者は作られていない（1 段目は入力の確かめだけで、作成は「登録を完了」のとき）。ログインしても 400

- 組織を指定しない登録は `type='personal'` の組織（slug `personal`）に入る（`backend/accounts/views.py:149`）
- 開発の DB で数えると、`personal` 組織の科目は 0 件・問題は 0 件（`python manage.py shell` で `Subject.objects.filter(organization__slug='personal').count()`。画面では、未認証で `/api/organizations/subjects/public/?slug=personal` が空の配列を返す）
- 登録には科目を 1 つ以上選ぶことが必須（`backend/accounts/serializers.py:59` の検証と、画面のボタンの無効化）
- 対照: 招待リンク `/register/<組織の slug>` から登録すると、その組織の科目が出て最後まで登録でき、ログインもできた

### 根本原因
- `personal` 組織に科目を用意する仕組みが無い（マイグレーション・種データ・管理画面のどれにも無い）。個人の利用者は管理者ではないので、自分で科目を作ることもできない（科目の作成は組織管理者だけ・`backend/problems/views.py:92`）
- その一方で、登録は「科目を 1 つ以上選ぶ」ことを必須にしているため、科目 0 件の組織では登録が必ず止まる
- 個人の利用者がどう学ぶのか（どの科目・問題を使うのか）という製品の決まりが未定のまま、組織なしの登録の入口だけがある

### 解決方針
grill-me で **案 A** に確定（設計確認メモ参照）。
- 組織を指定しない登録では、利用者ごとに専用の組織（`type='personal'`・名前「（ユーザーID）さんの学習」）を作り、その利用者を管理者（`role='admin'`）にする。科目・問題は本人が既存の科目管理の画面で作る
- 個人用の組織（`type='personal'`）で科目を作ったら、作った人の学ぶ科目（`UserSubjectAccess`）に自動で入れる（設定画面で選び直さずにクイズを始められる）。他の組織では今のまま入れない
- 個人用の組織（`type='personal'`）は本人ひとりだけ: 招待リンク（`/register/<slug>`）の登録先として受け付けず、未ログインの科目一覧も空の配列を返す
- 科目 0 件の組織への登録（組織なし・招待リンク経由の両方）では、科目選びを飛ばして登録を終えられるようにする（`backend/accounts/serializers.py` の科目必須の検証を、組織の科目が 0 件のときは求めない形にする）
- ログイン後、科目 0 件のときのダッシュボードの案内:
  - 自分が管理者（専用の組織）: 「まず科目と問題を作りましょう」＋科目管理の画面へのボタン
  - 管理者でない（招待された組織）: 「管理者が科目を用意するまでお待ちください」
- 既に共有の `personal` 組織（slug `personal`）にいる一般の利用者（`is_staff=False`）は、一人ずつ専用の組織を作って移し、その人を管理者にする（Danger Ops・承認制）。運営用のアカウント（`is_staff=True`）は移さず、`role` も変えない。その人に結びついた組織の記録の扱い（移す範囲）は計画で決める。共有の `personal` 組織は残す
- 上で決めていない細部（文言の細部・案内の置き場所や見た目・導線）は、ベストプラクティスと UI/UX の観点で Claude が最善の形を選び、自律判断の記録に残す（ユーザーの指示・2026-11-16）
- 採らなかった案: B（運営が中身を作り続ける負担・全員が 1 つの組織に混ざる C3 の心配）・C（品質基準で対象にしている個人の利用者を外すことになる）

## スコープ
### 含む
- 組織なしの登録を、利用者ごとの専用の組織を作って最後まで終えられるようにする
- 個人用の組織で作った科目を、作った人の学ぶ科目に自動で入れる
- 個人用の組織を招待リンクの登録先にできないようにし、未ログインの科目一覧も空にする
- 科目 0 件の組織への登録（招待リンク経由も含む）で、押せないボタンのまま止まらないようにする
- ログイン後の科目 0 件のときのダッシュボードの案内（管理者／管理者でない）
- 既に共有の `personal` 組織にいる一般の利用者を、一人ずつ専用の組織に移す（Danger Ops）
- E2E（組織なしで登録→ログイン→科目・問題を作る→クイズを始められる）
### 含まない
- 学校・会社など個人用でない組織で科目を作ったときの学ぶ科目への自動追加（今のまま入れない）
- 共有の `personal` 組織にいる運営用のアカウント（`is_staff=True`）の移し替え
- 科目がある組織への招待リンク経由の登録の変更（今は動いている）
- メールの確認の流れの変更
- 運営が用意する共有の科目・問題（案 B）

## 関連する品質基準
- C1 学習効果 — 登録できても解く問題が無ければ学べない。登録の後、科目・問題を作る画面に迷わず行けて、作ればそのままクイズを始められることを受け入れ条件に入れる
- C3 セキュリティ・テナント分離 — 専用の組織ごとに科目・問題・記録が分かれ、ほかの利用者のものが見えないこと。個人用の組織に他人が入れず、未ログインで科目名も見えないこと

## 受け入れ条件（Acceptance Criteria）
- [ ] ログイン画面の新規登録の入口から、招待リンクなしで登録した人が、科目選びで止まらずに登録を終えられ、ログインできる
- [ ] その人には専用の組織（名前「（ユーザーID）さんの学習」）が作られ、その人が管理者になっている。別の人が同じ入口で登録すると、別の組織になる
- [ ] その人がログインすると、ダッシュボードに「まず科目と問題を作りましょう」の案内と科目管理の画面へのボタンが出る
- [ ] 個人用の組織で科目を作ると、作った人の学ぶ科目に自動で入り、設定画面で選び直さずに、その科目の問題でクイズを始められる
- [ ] 個人用でない組織で管理者が科目を作っても、作った人の学ぶ科目は増えない
- [ ] 個人用の組織（`type='personal'`）の slug を使った招待リンクの登録（`/register/<slug>`）は受け付けられず、その組織の利用者は増えない。未ログインの科目一覧（`/api/organizations/subjects/public/?slug=<その slug>`）は空の配列を返す

- [ ] 共有の `personal` 組織にいる運営用のアカウント（`is_staff=True`）は移らず、組織も `role` も変わらない
- [ ] 移す操作は、何度流しても同じ結果になる（2 回目は何も変えない）
- [ ] 専用の組織の人から、ほかの利用者の科目・問題・記録が見えない
- [ ] 上の流れ（組織なしの登録→ログイン→科目・問題を作る→クイズを始める）が E2E で確かめられている
