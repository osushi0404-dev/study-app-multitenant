## 背景/目的

**背景**: Claude の Bash のコマンドはサンドボックスの中で動き、外に出すのは `.claude/settings.json` の `sandbox.excludedCommands`（`docker *`・`docker-compose *`・`gh *`・`git *`・`bash scripts/claude/*`）に当たるときだけ。一方で、Claude は `scripts/claude/` に書き込める（Edit・Write ツールは `.claude/settings.json:13` の `Edit(scripts/claude/**)` で承認なし。Bash もサンドボックスの書き込みは作業フォルダの下〔`.claude/worktrees` 以外〕が許されている）。そのため「`scripts/claude/` に新しいスクリプトを書く → `bash scripts/claude/<それ>` で流す」と、レビューを一度も通っていない中身がサンドボックスの外で動く。手順書は「スクリプトを足すときは外で動いてよいものかをレビューで見る」（`docs/runbooks/danger-ops.md:43`）と書くが、レビューは流した後に来るので、この順番では守りになっていない。
**目的**: サンドボックスの外で動くのは、レビューを通ったスクリプト（の中身）だけにする。`bash *` を外に出さないのと同じ理由（書いたファイルを外で動かせる）を、`scripts/claude/` にも効かせる。

### 現状の問題（証拠・再現手順）
1. `.claude/settings.json` の `sandbox.excludedCommands` に `bash scripts/claude/*`（glob）がある。新しく足したファイルも当たる
2. `.claude/settings.json:13` の `Edit(scripts/claude/**)` で、Claude は承認なしに `scripts/claude/` の下へ書ける。サンドボックスの `filesystem` の制限も `denyWrite: [".claude/worktrees"]` だけで、Bash からも書ける
3. 実例（I597・2026-11-20）: implement で `scripts/claude/db-backup.sh` を新しく書き、レビュー（review-gate）の前に、テスト（`bash scripts/claude/tests/test_i597_db_backup.sh`）の中からサンドボックスの外で動かした。中身は無害（DB を読むだけ）だったが、仕組みとしては、どんな中身でも同じように外で動く
4. 外で動くと、サンドボックスが禁じている `.env` の読み取り・作業フォルダの外への書き込み・ネットワークへの接続ができる。残る守りは、許可の設定・見張り（`scripts/claude/hooks/pretooluse_guard.py`）・auto モードの判定役だけで、どれもスクリプトの中身は読まない
5. （grill-me で追加）既存のスクリプトの中身を書き換えても同じように外で動く（名前の一覧に変える案 (a) だけでは塞がらない）。フック（`scripts/claude/hooks/*.py`）は Claude Code が毎回外で動かす。`scripts/claude/tests/run-all.sh` は引数で渡した任意のファイルを外で動かす

### 根本原因
- 外に出す一覧が「場所（`scripts/claude/` の下なら何でも）」で決まっていて、「中身がレビューを通ったか」で決まっていない
- `bash *` を外に出さない決まり（`docs/runbooks/danger-ops.md:42`）は、「書いたファイルを外で動かせる」穴を一般のシェルについてだけ塞ぎ、Claude が書ける場所の `bash scripts/claude/*` には同じ考えを当てていなかった

### 解決方針
grill-me で確定（設計確認メモ）。案 (b) を土台にする:
- 見張り（PreToolUse）が、`bash scripts/claude/…` を流すとき、`scripts/claude/` の下に `git merge-base HEAD origin/develop` の時点と中身が違うファイル（変更・新規）が 1 つでもあれば、コマンドを書き換えてサンドボックスの中で動かし、その旨を必ず出す。違いが無ければ今までどおり外で動く
- 中では動かない変更（gh・`claude -p` を使うスクリプトの変更）のときだけ、外で流すかをユーザーに確かめる。レビュー役のスクリプトを変えたブランチの扱いは I593 とそろえる（計画でどちらで扱うか決める）
- 計画の最初に、見張りの書き換え（`updatedInput`）の後のコマンドで外に出すかが判定されることを公式の資料と実際の動きで確かめる（`docs/runbooks/plan-writing-rules.md`「規約と依存の照合」）。できなければ「承認を求める（ask）」に切り替える
- フック（`scripts/claude/hooks/*.py`）の書き換えと、`run-all.sh` の引数で任意のファイルを外で動かせる穴も、同じ考えで塞ぐ（塞ぎ方は計画で決める）
- 見張りに判定を足すので `docs/runbooks/danger-ops.md`「見張りに判定を足すときの決まり」の 3 点を計画に書く
- 不採用: (a) 名前の一覧（既存のスクリプトの書き換えを塞げない）・(c) `scripts/claude/` への書き込みを承認制（ハーネスのイシューで毎回承認が出る）
