- Q: 苦手を優先の出題の順番 → A: 選んだ科目の中で、(1) 最後に答えたときに間違えた問題、(2) 苦手な難易度（下の基準）の問題、(3) まだ答えていない・しばらく答えていない問題、の順に優先する（同じ回では同じ問題を続けて出さない）。その科目の解答が 5 問未満で判定できないときは、通常と同じ順で出し、クイズの画面に「この科目はまだ解答が少ないため、いつもの順で出題しています」と 1 行出す
- Q: 「苦手」とみなす基準 → A: ダッシュボードの「間違いやすい分野」と同じにそろえる（5 問以上答えて正答率 70% 未満・`backend/dashboard/selectors.py` の `WEAK_MIN_ANSWERED`・`WEAK_ACCURACY_BELOW` を共有する）。難易度別の苦手も同じ基準。今のコードのばらばらの値（誤答率 30%・40% など）は使わない
- Q: 急いで答えた間違いの基準 → A: 直近 30 日に 20 問以上答えていて、その間の間違いのうち「自分の平均の解答時間の半分未満で答えたもの」が 25% 以上のとき、カードに「急いで答えた問題の間違いが多めです（間違いの ◯%）。落ち着いて解きましょう」と 1 行出す。当てはまらなければ何も出さない
- Q: 材料 → A: 実際のクイズの回答（`QuizAnswer`）にする（ダッシュボードと同じ材料・全モードの回答が入る）。`ProblemAttempt` はどこからも作られないので読まない。表は消さずに残す（Danger Ops 無し。表の削除は別イシュー）
- Q: `StudyLog` に頼る提案（`_generate_general_suggestions`）→ A: 提案の保存をやめるので一緒に外す（I473 で `StudyLog` は残すと決まり、書き込む経路が無いため、いつも「学習習慣の確立」が出ていた）。I190（→ I473）は完了済みなので着手順の問題は無い

## 背景/目的

**背景**: 学習記録の機能のうち、間違い分析（`/api/study/mistake-analysis/`）と適応的な問題選択（`/api/study/adaptive-learning/`）は、どの画面からも呼ばれていない。I452 で、難易度の型のずれによる 500 を直し、#446 の横断テストで経路を毎回呼ぶようにしたが、画面にはつながない（ユーザー決定）。一方、I473・I487 でダッシュボードに「間違いやすい分野（科目別）」「おすすめ」が `QuizAnswer` から出るようになった。
**目的**: 間違い分析（難易度別の苦手・急いだ間違い）と適応的な問題選択（苦手を優先した出題）を、学習者がダッシュボードとクイズから使える状態にする。材料・計算・定期処理を、実際のデータの流れ（`QuizAnswer`）に合わせて作り直す。

### 現状の問題（証拠・再現手順）
1. **画面から呼ばれていない**: `backend/studylogs/urls.py` の `mistake-analysis`・`adaptive-learning` を呼ぶ画面が `frontend/src/pages/` に無い
2. **材料の片方が作られない**: 2 機能は `ProblemAttempt` と `SpacedRepetitionReview` を材料にする（`backend/studylogs/mistake_analysis.py` の `_error_records`・`backend/studylogs/adaptive_selection.py` の `analyze_user_proficiency`）。クイズの回答から作られるのは `QuizAnswer` と `SpacedRepetitionReview` だけで、`ProblemAttempt` を作る経路は無い
3. **`StudyLog` への依存**: `mistake_analysis.py` の `_generate_general_suggestions` は `StudyLog` の件数で提案を作る。`StudyLog` を作る経路は無いため、いつも「学習習慣の確立」が作られる
4. **回数の足し込み**: `mistake_analysis.py` の `_analyze_subject_difficulties` などは、実行のたびに同じ期間の間違いを `occurrence_count`・`total_attempts` に足し込む。定期処理（5 分ごと）で回数が膨らみ続ける
5. **定期処理の間隔が開発用のまま**: `backend/core/celery.py` の `analyze_mistake_patterns_task`（5 分ごと）・`update_daily_analytics_task`（30 秒ごと）・`send_study_reminders_task`（1 分ごと・メールを送る）などは、コメントの「本番環境では」の値になっていない
6. **性能（I455 のレビューの F4・同梱）**: `adaptive_selection.py` の `_calculate_problem_score` が候補の問題ごとに `ProblemAttempt` を数えるため、候補の数だけ問い合わせと JOIN が増える

### 根本原因
2 機能は、クイズの機能とは別の記録（`ProblemAttempt`・`SpacedRepetitionReview`）を材料にする前提で、バックエンドだけが先に作られた。クイズの回答から材料を作る経路と画面は作られず、動くかを確かめるテストも無かったため、使われないまま定期処理の間隔（開発用の値）・回数の足し込み・問い合わせの数（F4）も見直されなかった（いつ・どの判断で画面の接続が見送られたかは未特定）。

### 解決方針（grill-me で確定）
- 材料を `QuizAnswer` にそろえ、結果は保存せず読むたびに計算する
- 間違い分析: ダッシュボードの「間違いやすい分野」のカードに「難易度別の苦手」と「急いで答えた間違い」を足す（基準は設計確認メモのとおり。科目別の苦手はダッシュボードの今の表示のまま）
- 適応的な問題選択: クイズのモード `weak`（苦手を優先）を足し、ダッシュボードの「学習を開始」の副ボタンと、おすすめの「間違いやすい分野」の「練習する」から始める
- 保存型の分析（`MistakePattern`・`LearningWeakness`・`LearningSuggestion` への書き込み）と、使われない API の経路（`/api/study/mistake-analysis/`・`/api/study/adaptive-learning/`）と、それを回す定期処理をやめる。表は残す
- 残る定期処理の間隔を本番の値にする
- 技術の選択（計画で決める）: 計算の置き場所（`dashboard/selectors.py` に寄せるか `studylogs` のサービスか）・苦手を優先の並べ方の実装（1 回の集計で候補をまとめて採点する。F4）・`adaptive_selection.py`・`mistake_analysis.py` を作り直すか消すか・キャッシュ・マイグレーション（`QuizSession.mode` の選択肢の追加）
