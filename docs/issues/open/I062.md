## 背景/目的

### 現状の問題（証拠・再現手順）
1. **太字 Blocker/High の取りこぼし（誤 `✅`）**: `scripts/claude/code-review.sh` の判定が `grep -qE "^\| Blocker \|"`（99行目相当）/ `grep -qE "^\| High \|"`（102行目相当）でプレーンなセル文字列を前提にしている。一方レビューエージェント（`.claude/review-agents/code-reviewer.md`）は重大度を **Markdown 太字** `| **Blocker** |` / `| **High** |` で出力するため、grep が一致せず**Blocker 残存でも `✅ コードレビュー完了` を誤表示**する。
   - 実害例: I060 の初回コードレビューで、レビュー本文に Blocker（未コミット）が記載されていたにもかかわらずスクリプトは `✅` を出力。人手で本文を読み直して救済した。
   - 再現: レビュー結果ファイルに `| **Blocker** |` を含む行があるとき `grep -qE "^\| Blocker \|" <file>` は非マッチ（exit 1）。
2. **計画書の再作成サフィックス（`plan_I###_N.md`）を読まない**: `code-review.sh` / `plan-issue-review.sh` の `find_file` が `plan_I###.md` 固定パターンのため、`plan-writing-rules.md` が定める再作成命名 `plan_I###_2.md` 等を拾えない。改訂計画がレビュー対象から外れる。
   - 実害例: I060 で `plan_I060_2.md` を作成したが plan-issue-review が読めず、`plan_I060.md` への統合を余儀なくされた。

### 根本原因
- レビュー結果の**機械判定（verdict 検出）が、生成側（review-agent）の出力装飾に対して頑健でない**。判定行のフォーマット契約も、表記揺れ許容パターンも無い。
- **ファイル命名規約（`plan_I###_N.md`）とそれを読むスクリプトの探索パターン（`find_file`）が不整合**で、規約変更がツール側に反映される仕組みがない。

### 解決方針（設計確認メモで確定済み）
1. **判定の堅牢化＝(b)主＋(a)保険の併用（Q1=c で確定）**:
   - (b) `code-reviewer.md` / `plan-reviewer.md` の出力末尾に**機械可読な固定判定行**（例 `VERDICT: BLOCKER|HIGH|OK`）を追加し、`code-review.sh` / `plan-issue-review.sh` はその行を**一次判定**に使う（Q4=統一適用）。
   - (a) 保険として `code-review.sh` の既存重大度 grep を装飾許容パターン（例: `^\|\s*\*{0,2}(Blocker|High)\b`）に直し、固定判定行が無い旧レビュー出力にも後方互換で対応する。`plan-issue-review.sh` の既存プレーン判定（`差し戻し`/`高リスク.*Yes`）は後方互換として残置。
2. **plan 命名対応（Q2=連番数値順・Q3=スクリプト側のみで確定）**: `find_file` を `plan_I###*.md` の中から**連番を数値ソートして最大**（`_10` > `_9`、無印を最古）を選ぶ実装にする。`plan-writing-rules.md` の `plan_I###_N` 再作成命名規約**自体は変更しない**（命名規約ドキュメントの是正は I064 の担当）。
3. 修正後、太字 Blocker/High を含むレビュー出力サンプルで誤判定しないこと、`plan_I###_2.md` が選択されることを検証する。

## 制約・引き継ぎ情報
- **バグの所在**: `code-review.sh` の判定（`scripts/claude/code-review.sh` 末尾の `grep -qE "^\| Blocker \|"` / `"^\| High \|"` 付近、99/102行目相当）が太字 `| **Blocker** |` に非マッチで誤 `✅`。`plan-issue-review.sh` は `判定:.*差し戻し`/`高リスク判定.*Yes`（プレーン文字列）で現状頑健だが、Q4=統一適用により**両スクリプト・両エージェントに `VERDICT` 固定行契約を導入**する（plan 側の既存判定は後方互換で残置）。
- **実装の手がかり（既存の判定セクション位置）**: `.claude/review-agents/code-reviewer.md` は既に「`## 高リスク判定` / `判定: Yes / No`」セクション（167行目相当）と「出力フォーマット（このフォーマットのみ出力）」指示（148行目相当）を持つ。`plan-reviewer.md` も `## 判定: ✅ 完了 / 差し戻し` 形式を出力する。**`VERDICT:` 固定行はこの判定セクションの直後（出力末尾）に追加**し、既存の出力フォーマット指示と矛盾しないようにすること。
- **検証材料**: 誤判定の実物が `docs/reviews/closed/I060_code_review_*.md`（太字 `| **Blocker** |` を含む回がある）と `docs/reviews/I061_code_review_*.md` 等に残る。これらをサンプルに「太字 Blocker で `✅` を出さない」回帰確認ができる。
- **bash 依存・CWD 前提**: `PIPESTATUS` 等の bash 依存や、相対 `scripts/...` 実行の CWD 前提に注意（過去に CWD 起因の exit 127 が発生）。スクリプト冒頭で repo root へ `cd` する既存実装を踏襲する。
