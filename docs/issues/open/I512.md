## 背景/目的

**背景**: I430 で、見張り（`scripts/claude/hooks/pretooluse_guard.py`）の判定のうち公式のサンドボックスと GitHub で止まるものを消した。コードレビューは、計画書で受け入れると明記した残余リスク 3 件（下の F1〜F3）を Medium として台帳に残し、retro の振り分け（`code-review.sh --route issue`）がそれらを後続イシューに回した。うち 2 件は `SECURITY=yes` なので、retro 4-0 の決まりで「次のハーネスの作業で最優先」になる。
**目的**: 計画で受け入れると明記した残余リスクが、毎回「最優先の後続」になって連鎖を続けないようにする。そのうえで、F1〜F3 を締めるかを決める。

### 現状の問題（証拠・再現手順）
- 台帳の後続イシュー行（`docs/reviews/I430_code_review_20261113_1911.md` の LEDGER 行）:
  - F1（Medium・`SECURITY=yes`・再現なし）: `bash scripts/claude/*` が `.claude/settings.json` の allow と `sandbox.excludedCommands` の両方にあり、Claude が書き換えた `scripts/claude/` のスクリプトを確認なしでサンドボックスの外で動かせる
  - F2（Medium・`SECURITY=yes`・再現なし）: `git *` をサンドボックスの外に出したため、git のリダイレクト（`git diff > <別のワークツリー>/x`）やフック経由の別のワークツリーへの書き込みは止まらない
  - F3（Medium・再現なし）: fork の PR への `gh pr edit` などの確認を消し、`gh pr edit *` は allow で確認なしで通る
- 3 件とも計画書（plan_I430 の 4-1・4-2・8 の R2）で、脅威モデル（事故。意図的な回避は対象外）に沿って受け入れると書いた残余リスク。コードレビューの指摘の本文にも「計画書で受け入れ済み」と書かれている
- それでも `code-review.sh --route issue I430` は 3 件を後続イシューにし、F1・F2 の理由は「SECURITY=yes・guard の Medium 以上」になる（retro 4-0 で最優先）。2026-11-14 の grill-me で流し直して同じ出力を確かめた

### 根本原因
- `route_reasons()` は台帳の欄（SEV・REPRO・SECURITY・KIND）だけで振り分ける。台帳には「計画で受け入れ済みか」の欄が無いので、受け入れ済みの残余リスクも、受け入れていない穴と同じく後続イシュー・最優先になる
- I480 は Low・再現なしを一覧に回したが、Medium・再現なしの受け入れ済みのものは残った。見張り・安全装置のイシューは、残余リスクを計画で受け入れることが多く（脅威モデルが事故のため）、この形が毎回出る
- 計画書の「受け入れる」の記述が決まった場所に無い（plan_I430 では 4-1 の表・4-2 の本文・8 の R2 に散らばっている）ので、機械で照合できない

### 解決方針（設計確認メモで確定）
- code-reviewer（`.claude/agents/code-reviewer.md`）が、計画書の「## 8. Risk & 回避策」の表で処遇が `受け入れ` の R 番号の行に当たる指摘に、FINDING 行の目印 `ACCEPTED=R<番号>` を付ける
- 目印をレビュー役（LLM）の自己申告だけで決めない: `code-review.sh` が計画書の「## 8. Risk & 回避策」の節にその R 番号の行があり、処遇の列が `受け入れ` かを照合する。合わなければ目印を捨てて今までどおり振り分ける（fail-closed）。台帳の LEDGER 行に `ACCEPTED=` の欄を持たせる
- 目印が効くのは「Medium 以下かつ `REPRO=no`」の行だけ。効く行は `route_reasons()` で後続イシューにせず一覧（`docs/reviews/backlog/`）へ回す（`SECURITY=yes`・`guard の Medium 以上` の理由も外す）。High 以上・`REPRO=yes` は目印があっても今までどおり
- 目印は振り分け（後続イシュー／一覧・最優先）にだけ効き、止める判定（STOP・`blocking()`）には効かせない。止める条件の正は `docs/runbooks/review-rules.md`「検証の全体設計」
- 受け入れた後に穴だったと分かったとき: 一覧の行の理由に「計画で受け入れ（R<番号>）」を出し、そのファイルを触るイシューの計画（`/plan-issue` の「台帳の残りの一覧」）で拾う。`REPRO=yes`・High 以上で出直せば目印は効かず後続イシューに戻る。定期の見直しの場は作らない
- F1〜F3 そのもの: 締めない。受け入れのまま `docs/reviews/backlog/I430.md` に手で行を足す（別イシューは作らない）
