# I064: レビュー命名・状態管理規約の一本化（reviewXXX 体系 → IXXX_review 体系）

## 関連資料
- GitHub Issue: #130
- 起点: I060 計画書 §3「別イシューに切り出す項目」/ I060 コードレビュー Low1・Low2
- 対象: `docs/runbooks/review-rules.md` / `docs/runbooks/plan-writing-rules.md`（ヘッダ基本情報ブロック全体）/ `docs/runbooks/issue-flow.md`

## 設計確認メモ（/grill-me）
- Q1: 正準命名の確定 → A: **新系統4種で確定**。`IXXX_review.md`（plan-issue 作成・open→closed）/ `IXXX_code_review_<ts>.md` / `IXXX_plan_review_<ts>.md` / `IXXX_issue_review_<ts>.md`（スクリプト生成・`docs/reviews/` 直下）。**廃止: `reviewXXX` グローバル通し番号・`_post` 別ファイル実装後評価・`in_progress` 状態**。機能損失はゼロ（実装後評価は `IXXX_review.md` の「テスト結果」「計画との差分」に集約、状態は open/closed の2系統、識別は issue 番号で一意）。`review_template.md` は既に新形式のため変更不要。
- Q2: 旧ファイル `review001〜003` の扱い → A: **リネームせず `closed/` に履歴として残す**。`review-rules.md` に「旧形式（廃止・履歴・リネーム不要）」と注記する。
- Q3: timestamped 監査記録の記述 → A: **現状の実体（`docs/reviews/` 直下に時系列蓄積・open/closed 管理外・移動しない）をそのまま記述**。「いずれ整理する」等の新ルールは足さない。ライフサイクル整理（理想形）は**別イシューに切り出す**（下記）。
- Q4: 書き換え範囲と全域整合 → A: **命名/状態/採番の是正に限定し、命名と無関係な部分（レビュー内容の必須要素 A/B/C/D・`.claude/skills/` 変更時の Claude Code ベストプラクティス準拠チェックリスト等）は保持**。grep 検証の結果、旧規約参照は `review-rules.md` と `plan-writing-rules.md` ヘッダのみで、**`.claude/skills/*` / `scripts/claude/*` / hooks / `review_template.md` は既に新規約**＝追従不要。よって対象3ファイルの是正で**全域整合が取れる**。
  - 精緻化1: `plan-writing-rules.md` は :180 だけでなく**ヘッダ基本情報ブロック全体（:177-183）**を是正（`作成根拠資料` を `reviewXXX` → `docs/issues/...IXXX.md`、`実装後評価` フィールドは残しつつ意味を `IXXX_review.md`（または未作成）に更新、実プラン実体に合わせ `Draft PR` 行を補う）。理由: 廃止する2概念（reviewXXX・_post）が同ブロックに同居しており、:180 だけ直すと :181 に旧 `_post` 概念が残り新旧併存が再発するため（I060 の in_progress 部分修正→D16 取りこぼしと同型の失敗回避）。
  - 精緻化2: timestamped 監査記録の**ライフサイクル整理は I064 のスコープ外**（close スキル＋review スクリプトの保存先変更＝コード変更を伴うため）。別イシュー候補として注記。

## 背景/目的

### 現状の問題（証拠・再現手順）
レビュー（および計画書）のファイル命名・状態管理について、**新旧2系統の規約が併存**している。

- **旧系統（`review-rules.md` が記述）**: 全レビュー通し番号 `reviewXXX_IYYY.md` / 実装後評価 `reviewXXX_IYYY_post.md` / 3状態 `open`→`in_progress`→`closed`。`review-rules.md` 内に `reviewXXX`/`in_progress` が計 10 箇所（例: lines 282,285 の `mv ... in_progress ...`）。
- **新系統（実運用・スクリプトが採用）**: イシュー単位 `IXXX_review.md` / `IXXX_code_review_<timestamp>.md` / `IXXX_plan_review_<timestamp>.md`、2状態 `open`/`closed`。`scripts/claude/code-review.sh` / `plan-issue-review.sh` がこの形式で生成し、`issue-flow.md`（D8 で統一済み）もこちらを使用。
- 実体の証拠: `docs/reviews/closed/` に旧形式 `review001_I004.md`〜`review003_I007.md` が現存（歴史的に使用）。一方、近年は `IXXX_*` 形式（I058〜I064）。`in_progress/` ディレクトリは実在しない。

派生する不整合（I060 コードレビュー指摘）:
- Low1: `issue-flow.md:241` の計画書命名 `plan_I{イシュー番号}_{概要}.md` が、実体 `plan_I###.md`（`plan-writing-rules.md` 準拠）と不一致。
- Low2: `plan-writing-rules.md:180` のヘッダ例 `reviewXXX_IXXX（問題分析と改善提案）` が旧系統のまま。

### 根本原因
- レビュー命名・状態管理の**正準規約が一意に定義されておらず、規約ドキュメント（review-rules.md）が旧系統のまま実運用（IXXX_* 系統）から乖離**している。新系統移行時に規約ドキュメントを同時更新する運用が抜けた（I060 では「運用設計判断を伴う」として本イシューへ切り出し）。

### 解決方針（grill-me で正準確定済み・設計確認メモ参照）
1. **正準規約**（確定）: 命名は新系統4種（`IXXX_review.md`／`IXXX_{code,plan,issue}_review_<ts>.md`）、状態は `open`/`closed` の2系統。旧 `reviewXXX_*` 通し番号・`_post` 別ファイル・`in_progress` 状態は**廃止**。`review001〜003` は**リネームせず closed に履歴として残す**（Q2）。
2. `review-rules.md` の**命名規則・状態管理・採番ロジック・`_post` 部分のみ**を新系統に是正。レビュー内容の必須要素（A/B/C/D）・`.claude/skills/` 変更時の準拠チェックリスト等の**命名無関係部分は保持**（Q4）。timestamped 監査記録は現状（`docs/reviews/` 直下蓄積・管理外）を**そのまま記述**（Q3）。
3. `plan-writing-rules.md` の**ヘッダ基本情報ブロック全体（:177-183）**を実体に是正: `作成根拠資料` を `reviewXXX` → `docs/issues/...IXXX.md`、`実装後評価` フィールドの意味を `IXXX_review.md`（または未作成）に更新、実プラン実体に合わせ `Draft PR` 行を補う（Low2＋精緻化1。:180 のみだと :181 に旧 `_post` 概念が残り新旧併存が再発するため）。
4. `issue-flow.md:241` の計画書命名 `plan_I{番号}_{概要}.md` を `plan_I###.md` に修正（Low1）。
