# I037: issue-bootstrap 軽量化と plan-issue へのブランチ管理移行

## 関連資料
- I029 retro 議論（2026-04-08）: issue-bootstrap の責務過多と plan-issue との分担再設計
- GitHub Issue: #62
- Draft PR: #63

## 背景/目的
- `/issue-bootstrap` は現在「採番・イシューファイル作成・ブランチ作成・コミット・プッシュ・GitHub Issue 作成・Draft PR 作成」を一括して行っている
- イシュー作成直後に計画書なしでブランチが切られるため、後から方向転換するとブランチが無駄になる
- ブランチ・PR は実装計画が確定した `/plan-issue` のタイミングで作成するほうが責務として自然
- `/issue-bootstrap` を「イシューの登録」に特化させ、ブランチ管理を `/plan-issue` へ移行する

## スコープ
### 含む
- `/issue-bootstrap` の軽量化: 採番・イシューファイル作成・GitHub Issue 作成のみに絞る（ブランチ・コミット・プッシュ・Draft PR を削除）
- イシューファイルに GitHub Issue 番号を記録するステップを追加
- `/plan-issue` にブランチ作成・イシューファイルのコミット＆プッシュ・Draft PR 作成を追加（`/issue-bootstrap` から内容を移行）
- `docs/runbooks/workflow.md` の各スキル説明を新しい責務に合わせて更新
- `docs/runbooks/issue-flow.md` の該当ステップを更新

### 含まない
- スキル以外の実装コード変更
- `/retro` スキルの改善（別イシュー I038 で対応）
- テンプレートファイルの変更

## 受け入れ条件（Acceptance Criteria）
- [ ] `/issue-bootstrap` を実行するとイシューファイルが `docs/issues/open/` に作成される
- [ ] `/issue-bootstrap` を実行すると GitHub Issue が作成される
- [ ] `/issue-bootstrap` を実行すると GitHub Issue 番号がイシューファイルに記録される
- [ ] `/issue-bootstrap` 実行後はブランチ切り替えが発生しない（現在のブランチのまま）
- [ ] `/plan-issue` を実行すると develop ベースのフィーチャーブランチが作成される
- [ ] `/plan-issue` を実行するとイシューファイルがコミット・プッシュされる
- [ ] `/plan-issue` を実行すると Draft PR が作成される
- [ ] 既存のワークフロー文書（workflow.md, issue-flow.md）が新しい責務を反映している

## 影響範囲（想定）
- Backend: なし
- Frontend: なし
- DB: なし
- Config/Infra: `.claude/skills/issue-bootstrap/SKILL.md`, `.claude/skills/plan-issue/SKILL.md`, `docs/runbooks/workflow.md`, `docs/runbooks/issue-flow.md`
