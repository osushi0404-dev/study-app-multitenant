## 背景/目的

### 現状の問題（証拠・再現手順）
- I121 の自動テスト TC-02 は「対象 advisory の不在」を `npm audit --json | grep -c "GHSA-..."` の**出力値が 0** であることで判定した。この形は合格（0 件一致）のとき **grep が exit code 1 を返す**ため、exit code を合否に使う自動実行（CI・スクリプト・`set -e` 環境）に組み込むと「合格なのに失敗扱い」に反転する。
- plan review（I121_plan_review_20260716_2021.md・Info）と code review（I121_code_review_20260717_0013.md・Low）の**独立レビュー 2 回で同じ指摘**が出た＝ルール不在による再発性が実証されている。

### 根本原因
- plan-writing-rules の false-green 節は「失敗条件を注入して NG（非ゼロ終了）になること」を要求するが、**合否判定インターフェースの向き（合格=exit 0 の統一）**を規定していない。このため出力値判定（合格時に非ゼロ終了）と exit code 判定が TC 間で混在できる（I121 retro の 5 Whys で特定）。

### 解決方針
- do（作成時に防ぐ）: plan-writing-rules の該当節に判定インターフェース統一ルールを追記する — 「決定論 TC の合否判定は exit code に統一する（合格=exit 0・不合格=非ゼロ）。出力値の目視比較（`grep -c` の出力 '0' 等）を合否基準にしない。不在判定は `! grep -q` 等の合格=exit 0 形で書く」。
- gate（レビューで止める）: plan-reviewer.md のテスト妥当性観点（P4）に「TC の合否基準が exit code の向きと一致しているか（合格時に非ゼロ終了するコマンドを合否基準にしていないか）」を追加する。さらに差し戻しファースト原則の「自動テストケース」表にも Blocker パターンとして 1 行追加し、検知が Info 止まりで素通りしない（該当すれば差し戻しになる）ようにする（/grill-me で確定）。
- do の消費箇所同期: plan-writing-rules と対で運用される `.claude/skills/plan-issue/SKILL.md` のセルフチェック項目にも同じ統一ルールを反映する（宣言だけ変えて消費箇所を取りこぼさない。/grill-me で確定）。
- do+gate の 2 層で、作成時点の防止とレビュー時の検知を両立する（I121 では gate 相当の指摘は出たが Info 止まりで、明文観点ではなかった）。
