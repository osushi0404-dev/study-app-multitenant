## 設計確認メモ（/grill-me）
- 前提の確認（2026-11-17・コードと開発の DB を読んで確かめた）: #466・#488・#491 は完了済みで、`backend/dashboard/` と `backend/studylogs/mistake_analysis.py` はもう `StudyLog` を読まない。本番環境はまだ無い。開発の DB の件数は `StudyLog` 0・`DailyStudySummary` 0・`StudyGoal` 0・`ProblemAttempt` 0・`SpacedRepetitionReview` 6（うち `study_session` が入っているもの 0）・`QuizAnswer` 217
- 本文に無かった読み手（2026-11-17 に見つけた）: `update_daily_analytics_task`・`send_study_reminders_task`（`backend/studylogs/tasks.py`）が「最近学習した人」を `study_logs__started_at` で判定している。間隔反復の `SpacedRepetitionViewSet.submit_review`（`backend/studylogs/views.py`）が動いている `StudyLog` を `study_session` に入れている
- `export_user_data_task`（`backend/studylogs/tasks.py`）・`generate_system_report_task`（`backend/core/tasks.py`）は、どこからも呼ばれず `backend/core/celery.py` の定期処理にも登録されていない。書き出しは件数を返すだけで中身を出さない
- Q: 表を消す段階（4・Danger Ops）も本イシューで行うか、別イシューに分けるか → A: 本イシューで 1〜4 を全部行う。消す前の件数の記録・バックアップ・戻し方の確認・承認は省かない
- Q: 3 つの表と一緒に消すもの → A: `StudyGoal` は消す（目標は `UserSettings.daily_study_goal_minutes` に一本化）。`ProblemAttempt` も消す（書き込む処理が無く 0 件・`QuizAnswer` が同じ役目）。これにより `ProblemAttempt.study_log` の外部キーを先に外す段階は要らない（`SpacedRepetitionReview.study_session` は外す）
- Q: 呼ばれていない `export_user_data_task`・`generate_system_report_task` をどうするか → A: 2 つとも消す。本人のデータを本当に書き出す機能（C2・開示の求めへの対応）は、画面や形式を決めてから作る別イシューとして起票する（→ #570・I570 として 2026-11-17 に起票済み）
- Q: 朝 7 時の学習リマインダーのメール（`send_study_reminders_task`）の「最近学習した人」の判定 → A: メールはいったん不要。`send_study_reminders_task` と `backend/core/celery.py` の `send-study-reminders` の登録を両方消す。作り直しの起票はしない（要るときに送る相手・文面を決め直して別イシュー）
- Claude の決定（技術）: 夜 2 時の `update_daily_analytics_task` の「最近学習した人」は、直近 7 日に `QuizAnswer.answered_at` があるか `SpacedRepetitionReview.reviewed_at` がある人にする。`submit_review` は `study_session` を渡さない形にし、`SpacedRepetitionService.review_card` の `study_session` 引数を消す

## 背景/目的

**背景**: I473 で、学習の数字の出どころをクイズの答えの記録（`QuizAnswer`）に 1 本化した。古い学習記録の表（`StudyLog`・`DailyStudySummary`・`StudyGoal`）と解答の試行の記録（`ProblemAttempt`）には、画面から書き込む経路が無い（`frontend/src`・`e2e/tests` から `/api/study/logs/`・`/api/study/statistics/`・`/api/study/goals/` を呼ぶところは無い・2026-11-13 に grep で確認。`ProblemAttempt` は管理画面だけ）。それでもモデル・API・定期処理が残っていて、読み手が新しい処理の材料にしてしまうおそれと、保守の手間がある。
**目的**: 古い学習記録の表と、それを読む・書くコードを片付ける。読み手を先に移し、最後にテーブルを消す。

### 現状の問題（証拠・再現手順）
2026-11-17 の develop で、テストとマイグレーション以外の読み手・書き手:
- ~~統計画面の API `DashboardAnalyticsView`~~ → #488 で移行済み（2026-11-17 に grep で確認）
- ~~間違い分析の `_generate_general_suggestions`~~ → #466 で移行済み（同上）
- 定期処理: `update_daily_analytics_task`・`send_study_reminders_task`（`backend/studylogs/tasks.py`。`study_logs__started_at` で最近学習した人を判定）
- 呼ばれていない処理: `export_user_data_task`（`backend/studylogs/tasks.py`）・`generate_system_report_task`（`backend/core/tasks.py`）
- 間隔反復の復習の提出: `SpacedRepetitionViewSet.submit_review`（`backend/studylogs/views.py`）が動いている `StudyLog` を読み、`SpacedRepetitionService.review_card`（`backend/studylogs/services.py`）の `study_session` に渡す
- 学習記録の API: `StudyLogViewSet`・`StudyStatisticsViewSet`・`StudyGoalViewSet`（`backend/studylogs/views.py`・`backend/studylogs/urls.py`）とシリアライザ（`backend/studylogs/serializers.py`）・`backend/studylogs/admin.py`（`ProblemAttempt` の管理画面を含む）
- **外部キーの依存（消す順番に関わる）**: `ProblemAttempt.study_log`（`on_delete=CASCADE`）と `SpacedRepetitionReview.study_session`（`on_delete=SET_NULL`）が `StudyLog` を指す。`ProblemAttempt` は表ごと消すので問題ない。`SpacedRepetitionReview.study_session` は列を外してから `StudyLog` を消す
- 組織の境界の横断テストの表（`backend/core/tests/test_I446_cross_api_tenant_isolation.py` の `api/study/logs/`・`statistics`・`goals` の行）と I431・I455・I473 のテスト（`backend/studylogs/tests/test_I431_studylogs_tenant_isolation.py`・`backend/studylogs/tests/test_I455_org_scoped_querysets.py`・`backend/dashboard/tests/test_I473_overview.py`）・定期処理の登録のテスト（`backend/core/tests/test_I466_celery_schedule.py`）

### 根本原因
- ダッシュボードの元の設計（I190 以前）が、画面から書かれない表を集計元にしていた
- I473 で集計元を移したが、表の削除は「別イシュー（retro で起票を決める）」とし、retro で決め損ねた
- 今すぐ消せないのは、読み手（定期処理・間隔反復の提出・API）と、ほかの表からの外部キーが残っているため

### 解決方針（grill-me で確定）
- 段階を分けて 1 つのイシューで行う（読み手を移す → コードを消す → 外部キーを外す → テーブルを消す）。テーブルを消すまでは元に戻せる
  1. 読み手を移す・消す: `update_daily_analytics_task` の判定を `QuizAnswer.answered_at`・`SpacedRepetitionReview.reviewed_at` にする。`send_study_reminders_task` と定期処理の登録を消す。`export_user_data_task`・`generate_system_report_task` を消す。`submit_review` と `review_card` から `study_session` を外す
  2. API・シリアライザ・admin・テストの表を消す（画面から呼ばれていないことを確かめてから）
  3. `SpacedRepetitionReview.study_session` の列を外す
  4. `StudyLog`・`DailyStudySummary`・`StudyGoal`・`ProblemAttempt` のテーブルを消すマイグレーション（Danger Ops。消す前の件数の確認・バックアップ・戻し方を計画に書き、承認を得る）
