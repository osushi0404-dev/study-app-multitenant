## 背景/目的

### 現状の問題（証拠・再現手順）
- GitHubリポジトリは単一（osushi0404-dev/study-app-multitenant）で、「学習アプリ開発」と「ハーネス改善」の2トラックのイシューが混在している。
- ラベルは種別軸のみ（bug / enhancement / documentation / refactoring。`gh label list` で確認済み）。どのトラック（＝どの worktree）で対応するイシューかを示す軸が存在しない。
- そのため `gh issue list` の結果からトラックを判別するにはタイトルの文言から推測するしかなく、トラック別の一覧・棚卸し・着手判断ができない。
- 現在のオープンイシューは 24 件（2026-07-14 時点、`gh issue list --state open` で確認）。全件がトラック未分類。

### 根本原因
- イシュー分類の設計時点ではトラック運用（worktree 分離。I092 で runbook 化）が存在せず、ラベル体系が種別1軸のまま更新されていない。起票フロー（issue-flow.md / issue-bootstrap SKILL.md）にもトラック判定・付与の手順がない。

### 解決方針
- 種別ラベルと独立した第2軸として prefix 付きトラックラベル `track:app` / `track:harness` を GitHub に新設し、起票フローで両軸の付与を必須化する（GitHub 慣例の多軸ラベル分類。`gh issue list --label track:harness` で即フィルタ可能）。
- ラベル定義:
  - `track:app` — 学習アプリ開発。対応 worktree: study-app-multitenant（primary checkout）
  - `track:harness` — ハーネス改善（運用フロー・スキル・ガード・runbook）。対応 worktree: wt-harness
- トラック判定基準を issue-bootstrap SKILL.md / issue-flow.md に明文化する:
  - 変更対象が `docs/runbooks/`・`scripts/claude/`・`.claude/`（skills/hooks/settings）・レビュー/ゲート/テンプレートの仕組み → `track:harness`
  - 変更対象が `backend/`・`frontend/`・`e2e/` 等のアプリ機能・アプリのテスト → `track:app`
  - 両方にまたがる場合は主目的側に単一付与（両付与はしない。判断に迷う場合はユーザーに確認）
- 既存オープンイシュー全件（24件＋I107）にトラックラベルをバックフィルする（分類は「設計確認メモ」の承認済み分類表に従う）。
