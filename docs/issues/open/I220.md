# I220: イシューの起票は Claude が実行して事後に報告する（価値の低いもの以外は確認なし）を、手順書とスキルの決まりにする

## 関連資料
- GitHub Issue: #400
- 起点: I200（#335）のマージ後のユーザーの指示（2026-10-30）
- 今の決まり（逆のことが書いてある箇所）:
  - `docs/runbooks/workflow.md:64-66`「スキル呼び出しルール」: `issue-bootstrap` は「ユーザーが打つスキル」で、Claude が自分から呼んでよいのは retro 段階の起票だけ
  - `docs/runbooks/workflow.md:74`「各段階で止まったときの案内」: イシュー作成の依頼を受けたら「`/issue-bootstrap [タイトル]` を入力してください」と案内する
  - `.claude/skills/issue-bootstrap/SKILL.md:3`（frontmatter の description）と「## 呼ばれ方」: 使うのはユーザーが打ったときと retro からの起票のときだけ
- 参考: Claude の記憶（`feedback-propose-issue-title-on-separate-issue`）には 2026-10-30 に反映済み。記憶は確実に読まれないので、手順書とスキルを正にする（ユーザーの指示「覚えておくではなくルールなどに記載しておいて確実に実行されるようにして」）

## 設計確認メモ（/grill-me）
- Q（2026-10-30）: 会話の途中で Claude が自分で起票するとき、イシューにユーザーの判断が要る点（何を作るか・受け入れ条件・画面の文言など）が残っていたらどうするか？ → A（ユーザーの決定）: **起票の前に止めて聞く**（ユーザーが `/issue-bootstrap` を打ったときと同じ扱い）。質問をまとめて出し、答えを本文に入れてから起票する。判断が要る点が無ければ確認なしで起票し、起票した後に報告する。retro からの起票の扱い（質問しない・「未定・grill-me で確認」と書いて進める）は今のまま

## 背景/目的

**背景**: これまで、別イシューにすると決めたとき、Claude は `/issue-bootstrap` のコマンドをクリップボードに入れてユーザーに渡し、ユーザーが打って起票していた（I078・I146 の決まり。手順書の `workflow.md:74` もそう案内する）。I200 のマージ後に、ユーザーから次の指示があった。
- ユーザーの言葉（2026-10-30）:「イシュー起票の判断をこちらに確認するのはいいが、起票（起票コマンドなどの実行）はそっちでやるようにして。今後も。イシューで対応する価値が低いもの以外は確認無しで起票して。ただ起票したら報告はすること。」「覚えておくではなくルールなどに記載しておいて確実に実行されるようにして」
**目的**: 起票は Claude が `issue-bootstrap` を自分で呼んで行い、起票した後に報告する。確認するのは、イシューで扱う価値が低いか迷うものだけ。この決まりを手順書とスキルに書き、どのセッションでも同じに動くようにする。

### 現状の問題（証拠・再現手順）
- `workflow.md:64-66` と `issue-bootstrap/SKILL.md` の description が、Claude が自分から `issue-bootstrap` を呼ぶのを retro の起票だけに限っている。会話の中で「別イシューにする」と決まっても、Claude は呼べない決まりになっている
- `workflow.md:74` が、ユーザーに `/issue-bootstrap` を打たせる案内を決まりにしている
- 2026-10-30 の I200 の後続（I219 #399）でも、Claude はコマンドをクリップボードに入れてユーザーに渡し、ユーザーに打たせようとした

### 根本原因
起票を「ユーザーが打つスキル」と位置づけた決まり（I193 の流れの整理の時点）が、ユーザーの今の方針（判断の確認はよいが、実行は Claude）と食い違っている。

### 解決方針
- `workflow.md`「スキル呼び出しルール」の Claude が自分から呼んでよいスキルに、`issue-bootstrap`（会話の中で別イシューにすると決まったとき・後続の不具合を見つけたとき）を足す。価値の低いもの以外は確認なしで起票し、起票した後に「I###（#番号）・タイトル・なぜ起票したか」を報告する。価値が低いか迷うもの（軽い指摘・既存イシューへの同梱で足りそうなもの）だけ、起票するかを聞く
- `workflow.md:74` の案内を「Claude が起票して報告する」に直す
- `issue-bootstrap/SKILL.md` の description と「## 呼ばれ方」に「Claude が会話の中で起票するとき」を足す。そのときの質問の扱いは、ユーザーが打ったときに合わせる（設計確認メモ: 要件・基本設計・UI/UX の判断が要る点があれば起票の前に止めて聞き、答えを本文に入れてから起票する。無ければ確認なしで起票して報告する）
- 同時に複数起票するときは 1 件ずつ（採番の衝突・I189 #321）
