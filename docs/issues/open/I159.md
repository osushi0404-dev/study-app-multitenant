# I159: フロントエンド依存の critical 脆弱性（proxy-addr / shell-quote）を npm audit fix で解消し CI を復旧

## 関連資料
- GitHub Issue: #276
- Draft PR: #277
- 発見元: I151（#267）の Draft PR #269 の CI（run 38564774555・2026-10-14）。`Frontend Lint & Security` ジョブの `npm audit` ステップが失敗
- 先例: I121（PR #224）— 前回フロントエンドの npm audit critical で CI が止まったときの対応
- 根治（CRA → Vite 移行）は未起票のまま残っている（memory: npm audit backlog）

## 背景/目的

**背景**: I151 の `/code-review` 実行時、CI の `Frontend Lint & Security` が `npm audit --audit-level=critical --omit=dev` で失敗した。I151 はバックエンドのみの変更で、原因はフロントエンドの推移的依存に新しく公開された critical の脆弱性である。develop の定期監査（Dependency Audit）も 2026-10-09 以降、Frontend / Backend とも毎日失敗している（Backend 側は I151 で解消予定）。このままでは**全 PR の CI が赤のまま**になる。
**目的**: critical の 2 件を解消し、`npm audit --audit-level=critical --omit=dev` を exit 0 に戻す。I151 を含む全 PR の CI を通る状態に戻す。

### 現状の問題（証拠・再現手順）
再現: `frontend/` で `npm audit --audit-level=critical --omit=dev` を実行すると exit 1。CI ログの集計は `85 vulnerabilities (3 low, 14 moderate, 66 high, 2 critical)`。

critical の 2 件（いずれも `fix available via npm audit fix`＝`--force` 不要）:

| パッケージ | 現在の版 | 脆弱性 | 最新版 | 依存経路 |
|---|---|---|---|---|
| `proxy-addr` | 2.0.7 | GHSA-jqcg-44mw-7w3h（IPv4-mapped IPv6 の trust subnet による IP 偽装） | 2.0.8 | react-scripts 5.0.1 → webpack-dev-server 4.15.2 → express 4.22.2 → proxy-addr |
| `shell-quote` | 1.8.4 | GHSA-395f-4hp3-45gv（`parse()` の二次計算量による DoS）／GHSA-pqg4-j6r4-53mv（`quote()` のコマンド注入） | 1.12.0 | react-scripts 5.0.1 → react-dev-utils 12.0.1 → shell-quote ／ webpack-dev-server → launch-editor 2.14.1 → shell-quote |

（2026-10-14 に `npm ls proxy-addr shell-quote --prefix frontend` と `npm view` で確認）

### 根本原因
- 推移的依存の既知脆弱性が新たに公開された（コード変更起因ではない）
- どちらも開発サーバー用の依存だが、CRA の慣習で `react-scripts` が `dependencies` にあるため `--omit=dev` でも監査対象に入る
- 構造的には CRA（react-scripts 5.0.1・メンテ停止）に依存していることが、同種の CI 停止を繰り返す原因（根治は CRA → Vite 移行。本イシューの範囲外）

### 解決方針
`frontend/` で `npm audit fix`（`--force` なし）を実行し、`package-lock.json` 内の `proxy-addr` を 2.0.8 以上、`shell-quote` を修正版以上へ更新する。どちらも親パッケージが宣言する semver 範囲内の更新で、`package.json` の直接依存は変えない。
- `npm audit fix` が critical 以外のパッケージも範囲内で上げる場合は、差分をレビューして許容する（範囲内更新のため）。差分が大きすぎる場合は 2 パッケージだけを狙った更新（`npm update proxy-addr shell-quote`）に切り替える。どちらにするかは /plan-issue で差分を実測して決める
- `--force`（react-scripts@0.0.0 への破壊的変更）は使わない

## スコープ
### 含む
- critical 2 件（proxy-addr / shell-quote）の解消
- `npm audit --audit-level=critical --omit=dev` が exit 0 になることの確認
- フロントエンドのビルド・テスト・型チェック・E2E の回帰確認
