# I060: CLAUDE.md と runbooks の棚卸し・最新化

## 関連資料
- GitHub Issue: #122
- 起点: ユーザー要望（2026-05-12）— 「ファイル作成時から大きく修正したから全体的に確認・最新化して」
- 対象: `CLAUDE.md` および `docs/runbooks/*`
- 直近の関連イシュー:
  - I058（レビュースクリプトのコマンド化、pre-commit hook 追加）— `docs/runbooks/pre-commit.md` を新設したが CLAUDE.md の参照先一覧には未反映
  - I059（イシューファイル自己完結度向上）— `issue-bootstrap` / `issue_template.md` の変更が runbooks 側にも波及する可能性あり

## 設計確認メモ（/grill-me）
- Q: CLAUDE.md 参照先一覧は「日常運用で使う runbook のみ列挙」か「全 runbook を網羅列挙」か → A: **全 runbook を網羅列挙する**。現在未参照の5本（`pre-commit.md` / `branch-protection-setup.md` / `mcp-github-setup.md` / `mcp-usage.md` / `onboarding.md`）をすべて CLAUDE.md の参照先一覧に追加する。AC「漏れ・誤参照ゼロ」は全14ファイルが過不足なく列挙されている状態を指す。
- Q: 実在する `posttooluse_check.py`（PostToolUse）も CLAUDE.md に記載するか／記載先は → A: **記載する**。理想状態＝CLAUDE.md「3. 権限と二重ガード」に2フックを各1行で併記する（PreToolUse: `pretooluse_guard.py`＝危険操作をブロック／PostToolUse: `posttooluse_check.py`＝Edit/Write 後に `.py`/`.json`/`.yaml` の構文チェック）。Claude Code フック専用の runbook は存在せず、新規 runbook 作成は本イシューのスコープ外のため、詳細はフックファイルの docstring に委ね CLAUDE.md は1行ずつの簡潔記載に留める（「短く保つ」方針を維持）。※`pre-commit.md` の「git hooks」は `.git/hooks` の別機構であり Claude フックとは無関係なので混同しないこと。
- Q: 再発防止の同期手順（新規 runbook 追加時に CLAUDE.md 参照先を更新）の追記先は workflow.md か template-sync.md か → A: **template-sync.md に追記する**。理想状態＝同ファイルが既に持つ「ルール変更時に関連ファイルを同時更新する」不変条件の一事例として手順を追加し、同期ルールを一箇所に集約する。workflow.md には重複記載しない。
- Q: 乖離一覧（修正前後の差分まとめ）の記録先は計画書か PR 本文か → A: **計画書に残す**。
- Q: runbook 記述と実体（`.claude/settings.json` / hooks / skills）が食い違った場合の修正方向は → A: **原則ドキュメント側を実体に合わせて修正する**。実体（コード／設定）側の修正が必要なケースは本イシューでは行わず別イシューに切り出す。
- Q: 「最新化」の深さは全文リライトか限定修正か → A: **対象14ファイルの全文リライト（文体・細部含む）まで実施する**。

## 背景/目的

### 現状の問題（証拠・再現手順）
`CLAUDE.md` は 2026-04-10 に最終更新され、参照先として 8 本の runbook を列挙している。
一方、`docs/runbooks/` 配下は同日以降にも実体が変化している:

- 新規ファイル: `pre-commit.md`（2026-05-02、I058 で追加）が CLAUDE.md の参照先一覧に未掲載
- 既存ファイルが CLAUDE.md と乖離していないかの点検が未実施:
  - `workflow.md`（2026-04-15）: 直近で `/grill-me` `/plan-issue-review` `/security-review` `/retro` 等の skills が追加・統合されているが、CLAUDE.md の「使うスキル」は `workflow.md` への委譲のみで実体追従が確認できていない
  - `plan-writing-rules.md`（2026-05-02）: 計画書原則（垂直スライス・未知リスク先行・検証コマンド禁止等）が追記されているが、CLAUDE.md の「絶対ルール」と整合しているか未点検
  - `issue-flow.md`（2026-04-10）: I059 で扱う「イシューファイルの自己完結度」と整合しているか未点検
  - その他（`danger-ops.md` / `common-commands.md` / `ux-rules.md` / `backend-check.md` / `review-rules.md` / `template-sync.md`）: 最終更新 3〜4 月で、実体（`.claude/skills/` / `.claude/settings.json` / `scripts/claude/hooks/`）との整合性が未確認
- CLAUDE.md 本体の項目「3. 権限と二重ガード」が参照する `scripts/claude/hooks/pretooluse_guard.py` の実体・現行ルールとの整合性も未点検

### 根本原因（推定）
- runbooks は I058 のような個別イシューで都度更新されるが、**CLAUDE.md の参照先一覧と runbooks 群を横断する棚卸し** がワークフロー上に組み込まれていない
- 新規 runbook を追加した際に CLAUDE.md の参照先を同時更新する仕組み（pre-commit / CI チェック / レビュー観点）が無い

### 解決方針
1. `CLAUDE.md` および `docs/runbooks/*` の全ファイルを横断点検し、以下 3 観点で乖離を洗い出す:
   - **参照整合性**: CLAUDE.md の参照先リストが現存ファイルと一致するか / 漏れ・誤参照が無いか
   - **実体整合性**: runbooks の記述が現在の `.claude/skills/` `.claude/settings.json` `scripts/claude/hooks/` `docs/issues/templates/` 等の実体と一致するか
   - **相互整合性**: runbooks 間で重複・矛盾・古い手順が無いか
2. 洗い出した乖離点を一覧化し、修正必要箇所を計画書で確定させてから一括更新する
3. 棚卸しの「再発防止」観点として、新規 runbook 追加時に CLAUDE.md 参照先一覧を更新する手順を `workflow.md` または `template-sync.md` に追記するか検討する

### 変更対象（既知の候補）
- `/mnt/c/app/study-app-multitenant/CLAUDE.md`
- `/mnt/c/app/study-app-multitenant/docs/runbooks/`配下全ファイル
  - `workflow.md` / `plan-writing-rules.md` / `danger-ops.md` / `common-commands.md` / `issue-flow.md` / `ux-rules.md` / `backend-check.md` / `review-rules.md` / `template-sync.md` / `pre-commit.md`
  - 参考: `branch-protection-setup.md` / `mcp-github-setup.md` / `mcp-usage.md` / `onboarding.md`（CLAUDE.md 未参照）

### 制約・引き継ぎ情報
- CLAUDE.md は「短く保つ（ルールを増やさない）」方針が明記されている（参照先集約スタイルを崩さない）
- runbooks の各文書は独立して読まれることがあるため、重複削除時は「どちらに残すか」を明示して片寄せする
- 本イシューはドキュメント変更が主体だが、`workflow.md` / `issue-flow.md` の手順変更はワークフロー全体に影響するため、変更前に計画書承認を必須とする

## スコープ
### 含む
- `CLAUDE.md` の参照先一覧・絶対ルール・権限ガード記述の最新化
- `docs/runbooks/*.md` 全ファイルの内容点検と最新化
- 乖離一覧の作成と修正実施
- 新規 runbook 追加時の同期手順の検討と追記

### 含まない
- `rules/` 配下のコーディング規約（Backend/Frontend）本体の修正（CLAUDE.md からの参照リンク健全性のみ確認）
- `.claude/skills/` 配下のスキル本体の改修（runbooks の記述と乖離がある場合は乖離の方向を計画書で確定）
- `docs/runbooks/legacy/` 配下の旧資料の更新
- 新しい runbook の新規作成（既存の更新に限定）
