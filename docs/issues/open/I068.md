## 背景/目的

### 現状の問題（証拠・再現手順）
ワークフローの指示ファイル（`.claude/skills/*/SKILL.md`・`docs/runbooks/*`・`.claude/review-agents/*`）を編集する際、コードに対しては行っている一貫性・決定論チェックが適用されておらず、レビュー段階で初めて不整合が顕在化している。I067 で具体的に 3 件発生した:

1. **分岐のコマンド粒度パリティ欠如（P1）**: I067 で plan-issue に「既コミット経路」分岐を追加した際、対になる通常経路は `git push -u origin feature/...` を明示していたのに、新規分岐は「push してから」と散文で済ませ非対称になった。code-review で **Medium** 指摘（`docs/reviews/closed/I067_code_review_20260618_1906.md`）。
2. **中核概念変更時の消費箇所取りこぼし（P2）**: I067 で test を「計画駆動（auto_test.md が正）」へ変更した際、テスト選択ロジックは更新したが同一ファイル内の `## 停止条件`（pytest/Jest/E2E 固定）の更新を初回に漏らした。plan-issue-review で **Warning** 指摘（`docs/reviews/closed/I067_plan_review_20260618_1849.md`）。
3. **設計メモ↔イシュー本文のスコープ不整合（P3）**: I067 の grill-me 設計メモは対象スキルに retro/close を追加したが、イシュー本文「想定する反映先」テーブルは plan-issue/test の 2 行のまま放置され、計画書の 4 ファイルと不一致になった。plan-issue-review で **Warning** 指摘。

### 根本原因
単一の根本原因に集約される: **ワークフロー指示ファイルの編集に、コード並みの「一貫性・決定論チェック」を適用する仕組みが無い**。具体的には、(a) 新規分岐を対の既存手順と突き合わせる手順、(b) 中核概念を変更したとき同一ファイル内の全消費箇所を洗い出す手順、(c) grill-me 設計メモがスコープを変えたとき本文を整合させる手順、がいずれも存在しない。検証も散文チェックリスト（①手続き）止まりで、決定論ゲート（②）に上げられていない。

### 解決方針
3 つの予防策を**検証強度で階層化**して導入する（②決定論ゲートに上げられるものは上げ、困難なものは①手続き＋レビュー観点として正直に置く）。各予防策は「do（実行手順）＋gate（レビュー観点）」の 2 層で表現する。

- **P3 → ②決定論ゲート**: 独立スクリプト `scripts/claude/check-memo-body-paths.sh` が、メモブロック内のバックティック囲みパス集合と、本文の構造化セクション（`## 実装対象` テーブル列＋`## 影響範囲` Config/Infra 行）のパス集合を比較し、**メモ ⊆ 本文**を判定する（メモにあって本文に無いパスを不一致として列挙・`未特定` 等プレースホルダ除外）。**grill-me が memo 追記後に実行**（既存「本文整合（必須）」の機械化）し、不一致はソフト警告 → その場で本文整合してから plan-issue へ。`plan-issue-review`（plan-reviewer）に grill-me skip 時の backstop 観点を追加。issue-review.sh には置かない（メモ生成前で比較対象が無いため）。
- **P2 → ①手続き＋grep 補助**: plan-writing-rules.md の「規約是正時の消費箇所の全件列挙」を、**概念・セマンティクスの変更（判定基準・『正とする対象』等）も対象に含める**よう拡張し、同一ファイル内の全参照箇所（停止条件・記録・後続ステップ参照）を grep で洗い出す手順とする。gate を plan-reviewer.md に追加。
- **P1 → ①手続き＋gate 観点**: 意味的パリティは完全な決定論化が困難なため、plan-writing-rules.md（do）に「指示ファイルへ条件分岐を追加する場合、対になる既存手順と同じ粒度＝具体コマンド/ステップまで書き、暗黙の省略を残さない」を追加し、plan-reviewer.md・code-reviewer.md（gate）に「新規追加の条件分岐に、対の既存手順が明示するコマンド・ステップの非対称な省略が無いか」を追加。

## 制約・引き継ぎ情報
- 検証強度は **①手続き ＜ ②決定論ゲート ＜ ③敵対的検証** の階層に従い、②に上げられる P3 はゲート化、P1/P2 は①＋gate に留める（理想化の過剰を避ける）。
- P3 のゲートは memo ⊆ body のパス集合比較（メモ内バックティック囲みパス vs 本文の構造化セクション）。誤検知を避けるため、本文の「未特定・grill-me で確認」等プレースホルダ行は比較対象から除外する。実装は独立スクリプト・grill-me 実行・ソフト警告（詳細は設計確認メモ参照）。
- scripts 側の変更を含むため、Dockerfile/CI への波及は plan-issue 時に確認する（既存 issue-review 経路の踏襲なら影響軽微の想定）。
- 詳細な do/gate の最終文言・P3 ゲートの実装方式（issue-review.sh への組込み vs 独立スクリプト）は /grill-me / /plan-issue で確定する。
