## 背景/目的

**背景**: I587 で問題・解説の画像の中身を DB に保存し、`GET /api/media/<id>/` から返すようにした。そのとき、画面から使われていない 2 つの action（`POST /api/problems/<id>/images/upload/`・`DELETE /api/problems/<id>/images/delete/<asset_id>/`）は、ファイルに書く経路を残さないことを優先し、「共通の保存・削除を呼ぶ」だけに直した。レビューで、その周りの作りの崩れと、移行・テストの細部が Low として残った。
**目的**: 画像の登録・削除の業務の処理をサービスに寄せ、エラーの形を規約にそろえる。移行 0025 が後のコードの変更で動きを変えないようにし、テストの比べ方を確実にし、読む所の無くなった列を片付ける。

### 現状の問題（証拠・再現手順）
1. F4: `backend/problems/views.py` の `upload_image`・`delete_image` が、ビューの中で `transaction.atomic` を開き、サービスの非公開の関数 `ProblemService._save_image_as_asset`・`_discard_asset` を直接呼んでいる。表示順の採番・紐づけの作成・共有の判定もビューに書かれている（規約 `rules/ultimate_django_coding_standards.md` §6・§7）
2. F5: 同じ 2 つの action が `Response({'error': '...'})` の独自の形でエラーを返しており、`core.exceptions.custom_exception_handler` の形（`{"error": {"main_message", "sub_message", "details"}}`）とそろっていない（ファイルが無い・`usage_kind` の誤り・紐づけが無い・画像が無い）
3. F7: `delete_image` が自分の紐づけ（`problem_link`）を探すとき `is_deleted=False` で絞っていない。論理削除済みの紐づけを物理削除して 200 を返しうる（I587 の F1 で、共有の判定だけは `is_deleted=False` にそろえた）
4. F3: `backend/problems/migrations/0025_move_media_files_to_db.py` が今の `problems.media_migration` と `problems.utils`（`ALLOWED_IMAGE_FORMATS`・`detect_mime`）を読んでいる。後で許す形式などを変えると、新しい環境で `migrate` を最初から流したときの 0025 の動きが変わる
5. F6: `backend/problems/tests/test_I587_media_migration.py` の `assert f"id={present.id}" not in out` は部分文字列の比べで、ID が別の ID の接頭辞のときに誤って落ちうる（UUID なので起きにくい）
6. `backend/problems/models.py` の `Subject.image_directory` は、読んでいたメソッド（`get_image_base_directory` など）を I587 で外したので、読む所が無い

### 根本原因
I587 は「画像の置き場を DB にする」ことが範囲で、画面から使われていない 2 つの action は動きを変えずに保存・削除の呼び先だけを替えた。作りの整理（サービスへの寄せ・エラーの形）は範囲の外として残した。0025 は移行の中身を管理コマンドと共有するため、アプリのモジュールを読む形にした。

### 解決方針
- 画像の追加・削除をサービスの公開の関数（例: `ProblemService.add_image(problem, file, usage_kind)`・`remove_image(problem, asset)`。`@transaction.atomic`）にまとめ、ビューはそれを呼ぶだけにする。共有の判定・自分の紐づけの絞り込みを 1 か所にする（F4・F7）
- エラーは DRF の例外（`ValidationError`・`NotFound`）で投げ、`custom_exception_handler` の形にそろえる（F5）
- 0025 の扱い（今の形のままにして、許す形式などを変えるときに 0025 を凍結した写しにするか、今のうちに 0025 の中へ判定を写すか）は、計画で決めて理由を書く（技術の判断・grill-me で確認済み）
- テストは行全体で比べる形にする（F6）
- `Subject.image_directory` を外す（確定・grill-me）。列の削除のマイグレーションを足し、流す直前に値の入った行の数を数えて見せ、ユーザーの承認を得る（Danger Ops）
