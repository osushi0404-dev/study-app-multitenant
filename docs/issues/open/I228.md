## 背景/目的

**背景**: 敵対的レビュー（高リスクの変更で、合格を反証する別のレビュー）は、計画書の「## 必ず確かめる項目」の実験必須の項目がすべて実験で確かめられないと合格にしない。中身と関係のない理由で実験必須の項目が未検証になり、HIGH → 周の追加・上限到達でユーザーの判断が要る回が続いている（I213・I431・I446・I452・I455・I463・I469）。
**目的**: 中身が変わっていないのに確かめ直しで未検証になる回、実験の環境が無くて実験が空振りする回、決定論で覆える性質を実験に頼って周を失う回を無くし、敵対的レビューが無駄な周・上限到達で止まらないようにする。

### 現状の問題（証拠・再現手順）
1. **確認済みの引き継ぎが無い**: 前の周で実験により確認済みだった項目（I213 の V2〜V4・I469 の V2・V3）が、記録の文書だけの差分を見た次の周で実験されず「未検証」になった。その間、記録の場所の外のファイルは 1 行も変わっていない。I469 は上限に達し、ユーザーの承認で 3 周目を回した
2. **実験役がアプリのテストを流せない**: 実験役はホストのシェルで動くが、ホストに `python` が無く（アプリのテストはコンテナの中だけ）、`python -m pytest …` が `No such file` / `failed to run command 'python'` で空振りする（I431・I446・I455・I452 の 4 回連続）
3. **決定論で覆える性質を実験必須にしている**: 失敗の注入（守りを外すと落ちるか）や表と `--help` の突き合わせを実験必須にし、レビュー役が実験を選ばない・実験が走らないと 1 周を失う（I446 の V6・I463 の V1）。どちらも後から決定論の TC を足して「読んで可」に下げて通した

### 根本原因
1. 前の周の確認結果を、記録の場所の外が変わっていなければ次の周に引き継ぐ仕組みが無い
2. 実験役への案内（`.claude/agents/adversarial-reviewer.md`・`scripts/claude/adversarial-review.sh` の実験の段取り）に、アプリのテスト・管理コマンドはコンテナ（`docker compose exec -T backend …`）で流すことが書かれていない
3. 計画の段階で、実験必須にする前に決定論の TC（失敗の注入つき・本物のファイルを書き換えない）で覆えないかを考える手順と、それを確かめる関所が無い

### 解決方針
- 1（引き継ぎ）: 前の周（周に数えた最新の記録）に「確認済み（実験）」だった項目は、その記録の `REVIEWED_COMMIT` から HEAD までに記録の場所の外のファイルが 1 つも変わっていなければ「確認済み（前の周から引き継ぎ）」として数え、記録に引き継いだこと（元の記録のファイル名）を書く。記録の場所の外が 1 つでも変わっていれば引き継がない。`REVIEWED_COMMIT` が無い・HEAD の祖先でないときも引き継がない。判定は既存の「記録の場所だけか」の決まり（`gate-check.sh`・`code-review.sh` の `changed_outside_records`）と同じもので決定論に出し、レビュー役の判断は使わない
- 2（コンテナの案内）: 実験役への案内に「アプリのテスト・管理コマンドは `docker compose exec -T backend <コマンド>` で実行する（ホストに python は無い）」を足す。実験の出力が「command not found」「No such file」だけのときは、その実験を「実行できなかった」に数える（往復の中で 1 回だけ言い直させるかは計画で決める）
- 3（決定論の TC への寄せ）: `docs/runbooks/plan-writing-rules.md` の高リスクの「必ず確かめる項目」に「実験必須にする前に、決定論の TC（失敗の注入つき・`mock.patch` などで本物のファイルを書き換えない）で覆えないかを書く。覆えるなら TC を書いて『読んで可』にする」を足し、`.claude/agents/plan-reviewer.md` の高リスクの観点に「実験必須の項目に、決定論で覆える性質のものが無いか」を足す
