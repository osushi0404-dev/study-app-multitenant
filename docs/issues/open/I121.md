## 背景/目的

### 現状の問題（証拠・再現手順）
- CI「Frontend Lint & Security」ジョブの `npm audit --audit-level=critical --omit=dev` ステップが exit 1 で fail し、**全ブランチの PR CI がブロック**されている（frontend 無変更の PR #219 でも fail を実証・2026-07-16）。
- develop の定期監査（dependency-audit.yml・毎日 JST 7:00）も 2026-07-15 22:48 に fail し、#220 が自動起票済み。
- 監査結果: **25 件（critical 1 / high 7 / moderate 7 / low 10）**。前日までは 24 件（critical 0）で、ゲートは critical のみ fail 対象のため通過していた。

### 根本原因
- リポジトリ無変更のまま、新規 advisory の公開（websocket-driver: critical ×2 件・ws: high 1 件）で監査結果がドリフトした（I109 が想定した「時間経過で発生する依存脆弱性ドリフト」の実例）。
- 対象パッケージは CRA（react-scripts）のツールチェーン依存。react-scripts は package.json の `dependencies` 側にあるため `--omit=dev` でも監査対象に含まれる。
- CI ゲートは `--audit-level=critical` のため、**fail の直接原因は websocket-driver（critical）のみ**（ws high はゲート非対象だが同時に fix 可能）。

### 解決方針
- `npm audit fix`（非破壊・semver 互換範囲の更新のみ）を frontend に適用し、critical（websocket-driver）を解消して CI ブロックを解除する。監査ログに「fix available via `npm audit fix`」と明示されている（websocket-driver・ws とも）。
- 変更は package-lock.json の更新を想定（必要な場合のみ package.json の既存 `overrides` 運用に追記）。`npm audit fix --force`（react-scripts@0.0.0 への破壊的変更）は**使わない**。
- react-scripts 固定で fix 不可能な残存指摘（serialize-javascript / uuid 系等・本番露出なし）は従来決定どおりスコープ外を維持（根治の Vite 移行は別の中期イシュー）。
- 適用後の実測件数・fix 可能範囲は計画段階で `npm audit` を実走して確定する（ツール実行による完了基準の確定。実行は track:app の worktree で行う）。
