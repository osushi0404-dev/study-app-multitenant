# I034: pre-commit hooks の導入（シークレット検出・コード品質チェック）

## 関連資料
- docs/proposals/I026_ai_dev_improvement_proposal.md（改善案 A の PostToolUse 議論から派生）
- I029: PostToolUse フックは軽量構文チェックに限定。コミット前のシークレット検出は pre-commit hooks で対応することとした。

## 背景/目的
- I029 の計画策定時に、シークレット検出は PostToolUse ではなく git commit 時の pre-commit hooks が業界標準であると判断した
- 現状、コード内へのシークレットハードコードを防ぐ仕組みがない（`.env` の deny はあるが、コード内の直書きは防げていない）
- `pre-commit` フレームワークを導入し、`git commit` 時に自動でシークレット検出・基本的な品質チェックを実行する

## スコープ
### 含む
- `.pre-commit-config.yaml` の作成
- `detect-secrets`（シークレット検出）フックの設定
- Python 基本チェック（`check-yaml`・`end-of-file-fixer`・`trailing-whitespace` 等）
- `.secrets.baseline` の初期生成
- `docs/runbooks/` への pre-commit 利用手順の追記

### 含まない
- flake8・eslint の pre-commit 組み込み（Docker 経由の lint は現状維持）
- CI への pre-commit 組み込み（別途検討）

## 受け入れ条件（Acceptance Criteria）
- [ ] `.pre-commit-config.yaml` が作成されている
- [ ] `git commit` 時に `detect-secrets` が自動で走る
- [ ] シークレットを含むファイルをコミットしようとするとブロックされる
- [ ] `.secrets.baseline` が生成されており、既存の誤検知が除外されている
- [ ] pre-commit のインストール・初期設定手順が runbook に記載されている

## 影響範囲（想定）
- Backend: なし（コード変更なし）
- Frontend: なし（コード変更なし）
- DB: なし
- Config/Infra: `.pre-commit-config.yaml`（新規）・`.secrets.baseline`（新規）

## Danger Ops（有/無）
- 無
