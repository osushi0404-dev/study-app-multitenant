# I207: 台帳の残りを捨てるときに目印・重大度が消える穴を直し、軽い指摘は後続イシューにせず一覧へ回す

## 関連資料
- GitHub Issue: #346
- 起点: I206（#344・PR #345）の retro（手順 4-0「台帳の残り」）。記録は `docs/reviews/closed/I206_review.md`「## 振り返り」
- 台帳: `docs/reviews/closed/I206_code_review_20261027_1815.md`（1 周目・最新）の「## 台帳（累積・スクリプトが書く）」の `STATUS=open` の 6 件（F1〜F6）。指摘の本文と再現は同じ記録の FINDING 行
- I206 の計画: `docs/plans/closed/plan_I206.md`（4.0 の採否の表・4.2 台帳の残りの open の書き直しの扱い）
- 範囲の見直し（2026-10-27・ユーザー決定）: I206 の close の後、「ループ/ハーネスエンジニアリングの BP とサクサク進める観点で適切か」の確認で、後続の「レビューの残り」イシューが毎回生まれる連鎖（I197 → I202 → I205 → I206 → I207）を指摘し、①I207 を F1・F2 に絞る ②軽い指摘は毎回イシューにせず一覧へ回すよう retro の決まりを変える、の 2 つで進めることになった

## 背景/目的

**背景**: I206 で台帳の更新（`scripts/claude/code-review.sh` の `_LEDGER_PY` の `update`）の番号の合流と中身の無い指摘の増え方を直した。I206 自身の review-gate（1 周で OK）で、止める条件に当たらない指摘が 6 件、台帳に残った。retro の手順 4-0 は、止めなかった指摘を軽いものも含めてすべて後続イシュー（または既存イシューへのコメント）に回す決まりなので、台帳を直すたびに「レビューの残り」のイシューが 1 件ずつ生まれ、軽い指摘のために計画・レビュー・テストの全工程が毎回回っている。
**目的**: ①I206 で足した「台帳の残りの open の書き直しを捨てる」処理が、その行の止める側の値（目印・重大度・セキュリティ）まで捨てる穴（F1）と、同じ回の 2 回目の書き直しで resolved が open に戻る穴（F2）を直す。②軽い指摘で後続イシューが連鎖しないよう、retro の決まりを変える。

### 現状の問題（証拠・再現手順）
- F1（Medium・判定の仕組み）: `scripts/claude/code-review.sh` の `update` で、台帳の残りの番号を open で書いた行が止める中身でないときは丸ごと捨てる（I206 4.2）。そのため、その行に付いた `RISK=up`（計画の見立てを超えた高リスクの目印）・重大度の引き上げ・`SECURITY=yes` も消える。既にある指摘の書き直しで効く「止める側の値を残すマージ」と非対称。再現: 前の台帳の F2（app・Low・outside・open）に対し、レビュー役が同じ番号で `SEV=Medium … RISK=up` の open の行を書く → 捨てられ、`ledger_risk` は NO のまま
- F2（Low）: 同じ回で台帳の残りの番号を resolved で書いた後に open（止めない中身）で書くと、2 行目は `fid in seen` で捨てる条件をすり抜け、resolved が open に戻る
- 後続イシューの連鎖: `.claude/skills/retro/SKILL.md` の手順 4-0 は「拾った指摘は、1 件ずつ起票せず、まとめて 1 か所に振り分ける」としつつ、振り分け先が「後続イシュー」か「既存イシューへのコメント」だけ。軽い指摘（Low・再現なし）だけでも後続イシューができる。I206 の 6 件のうち、実害につながりうるのは F1 だけで、F3〜F6 は Low、うち F5・F6 は再現なし

### 根本原因
- F1・F2: 台帳の残りの open の書き直しを「振り直す／捨てる」の 2 択にしたとき（I206 4.2）、捨てる側で、その行が持つ止める側の値を前の行へ合流させる扱いを、既存の「止める側の値を残すマージ」と並べて比べていなかった。同じ回の 2 回目の書き直しの扱いも、捨てる条件の前提（初めて読む番号）に入っていない
- 連鎖: retro の手順 4-0 に、指摘の重さで振り分け先を変える決まりが無い（重さに見合わない工程が毎回回る）

### 解決方針
1. F1・F2: 台帳の残りの番号を open で書いた行を捨てるときも、止める側の値（`RISK=up`・重大度の引き上げ・`SECURITY=yes`・REPRO=yes）だけは前の行へ合流させる（既存の書き直しのマージと同じ規則）。同じ回に resolved と書いた番号を、後の open の行で open に戻さない。細かい直し方は計画で Claude が決める。I197-F1 の守り（止める中身なら新しい指摘として振り直す）と、I206 の「中身の無い指摘を増やさない」は保つ
2. retro の手順 4-0 を変える:
   - 後続イシュー（または既存イシューへのコメント）にするのは、台帳の残りのうち「再現のある Medium 以上」「`SECURITY=yes`」「`KIND=app`（アプリ本体）」のどれかに当たるものだけ
   - それ以外（Low、または再現なし）は、記録の場所の一覧ファイル（例: `docs/reviews/ledger_backlog.md`。名前・形は計画で決める）に、起点のイシュー・番号・要約・記録へのパスを 1 行ずつ追記する（イシューにしない）
   - 一覧は、ハーネスのイシューの計画（/plan-issue）で、実装対象のファイルに当たる行を見て、同梱するか残すかを決める（同梱した行は一覧から消す）。細かい手順は計画で決める
   - retro が書いてよい場所（記録の場所）の中で完結させ、手順は増やさない（判定は機械的にできる欄で決める: `SEV`・`REPRO`・`SECURITY`・`KIND`）
3. I206 の F3〜F6 は、2. の一覧の最初の行として載せる（直さない・受け入れ）
