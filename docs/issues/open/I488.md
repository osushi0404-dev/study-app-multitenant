## 設計確認メモ（/grill-me）
- 決め方: ユーザーの指示「BP,UI/UXの観点でベストなやり方で進めて」（2026-11-14）で、以下を Claude の推奨案で確定した

- Q: 期間の選び方とグラフの区切り → A: 「日別・週別・月別」の選択をやめ、期間を「直近 7 日・30 日・90 日・1 年」（`days` = 7・30・90・365）から選ぶ。既定は 30 日。グラフの区切り（棒 1 本の単位）は期間で自動に決める: 7 日・30 日は日ごと、90 日は週ごと、1 年は月ごと。期間の末日は今日（`timezone.localdate()`）で、今日を含む `days` 日。区切りの境目（週の始まり・月の始まり）の決め方は計画で決める。`days` の入力は I459 の `AnalyticsQuerySerializer`（1〜365 の整数）を残す（画面は 4 つの値だけを送る）
- Q: 上の数字のカードと科目の絞り込み → A: カードは選んだ期間の「合計の学習時間」「正答率」「解いた問題数」「学習した日数」の 4 つ。正答率は期間の正解の合計 ÷ 解答の合計（日ごとの正答率の平均にしない）・答えが 0 件なら「—」。学習時間は #473 と同じ（`time_taken` の合計・1 問 300 秒上限）。学習した日数は答えが 1 件以上ある日の数（日本時間）。科目の絞り込みは残し、ダッシュボードと同じ `subject_id`（`OrgSubjectField`・不正なら 400）で絞る。「科目別」のタブは、科目ごとの学習時間の円グラフと、科目ごとの学習時間・正答率・問題数のカード（中身を `QuizAnswer` 基準の本物にする）
- Q: 「間違いパターン」のタブ → A: 本イシューでは画面から外す（API も `mistake_patterns` を返さない）。どこにどう出すかは #466（間違い分析を画面につなぐ）で決める
- Q: 「データをエクスポート」のボタン → A: 外す（今は `console.log` だけで何もしない。押しても何も起きないボタンは置かない）。書き出しが要るなら別イシューにする
- Q: ダッシュボードとの役割分担・データ無しの表示 → A: ダッシュボード＝今日と直近 7 日・次の行動、統計画面＝期間を選んだ振り返り（推移と科目別の内訳）。学習データが 0 件のユーザーには、ダッシュボードと同じ「まだ記録がありません」とクイズを始める導線を出し、空のグラフは出さない。データはあるが選んだ期間（と科目）に答えが無いときは、グラフの所に「この期間の記録はありません」と出す（数字のカードは 0 と「—」）

## 背景/目的

**背景**: 学習統計の画面（`/statistics`）も、ダッシュボードと同じ理由で数字・グラフがほぼ 0 か空になっている。集計元が、どこからも書き込まれない `DailyStudySummary` / `StudyLog` であること、画面と API の受け渡し形式が合っていないことが理由。
**目的**: クイズの結果が統計画面の推移・科目別の内訳に正しく出る状態にする。#473 で作る集計のサービスを使い回し、ダッシュボードと統計画面で同じ数字の決まりにする。

### 現状の問題（証拠・再現手順）
- 再現: dev 環境でクイズを数問解く → 学習統計の画面を開く → 推移のグラフ・科目別の内訳が空か 0
- 画面と API のキーが合っていない: 画面は `study_time_trend`・`accuracy_trend`・`subject_breakdown`・`mistake_patterns` を読むが（`frontend/src/pages/Statistics.tsx:100-103`）、API（`GET /api/dashboard/analytics/`・`backend/dashboard/views.py:188-244`）は `daily_data`・`subject_distribution`・`performance_trends`・`subject_breakdown` を返す。名前が一致するのは `subject_breakdown` だけで、中身も、画面は科目ごとの成績（`subject_name` など・`Statistics.tsx:307-310`）を期待するが、API はプルダウン用の科目一覧（`subject_service.get_subjects_for_dropdown`）を返している
- 集計元が空: `DailyStudySummary`（`views.py:210-213`・`:254-262`）と `StudyLog`（`views.py:226-231`）を読むが、どちらも画面からの書き込み経路が無い（#473 の根本原因 1 と同じ）
- 日ごとに 1 クエリ・週ごとに 1 クエリを回している（`views.py:209-223`・`:251-272`。最大日数ぶんのクエリ）
- 書き出しのボタンは `console.log('Exporting data...')` だけで何もしない（`Statistics.tsx:86`）
- 「今日」を `timezone.now().date()`（UTC）で出している（`views.py:202`。#481 の対象）

### 根本原因
- #473 と同じ: 集計元の表に書き込む経路が無いこと、画面と API が別々の仕様で作られ、照合する仕組みが無いこと（画面の `|| []` が不一致を空で隠している）

### 解決方針
- #473 で作った `backend/dashboard/selectors.py` の集計（`QuizAnswer` 基準・学習時間は `time_taken` の合計で 1 問 300 秒上限・日本時間の日付・今日の復習の回も含める）を使い回し、analytics の応答を作り直す
- 応答の形をシリアライザで固定し、画面と API のキーを 1 本にする（単位をキー名に含める・比率は 0〜1・「データ無し」を区別する。#473 の契約の決まりに合わせる）
- 期間（`days`）の入力の確かめ方（I459 の `AnalyticsQuerySerializer`）は残す。画面は「直近 7 日・30 日・90 日・1 年」（既定 30 日）から選び、グラフの区切りは 7・30 日＝日ごと、90 日＝週ごと、1 年＝月ごと（設計確認メモ）
- 科目の絞り込みはダッシュボードと同じ `subject_id`（`OrgSubjectField`）で行う
- 数字のカードは期間の合計の学習時間・正答率（正解の合計 ÷ 解答の合計）・解いた問題数・学習した日数。「科目別」のタブは科目ごとの学習時間の円グラフと、科目ごとの学習時間・正答率・問題数
- クエリ数を期間に依らない定数本に抑える
- 「間違いのパターン」のタブは外す（API も返さない・#466 で扱う）
- 「データをエクスポート」のボタンは外す
- 役割分担: ダッシュボード＝今日と直近 7 日・次の行動、統計画面＝期間を選んだ振り返り。データ 0 件のユーザーには「まだ記録がありません」とクイズを始める導線、期間に答えが無いときは「この期間の記録はありません」
