# I016: スキルファイルとランブック間のファイル命名規則不統一の解消

## 関連資料
- .claude/skills/plan-issue/SKILL.md
- .claude/skills/implement/SKILL.md
- .claude/skills/close/SKILL.md
- docs/runbooks/issue-flow.md
- docs/runbooks/plan-writing-rules.md

## 背景/目的
I015 の調査で発覚した pre-existing 問題。スキルファイル間でファイル命名規則が不統一になっており、
`/implement` や `/close` が実際のファイルを正しく参照・操作できない可能性がある。

- `plan-issue/SKILL.md` が生成する計画書: `$ARGUMENTS_plan.md`（= `I015_plan.md`）
- `plan-writing-rules.md` が規定する計画書: `plan_I###_{概要}.md`
- 実際に存在するファイル: `plan_I015_概要.md`（plan-writing-rules 形式）
- `implement/SKILL.md` が読もうとする計画書: `$ARGUMENTS_plan.md`（= `I015_plan.md`）→ 実ファイルと不一致
- `close/SKILL.md` が移動しようとするパターン: `I###_*.md` → `plan_I###_*.md` にマッチしない
- `issue-flow.md` のテスト命名: `test_IXXX_manual.md` → 実ファイル `I###_manual_test.md` と不一致
- `issue-flow.md` のレビュー命名: `reviewXXX_IYYY.md` → 実ファイル `I###_review.md` と不一致

## スコープ
### 含む
- どの命名規則を「正」とするか決定（plan-writing-rules vs plan-issue SKILL vs 実ファイル）
- 決定した命名規則に合わせて `implement/SKILL.md`・`close/SKILL.md`・`plan-issue/SKILL.md` を統一
- `issue-flow.md` のファイル命名規則記述を実態に合わせて修正
- 必要に応じて既存ファイルのリネーム

### 含まない
- 命名規則以外のスキル変更

## 受け入れ条件（Acceptance Criteria）
- [ ] 計画書・テスト・レビューのファイル命名規則が1つに統一されている
- [ ] `implement/SKILL.md` が実際に生成されたファイルを正しく読める
- [ ] `close/SKILL.md` が全ドキュメントを正しく closed へ移動できる
- [ ] `issue-flow.md` のファイル命名記述が実態と一致している

## 影響範囲（想定）
- Backend: なし
- Frontend: なし
- DB: なし
- Config/Infra: なし（スキルファイル・runbooks のみ）

## Danger Ops（有/無）
- 無
