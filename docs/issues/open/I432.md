## 背景/目的

**背景**: Dependabot の PR #377 は、必須のチェック 6 件がすべて通り、「E2E Tests (Playwright)」だけが失敗したまま開いている（2026-11-10 に `gh pr checks 377` で確認）。E2E は今ブランチ保護の必須チェックに入っていないので、画面から承認すればこのままマージできてしまう。運用の決まりでは、赤い Dependabot の PR は直すイシューを立てることになっているが、まだ立っていなかった。
**目的**: #377 の版上げで E2E が落ちる原因を突き止めて直し、E2E を含む CI が緑の状態で版上げを取り込めるようにする（または、直せない理由を記録して PR を閉じる）。

### 現状の問題（証拠・再現手順）
- #377 の CI: Backend Lint & Security・Backend Tests・Frontend Type Check・Frontend Lint & Security・Frontend Tests・Harness Tests は成功、E2E Tests (Playwright) だけ失敗
- #376（同じ版へのイメージの更新）は E2E を含め全部成功
- CI の E2E（`.github/workflows/e2e.yml:48`）はイメージを使わず、`npm ci && npx playwright install --with-deps chromium` でブラウザを入れる。手元の E2E（`docker-compose.yml:172-193`）はイメージ上で `npx playwright install chromium` を流す
- 失敗したテストの名前と理由: 未特定（計画で CI の失敗ログを読んで確かめる。ログの中身はイシューに貼らない）

### 根本原因
未特定・計画で確認（候補: 1.64 での振る舞いの変化に既存のテストが合っていない・テストの不安定さ・ブラウザの入れ方）。

### 解決方針
- CI の失敗の記録を読み、落ちたテストと理由を特定する
- テストやアプリの側を直すべきもの（版上げで正しく見つかった不具合・古い書き方）は、このイシューのブランチで直す。Dependabot のブランチには直接コミットしない（取り込みは develop に直してから Dependabot に作り直させる、または直した版上げを自分のブランチで行う。どちらかは計画で決める）
- #376（イメージ）と #377（npm）は版がそろっていたほうが手元と CI の差が出にくいので、取り込む順も計画で決める
