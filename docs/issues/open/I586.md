## 背景/目的

**背景**: このアプリの使い勝手は、確かめ用のデータ（`verify_i487`・起動のたびに作り直す・問題は「確かめ数学の確かめ問題 1」のような中身の無いもの）と E2E でしか見ていない。本物の問題で、本当に勉強する利用者として使ったことがない。開発用のワークツリー（app-1 など）の DB は、起動し直し・作業中のブランチのマイグレーション・E2E で変わるため、勉強の記録を長く残す場所に向かない。

**目的**: 開発とは別の勉強用のワークツリー（`develop` のまま使う）に、ユーザー本人の利用者・組織・科目「データベーススペシャリスト」と、IPA の公開過去問（午前の選択式）を登録し、ユーザーが毎日の勉強に使える状態にする。使っていて気づいた使いにくさを、イシューの候補として集める。

### 現状の問題（証拠・再現手順）
1. 開発の DB には、本物の問題の入った科目が無い（確かめ用の科目の問題は中身の無いもの・`backend/dashboard/verify_data.py`）
2. 問題をまとめて入れる道具は管理コマンド `import_problems`（`backend/problems/management/commands/import_problems.py`・Markdown を読む・引数は `--subject-id`・作成者のメール・既定の難易度・試し実行・重複のスキップ）だけ。問題文の画像は扱わない（`:279-313` の引数に画像が無い）。本物の過去問で使ったことはない。画像は I587 から問題管理の画面で付けられる（DB に保存）
3. 解説が必須で、出典を書く決まった欄が無い（`backend/problems/models.py:96`）。#609 で直す
4. 勉強用の環境の作り方・過去問の扱い（出典・公開リポジトリに入れない）を書いた手順が無い

### 根本原因
3 つが重なっている。(1) 長く残せる DB が無い（開発用のワークツリーの DB は起動し直し・作業中のブランチのマイグレーション・E2E で変わり、確かめ用のデータは起動のたびに作り直される）。(2) 本物の問題を入れたことがなく、取り込みの道具（`import_problems`）が過去問の形で動くか確かめていない。(3) 勉強用の環境の作り方と、過去問の扱い（出典・公開リポジトリに入れない・公開されている情報だけを登録する）を書いた手順が無い。

### 解決方針
- 勉強用のワークツリーは、ユーザーが primary で作る（`claude --worktree <名前>`・サンドボックスの中からは作れない）。以降の作業はそのワークツリーの Claude が行う
- **#609 のマージ後に登録する**（解説を空にでき、出典の欄がある状態で入れる）
- 登録するのは公開されている情報だけ: 問題・選択肢・正解は IPA の公開 PDF（問題冊子・解答例）から取る。解説は入れない（IPA は午前の解説を出していない。過去問サイト・参考書の解説は写さず、Claude の自作の解説も入れない）
- 出典は #609 の出典の欄に「令和6年度 秋期 データベーススペシャリスト試験 午前Ⅱ 問N」と入れる。問題文に手を入れた（図を文章に直したなど）ときは「（一部改変）」を付ける
- 問題を書いた Markdown と、切り出した図・表の画像はリポジトリの外に置き、コミットしない（リポジトリは公開）
- 図・表が要る問題（問題冊子で、問題文または選択肢に図・表・グラフ・ER 図などの絵が入っている問題）も入れる。Claude が問題冊子から画像に切り出し、`import_problems` で問題を入れた後、問題管理の画面の操作（Playwright MCP）で画像を付ける（`import_problems` は画像を扱わないため）
- 難易度は Claude が問題ごとに判断し、理由を作業の記録に残す（`import_problems` の Markdown に問題ごとの難易度を書くか、画面で直すかは計画で決める）
- 午前Ⅰ（高度共通）や他の年度を入れるかは、最初の回を使ってから会話でユーザーと決める（未定・このイシューの外）
