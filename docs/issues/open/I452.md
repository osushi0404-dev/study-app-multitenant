## 背景/目的

**背景**: I431 の設計確認で、学習記録の API（`/api/study/` の下）がどの画面からも呼ばれていないこと、また間隔反復・適応的な問題選択・間違い分析・おすすめの作りが壊れていることが分かった。さらに grill-me（2026-11-12）で、これらはクイズの回答を材料にしておらず、直してつないでも中身が空のままになることが分かった。品質基準 C1 はこれらを最優先の価値に挙げているので、消さずに使えるようにする。
**目的**: クイズの回答から次の復習日が自動で決まり、ダッシュボードから復習を始められるようにする（間隔反復を端から端まで通す）。間違い分析・適応的な問題選択は 500 にならない状態にしてテストで固定する（画面は別イシュー）。画面側の使われていない関数は消す。

### 現状の問題（証拠・再現手順）
1. **画面から呼ばれていない**: `backend/core/urls.py:34` は `/api/study/` の下に `logs`・`statistics`・`goals`・`spaced-repetition`・`sr-cards`・`sr-reviews`・`mistake-analysis`・`adaptive-learning` を置く（`backend/studylogs/urls.py:10-17`）。`/api/dashboard/recommendations/`（`backend/dashboard/urls.py:7`）もある。しかし、どの画面（`frontend/src/pages/`）からも呼ばれていない。画面から呼ばれているのは `dashboard/overview/`・`dashboard/analytics/`・`/api/settings/` だけ（`frontend/src/pages/Dashboard.tsx:129`・`Statistics.tsx:72`・`Settings.tsx:124,163`）。
2. **画面側に、存在しないアドレスを指す関数が残っている**: `frontend/src/services/dashboard.service.ts` の `getStudyStats`・`getRecentSessions`・`startStudySession`・`endStudySession`・`recordProblemAttempt` は存在しない `/api/studylogs/` を指す（7 行目）。`getWeeklyProgress`・`getSubjectProgress` は存在しない `/api/dashboard/weekly-progress/`・`subject-progress/` を指す。これらと `getRecommendations` は、どの画面からも使われていない。
3. **難易度の型が合っていない**: `Problem.difficulty` は数字の欄（`backend/problems/models.py:129`・`IntegerField`・`DIFFICULTY_CHOICES` は 106 行目）。一方、`backend/studylogs/adaptive_selection.py`（131-158・389-399・441-448・505-519 行目など）・`mistake_analysis.py`（127-166 行目）・`services.py`（319-322 行目）・`views.py`（963-1102 行目）は `'easy'/'medium'/'hard'` の文字で扱う。適応的な問題選択は 500（`Field 'difficulty' expected a number but got 'easy'`。I166 の敵対的レビューで実測）。
4. **Problem に無い欄で絞っている**: `is_active` で絞っている（`backend/studylogs/adaptive_selection.py:295`・`backend/studylogs/services.py:62-63`・`backend/dashboard/views.py` の `SubjectRecommendationView`）。Problem モデルに `is_active` の欄は無い。
5. **テストが無い**: 上の API を使うテストは 1 本もない（`backend` の下を `spaced-repetition|adaptive-learning|mistake-analysis|sr-cards|sr-reviews|recommendations` で検索しても、テストのファイルに当たらない）。
6. **材料が書き込まれない**: 4 機能が読む `ProblemAttempt`・`SpacedRepetitionReview`・`StudyLog` に書き込む画面の経路が無い。クイズの回答は `QuizAnswer`（`backend/problems/models.py:238`）に入るが、どの機能も読まない。

### 根本原因
学習記録の機能はバックエンドだけが作られ、画面からつなぐ作業とテストは行われなかった。クイズの機能とは別の記録を材料にしたまま、クイズの回答から材料を作る経路も作られなかった。そのため、`Problem` モデルとのずれ（難易度の型・無い欄）が、どのテストにも画面にも引っかからなかった。ずれがいつ生じたか（作った時点からか、後のモデルの変更か）は未特定で、計画で git の履歴から確かめる。直接の原因は、モデルの欄を参照する側を確かめる仕組み（テスト）が無かったこと。

### 解決方針
- **間隔反復を端から端まで通す**: クイズで 1 問答えるたびに（`submit_answer`）、その問題の `SpacedRepetitionCard` を作るか更新する。次の復習日は正解・不正解から自動で決める（正解なら間隔を広げ、不正解なら翌日）。自己評価のボタンは置かない。同じ日に同じ問題を何度答えても、カードを更新するのはその日の最初の回答だけ。
- **復習のクイズの終わり**: 対象をすべて答え終えたら終える（「今日の復習が終わりました（○問中○問正解）」と「ダッシュボードへ戻る」ボタン）。いつものクイズの、全問の後も既出問題を出し続ける動きは変えない。
- **画面**: ダッシュボードのいちばん上（数字の並びより上）に「今日の復習 ○問」のカードと「復習を始める」ボタンを置く。押すと、いつものクイズ画面で、復習する日が来た問題だけを、上限なしですべて出題する（途中の中断は可。答えなかった問題は翌日以降も対象に残る）。件数と出題は、上部の科目選択に合わせる（科目を選んでいればその科目だけ、「すべて」なら全科目を混ぜる）。0 問の日は「今日の復習はありません（次は ○月○日）」と表示する（次の日付も選んでいる科目の中で決める）。
- **過去の回答は使わない**: 復習の対象は、この変更の後に答えた問題から作る（過去の `QuizAnswer` から一括で作らない）。
- **間違い分析・適応的な問題選択**: 壊れた箇所（難易度の型・無い `is_active`）を今のモデルに合わせて直し、500 にならないことをテストで固定する。画面へのつなぎ込みは別イシュー（本イシューの計画の段階で Claude が起票）。
- 難易度の文字と数字の対応（`Problem.DIFFICULTY_CHOICES` に合わせる）、`is_active` の直し方（絞り込みを消すか、欄を足すか）、正解・不正解から次の間隔への対応、復習の出題をクイズの開始処理（`QuizService.start_session`）にどう渡すかは、技術の選択として計画で決める。欄を足す場合はマイグレーションが要るため、Danger Ops の要否も計画で判断する。
- **不要なものは消す**: 存在しないアドレスを指す画面側の関数 7 つ（`getStudyStats`・`getRecentSessions`・`getWeeklyProgress`・`getSubjectProgress`・`startStudySession`・`endStudySession`・`recordProblemAttempt`）と定数 `STUDYLOGS_BASE_URL` を消す。
- **I190 に任せるもの（本イシューでは触らない）**: おすすめ（`SubjectRecommendationView`・`getRecommendations`）、`logs`・`statistics`・`goals` を残すか消すか。
- 組織の境界は、I431 で全経路を先に塞いでいる前提で進める（このイシューで境界を緩めない。I431 の回帰テストを保つ）。復習の対象は自組織で解ける問題（`problems.services.tenant_scope.available_problems`）に限る。

## 受け入れ条件（Acceptance Criteria）
- [ ] クイズで 1 問答えると、その問題の次の復習日が決まる。正解なら前回より間隔が広がり、不正解なら翌日になる（テストで固定）
- [ ] ダッシュボードのいちばん上（数字の並びより上）に「今日の復習 ○問」が表示され、「復習を始める」を押すと、復習する日が来た問題だけで、上限なしにすべてを出題するクイズが始まる（テストで固定）
- [ ] ダッシュボードで科目を選ぶと、復習の件数と出題がその科目だけになる。「すべて」のときは全科目をまとめて数え、全科目を混ぜて出す（テストで固定）
- [ ] この変更より前のクイズの回答からは、復習の対象が作られない
- [ ] 復習のクイズで対象をすべて答え終えると、「今日の復習が終わりました（○問中○問正解）」と「ダッシュボードへ戻る」ボタンが出て、それ以上は出題されない（テストで固定）。いつものクイズの出し続ける動きは変わらない
- [ ] 同じ日に同じ問題を 2 回以上答えても、次の復習日はその日の最初の回答だけで決まる（テストで固定）
- [ ] 復習の途中で中断すると、答えた問題は次の復習日が更新され、答えなかった問題は翌日以降も対象に残る（テストで固定）
- [ ] 復習が 0 問の日は「今日の復習はありません（次は ○月○日）」と表示される（次の復習日が無いときは「今日の復習はありません」）
- [ ] 他組織の問題や、自組織で解けなくなった問題は、復習の件数にも出題にも入らない（テストで固定）
- [ ] 間違い分析・適応的な問題選択の API が、自組織のデータで 500 にならずに結果を返す（テストで固定）
- [ ] 存在しないアドレスを指す画面側の関数 7 つと `STUDYLOGS_BASE_URL` が残っていない
- [ ] 間違い分析・適応的な問題選択を画面につなぐ別イシューが起票されている

- [ ] 全テストが pass する
