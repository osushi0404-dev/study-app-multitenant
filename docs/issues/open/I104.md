# I104: 科目管理を組織管理者権限に限定（非admin の科目 update/destroy を禁止・/subject-management ルートガード追加・参照は全ユーザー維持）

## 関連資料
- GitHub Issue: #196
- Draft PR: #209
- 発見経緯: I102（問題管理を組織管理者限定）の /retro（2026-07-09）で判明した、`quiz-management` と**同型の認可穴**（科目管理側）。C1 として起票。
- 関連イシュー: I102（#192）で `ProblemViewSet` と `quiz-management` を admin 限定化済み。本 I104 は同じ是正を `SubjectViewSet` / `subject-management` に適用する（ただし参照範囲の扱いが I102 と異なる＝下記）。

## 背景/目的

### 現状の問題（証拠・再現手順）
科目管理 API（`SubjectViewSet`）と画面（`/subject-management`）で、**組織管理者でない一般ユーザー（`role='user'`）が科目を編集・削除できる**。

証拠（2層）:
1. **BE**: `backend/problems/views.py` の `SubjectViewSet.get_permissions()` は `create` のみ `IsOrgAdmin`、それ以外（`update`/`partial_update`/`destroy` 含む）は `IsAuthenticated` のみ。コード内コメントに「update/destroy は別イシュー」と**既知の未対応**として明記されている。
   ```python
   def get_permissions(self):
       """create は org admin のみ許可（update/destroy は別イシュー）"""
       if self.action == 'create':
           return [permissions.IsAuthenticated(), IsOrgAdmin()]
       return [permissions.IsAuthenticated()]
   ```
2. **FE**: `frontend/src/App.tsx` の `subject-management` ルート（および `subject-management/:id`）は `OrgAdminRoute` でラップされていない。`Layout.tsx` のナビは `isOrgAdmin` で隠れているが、**非admin が `/subject-management` を直接 URL 入力すると管理 UI に到達できる**（I102 前の quiz-management と同状態）。

再現:
1. 一般ユーザー（`role='user'`）で認証する。
2. `PUT`/`PATCH`/`DELETE /api/subjects/{id}/` を直接叩く（または `/subject-management` に直接遷移して編集/削除）。
3. 認可が `IsAuthenticated` のみのため成功してしまう（自組織スコープ内だが、学生ロールがカリキュラム構造＝科目を改変・削除できる）。

### 根本原因
`SubjectViewSet` の更新系（update/partial_update/destroy）が `create` と非対称に admin 限定化されておらず、FE も管理画面ルートを admin ガードしていない。I102 で問題管理に対して行った是正が、姉妹リソースである科目管理に未適用のまま残っている。

### 解決方針
**科目の参照は全ユーザーに開いたまま、更新系（create/update/partial_update/destroy）を組織管理者（`role == 'admin'`）限定**にし、FE・BE の二重ガードで担保する。
- **I102 との差異（重要）**: 問題(I102)は「参照も admin 限定」にしたが、**科目は非admin も参照が必要**（新規登録画面で科目を選択・ダッシュボードで科目表示）。よって科目は「**参照(list/retrieve)=全ユーザー / 更新系=admin**」とする。`public`（AllowAny・未認証登録用）アクションは不変更。
- バックエンド: `SubjectViewSet.get_permissions()` を、`create`/`update`/`partial_update`/`destroy` = `[IsAuthenticated, IsOrgAdmin]`、`list`/`retrieve`/`public` = 現状維持（`public` は AllowAny）に是正。
- フロント: `/subject-management` および `/subject-management/:id` ルートを I102 で新設済みの `<OrgAdminRoute>` でラップ。

## 実装対象（既知のもの）
| ファイル | 変更内容 |
|---------|---------|
| `backend/problems/views.py` | `SubjectViewSet.get_permissions()` で `update`/`partial_update`/`destroy` を `[IsAuthenticated, IsOrgAdmin]` に（`create` は現状維持で admin・`list`/`retrieve` は `IsAuthenticated`・`public` は AllowAny 維持） |
| `frontend/src/App.tsx` | `subject-management`・`subject-management/:id` ルートを `<OrgAdminRoute>`（I102 で新設済み）でラップ |
| `backend/problems/tests/` | 認可回帰テスト追加（非admin=update/destroy 403・list/retrieve 200 / admin=update/destroy 200-204） |

## スコープ
### 含む
- `SubjectViewSet` の更新系（update/partial_update/destroy）を組織管理者限定にする（create は既存 admin 維持）
- `/subject-management`・`/subject-management/:id` の FE ルートガード（`OrgAdminRoute`）
- 認可回帰テスト（非admin=更新系403・参照200 / admin=更新系成功）
### 含まない
- 科目の参照（list/retrieve）を admin 限定にすること（**非admin の参照は維持**＝登録画面・ダッシュボードが依存）
- `public` アクションの変更（未認証登録用・AllowAny 維持）
- `ProblemViewSet`（I102 で対応済み）・その他 ViewSet の認可
- E2E の追加（必要なら別途。まずは BE 認可回帰＋FE ガードで担保）

## 関連する品質基準
- C1 正確性/信頼性 — 権限のない科目改変・削除を構造的に禁止する。
- C2 プライバシー/情報露出・マルチテナント — 更新系を管理者に限定し、操作範囲を明確化する。

## 受け入れ条件（Acceptance Criteria）
- [ ] 非admin（`role != 'admin'`）が `PUT`/`PATCH`/`DELETE /api/subjects/{id}/` を叩くと **403** を返す
- [ ] 非admin が `GET /api/subjects/`・`GET /api/subjects/{id}/` は従来どおり **200**（参照は維持）
- [ ] admin（`role == 'admin'`）は科目の作成・更新・削除を従来どおり実行できる（200/201/204）
- [ ] 非admin が `/subject-management`・`/subject-management/:id` に直接遷移するとアクセス不可（`OrgAdminRoute` の権限エラー表示）
- [ ] 上記を検証する認可回帰テストが追加され全て PASS する

## 影響範囲（想定）
- Backend: `problems/views.py`（`SubjectViewSet.get_permissions`）、`problems/tests/`（認可回帰テスト）
- Frontend: `App.tsx`（subject-management 系ルートを `OrgAdminRoute` で保護）
- DB: なし
- Config/Infra: なし

## 制約・引き継ぎ情報
- I102 の /retro（C1）で発見。`SubjectViewSet` のコードに「update/destroy は別イシュー」と既知未対応として明記されていた分の是正。
- `OrgAdminRoute`（`role === 'admin'` 判定）と `IsOrgAdmin`（`role == 'admin'`）は I102 で新設/既存＝再利用する。新規の権限部品は不要。
- **I102 との差異**: 科目は参照を全ユーザーに開いたまま更新系のみ絞る（問題は read+write とも admin 限定だった）。理由は非admin の科目参照利用者（登録画面・ダッシュボード）が実在するため。

## Danger Ops（有/無）

- 認可の厳格化（許可範囲を狭める）とフロントのルートガード追加。データ削除・破壊的マイグレーションなし。既存 admin の操作は不変。認可回帰テストで担保する。
