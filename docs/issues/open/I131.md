# I131: organization_id 改名漏れ修正 — 組織スラッグ検証API（validate-slug）が有効組織でも500・新規登録APIが全件400

## 関連資料
- GitHub Issue: #239
- Draft PR: #248
- 発見経緯: I127 手動テスト No.4 実施中に検出（docs/tests/open/I127_manual_test.md 備考・2026-07-19）。登録 API 分（views.py:88・serializers.py:91）は /plan-issue I131 の事前調査（改名漏れの全件 grep・2026-07-19）で発見し実測確認のうえスコープに追加（計画承認済み・plan_I131.md「スコープ判断」参照）
- I127 とは無関係の既存バグ（レート制限導入前から存在）

## 背景/目的

### 現状の問題（証拠・再現手順）
- **validate-slug**: `GET /api/organizations/validate-slug/personal/` → **500**（`{"valid": false, "message": "エラーが発生しました"}`）。有効な組織スラッグでも常に 500。サーバーログ（2026-07-19 実測）: `accounts/views.py:230` で `AttributeError: 'Organization' object has no attribute 'organization_id'`（組織検索成功後のレスポンス組み立てで発生）。
- **登録 API**: `POST /api/auth/register/`・`POST /api/auth/register/<slug>/` → **全リクエストが 400**（`{"error": {"main_message": "エラーが発生しました", ...}}`）。2026-07-19 実測: `accounts/views.py:88` で同一の AttributeError。組織決定（personal 自動選択を含む）成功後・serializer 検証前に落ちるため、ペイロードの有効/無効に関係なく必ず失敗。
- さらに `accounts/serializers.py:91` の `Organization.objects.filter(organization_id=value)` は存在しないフィールド参照のため `FieldError`（shell 実測済み）。views.py:88 だけ修正しても serializer 検証で再び 400 になる。
- **ユーザー影響**: (1) 登録画面の組織URL付き導線（`/register/<slug>`）で組織検証が必ず失敗し「組織の確認中にエラーが発生しました」が表示され続ける（Register.tsx:117-122）。(2) **新規登録の送信自体が全件失敗し、新規ユーザー登録が完全に不能**。

### 根本原因
`Organization` モデルの主キーは `organization_id` から `id` へ改名済み（`backend/accounts/models.py:34`・migration `0021_rename_organization_id_to_id.py`）だが、参照側の**改名漏れが 3 箇所**残った:
1. `backend/accounts/views.py:88` — `organization.organization_id`（登録ビュー・全リクエスト経路）
2. `backend/accounts/views.py:230` — `organization.organization_id`（validate-slug）
3. `backend/accounts/serializers.py:91` — `Organization.objects.filter(organization_id=value)`（登録 serializer の組織検証・FieldError）

いずれも広域 `except Exception` がエラーを 500/400 に丸めるため露見せず、両エンドポイントの自動テストが存在しないため回帰検知の網もなかった。backend 全体の `.organization_id` 参照は全件 grep で分類済みで、上記 3 箇所以外はすべて FK 属性（`user.organization_id` 等）の正当利用（plan_I131.md 調査結果の表参照）。

### 解決方針
- 改名漏れ 3 箇所の参照を現行フィールド名 `id` に揃える（計 3 行）。外部契約（validate-slug のレスポンスキー `organization_id`・登録 API の入力フィールド名 `organization_id`）は互換のため維持（FE は `valid` / `organization_name` のみ参照＝Register.tsx:111-112 のため影響なし）。
- 再発防止として validate-slug ＋登録 API の回帰テストを新規追加（validate-slug: 有効 200・無効 404・非アクティブ 404／登録: 両ルート 201・無効 slug 400）。有効系テストがあれば本バグは即検出できた。
