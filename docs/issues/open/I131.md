# I131: 組織スラッグ検証API（validate-slug）が有効組織でも500 — organization_id 属性誤り修正

## 関連資料
- GitHub Issue: #239
- 発見経緯: I127 手動テスト No.4 実施中に検出（docs/tests/open/I127_manual_test.md 備考・2026-07-19）
- I127 とは無関係の既存バグ（レート制限導入前から存在）

## 背景/目的

### 現状の問題（証拠・再現手順）
- 再現: `curl http://localhost:8000/api/organizations/validate-slug/personal/` → **500**（`{"valid": false, "message": "エラーが発生しました"}`）。有効な組織スラッグ（personal 等・migration 0014 で必ず存在）でも常に 500 になる。
- サーバーログ（2026-07-19 実測）:
  ```
  File "/app/accounts/views.py", line 230, in get
      'organization_id': organization.organization_id
  AttributeError: 'Organization' object has no attribute 'organization_id'
  ```
- ログには「Valid organization found: 個人利用」まで出力されており、組織検索は成功した後のレスポンス組み立てで落ちている。
- **ユーザー影響**: 登録画面の組織URL付き導線（`/register/<slug>`）で組織検証が必ず失敗し、「組織の確認中にエラーが発生しました」が表示され続ける（Register.tsx:117-122 は 404 以外を一律この文言にするため）。組織スラッグ経由の新規登録が実質不能。

### 根本原因
`Organization` モデルの主キーは `organization_id` から `id` へ改名済み（`backend/accounts/models.py:34` に「organization_idから変更」のコメントあり）だが、`OrganizationSlugValidationView`（`backend/accounts/views.py:230`）の参照が旧属性名 `organization.organization_id` のまま残った**改名漏れ**。ビュー全体を `except Exception` で包んで 500 に丸めているため（views.py:239-244）、AttributeError が露見せず残存した。加えて本エンドポイントの自動テストが存在しない（テスト不在で回帰検知の網がなかった）。

### 解決方針
- `views.py:230` を `organization.id` へ修正（レスポンスキー名 `organization_id` は互換のため維持。FE は `valid` / `organization_name` のみ参照＝Register.tsx:111-112 のためキー名変更の影響なし）。
- 再発防止として validate-slug の API 回帰テストを新規追加（有効 slug → 200・`valid: true`・組織名/ID 一致、無効 slug → 404・`valid: false`）。有効系テストがあれば本バグは即検出できた。

| `backend/accounts/views.py`（:230） | `organization.organization_id` → `organization.id`（1 行） |
