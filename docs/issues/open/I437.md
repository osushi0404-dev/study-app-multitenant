## 設計確認メモ（/grill-me）
- 調べて分かったこと（2026-11-12）: 元の 2 か所のほかに、ログに個人情報が残る箇所が 4 種類ある。(1) `backend/core/middleware.py:221` が API の呼び出しのたびに `request.user.email` を `[START] ... - User:` に書く（量が最大）(2) `backend/accounts/views.py:106` が新規登録のたびに `user.email` を書く (3) `backend/core/enhanced_logging.py` の `_safe_body`（228 行目〜）が、エラーになった POST の本文を記録するとき `email`・`first_name`・`last_name`・`user_id`（ログイン ID）をそのまま残し、`refresh`（リフレッシュトークン）も伏せていない（失敗したログインの入力もここに入る）(4) 同 `_log_exception`（180 行目）が `include_locals: True` を常に付け、`_get_error_context`（83 行目〜）がその場の変数を全部 `str()` で記録する。`User.__str__` はメールアドレスを返す（`backend/accounts/models.py:149`）。コメントは「デバッグモード時のみ」だが本番でも動く
- 記録を読む側: `frontend/src/pages/Monitoring.tsx` と `backend/core/views.py` の集計は `user_email` を使っていない（集計は `user_id` で持つ）。外しても読む側は壊れない
- Q: 上の (1)〜(4) をどこまで I437 で直すか → A: 全部 I437 で直す（同じ原因なので、別イシューに分けない）
- Q: エラーの送信内容の記録（(3)）で個人情報をどう扱うか → A: 個人情報の欄だけ伏せ字（`[REDACTED]`）にする。対象は `email`・`first_name`・`last_name`・`user_id`（ログイン ID）、あわせて `refresh` も伏せる。そのほかの入力は原因調べのために残す
- Q: その場の変数を全部記録する（(4)）をどうするか → A: 開発環境（`settings.DEBUG` が真）のときだけ記録する。本番ではファイル名・行番号・関数名・コードの行だけを残す
- Claude が決めたこと: `backend/accounts/views.py:178` の開発時だけの `print`（認証トークンとメールアドレス）は、メールアドレスを利用者 ID に替える（トークンは開発の確認に使うので残す）。`backend/problems/management/commands/import_problems.py:351` の画面出力（運用者が自分で打つコマンドの画面表示でログではない）と、組織名のログ（個人情報ではない）は直さない

## 背景/目的

**背景**: 監視のコードが、エラーなどの記録に利用者のメールアドレスをそのまま入れている（2 か所）。学習アプリの利用者には未成年も含まれうるので、ログに個人を特定できる値を残すのは避けたい。ログは調べものの途中で外に出やすい（イシューへの貼り付け・外部の監視サービスへの送信など）。
**目的**: 監視の記録から、メールアドレスを外し、利用者の ID だけで追えるようにする。

### 現状の問題（証拠・再現手順）
- `backend/core/monitoring.py:173`: `'user_email': user.email if user else None`
- `backend/core/monitoring.py:382`: `'user_email': user.email`
- どちらも、利用者の操作やエラーのたびに記録に入る（記録の出力先は計画で確かめる）

### 根本原因
監視の記録を作ったときに、個人情報を入れない決まりが無かった。

### 解決方針
- `user_email` を記録から外し、利用者の ID（既に入っていなければ足す）で追えるようにする
- grill-me で見つかった (1)〜(4)（設計確認メモ）も同じイシューで直す: (1)(2) はメールアドレスを利用者 ID に替える／(3) は `_safe_body` の伏せる欄に `email`・`first_name`・`last_name`・`user_id`・`refresh` を足す／(4) はその場の変数の記録を `settings.DEBUG` が真のときだけにする
- 上のほかに `backend/` の logger の呼び出しでメールアドレス・氏名などを書いている所が無いかを計画で全件確かめ、あれば同じく直す
- 記録を読む側（`frontend/src/pages/Monitoring.tsx`・`backend/core/views.py`）は `user_email` を使っていないことを確認済み（設計確認メモ）
