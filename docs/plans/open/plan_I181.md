## 1. 背景/目的

**背景**: ハーネス（スキル・スクリプト・レビュー指示など）を少しでも変えると、高リスク判定がファイルの場所だけで YES になる。YES になると `/code-review` は敵対的レビュー（最大 3 周・15 体）を必須にする。1 体あたりの時間の上限は無く、`/code-review` をやり直すたびに周回の数え直しとブランチ全体の見直しが起きる。その結果、1 回の敵対的レビューが数時間〜1 日以上かかることが続いた（I151・I174・I178・I179。イシュー「現状の問題」）。

**目的**:
- 「GitHub が最後の守り」の前提（イシュー「前提」）に合わせて、ハーネスで敵対的レビューを回すのを「GitHub から復旧できない例外」に関わる変更だけにする。
- 回すときも、決まった時間（1 体 15 分・イシュー全体で 2 周）で終わるようにする。
- レビュー工程全体を実測で棚卸しし、小さく減らせるものを減らす。

アプリの高リスク条件（認証・テナント境界・個人情報など）と、その敵対的レビューは変えない（上限だけは共通で適用する）。

### 3-3. 現状のコードの問題（原因の詳細）
**原因の概要**: 敵対的レビューを回すかどうかが「どの場所のファイルが変わったか」だけで決まっていて、その場所の範囲が「GitHub から戻せない変更か」と合っていない。回すときも時間と周回に歯止めが無い。

1. **判定の範囲が広すぎる**: `scripts/claude/code-review.sh:61-70` の `path_risk_trigger()` は、`scripts/claude/hooks/*`・`scripts/git-hooks/*`・`.claude/settings*.json`・`scripts/claude/*.sh`（`tests/` も含む）・`.claude/skills/*`・`.claude/review-agents/*`・`.claude/agents/*`・CLAUDE.md・workflow.md・review-rules.md のどれか 1 つでも変わると YES を返す。LLM 側の条件（`code-reviewer.md:168-169`）も同じ範囲。最終判定は両者の OR（`combine_risk()`）なので、片方を狭めただけでは効かない。
2. **判定の範囲が狭すぎる（漏れ）**: 一方で、I182 で決めた「GitHub から戻せない例外」のうち、`.github/`（ワークフロー・CODEOWNERS）・`.pre-commit-config.yaml`・`.secrets.baseline` は判定に入っていない。
3. **名前変更で判定をすり抜けられる**: `code-review.sh:304` の `GIT_FILES` は `git diff --name-only` で、名前変更は新しい名前だけを返す（3-2 のスパイク）。監視しているファイルを外へ移す（＝その場所から消す）変更が NO になる。今の判定にも同じ穴がある。
4. **計画レビューにハーネスの条件が無い**: `plan-reviewer.md:200-213` の高リスク判定はアプリの条件だけで、ハーネスの例外（ワークフローなど）を変える計画でも HIGHRISK（→ `/security-review`）にならない。
5. **上限が手順に無い**: `code-review/SKILL.md` §3-2 は「最大 3 周・総数 15」だけで、1 体あたりの時間・攻め筋の上限が無い（I174 で 1 体 4 時間 20 分）。周回は `/code-review` 1 回ごとに数え直しになり、やり直しのたびにブランチ全体（`origin/develop` との差分）を見直す。上限到達時は「打ち切り・エスカレーション」だけで、指摘の種類を見て方式の限界を判断する手順が無い（I146 は 8 周、I179 は 11 周）。
6. **レビュー役の資源の上限が無い**: `adversarial-reviewer.md` のツール境界に、判定対象を実行するときのメモリ・時間の上限が無い（I179 第 10 周でメモリを使い切り WSL ごと落ちた）。

### 4-1. `scripts/claude/code-review.sh`
**修正方針**: パス判定の範囲を例外の一覧に置き換え、名前変更で元の場所が落ちないようにする。ほかの関数（`combine_risk`・`adversarial_stage_decision`・`emit_decision_lines`・CI 待ち）は変えない。

```bash
# I086→I181: パス決定論トリガ。「GitHub から復旧できない例外」（docs/runbooks/danger-ops.md
# 「GitHub から復旧できる範囲（I182）」）に関わるファイルの変更だけを強制 YES にする。
# それ以外の手元のハーネス（スキル・スクリプト・レビュー指示・中核文書・テスト）は GitHub が最後の守り
# （docs/runbooks/review-rules.md）なので対象外。LLM 側（code-reviewer.md・plan-reviewer.md）も同じ集合。
# case glob の * は / にも一致するため .github/* はワークフロー・CODEOWNERS を含む配下すべてに一致する。
path_risk_trigger() {
  local files="$1" f
  while IFS= read -r f; do
```
