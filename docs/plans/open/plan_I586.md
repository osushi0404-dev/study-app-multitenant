## 1. 背景/目的
- 開発とは別の勉強用のワークツリー（`study`・このワークツリー）に、ユーザー本人の利用者・組織・科目「データベーススペシャリスト」と、IPA の公開過去問（令和6年度 秋期 午前Ⅱ・25 問）を登録し、ユーザーが毎日の勉強に使える状態にする。使っていて気づいた使いにくさを、イシューの候補として集める
- リポジトリに入れるのは、手順書（`docs/runbooks/worktree.md` に足す節）とこのイシューの記録だけ。問題データ・画像・PDF は入れない（リポジトリは公開）

### 調査結果
**原因の概要**: 本物の問題で、本物の利用者としてこのアプリを使ったことがない。長く残せる勉強用の DB と、過去問を入れる手順・決まりが無かった。

**詳細**:
1. 取り込みの道具 `import_problems`（`backend/problems/management/commands/import_problems.py`）の今の形（I609 の直しの後）:
   - 欄は `**キー**：値` の **1 行** だけを読む（`FIELD_PATTERN`・`:93`、`_extract_fields`・`:213-232`）。問題文・解説に改行は入れられない（入れても 2 行目以降は捨てられる）
   - 選択肢は `- A. 本文` の形（`CHOICE_PATTERN`・`:95`）。A〜D は並び順になり（`order = ord(choice_id) - ord('A') + 1`・`:265`）、画面は `order` の順に出す（並び替えは無い・`grep` で `shuffle` 無し）
   - 難易度はファイル全体の既定値 `--difficulty 1|2|3` だけ（`:296-302`・登録は `difficulty=default_difficulty`・`:422`）。問題ごとの `**難易度**：` は metadata に入るだけで使われない → **難易度ごとにファイルを分けて 3 回流す**
   - 解説・出典は任意（I609・`:186-188`）。出典の上限は 2000 文字（`Problem.SOURCE_MAX_LENGTH`・`backend/problems/models.py:84`）
   - `--skip-duplicates` は同じ科目に同じ問題文があれば飛ばす（`:403-410`）。1 問ずつ `transaction.atomic()`（`:401`）。登録後に一覧のキャッシュを消す（`:446-447`）
   - 画像は扱わない（引数に無い）
2. 画面の表示（`frontend/src/pages/QuizSession.tsx`）:
   - 問題文（`:512-514`）・解説（`:644-646`）は `Typography` でそのまま出し、改行を保つ指定（`white-space: pre-wrap`）が無い → 改行は出ない。1 行で書く形と食い違わない
   - 選択肢は `choice.text` だけを出し、ア・イ・ウ・エの記号を出さない（`:555`）→ 問題文が「ア〜エ」を指すときに対応が分からない。**選択肢の本文の先頭に記号を書く**（下の 9）
   - 問題画像（`:517-521`）→ 出典（`:524`・I609）の順に出る
3. 画像（I587 から DB に保存）: PNG・JPEG・WebP、5MB まで、4096×4096 ピクセルまで（`backend/problems/utils.py:14-24`）。付けるのは問題管理の画面の「問題用画像」欄（`frontend/src/pages/QuizManagement.tsx:709-725`）。解説用画像の欄もある（`:901-`）
4. 会員登録（`backend/accounts/serializers.py:110-136`・I539）: 招待なしで登録すると、本人ひとりの組織を作って本人を管理者（`role='admin'`）にする → 勉強用の組織は確かめ用・E2E の組織と自然に分かれる（C4）。ログインにメールの確認は要らない（`is_email_verified` をログインで見ていない）
5. IPA の PDF: Claude の `curl`（`www.ipa.go.jp`）は 2026-11-22 も 2 回止められた（承認画面は出ず）。ユーザーが `C:\Users\tacic\Downloads` に保存した 2 つを使う:
   - `データベーススペシャリスト2026午前2問題.pdf`（20 ページ・表紙に「令和6年度 秋期 データベーススペシャリスト試験 午前Ⅱ 問題」・問1〜問25）
   - `データベーススペシャリスト2026午前2正答.pdf`（「令和6年度 秋期 データベーススペシャリスト試験 解答例 午前Ⅱ試験」・25 問の正解）
   - 問題冊子は画像の PDF（文字の層が無い）。Read で全ページを読めた。図・表・枠のある問題: 問3・6・7・8・9・10・13・14
6. **スパイク（成立）**: 図の切り出しに使う PDF を画像にする道具（poppler の `pdftoppm`）はホストに無い（`which pdftoppm` 無し・Python の PIL/fitz も無し）。手元にある `python:3.11-slim` の使い捨てコンテナに `apt-get install poppler-utils` で入れ、問題冊子の 4 ページ目を 150dpi の PNG にできた（`.evidence/I586/exam/pages/p-04.png`・Read で問3 の図を確かめた）。`pdftoppm` は `-x -y -W -H` で範囲を切り出せる
7. Playwright MCP（`.mcp.json`）は `--allowed-origins http://localhost:*;http://127.0.0.1:*` で外のサイトを開けない（IPA のページは `ERR_BLOCKED_BY_CLIENT`）。`--secrets e2e/.env.e2e` で、パスワード欄に名前を入れると値に置き換える（`docs/runbooks/frontend-verify.md:39`）。ファイルを渡す `browser_file_upload` は使うたびに確認が出る（同 `:85`）
8. このワークツリーの状態: 直下の `.env` が無い（`wt-ports.sh` を流していない）。Docker のコンテナは動いていない
9. 置き場所: `.evidence/` は `.gitignore:54` で git の対象外。`.evidence/I586/exam/` を作業の置き場所にする（`git check-ignore -v` で確かめた）。サンドボックスの中から書けるのはワークツリーと `$TMPDIR` だけで、`$TMPDIR` は消えうる

- アプリのコードは変えない。手順書に節を 1 つ足し、データは `study` の DB にだけ入れる
- 問題文・選択肢・正解・出典・解説は Markdown（`.evidence/I586/exam/`・git の対象外）に書き、`import_problems` で入れる。難易度ごとに 3 ファイルに分ける

## 5. 実装手順（ステップ）
1. **環境の起動と取り込みの通り道の確かめ（未知リスク先行）**: `study` で `wt-ports.sh`、起動。1 問だけの見本の Markdown を `docker compose cp` でコンテナに渡し、`import_problems --dry-run` が 1 問とパースすること（→ MT-01・MT-02）。`docker compose cp` が通らなければ、`docker compose run --rm -v <絶対パス>/.evidence/I586/exam:/exam:ro backend …` に替える（どちらも DB に書かない試し）。ステップ 5 はこの後
2. **会員登録（ユーザー）**: ここで止めて、ユーザーに 1 つだけ頼む — `http://localhost:<FRONTEND_PORT>/register` で本人の利用者を登録し、`study` の `e2e/.env.e2e` に `STUDY_USER_PASSWORD=<登録したパスワード>` の行を足して、`/mcp` で playwright をつなぎ直す。パスワードは会話に書かない。Claude は Playwright MCP でパスワード欄に名前 `STUDY_USER_PASSWORD` を入れてログインできることを確かめる（→ MT-03）。ステップ 3 以降はこの後
3. **科目の作成と画像を渡せるかの先の試し**: 本人の利用者で科目管理の画面から科目「データベーススペシャリスト」を作る（→ MT-04）。続けて、問題管理の画面の新規作成の入力欄で、`.evidence/I586/exam/pages/p-04.png` を `browser_file_upload` で「問題用画像」に渡し、プレビューに出ることを確かめてから、保存せずに閉じる（→ MT-04b）。渡せなければ、ステップ 7 の前に渡し方を計画変更記録で決め直す。ステップ 2 の後
4. **書き写し・難易度・解説（ステップ 1〜3 と並行してよい）**: 問題冊子・解答例から 25 問を Markdown に書き写す（下の 9 の書き方）。難易度を問題ごとに決め、理由を手動テスト文書の「## 作業の記録」に 1 問 1 行で書く。解説を書く。書き終えたら、Claude とは別の点検役（Agent・時間と見る範囲を区切る）に、問題冊子・解答例・Markdown だけを渡して「解説が解答例の正解を支持しているか・事実の誤りが無いか」を全問見てもらい、指摘を直す（→ MT-05・MT-06）
5. **取り込み**: 3 ファイルを試し実行（`--dry-run`）で件数を確かめてから本番（`--difficulty` 1・2・3・`--skip-duplicates`・`--created-by` は本人のメール）（→ MT-07）。ステップ 1・3・4 の後

7. **画像を付ける**: 問題管理の画面で、8 問に問題用画像を付ける（`browser_file_upload`。使うたびに確認が出るので、始める前にユーザーに予告する）（→ MT-09）。ステップ 5・6 の後
8. **全問の見比べ**: 登録した 25 問（問題文・選択肢・正解・出典・難易度・画像の有無）を API で読み出し、問題冊子・解答例と見比べる（→ MT-10）。ステップ 7 の後
9. **画面で解く**: 本人の利用者でクイズを始め、図の入った問題を含む数問を解き、問題文・画像・選択肢・出典・解説の表示を確かめる。気づいた使いにくさを書き留める（→ MT-11）。ステップ 8 の後
10. **手順書**: `docs/runbooks/worktree.md` に §11 を足す（4-1）（→ TC-01）。ほかのステップと並行してよい
11. **使いにくさの候補の一覧と控えの案内**: レビュー文書に一覧を書く。ユーザーに `bash scripts/claude/db-backup.sh` を案内する（→ MT-12・MT-13）

## 7. ロールバック
- 手順書: PR を戻す（revert）
- データ: `study` の DB にだけある。入れ直すときは、問題管理の画面から問題を消すか、科目を消す（科目を消すと問題も消える・多くの行を消すので `docs/runbooks/danger-ops.md` の承認制。ユーザーの承認を得てから）。消す前に `bash scripts/claude/db-backup.sh` で控えを取る
- 取り込みを途中で失敗したとき: 1 問ずつのトランザクションなので、入った分は残る。`--skip-duplicates` を付けて流し直せば、入っていない問題だけ入る
