## 1. 背景/目的

`docs/runbooks/workflow.md` において、`/retro` スキルが「任意」扱いとなっている。
テスト OK 後に `/retro` を省略されるケースがあり得るため、振り返りが蓄積せず同じ失敗が繰り返されるリスクがある。

`/retro` を「推奨（テスト OK 後は原則実施）」に格上げし、継続的改善サイクルを確立する。

---

## 2. 受け入れ条件（Acceptance Criteria）

- [ ] 省略可能なケース（小規模修正等）の基準が明記されている

## 6. 実装手順

### ステップ 1: workflow.md の変更

**変更箇所 1（フロー step 7 — 行 31 付近）**

修正前:
```
7. OK の場合 /retro I###（任意）または /close I###（open→closed へ移動、PR説明を整備、マージ依頼）
```

修正後:
```
7. OK の場合 /retro I###（推奨: テスト OK 後は原則実施。小規模ドキュメント修正等の場合は省略可）→ /close I###（open→closed へ移動、PR説明を整備、マージ依頼）
```

**変更箇所 2（スキル呼び出し表 — 行 60 付近）**

修正前:
```
| test OK 後 | 「`/retro I###` または `/close I###` を入力してください」と案内 |
```

修正後:
```
| test OK 後 | 「`/retro I###` を入力してください（推奨）。小規模修正等で省略する場合は直接 `/close I###` を入力してください」と案内 |
```
