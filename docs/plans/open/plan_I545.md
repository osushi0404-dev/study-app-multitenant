## 4. 変更点一覧（具体）

### 4.1 規約の新しい形（両方の規約で共通）
修正方針: 「このプロジェクトではこうする」を照合しやすい形に絞る。1 つの決まりは 1 行の言い切り＋（要るときだけ）悪い例・良い例＋公式の文書の URL。

```
# <Django/React> コーディング規約
## 0. 前提の版（点検した日: YYYY-MM-DD）
| 道具 | 前提の版 | 区分（LTS／最新の安定版） | サポートの終わり | 出典（URL） |
## 1. 使う道具（このプロジェクトではこれ）
## 2. 構成（実際のディレクトリと置き場所の決まり）
## 3〜. 決まり（話題ごと。各決まり = 言い切り 1 行 + 例 + 参照）
## N. このアプリの事故から来た決まり（テナント境界・日付・入力の検証 など。元のイシュー番号つき）
## 自動で止める範囲／レビューで見る範囲（今の節を残す。中身と設定の食い違いは #520）
```

### 4.2 使う道具の確定（選択肢を 1 つに決める）
修正方針: 今入っているかを理由にせず、公式の推奨・このアプリの形（Django の API ＋ React の SPA・マルチテナント）で最適なものに決める。実装のステップ 1 で公式の文書で裏付けを取り、取れなければ計画変更記録に書いて決め直す。

| 話題 | 決めるもの | 理由 | 今のアプリとの差 |
|---|---|---|---|
| 画面のビルド | Vite | React の公式が、既存の SPA には Vite などのビルド道具を勧め、Create React App は非推奨 | 差あり（react-scripts） |
| 画面のテスト | Vitest＋React Testing Library＋user-event 14 | Vite と設定を共有でき、Jest 互換の API。Vite を使うなら公式に近い組み合わせ | 差あり（Jest・user-event 13） |
| API の差し替え（テスト） | MSW v2（`http`・`HttpResponse`） | 通信の層で差し替えるので、axios の内部に依存しない。#511 の決定をここで出す | 差あり（axios-mock-adapter・#511） |
| サーバーの状態 | TanStack Query v5 | すでに採用。SWR を消して 1 つに | 差なし |
| 画面だけの状態 | `useState`／`useReducer`、画面全体で共有するものだけ Context。外部の状態管理ライブラリは入れない | このアプリの共有状態は認証・組織などに限られ、Zustand・Redux を入れる理由が無い | 差なし |
| 部品とスタイル | MUI（最新の安定版）と、その `sx`・`styled`。Tailwind・CSS Modules は使わない | アクセシブルな部品がそろい、既に全画面で使っている。入れ替える利点が無い | 版の差（v5） |
| フォーム | React Hook Form＋Zod（`@hookform/resolvers/zod`） | 型をスキーマから導けて TypeScript と二重に書かない | 差あり（yup） |
| ルーティング | React Router（最新の安定版） | 既に採用 | 版の差（v6） |
| グラフ | chart.js（react-chartjs-2） | #516 で決定済み | 差あり（recharts・#516） |
| 部品の書き方 | 関数＋props の型。`React.FC` は使わない | 今の規約 `:293` と同じ・#510 | 差あり（#510） |
| Python の DB ドライバ | psycopg（3） | Django の公式が psycopg 3 を勧める（psycopg2 は旧来） | 差あり（psycopg2-binary） |
| Django のビュー | 同期のビューだけ（WSGI・gunicorn）。async のビューは使わない | 非同期の利点が要る処理は Celery に回す方針 | 差なし |
| 業務の処理の置き場所 | サービス（書き込み）・セレクタ（読み取り）。ビュー・シリアライザーは薄く | 今の規約 §6 を維持 | 一部差（I470 などで進行中） |
| Python のリントと整形 | Ruff | 既に `backend/pyproject.toml`・pre-commit で採用 | 差なし |
| Python のテスト | pytest＋pytest-django | 既に採用（`backend/pytest.ini`） | 差なし |

前提の版（ステップ 1 で点検した日の公式の文書で確定する。ここに書く版は計画の時点の見込み）: Django 5.2 LTS／Python は Django 5.2 が対応する最新の安定版／PostgreSQL・Redis は最新の安定版（Django 5.2 が対応する範囲）／Node.js は最新の LTS／React・TypeScript・TanStack Query・MUI・React Router・DRF・Celery は最新の安定版。
