## 背景/目的

I079 では計画書自身が「deny が broad allow に優先するか」を"最大の未知リスク"と明記していたのに、実証はテスト工程まで先送りされ、結果としてその前提が**不成立**と判明し設計の作り直し（→ フック方式）が発生した。さらに権限/フック挙動の統合テストは稼働中セッションからは観測できず（権限モード・フックのロードに依存）、合否判定が混乱した。

本イシューは、計画・テストが依存する「不確実な外部（ハーネス/FW/ツール）挙動」を、**適切な工程・環境で実証/検証する仕組み**をルール化する（I079 retro 予防処置 P1＋P3 を集約）。**ドキュメント追記のみ**でコード変更は無い。

### 1. `docs/runbooks/plan-writing-rules.md`（「計画書作成前の事前調査（必須）」に新規サブセクション追加）

「環境前提確認（全イシュー必須）」サブセクションの直後（L83 の後）に、以下のサブセクションを追加する:

```markdown
### 外部/ハーネス挙動依存のスパイク実証（計画が「未知リスク」と認識する場合・必須）

計画の正しさが、不確実な外部（ハーネス／フレームワーク／ツール）の挙動に依存し、計画自身がそれを「未知リスク／最大の未知リスク」と認識する場合は、その前提を**スパイク（最小実証）で検証**してから計画を確定する。これは実装手順の「未知リスク先行原則」を計画確定前の実証まで**前倒しで拡張**したものであり（重複定義はせず同原則を参照する）、スパイク可否で次の二分岐に従う。

- **(1) 稼働中セッションで実証可能な挙動**（CLI フラグの効果・フレームワークの戻り値・設定ファイルのパース結果 等）: **計画確定前にスパイクで実証**し、結果（成立／不成立）を計画書「調査結果」に記録する。不成立の場合は設計をやり直してから承認に進む。
- **(2) 稼働中セッションでは実証不能な挙動**（権限モード・フックのロードに依存するハーネス挙動 等）: 計画確定前の in-session 実証はできないため、「未実証」であることを計画書「調査結果」に明記し、指定実施環境（プレーン default の新規セッション／Human 目視）での実証を**実装ステップ1に前倒し**する。ステップ1の結果は後続ステップを止めるゲートとして扱い、不成立なら計画をやり直す。

**スパイク完了基準**: 想定挙動を**実行可能な確認（コマンド出力・Read による観測・CI ログ 等）で再現**し、その結果（成立／不成立）を計画書「調査結果」に記録した時点で実証完了とする（計画者の解釈ゆれ防止）。
```

### 2. `.claude/review-agents/plan-reviewer.md`（「ベストプラクティス」節に gate 追加）

「破壊的取り消し」bullet（L74）の直後に、以下の bullet を追加する:

```markdown
- **外部挙動依存の未実証**: 計画が依存する外部（ハーネス／FW／ツール）挙動の前提が未実証のまま進んでいないか。重大度は条件付き: (a) 計画が「未知リスク」と認識する外部前提が**未実証 かつ 実証手段（実施環境・ステップ）の明記もない**＝**Blocker**、(b) 稼働中セッションで実証可能だったのに未実証＝**Warning**、(c) 実証不能クラスで指定実施環境（プレーン default の新規セッション／Human 目視）＋実装ステップ1への前倒しが明記済み＝**問題なし**。
```

```markdown
### ハーネス挙動テストの実施環境（条件付き列）

ハーネスの**権限モード／フック（hook）／権限プロンプト／settings 権限**に依存する挙動を確認するテストは、稼働中セッションの Claude 実行ではプロンプトの発生源（フックの ask／通常権限／モード）を区別できず検証にならない。これらの TC を含む手動テスト文書では、テーブルに**「実施環境」列**を追加し、該当行に実施環境を明記する。
```

- **自動テスト**（`I082_auto_test.md`）: TC-A1〜TC-A5 を grep ベースの決定論テストとして実施。すべて「規定が文書に存在するか／イシュー番号が混入していないか」を検証する肯定・否定テスト。実装前に全アンカーが不在（NG）であることを確認済み（false-green でないことを実証済み）。
