## 1. 背景 / 目的

`/fix-loop`・`/plan-issue`・`/implement` の3スキルは失敗修正・計画立案・実装の中核フローを担うが、
いずれもセキュリティ・ベストプラクティス・モダン開発の評価軸が手順に明示されていない。
具体的には以下の問題がある。

- `/fix-loop`: 対応案のメリット/デメリット評価軸にセキュリティ観点がなく、修正後チェックがテストのみ
- `/plan-issue`: 計画立案時にセキュリティ影響を確認するステップが存在しない
- `/implement`: 実装後チェックがビルド・型チェックのみで、リント・セキュリティスキャンが未定義

本イシューでは3スキルを改善し、プロジェクトに導入済みのツール（bandit・flake8・eslint-plugin-security）を活用する。

## 4. 変更点一覧

### 4.1 `.claude/skills/fix-loop/SKILL.md`

**変更箇所 ①: Step 2 — 根本原因分析にセキュリティ観点を追加**

```diff
-2) 根本原因を調査・分析して報告（なぜ失敗したか）
+2) 根本原因を調査・分析して報告（なぜ失敗したか）
+   - セキュリティ観点も確認する（認証・認可の欠落、インジェクション、XSS、機密データ露出等に該当しないか）
```

**変更箇所 ②: Step 3 — 対応案の評価軸を明示**

```diff
-3) 対応方法を複数案提示（各案にメリット・デメリットを添える）
+3) 対応方法を複数案提示。各案に以下の軸でメリット・デメリットを添える:
+   - セキュリティ影響（OWASP Top 10 関連リスクの有無、Django / React セキュリティガイドライン準拠）
+   - ベストプラクティス適合（フレームワーク推奨パターン・コーディング規約との整合性）
+   - 保守性・拡張性
+   - リスク・副作用
```

**変更箇所 ③: Step 6 — 修正後チェックにリント・セキュリティスキャンを追加**

```diff
-6) 自動テスト実行
-   - 成功: 手順 7) へ
-   - 失敗: 手順 1) に戻る（ループ）
+6) 自動テスト・リント・セキュリティスキャンを実行:
+   - Backend: pytest / flake8 / bandit
+   - Frontend: Jest / ESLint（eslint-plugin-security 含む）/ npm audit
+   - 成功（警告・エラーなし）: 手順 7) へ
+   - 失敗: 手順 1) に戻る（ループ）
```

**変更箇所 ④: Step 7 — 再発防止記録にセキュリティ考慮点を追加**

```diff
 7) 再発防止記録を docs/tests/open/$ARGUMENTS_auto_test.md に追記:
    - なぜ失敗したか
    - 何を変えたか
+   - セキュリティ上の考慮点（該当する場合）
    - 次回どう防ぐか
```

### 4.2 `.claude/skills/plan-issue/SKILL.md`

**変更箇所: 承認ポイント提示前の必須ステップに「セキュリティ・ベストプラクティスチェック」を追加**

既存の「設計判断の明示チェック（必須）」の直後に以下を追加する。

```diff
+**セキュリティ・ベストプラクティスチェック（必須）**
+計画書の変更点について以下を確認し、該当する項目を承認ポイントに記載する:
+- 入力バリデーション・サニタイズの考慮が含まれているか
+- 認証・認可の変更が適切に設計されているか（最小権限の原則）
+- 機密データ（パスワード・トークン・個人情報）の扱いが適切か
+- OWASP Top 10 関連リスク（XSS・SQLインジェクション・CSRF 等）への対策が含まれるか
+- フレームワーク推奨パターン（Django セキュリティ設定・React のセキュアコーディング）に準拠しているか
+- 追加・更新する依存ライブラリに既知脆弱性がないか（必要に応じて pip-audit / npm audit）
+該当なし（バックエンド・フロントエンドのコード変更がない等）の場合は「セキュリティ影響なし」と明記する。
```
