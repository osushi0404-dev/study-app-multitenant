# plan_I040: /plan-issue に設計インタビュー（Grill Me）フェーズを追加する

## 基本情報
- **計画書ID**: plan_I040
- **関連イシュー**: #84
- **作成日**: 2026-04-12

---

## 背景/目的

現在の `/plan-issue` スキルは、イシューファイルを読んで即座に計画書を作成する。
設計上の曖昧な点を Claude が「平均的な判断」で埋めてしまうリスクがあり、
それが `/fix-loop` 発生の上流原因になりうる。

独立した `/grill-me` スキルを新設し、計画書作成前に設計認識のギャップを解消できる仕組みを追加する。

---

## 設計確認結果（ユーザー承認済み）

- **スキルの形態**: `/plan-issue` への埋め込みではなく、独立スキル `/grill-me` として実装する
  - 単一責任の原則に従い、各スキルが1つの役割に集中する
  - シンプルなイシューはスキップ可、複雑なものは繰り返し実行可能
  - 記事の設計意図（スタンドアロンスキル）に完全に一致する
- **質問の提示形式**: 曖昧な点をすべて番号付きリストで一括提示、ユーザーが一括回答
- **スキップ判定**: 常に実行。質問がゼロなら「設計上の疑問点はありませんでした。計画書作成に進みます。」を表示

---

## 受け入れ条件

- [ ] `/grill-me I###` を実行すると、イシューの設計上の曖昧な点が番号付きリストで提示される
- [ ] 質問はコードベース探索で自己解決できる疑問を除いた「本当に曖昧な点」に絞られている
- [ ] 質問がゼロの場合は「設計上の疑問点はありませんでした。」を表示してスキップする
- [ ] ユーザーの回答を受けて、イシューファイルの「設計確認メモ」に回答内容が追記される
- [ ] `workflow.md` に `/grill-me` がスキルとして追記され、フロー図に組み込まれている

## 実装手順

### ステップ1: `.claude/skills/grill-me/SKILL.md` を新規作成する

**作成内容**:

```markdown
---
name: grill-me
description: Interview the user about design ambiguities before plan creation.
argument-hint: "I###"
disable-model-invocation: true
allowed-tools: Read, Bash, Glob, Grep, Edit
---

# /grill-me

計画書作成前に、イシューの設計上の曖昧な点をユーザーに確認する。

## 実施手順

### 1. イシューファイルを読み込む
\```bash
cat docs/issues/open/$ARGUMENTS.md
\```

### 2. コードベースを探索して自己解決できる疑問を除去する
- 関連スキルファイル・既存コード・runbooks を読み、コードを見れば分かる疑問は除く

### 3. 設計上の曖昧な点を一括提示する

**提示フォーマット**:
\```
## 設計確認（/grill-me I###）

以下の点について確認させてください。

1. [質問1]
2. [質問2]
...

回答いただけましたら `/plan-issue $ARGUMENTS` を実行してください。
\```

設計上の疑問点がない場合は以下を表示する:
\```
設計上の疑問点はありませんでした。
`/plan-issue $ARGUMENTS` を実行してください。
\```

### 4. ユーザーの回答をイシューファイルに追記する

ユーザーが回答したら、イシューファイルの「## 関連資料」セクションの直後に以下を追記する:

\```markdown
## 設計確認メモ（/grill-me）
- Q: [質問1] → A: [回答1]
- Q: [質問2] → A: [回答2]
\```

**質問の観点（該当する場合のみ）**:
- UI のレイアウト・ラベル・フロー（フロントエンド変更がある場合）
- エラー時の挙動・フォールバック方針
- 認証・権限の扱い
- 外部サービスとの統合方針
- パフォーマンス要件・データ量・ページネーション
- 既存機能との互換性・後方互換の要否
```

### ステップ2: `docs/runbooks/workflow.md` を編集する

**スキル一覧への追記**（`/issue-bootstrap` の行の直後）:
```
- /grill-me I### : 計画書作成前の設計インタビュー（推奨。複雑なイシューや設計判断が多いイシューで実行する）
```

**フロー図への追記**（ステップ1と2の間に挿入）:
```
1. /issue-bootstrap → ユーザーがイシューファイル確認（OK/NG）
1.5. /grill-me I### → 設計上の疑問点を解消（推奨・任意）
2. /plan-issue I### → ユーザーが計画書確認（OK/NG）
```

**スキル呼び出しルールの移行テーブルへの追記**:
```
| イシュー作成・確認後 | 「/grill-me I### を実行することを推奨します（複雑なイシューの場合）。準備ができたら /plan-issue I### を入力してください」と案内 |
```
