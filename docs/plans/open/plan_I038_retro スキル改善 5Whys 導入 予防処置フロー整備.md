## 1. 背景/目的

現在の `/retro` は改善案が個別事象にとどまりやすく、根本原因を掘り下げる手法がない。
また是正処置（今回限り）と予防処置（仕組み変更）が混在しており、予防処置を正規フロー（/issue-bootstrap → /plan-issue）で扱う仕組みがない。

**目的**: 5 Whys による根本原因分析と、是正/予防の明示的分離を導入する。

---

## 2. 受け入れ条件

- [ ] `/retro` を実行すると各改善候補に対して 5 Whys（最低 3 Why）が提示される
- [ ] 是正処置と予防処置が別テーブルで明示される
- [ ] 予防処置が現イシューのスコープを大きく外れる場合、`/issue-bootstrap` 実行を促すガイドが表示される
- [ ] 予防処置が現イシューのスコープ内で対応できる場合、現イシューの `/plan-issue` で対応する旨のガイドが表示される
- [ ] SKILL.md の変更案をユーザーに提示して承認を得てから書き込む

## 4. 調査結果

セキュリティ影響なし（Markdown のみ）。

**現在の retro SKILL.md 構造**:
1. git log 確認
2. カテゴリ表で振り返り
3. 改善点テーブル（カテゴリ/内容/改善案/対象ファイル）を出力
4. ユーザーが対応方法を選択（a/b/c）
5. /close を提案

**問題点**:
- 改善案が「この事象の再発防止」レベルにとどまり、なぜその事象が起きたかの根本分析がない
- 是正処置（今回の修正）と予防処置（仕組みの変更）が同じテーブルに混在
- 改善案が個別事象にしか適用できないものにとどまりやすく、根本原因を他のイシューに一般化・ルール化する工程がない
- 予防処置が「issue 化」の場合は `/issue-bootstrap`、「ルール・ドキュメント更新」の場合は `/plan-issue` と案内を分けるべきだが、区別がない
- SKILL.md 変更案を提示せずに書き込んでいた（I037 retro で指摘）

## 5. 変更点一覧と実装手順

### 5-1. ステップ 2.5 を追加: 5 Whys による根本原因分析

改善点の候補が出た後、各項目に対して以下を実施:

```
#### 5 Whys: [改善項目名]
- Why 1: なぜその問題が起きたか？
- Why 2: なぜそうなったか？
- Why 3: なぜそうなったか？
（根本原因に達するまで繰り返す。最低 3 回）
→ 根本原因: [特定した根本原因]
→ 一般化: この根本原因は今回の I### に特有か、他のイシューや今後の作業全般にも起こり得るか？
  - 今回限りの事象 → 是正処置（corrective）
  - 他でも繰り返し起こり得る / プロセス・仕組みに問題がある → 予防処置（preventive）として一般化・ルール化
→ 分類: 是正処置 / 予防処置 / 両方
```

**挿入位置**: 現在の手順 2（カテゴリ振り返り）の後、手順 3（報告）の前。

### 5-2. 報告フォーマットを是正/予防に分離

**変更前**:
```markdown
### 改善点
| # | カテゴリ | 内容 | 改善案 | 対象ファイル |
```

**変更後**:
```markdown
### 是正処置（Corrective）
今回の事象への対処。同じ問題が再発しないための直接的な修正。
| # | カテゴリ | 根本原因 | 対処内容 |
|---|---------|---------|---------|

### 予防処置（Preventive）
仕組み・ルール・スキルの変更により、類似の問題が他イシューでも起きないようにする。
| # | カテゴリ | 根本原因 | 予防策 | 対象ファイル |
|---|---------|---------|--------|------------|
```

### 5-3. 予防処置への対応ガイドを追加

予防処置テーブルの後に以下を追加:

```markdown
### 予防処置への対応

予防処置のスコープに応じて以下の正規フローを使う（インライン修正は禁止）:

**現イシューのスコープを大きく外れるもの**:
→ `/issue-bootstrap [予防策の内容]` で新イシューを起票して正規フローを開始

**現イシューのスコープ内で対応できるもの**（軽微なルール・ドキュメント更新等）:
→ 現イシューの `/plan-issue` または既存計画書の更新で対応

どちらの場合も `/plan-issue-review` → `/implement` → `/test` の正規フローを経由してマージする。
**禁止**: インライン修正（その場での Edit/Write）は禁止。必ず正規フローを使う。
```

### 5-4. SKILL.md 変更案の提示・承認ゲートを追加

是正処置でインライン修正を選択した場合の手順として以下を追加:

```
4) 是正処置としてその場でインライン修正を行う場合は、変更内容（変更前/変更後）を先に提示して
   ユーザー承認を得てから Edit/Write を実行する。承認なしの書き込みは禁止。
   （予防処置は承認ゲートの対象外。必ず /issue-bootstrap → /plan-issue の正規フローを使う）
```
