## 1. 背景/目的

### 原因の概要（平易な説明）
レビュー観点フレームワーク（`review_perspective_framework.md` の P1〜P8）は I043〜I046 で整備されたが、その後に確定した「良い学習アプリの設計思想」（`learning_app_quality_criteria.md` の C1〜C8）のうち **C2（プライバシー・コンプライアンス）に対応するレビュー観点が存在しない**。そのため plan-reviewer / code-reviewer が「同意なき個人情報利用・保持期間超過・削除権の無視・未成年データ配慮漏れ・ポリシー面のテナント混在」といった C2 違反を**構造的に検知できない**。

本イシューは **P9 プライバシー・コンプライアンス**を新設して C2 を検知可能にし、あわせて **C1（学習効果）は意図的に観点化しない**（開発時検証不能・KPI 計測で担保）ことを明文化する。

### 詳細な原因分析
- `review_perspective_framework.md §8`（プロダクト品質基準との対応）で、C2 は「対応するレビュー観点を持たない品質基準」に分類されたまま。I070（commit c8c59bc）が「**P9 の実体追加は I071（#145）で対応予定**」というプレースホルダを §8 に張った段階で止まっている。
- 観点本体（§2 表・§3 詳細・§4 含めないもの・§5 スキル別マッピング）に P9 が無いため、観点を消費する review-agents（`### P〇.`）と plan-issue / implement スキルの P 運用にも P9 が存在しない。
- C2 は最厳格セグメント基準（学校・未成年を含む）では北極星級の必須基準であり、観点欠落＝レビューの盲点となっている。

### 解決方針（修正アプローチ）
P9 を「宣言（framework 定義）」だけでなく「**消費箇所（review-agents の観点列挙・plan-issue / implement の P 運用）を全件**」反映する。具体的には:
1. `review_perspective_framework.md` に P9 を観点本体として追加し、P2 との境界を明文化。§8 のプレースホルダを「追加済み」へ確定し、C2↔P9 を正規の対応表へ移す。
2. `learning_app_quality_criteria.md §6` に C2↔P9 を確定追記し、C1 は「レビュー観点なし（意図的）」と明記。
3. review-agents（plan-reviewer / code-reviewer）に `### P9.` を追加（該当時のみ発火・影響なし明記可）。
4. plan-reviewer の **高リスク判定**（I043 実装分）に P9 のうち「未成年データ・個人情報のテナント越境・目的外利用」を接続し、`/security-review`（I044）対象に含める。
5. plan-issue / implement スキルの P 運用に P9 を反映（plan-issue＝「P9 影響なし明記」運用、implement＝条件付き確認）。
6. 概念変更（P1〜P8 → P1〜P9 / 8観点 → 9観点）に伴う**ライブ消費箇所**を同時更新。

```
### P9. プライバシー・コンプライアンス（ゼロカバー / C2 対応）

**現行**: 確認項目なし（C2 を構造的に検知できない）

```
