## 実装手順

### ステップ1: `plan-writing-rules.md` の「5) 実装手順（ステップ）」直下に3原則を追記する

**挿入位置**: 8〜9行目の既存記述の直後

**追記内容**:

```markdown
   - **垂直スライス原則**: 特定レイヤー（DB層だけ・API層だけ）を横に広げるのではなく、
     全レイヤー（DB → API → UI）を薄く縦に貫通する単位でステップを切る。
     例: 「ステップ1: モデル追加のみ」ではなく「ステップ1: モデル追加 + API 1本 + 画面への表示」
   - **未知リスク先行原則**: 実現可能性が不確かなもの（新外部サービス連携・未経験ライブラリ等）を
     最初のステップに置く。失敗コストを早期に顕在化させる。
     例: 外部決済 API 連携を含む機能では「ステップ1: 決済 API の疎通確認」を最初に置く
   - **依存関係の明示**: ステップ間のブロッキング関係を明記する。
     例: 「ステップ3はステップ1の完了が前提」「ステップ2とステップ3は並行実施可能」
   - セキュリティ制御（認証・認可・入力バリデーション）は、保護対象の機能と分離してマージしない
   - （各原則はプロジェクトの技術スタックに合わせて読み替える。例: Django + DRF + React の場合、「DB/API/UI」= 「model / viewset / React component」）
```
