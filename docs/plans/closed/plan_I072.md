## 1. 背景/目的

### 原因の概要（平易な説明）
`grep` 等で「存在しない／壊れていない／改変されていない」を判定する決定論テスト（否定・不在・回帰・無改変アサーション）は、**検証対象が壊れても合格（OK）を返してしまう false-green** になりやすい。I071 で実際に2件発生し（plan-reviewer が指摘・修正済み）、「正常時に OK」だけ確認され「異常時に NG」が未検証だった。現行ゲートはこの失敗注入検証を一般化された形で要求していない。

本イシューは、do（提出前の自己検証）と gate（レビューでの捕捉）の2層で false-green を防ぐ仕組みを指示ファイルに追加する。

### 詳細な原因分析
- 「文書品質ゲート」チェックリスト（lint 異常系項目を含む）の実体は **`.claude/skills/plan-issue/SKILL.md`（L169）にのみ存在**し、`docs/runbooks/plan-writing-rules.md` には無い（grill-me I072 Q1 で確定。当初イシューの前提は逆だった）。
- 既存の lint 異常系項目は「lint / 静的解析ツールの異常系」という**特定ケース**にのみ失敗系実行を求め、grep / 存在否定 / 無改変確認など**一般の決定論 TC** へ一般化されていない。
- この原則は計画書・テスト文書の書き方の正本である `plan-writing-rules.md` に記載が無く、SKILL の checklist のみに留まる。

### 解決方針（修正アプローチ）
2層で配置する（grill-me Q1＝両方／根治）:
1. **(do層・正本)** `plan-writing-rules.md` のテスト品質ルール群に、false-green 禁止の**一般原則を新規追加**。
2. **(do層・強制チェック)** `plan-issue/SKILL.md` の文書品質ゲート L169 の lint 異常系項目を**一般形へ更新**（lint 異常系を特例として包含）。
3. **(gate層)** `plan-reviewer.md`・`code-reviewer.md` の P4 テスト妥当性観点に false-green 検出 bullet を追加。
- 文言は I071 固有語（grep の具体例は可だが P9 / VERDICT / HIGHRISK 等の I071 固有トークンは含めない）を避けた一般形で記述する（grill-me Q2）。

## 4. 変更点一覧（確定文面）

### 4.1 `docs/runbooks/plan-writing-rules.md`（do層・正本／新規サブセクション）
L148「lint/audit/scan 系ツール導入時の副作用事前調査」サブセクションの直後（L150 の `---` の前）に追加:
```
### 否定・回帰系の決定論テストの自己検証（false-green 禁止）

否定・不在・回帰・無改変を検証する決定論的な合否判定テスト（`grep` 等で「存在しない」「壊れていない」「改変されていない」を判定する TC、lint / 静的解析ツールの異常系を含む）は、**失敗条件を注入して実際に不合格（NG / 非ゼロ終了）になることを確認してから採用する**。

- 正常系で合格（OK）を返すことだけを確認した TC は、検証対象が壊れても合格を返す **false-green**（見かけ上のゲート・実体は手続き未満）になり得る。
- 確認手順: 検証対象を一時的に壊した状態（該当行を削除/改変した入力・対象を欠いたダミー等）に対して TC を実行し、**NG（非ゼロ終了）を返すこと**を確認する。確認できない TC は判定ロジックを修正してから採用する。
- これは「検証コマンドを書かない（TC へ昇格させる）」ルールの品質保証であり、昇格させた TC が実際に回帰を捕捉できることを担保する。
```

### 4.2 `.claude/skills/plan-issue/SKILL.md`（do層・強制チェック／L169 を一般形へ更新）
- 旧（L169）: `- [ ] lint / 静的解析ツールの異常系テストがある場合、インプットコードを対象ツールで実際に実行し非ゼロ終了することを確認済みか`
- 新: `- [ ] 否定・不在・回帰・無改変を検証する決定論テスト（grep 等の合否判定 TC・lint / 静的解析ツールの異常系を含む）は、失敗条件を注入して実際に不合格（NG / 非ゼロ終了）になることを確認済みか（正常系で合格するだけの false-green でないか）`
- → lint 異常系（非ゼロ終了確認）を**特例として包含**しつつ一般化。`plan-writing-rules.md` の原則と粒度パリティを保つ。
