## 1. 背景/目的

### 原因の概要
`/retro` の対ユーザー報告・確認が、内部管理用の専門用語（是正処置/予防処置/5 Whys）・記号（C1/P1）・表構成のまま提示されるため、コンテキストを持たないユーザーには読み取りにくい。一方で単純に短く要約すると経緯・理由まで削れてしまう（I104 retro で両方の失敗を実証済み）。

### 詳細な原因分析
- retro SKILL.md（`.claude/skills/retro/SKILL.md`）が「記録用の詳細フォーマット」と「ユーザーへの説明・確認フォーマット」を分離しておらず、手順3（報告）・手順2.5（5 Whys）・手順4/5（確認ガイド）が内部フォーマットをそのまま対ユーザー出力に流用している。
- 「平易さ」と「情報の完全性」を両立させる明示ルールが SKILL.md に無いため、平易化の試みが「省略」に流れる（I104 で再指摘された失敗モード）。
- 根本原因（コードレベル）: SKILL.md 手順3 の報告フォーマット定義（1種類のみ）と、手順2.5/4/5 の提示指示に、対ユーザー向けの提示ルールが存在しないこと。

### 修正アプローチ（全体像）
SKILL.md に「対ユーザー出力の平易化ルール」を独立セクションとして追加し、手順2.5/3/4/5 の各提示箇所に適用指示を追記する。**報告は「平易版 → 詳細版（既存フォーマットの表）」の順で併記**し、詳細版・分析ロジック・承認ゲートは一切変更しない。記録ファイルの新設はしない（/grill-me 設計確認メモで確定済み）。

### 調査結果（事前調査）
- **環境前提確認**: 変更は Markdown（スキル指示文）のみ。前提ツールは grep / bash のみで、ホストで動作確認済み（下記ベースライン実走）。新規インストールなし。
- **決定論ゲートのベースライン実走（2026-07-15・TDD Red の確認）**: 実装で追加する文言 10 件（G1〜G10）を現状の SKILL.md に grep → **全件 NO-HIT（exit 1）**。ゲートが「文言の不在」を確実に検知できることを実装前に確認済み。
- **false-green 注入検証（維持系・2026-07-15 実施済み）**: 維持対象の既存文言 4 件（R1: 是正処置表ヘッダ／R2: 予防処置表ヘッダ／R3: 「5 Whys の実施（最低 3 回）」／R4: 「**承認ゲート**」）は現状 HIT。**該当行を削除した一時コピー**（実ファイル無改変・scratchpad 上）に対して grep → **全件 NO-HIT（exit 1）**。維持検証も false-green ではないことを確認済み。
- **既存テストの事前実行**: 本イシューはアプリコード・アプリテストに触れない（スキル Markdown のみ）ため、backend pytest / frontend Jest のベースライン実行は対象外。既存の `scripts/claude/tests/*.sh` 群には影響しない（新規スクリプトを 1 本追加するのみ）。

- **スパイク**: 外部・ハーネス挙動への依存なし（未知リスクなし・スパイク不要）。

## 4. 変更点一覧（具体）

### 4-1. `.claude/skills/retro/SKILL.md` — 新セクション「対ユーザー出力の平易化ルール」追加
**修正方針**: 平易化の原則を 1 箇所に集約定義し、各手順からは適用指示で参照する（重複定義を避ける）。挿入位置は導入文（「対象イシューの対応全体を振り返り〜」）直後・「## 手順」の直前。

```markdown
## 対ユーザー出力の平易化ルール（手順2.5/3/4/5 共通・必須）

ユーザーへの報告・確認（チャット出力）は以下に従う。記録・分析の内部手続きは変えない。

1. **提示順**: 平易版を先に提示し、その後に詳細版（内部管理フォーマットの表）を併記する。詳細版を省略しない（チャットが唯一の記録のため）。
2. **置換（省略ではない）**: 専門用語・内部記号は平易な言葉に置換する（省略ではない）。
   - 例: 「是正処置（Corrective）」→「今回の問題への直接の対処」／「予防処置（Preventive）」→「同じ問題を次回から防ぐ改善」／「5 Whys」→「なぜを繰り返す原因分析」
   - 内部記号（表の # 列の C1・P1 等）は平易版では使わず、内容そのもので示す。
3. **経緯・理由を残す**: 各項目に「何が起きたか・なぜそうするのか」（経緯・理由・判断根拠）を一言添える。過度な要約で情報を削らない。
4. **記録は詳細維持**: 記録ファイル（`docs/reviews/` 等）は詳細フォーマットを維持する。本スキルへの記録ファイル新設はしない（詳細版はチャット併記で残す）。＝「資料は詳細・対話は平易」。
5. **平易化の対象外**: コマンド名（`/issue-bootstrap` `/plan-issue` 等）と選択肢記号（a/b/c）はユーザーの入力に必要なため平易化の対象外とする（説明文のみ平易化する）。

**文例（変換前→変換後）**:
- 変換前: 「予防処置（Preventive）P1: 根本原因は grill-me の確認観点に運用設計の項目がなかったこと。grill-me/SKILL.md に観点を追加する。」
- 変換後: 「同じ問題を次回から防ぐ改善: 設計の確認をするとき、運用まわり（ログの残し方や失敗時のやり直しなど）を尋ねる項目がそもそも無かったため、問題を事前に見つけられませんでした。確認項目に追加して、次のイシューからは自動的に確認されるようにします。」
```

### 4-3. 手順3 — 報告を「平易版 → 詳細版」の併記に変更
**修正方針**: 冒頭行「3) 以下の形式で報告する:」を「3) 報告は**平易版 → 詳細版の順で併記**する（平易化ルール参照）。まず平易版:」に変更し、平易版フォーマット（下記）を追加。既存の詳細フォーマット（是正/予防の表）はその直後に「続けて詳細版（記録用フォーマット・変更しない）:」として**無改変で維持**する。

```markdown
   ## $ARGUMENTS 振り返り（かんたんなまとめ）

   ### 良かった点
   - [内容]（理由: なぜ良かったか）

   ### 今回の問題への直接の対処
   - [何が起きたか]。[なぜ起きたか（経緯・理由）]。→ [どう直すか・なぜその方法か]

   ### 同じ問題を次回から防ぐ改善
   - [何が起きたか]。[なぜ起きたか（経緯・理由）]。→ [どのルール・スキルをどう変えるか]
```

### 4-4. 手順4 — 予防処置ガイドの提示前指示（ガイドブロック直前に追記）
**修正方針**: ガイド本文（コマンド名・正規フロー・ハンドオフ invariant）は無改変。提示のしかたを記入例つきで追記する（手順3 のテンプレートと粒度をそろえる・plan review Warning 対応）。

```markdown
   提示の際は、まず各予防処置を「どんな問題を、どの仕組みの変更で防ぐのか・なぜその変更にしたのか」が分かる平易な文で説明し、そのうえで以下のガイドを提示する（コマンド名は平易化の対象外・そのまま示す）。
   記入例: 「同じ問題を次回から防ぐ改善が 1 件あります。設計確認のときに◯◯を尋ねる項目が無かったため見逃しが起きたので、確認項目に追加します。以下のどちらの進め方にするか選んでください。」
```

### 4-5. 手順5 — 是正処置の選択肢提示前指示（選択肢ブロック直前に追記）
**修正方針**: a/b/c の選択肢・承認ゲートは無改変。提示のしかたを記入例つきで追記する（手順3 のテンプレートと粒度をそろえる・plan review Warning 対応）。

```markdown
   提示の際は、各是正処置について「何が起きて、どう直すのか・なぜその方法にしたのか」を平易な文で添えてから、以下の選択肢を提示する（a/b/c の記号とコマンド名はそのまま）。
   記入例: 「1 件目: ◯◯が△△のまま残っていました（原因: □□を確認する手順が無かったため）。××の方法で直すのが安全です。対応方法を a〜c から選んでください。」
```

### 4-6. `scripts/claude/tests/test_i114_retro_plain_output.sh`（新規・決定論ゲート）
**修正方針**: AC の「（決定論チェック）grep で確認できる」を、リポジトリ既定の決定論ゲート方式（`scripts/claude/tests/`・I107/I109 と同型）で実装する。追加文言 10 件（G1〜G10）の存在＋既存詳細フォーマット 4 件（R1〜R4）の維持を検証し、1 件でも欠けたら非ゼロ終了。false-green 注入用に検証対象を環境変数で差し替え可能にする（I109 と同方式・実ファイル無改変で注入検証できる）。

```bash
#!/bin/bash
# I114 決定論ゲート: retro SKILL.md の平易化ルール文言の存在＋既存詳細フォーマットの維持を検証
set -u
SKILL="${I114_TEST_SKILL:-.claude/skills/retro/SKILL.md}"
NG=0
req() {
  if grep -Fq -- "$1" "$SKILL"; then echo "OK: $2"; else echo "NG: $2"; NG=$((NG+1)); fi
}
# G系: I114 で追加する平易化ルール文言
req "平易版を先に提示し、その後に詳細版" "G1 提示順（平易版→詳細版の併記）"
req "平易な言葉に置換する（省略ではない）" "G2 置換原則（省略ではない）"
req "過度な要約で情報を削らない" "G3 経緯・理由の保持"
req "詳細フォーマットを維持" "G4 記録は詳細維持"
req "本スキルへの記録ファイル新設はしない" "G5 記録ファイル新設なし"
req "経過（Why の連鎖）の提示を維持" "G6 5 Whys 経過維持・用語のみ平易化"
req "平易化の対象外" "G7 コマンド名・選択肢記号は対象外"
req "変換前" "G8 文例（変換前）"
req "変換後" "G9 文例（変換後）"
req "平易版 → 詳細版の順で併記" "G10 手順3 の併記指示"
# R系: 既存詳細フォーマット・分析手続きの維持（無改変検証）
req "| # | カテゴリ | 根本原因 | 対処内容 |" "R1 是正処置の詳細表ヘッダ維持"
req "| # | カテゴリ | 根本原因 | 予防策 | 対象ファイル |" "R2 予防処置の詳細表ヘッダ維持"
req "5 Whys の実施（最低 3 回）" "R3 5 Whys 内部手続き維持"
req "**承認ゲート**" "R4 手順5 承認ゲート維持"

if [ "$NG" -gt 0 ]; then
  echo "RESULT: NG ($NG 件)"
  exit 1
fi
echo "RESULT: OK (14/14)"
```

## 8. Risk & 回避策
- **リスク1: 平易版の追加で retro 出力が長くなる** → 平易版は各項目 1〜2 文の要約構成（テンプレートで固定）。詳細版は従来どおりで増分は限定的。分かりにくさの解消が主目的であり、ユーザー決定（案B: 併記）に沿う。
