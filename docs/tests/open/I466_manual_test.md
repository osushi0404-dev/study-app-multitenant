# I466 手動テスト: 間違い分析と苦手を優先した出題を画面につなぐ

手順は `docs/runbooks/frontend-verify.md`（Playwright MCP・幅 1440×900・画像は `.evidence/I466/`）。アカウントは確かめ用の利用者 `verify_i487@example.com`（専用の組織・科目「確かめ数学」「確かめ英語」各 20 問・起動のたびに答えが作り直される。パスワードは秘密の名前 `E2E_TEST_PASSWORD`）。

準備（test-gate の最初に Claude が行う）: 確かめ用データを作り直す（`docker compose run --rm --no-deps e2e-init python manage.py seed_dashboard_verify --password-env E2E_TEST_PASSWORD`。問題はすべて初級・正答率 60% 前後・毎回違う数）。データを手で足さない（ループでの一括作成は見張りが承認を求めるため・plan 計画変更記録）。期待値は、画面の集計の関数を使わずに shell の読み出しで数える: 全科目の難易度ごとの解答数・正解数（5 問以上・70% 未満のもの）、直近 30 日の解答数・間違いの数・`time_taken > 0` の答えの平均（300 秒で頭打ち）・平均の半分未満の間違いの数、科目ごとの「最後の答えが不正解の問題のうち最後の答えが最も古いもの」。
上級が苦手になる形・急いだ間違いが 25% 以上になる形は、単体テスト（TC-02・TC-04・TC-20・TC-21）が受け持つ。
