## エラー対応

### 発生したエラーの詳細

**エラー内容**: 問題管理画面でsubject_id=20（104件）を選択すると「問題が見つかりません」が表示される

- **エラーの種類**: データ表示不整合（エラーメッセージではなくUX問題）
- **発生状況**: 初回実装（plan_I025_問題管理API改善.md）のテスト時
- **環境**: ブラウザ（フロントエンド）、問題管理画面
- **影響範囲**: 20件を超える問題を持つ科目の全問題が表示できない

### エラーの原因

**根本原因**: バックエンドとフロントエンドのページネーション戦略の不整合

1. **バックエンド側**（`backend/problems/views.py:130`）:
   - `self.paginate_queryset(queryset)`により、デフォルトで20件ずつページネーション
   - レスポンス形式: `{"count": 104, "next": "...", "results": [20件]}`
   - subject_id=20には104件あるが、最初の20件のみ返却

2. **フロントエンド側**（`QuizManagement.tsx:186, 434`）:
   - `response.data.results`から20件のみ取得して`problems`ステートに設定
   - クライアントサイドページネーション（`.slice()`）で表示
   - 全データを期待しているが、20件しか持っていない

3. **原因箇所**:
   - `backend/core/settings.py:149` - `'PAGE_SIZE': 20`
   - `backend/problems/views.py:130` - `page = self.paginate_queryset(queryset)`
   - フロントエンドとバックエンドの設計方針が統一されていなかった

### 実施した対応

**対応1: バックエンド修正**

**修正ファイル**: `backend/problems/views.py`

**修正内容**:
1. `ProblemViewSet`に`pagination_class = None`を明示的に設定
2. `list()`メソッドからページネーション処理を削除
3. 全データを配列形式（`[...]`）で返却
4. パフォーマンス監視ログ追加
5. docstring追加（将来の拡張性コメント）

**修正前**:
```python
def list(self, request, *args, **kwargs):
    queryset = self.filter_queryset(self.get_queryset())
    page = self.paginate_queryset(queryset)  # ← ページネーション実施

    if page is not None:
        serializer = self.get_serializer(page, many=True)
        response_data = self.get_paginated_response(serializer.data).data
    else:
        serializer = self.get_serializer(queryset, many=True)
        response_data = serializer.data
```

**修正後**:
```python
def list(self, request, *args, **kwargs):
    # ページネーションを無効化して全データを取得
    queryset = self.filter_queryset(self.get_queryset())
    serializer = self.get_serializer(queryset, many=True)
    response_data = serializer.data

    # パフォーマンス監視
    elapsed = (timezone.now() - start_time).total_seconds()
    if elapsed > 2.0:
        logger.warning(f"Slow API response: /api/problems/ took {elapsed:.2f}s")
```

**修正理由**:
- 問題管理画面では全問題を一度に取得し、フロントエンドでクライアントサイドページネーション実施する方針を採用
- UX向上：ユーザーはフィルタ後の全データをすぐに閲覧・ページ切替可能
- シンプルさ：フロントエンドの既存実装を活かせる
- キャッシュ効果：2回目以降は全データがキャッシュから即座に返却

**動作確認結果**:
- subject_id=20: 104件すべて取得成功
- HTTPステータス: 200
- レスポンス時間: 初回111ms、2回目18ms
- レスポンス形式: 配列（`[...]`）で統一

**対応2: フロントエンドUX改善**

**問題**: 科目切り替え時にページ番号がリセットされず、データが表示されない

**修正ファイル**: `frontend/src/pages/QuizManagement.tsx:163`

**修正内容**:
```typescript
// フィルタ変更時に問題を再取得し、ページをリセット
useEffect(() => {
  if (subjects.length > 0) {
    setPage(0);  // ← ページを1ページ目にリセット
    fetchProblems();
  }
}, [filterSubject, filterDifficulty]);
```

**修正理由**:
- 科目切り替え時に`page`状態が保持されると、前の科目のページ番号で新しい科目を表示しようとする
- 例：AWS（6ページ）で5ページ目→数学（1ページ）切り替え時、5ページ目を表示しようとして空表示
- `setPage(0)`で常に1ページ目から表示することで、自然なUXを実現

**動作確認結果**:
- ユーザー確認：OK
